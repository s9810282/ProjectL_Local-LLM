## 원문

입력 유지 방식에 동의한다.
명령·자동 진행은 등록 조건이 실행까지 유지되는 것을 전제로 한다. 해당 호출에서 처리 기록이 남지 않으면 Flow가 정지하는 방식에 동의한다. 미리보기의 교체·취소는 정상으로 처리한다.

호출 한 번에 최종 결과 하나를 게시한다.
여러 명령을 한 번에 처리하지 않는다. 이동·피해·반사·사망 등 한 처리에서 발생한 사건은 결과 하나의 사건 목록에 담는다. 자동 진행 한 단위의 구체적인 범위는 Core 구현 시 공유한다.

결과 순번의 원본은 CombatStateBuffer의 발행 카운터로 둔다.
CombatResult.Sequence는 그 발행 번호를 담는다. 결과·순번·관련 상태를 함께 반영하며, 결과가 존재할 때 두 번호가 다르면 오류로 판단해도 된다.

결과 없음과 양수 순번이 함께 존재하는 상태는 정상이다.
이전 전투의 결과를 View와 Flow가 소비한 뒤 정리하면, 결과는 없어도 마지막 발행 번호는 유지한다. 다음 전투 준비 후 첫 결과가 나오기 전에도 이 상태가 가능하다. View의 확인 번호도 유지하므로 이전 결과를 다시 기다리지 않는다. 실제 정리 시점은 F2에서 맞춘다.

정상 자동 진행에서는 거절로 전투를 멈추지 않도록 한다.
활성 유닛 없음처럼 정상적으로 발생하는 상황은 기존 게임 규칙에 따른 처리 완료와 다음 국면으로 표현한다. 자동 진행 거절은 계속 진행할 수 없는 것으로 정의된 경우에 사용하고, View가 정지시키는 방향에 동의한다. 예상 밖 예외는 거절로 위장하지 않고 전파한다. Timeline.NoActiveUnit은 테스트 예시였으며 실제 정지 정책이 아니다.

실제 명령·미리보기·자동 진행 API 구현은 현재 Core 계획의 Task 7이다. Task 5 완료만으로 Job 연결을 시작하는 일정은 조정해주삼
