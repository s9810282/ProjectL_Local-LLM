# 공격 시 선행 특성 연출 기준 공격 애니메이션 시작 시점 계획 (2026-11-10)

설계: [공통 공격 애니메이션 시작 시점](../specs/2026-11-10-pull-attack-animation-sync-design.md).

**현재: P0 조사·설계 완료, P1~P4 코드 완료·Unity 컴파일 확인. P5 수동 확인 일부 진행, 운영 값 설정·잔여 회귀 확인 대기.** 사용자가 “P3·P4를 함께 구현하고 한 번에 리뷰”를 승인하여 예약·합류와 피해 Gate·취소를 함께 연결했다. 이어 “너가 유니티에서 확인해줘” 지시로 직접 Unity를 조작했다. PullApplied의 아군 0초·적 3초 설정 재생을 확인했으며 임시 SO 값은 원본으로 복구했다. 아래 단계별 컴파일 미확인 기록은 당시 상태이고 최신 증거는 Unity 직접 확인 기록을 따른다.

## P0 — 범위 재조사 (완료)

- 현재 지원 대상은 Pull/PullApplied, Vanguard/AttackGranted, CleanSweep/AttackGranted다. 카우보이 유닛 키로 제한하지 않는다.
- 공격 생성자 → 요약 조립 → 사건/전이 보관 → 합성 → CombatStateBuffer 공개까지 동일 발동 객체 참조가 유지됨을 확인했다.
- 해당 공격 요약과 사건의 동일 참조, 선행 사건 인덱스, 대상 발동 분류를 함께 사용하면 현재 범위의 소속을 판정할 수 있다.
- 단순 요약 membership + 앞쪽 순서만 사용하면 Hunter 재선택·당김 중 처치 보상을 잘못 포함할 수 있어 지원 발동 종류를 명시한다.
- 도발·이동·턴·피격·사망·처치·공격 후·추가 공격 시작·가로채기는 새 시작 기준에서 제외한다.
- 광범위 Core 관계 공개를 필수로 요청한 결론을 [경계 인계 §66](../handoffs/2026-09-24-view-core-data-boundary-handoff.md)에서 정정·철회했다. 새 Core 구현 대기는 없다.
- 사용자 선택에 따라 CombatUnitAnimationSO에 시작 모드·기준 TraitActivationKind 하나·지연 시간을 두는 것으로 문서를 갱신했다. 지원 발동 자격/소속을 먼저 판정한 뒤 지정 Kind로 시작 후보를 선택한다.

## P1 — 지원 범위와 결과 대응 (코드 완료, 컴파일 미확인)

사용자 구현 진행 지시를 받았다. 새 Core 계약 인수는 선행 조건이 아니다.

- 지원 발동 분류를 한 곳에 둔다. 효과량·확률·발동 조건을 복제하지 않는다. 설정 가능한 Kind는 이 분류의 종류를 중복 제거해 제공한다.
- 최종 결과에서 명시적 참조 비교로 발동 → 사건 위치 색인을 만들고 AttackResult.TraitActivations와 대응한다.
- 지원 발동 + 동일 참조 + 해당 공격보다 앞선 위치를 모두 요구한다. CombatResult.Attack을 중복 출처로 등록하지 않는다.
- 소속 중복·필요한 발생 누락은 위치를 명시한 검증 오류로 보고한다. 값 비교·근접 사건 추정으로 보정하지 않는다.
- 결과/재생 세대 + 공격 출처 사건 인덱스로 수명을 구분한다. Pull 이동 시작은 AttackResult.Pull과 같은 이동 객체를 보관한 CombatPullEvent에 연결한다.
- 리뷰: 적/아군 Pull, 근원 없는 두 AttackGranted, 다른 아군 발동, 반복 값, 공격 후 발동, Hunter 재선택·처치 보상·도발 제외. 확인된 인메모리 참조 보존 경로의 변화 여부도 점검한다.

### P1 실행 기록 (2026-11-10)

- `Data/View/CombatPresentation/CombatPreAttackTraitKinds`에 지원 쌍 3개를 모았다. `Choices`는 이 목록에서 중복 Kind를 제거해 한 번 만들고 `SupportsKind`도 같은 선택지를 읽는다. P2에서 SO 입력·검사가 사용할 기반이다.
- `ViewSystem/Combat/Playback/Ordering/CombatPreAttackTraitMap.Build(result, generation)`은 최종 사건을 색인하고 공격 사건/공격 결과가 있는 포효 사건의 요약만 대조한다. 최상위 `CombatResult.Attack`, 추가 공격 발동, 가로채기 반응은 별도 출처로 등록하지 않는다. 포효 요약을 읽는 것은 소속 대응이며 포효의 시작 시점을 변경한 것은 아니다.
- `CombatPreAttackSourceKey`는 결과 객체 참조·재생 세대·출처 사건 인덱스를 명시적으로 비교한다. `CombatPreAttackTraitBinding`은 발동 위치와 선택적인 당김 사건 위치만 보관한다. 발동 참조 조회와 당김 사건 인덱스 역조회가 가능해 P2 어댑터에서 목록을 재검색할 필요가 없다. 시간·실행·취소 상태는 추가하지 않았다.
- 동일 값의 다른 발동 객체는 합치지 않는다. 지원 발동의 사건 중복·요약 중복/다중 소속·필요한 참조 누락, 당김 이동 누락/중복/순서 오류는 결과·사건·발동/요약 위치를 포함한 `InvalidOperationException`이다. 공격 뒤 발동은 후보에서 제외하며 정상 조회 실패와 연결 오류를 구분한다.
- Pull은 같은 이동 참조를 사용하며 발동의 행위자·대상·경로 칸을 교차 확인한다. 버프는 발동자와 공격자가 같아야 한다는 조건을 두지 않아 다른 아군의 Vanguard도 연결할 수 있다. 발동 여부·효과량은 재계산하지 않는다.
- `.cs` 4개와 대응 `.meta` 4개를 추가했다. 기존 재생기·SO·에셋·Core는 이번 단계에서 수정하지 않았다. **P1 시점에는 Build 호출자가 없어 플레이 동작과 인스펙터가 그대로였다.** P2/P3에서 새 모드의 시작 통지·수명 소유자에 연결한다. 기본 순차 경로의 필수 검사로 무조건 삽입하지 않는다.

정적 리뷰: 생산자 → 요약 → 사건/전이 → 합성 → Buffer의 참조 유지 경로와 적/아군 공통 Pull, 다른 아군 버프, 제외 Kind/특성 쌍, 참조 중복/누락 분기를 코드로 대조했다. 실행 시험 통과를 의미하지 않는다. 새 파일의 공백·UTF-8/LF·메타 연결과 새 GUID 중복 여부를 확인했다. **컴파일 미확인**, Test 코드·MSBuild·Unity 재생은 실행하지 않았다.

원칙 리뷰: 지원 목록·소속 해석·소속 값의 책임을 분리했다(SRP/SSOT). 지원 범위 추가는 목록, 참조 전달 변경은 대응기에 국한되며 타이머에 특성별 분기를 요구하지 않는다(OCP/독립성). 기존 재생 계약을 변경하지 않았고(LSP), Core Contracts만 읽으며 서비스·전역 등록·구독을 추가하지 않았다(ISP/DIP/FW). 색인은 결과당 한 번 생성할 용도이며 사건·발동·요약·당김 경로의 총 길이에 선형이고 조회는 사전 탐색이다. 실행 측의 세대 변경·해제 연결 검증은 P3/P4에 남아 있다.

사용자 확인: Unity 스크립트 컴파일 오류가 없는지 확인한다. 화면상 새 타이밍 동작은 P1의 기대 결과가 아니며 SO 설정과 타이밍 재생은 후속 Phase에서 제공한다.

## P2 — 애니메이션 입력과 시작 통지 (코드 완료, 컴파일 미확인)

- CombatUnitAnimationSO에 attackAnimationStartMode, attackAnimationStartKind(TraitActivationKind), attackAnimationStartDelaySeconds를 추가한다. 한 클립에 기준 Kind 하나를 설정하고 기본은 기존 순차 모드다.
- 지정 Kind 모드는 FromSelectedTraitPresentationStart다. 인스펙터에서 이 모드일 때 Kind·지연을 편집하도록 하고 선택지는 지원 분류에서 얻는다(현재 PullApplied/AttackGranted). 에디터와 런타임에 Kind 목록을 복제하지 않는다.
- 지정 Kind 모드에서만 공격 클립·유효한 지원 Kind·유한한 0 이상 지연을 검사한다. 클립 길이 이하 제한은 두지 않는다. 기본 모드의 미사용 설정 때문에 기존 에셋을 깨뜨리지 않는다.
- 기존 특성 큐·글자·유닛 행동 실행 시작을 발동에 연결한다. ActivationStart/StateApplied를 구분한다.
- Pull의 큐가 비어 있어도 실제 이동 레인의 실행 시작이 기준이 되도록 연결한다. 특성 자체를 다시 재생하지 않는다.
- 리뷰: 기본 데이터 호환, 지원하지 않는 Kind의 설정 오류, 빈 TraitVisual의 당김, 표시 없는 버프, 다른 아군 발동, 지정 Kind 후보만 전달되는지 확인.

### P2 실행 기록 (2026-11-10)

- SO에 계획의 시작 모드·Kind·지연을 추가했고 `CombatClipAttackData.AnimationStart`로 불변 값을 전달한다. 모드 0은 기존 순차 모드이며 기존 에셋 값은 변경하지 않았다.
- `CombatAttackAnimationStartData`가 모드·Kind·지연 검증의 원본이다. 기본 모드의 미사용 Kind/지연은 무시하고 None/0으로 정규화한다. 지정 모드에서는 지원 Kind와 유한한 0 이상 지연을 요구하고 SO가 공격 클립 존재도 검사한다. 오류에는 필드와 SO 이름이 포함된다. 클립 길이 제한은 없다.
- `CombatUnitAnimationSOEditor`는 지정 모드에서만 Kind·지연을 보여 준다. 선택지는 P1의 `Choices`에서 얻는다. SerializedProperty로 다중 편집·Undo를 지원하며 잘못된 Kind를 자동 덮어쓰지 않는다.
- `CombatPreAttackPresentationStarts`는 결과 시작에 공격자 설정을 읽고 지정 모드가 있을 때만 P1 색인을 만든다. 기본 모드만 있는 결과에는 새 참조 검사를 요구하지 않는다. 소속이 확인되고 공격자의 선택 Kind와 일치하는 통지만 전달하며 다른 아군이 발동해도 공격자 설정을 사용한다.
- 큐는 `TryPlayAccent`로 실제 항목이 있는 실행을 연 경우만 통지한다. ActivationStart는 발동 순간, StateApplied는 기존 상태 반영 뒤의 실행 시작이다. 기존 `PlayAccent` 호출은 유지한다. 큐 내부 지연이나 픽셀 가시성은 추적하지 않는다.
- 텍스트는 `CombatBodyTextWindow.TryShow`에서 표시 대상을 확보해 실행을 만든 경우만 조각의 콜백으로 통지한다. 기존 `Show`도 유지한다. 유닛 행동은 기존 `TryBegin` 성공 뒤 통지하며 몸 없음·대여 실패·생략은 통지하지 않는다. StateApplied 행에 있는 유닛 행동의 기존 실행 순서도 유지한다.
- Pull은 큐/글자/특성 행동을 기준으로 삼지 않고 이동 레인이 배치를 확보해 선행 회전을 포함한 실행을 연 순간 통지한다. 빈 TraitVisual이어도 이동이 기준이다. 기존 속도·경로·완료 흐름은 유지한다.
- 생성·주입·BeginPresentation/최종 Refresh/Cancel 연결은 기존 사건 Presenter가 맡고 기능 판단은 어댑터에 둔다. 캡처한 통지는 결과 참조·재생 세대가 맞아야 전달된다. 전역 서비스·이벤트 구독을 추가하지 않았다.
- **P2는 시작 통지 경계까지다. `BindReceiver`의 예약 소비자는 P3에서 연결한다.** 아직 첫 통지 선택·타이머·조기 실행·합류·피해 Gate를 추가하지 않았으므로 공격 시작은 기존 순차 동작이다. 여러 실제 시작 통지 중 처음 하나만 예약하는 책임은 P3 조정자에게 있다.

정적 리뷰: 기본값 호환, 잘못된 모드/Kind/지연·클립 누락, 빈 큐·텍스트 대상 없음·유닛 행동 실패, Pull 레인 시작, 다른 Kind 제외와 취소 뒤 콜백 경로를 대조했다. 변경된 API의 호출부를 검색했다. 기존 인자 호출을 유지하며 Test 코드는 변경하지 않았다. **컴파일 미확인**이며 MSBuild·Unity 실행은 하지 않았다.

원칙 리뷰: 입력·불변 설정/검증·소속/Kind 연결·연출 실행을 분리했다(SRP/SSOT). 지원 목록 하나가 선택지까지 제공한다(OCP). 기존 기본 모드·완료·대여 흐름과 호출을 유지한다(LSP). 클립 조회와 시작 콜백만 주입하고(ISP/DIP), 기존 조립·수명 소유자를 사용한다(FW/기능 독립성). 결과당 색인을 만들고 선택된 발동의 시작 콜백만 캡처하며 프레임별 검색은 추가하지 않았다.

사용자 확인:

1. Unity에서 스크립트 컴파일 오류가 없는지 확인한다.
2. 유닛의 CombatUnitAnimationSO에서 지정 모드 선택 시 기준 Kind(PullApplied/AttackGranted)·시작 지연이 나타나고 기본 모드에서는 숨겨지는지 확인한다.
3. 기본 모드 공격·버프·Pull·낙석 큐·몸 위 글자가 기존처럼 재생되는지 확인한다. 공유 큐/텍스트 경로는 성공 여부와 통지만 추가한 범위의 회귀 확인이다.
4. 지정 모드를 선택해도 P2에서는 공격 클립이 조기 재생되지 않는 것이 기대값이다. 시각 동기화 확인은 P3/P4 이후다. 이번 작업은 SO 에셋 값을 수정하지 않았다.

## P3 — 예약과 공격 실행 합류 (코드 완료, 컴파일 미확인)

- 지정 Kind와 일치하는 첫 유효 선행 연출 시작 t0 + 지연 d에 클립을 한 번 시작한다. 다른 Kind의 선행 연출은 기준으로 삼지 않는다.
- 원래 공격 사건에 도달할 때까지 일치하는 연출 시작이 없으면 기존 경로를 사용한다. 소속 연결 오류는 정상 미일치로 숨기지 않는다.
- 선행 연출이 먼저 끝나도 남은 지연을 기다린다. 같은 Kind의 두 번째 발동·다른 표시 단계도 타이머를 재설정하거나 클립을 재시작하지 않는다.
- 기존 시간축과 대여 규약을 사용한다. Pose/Clip 충돌이면 기존 행동 완료 뒤 시작하고 지연 진단을 남긴다.
- 원래 공격 사건은 조기 실행에 합류한다. 다른 유닛·다른 공격 실행의 Gate를 우회하지 않는다.
- 리뷰: 0초/양수/긴 지연, 두 Kind가 함께 있는 공격에서 선택한 Kind만 기준, 같은 Kind 복수 발동, 미일치·표시 없음의 정상 재생, 자원 충돌, 중복 클립 없음.

## P4 — 피격 Gate·취소·기존 경로 (코드 완료, 컴파일 미확인)

- 선행 필수 처리와 타격 준비를 모두 기다린 뒤 공격 피해를 해제한다.
- 선행 이동·지형 피해·처치 보상은 원래 순서로 처리하고 조기 클립이 이를 막지 않게 한다.
- 피해 없는 아군 당김은 IsMovementOnly 생략 분기와 합류하되 피해를 만들지 않는다.
- 취소·세대 변경·공격자 사망/제거 시 예약·준비 신호·대여를 반환한다.
- 리뷰: 빠른 타격 신호, 선행 처치, 교착, 소리/효과 중복, 다음 결과 잔여 상태. 추가 공격·가로채기·포효는 기존 경로와 공유 Gate 영향만 필요한 범위에서 대조한다.

### P3·P4 실행 기록 (2026-11-10)

단계 조정: 기존 공격 조립을 그대로 조기 실행하면 즉시 행동 슬롯과 공격 Gate를 열어 선행 당김을 막고, Hit와 수호자 복귀가 너무 일찍 시작될 수 있었다. 사용자에게 이 의존성을 설명했고 **P3·P4 동시 구현·일괄 리뷰**를 승인받았다.

- `CombatPreAttackPlayback`은 첫 유효 시작의 예약 시각, 한 실행, 원래 공격 사건의 합류를 소유한다. 기존 `TickPresentation`의 deltaTime만 누적하며 별도 Update/Coroutine/전역 시계를 만들지 않는다. 같은 공격의 후속 통지는 예약을 재설정하지 않고, 원래 사건이 먼저 들어오면 이후 통지가 기존 경로를 다시 시작하지 못한다.
- `CombatAttackStart`에서 기존 클립 조립을 공유한다. `CombatPieceRunPlayer`는 조기 실행도 같은 실행 목록에서 Tick·대여·회수하지만, 원래 사건 합류 전에는 행동 슬롯에 넣지 않는다. 공격자는 자세/클립을 소유하고 당김 대상의 이동 레인은 계속 진행한다. 원래 공격 사건은 같은 실행을 행동 슬롯에 합류시키며 두 번째 클립을 만들지 않는다.
- `CombatDeferredAttackSource`가 출처 수명만 지연한다. 원래 공격 사건 도착 전에는 실제 `CombatHitGate`를 열지 않는다. `CombatReleasePiece`/`CombatVolleyReleasePiece`는 타격 준비가 먼저 끝나도 합류를 기다린다. **타격 준비 + 합류**가 모두 되면 기존 Release → Hit 순서를 한 번 실행하여 피해·Hit 큐·수호자 복귀를 연다. 원거리 발사/물리 Contact 큐는 기존 클립·투사체 시점을 유지하며 Hit 큐와 구분한다.
- 기본 모드, 지정 Kind 미발동·표시 없음은 기존 경로다. 피해 없는 아군 Pull은 예약이 있을 때만 기존 `IsMovementOnly` 생략보다 먼저 합류한다. Core 피해를 만들지 않고, 해제할 대상이 없으면 기존 Gate의 전체 종료 완료를 사용한다.
- Pose/Clip/Stand/이동 배치 또는 같은 유닛의 실행이 사용 중이면 기존 연출을 우선한다. 공격 조립 전 수호자 반응, 선행 구간의 다른 행동/공격 출처, 공격자 자신의 사실, 공격자의 후속 특성 행동 가능성을 확인한 경우에는 **원래 공격 사건 도착까지 보수적으로 시작을 미룬다**. 특성 행동 조회는 기존 처리기의 같은 연출 줄을 사용하며 타이머에 특성별 지식을 복제하지 않는다. Pull은 실제 이동 사건 뒤만 검사한다. 지연 시 예약당 경고 한 번을 남기며 수호자의 기존 나가기 시간도 유지한다.
- 유닛 표시의 실제 대여 상태가 준비 여부의 원본이다. `HasClip` 조회만 표시 계약에 추가했다. 활성 표시/클립 지원이 없으면 정상 대기처럼 무한 재시도하지 않고 기존 시작 실패와 같이 예외로 드러낸다.
- 사망/필드 제거 사실을 표시하기 전 예약 실행을 취소하고 대여를 돌려준다. 실행 중 표시 대여 상실도 그 예약을 폐기한다. 전투 취소/연결 해제는 재생 세대를 올리고 예약·콜백·실행·출처를 정리한다. 예약이 남은 동안 최종 Refresh/다음 결과를 허용하지 않는다.
- 적용 출처는 **일반 `CombatAttackEvent`**다. P1이 포효 요약을 읽는 것은 소속 대응 검사이며 포효 전용 코드 모션을 일반 공격 클립으로 교체하지 않는다. 추가 공격·가로채기를 독립 시작 기준으로 넣지 않았다.
- 생성과 연결은 기존 Presenter, 시각 예약은 조정자, 채널 소유는 기존 실행, 피해 해제는 기존 Gate가 각각 맡는다. 신규 서비스 등록·Core/Buffer/InGame DB 변경은 없다. 수치 변경은 SO, 지원 발동 확장은 분류/통지, 공격 조립 변경은 기존 공격 조립에 한정한다(SSOT·SOLID·FW·기능 독립성).
- 성능: 결과 대응 색인은 P1과 같다. 예약 시 선행 구간을 한 번 검사하며 특성 행동 줄은 기존 캐시를 사용한다. 비용은 색인 비용 + 예약별 검사 구간 길이의 합이다. 프레임에서는 활성 예약만 순회하고 사건/발동 목록을 재검색하지 않는다. 조기 실행은 기존 실행 목록에 하나만 추가한다. 반복 실패 시에도 별도 클립 실행을 누적하지 않는다.

정적 검토 범위: 호출부·대여 소유자·출처 시작/해제/끝·취소 재진입·원래 사건 참조 유지·기본 선택값을 코드로 대조했다. 변경 코드의 `git diff --check`, UTF-8/LF 및 새 파일의 메타·GUID 중복 검사를 통과했다. **컴파일 미확인**, Test 코드 작성·MSBuild·Unity 실행은 하지 않았다. 기존 사용자 에셋 변경을 유지했고 이번 묶음에서 SO 에셋 값을 설정하거나 커밋·push하지 않았다.

사용자 Unity 확인 기대값:

1. 컴파일 오류 없음. 기본 `AfterPreAttackPresentation`은 기존 순차 공격 유지.
2. 카우보이의 `FromSelectedTraitPresentationStart` + `PullApplied` + 0초에서 실제 당김 이동 시작과 함께 공격 클립 한 번 시작. 빈 TraitVisual도 이동이 기준이다.
3. 양수 지연은 그만큼 뒤에 시작. 지연이 당김보다 길면 원래 공격 사건에서 남은 시간을 기다리고, 같은 Kind 재통지로 시간이 늘어나거나 클립이 재시작되지 않음.
4. 타격 이벤트가 당김보다 빨라도 선행 이동/지형 피해/처치 보상이 먼저 진행되고 공격 피해와 Hit 큐는 원래 공격 도착 이후. 피해 없는 아군 당김은 HP 감소/피격을 추가하지 않음.
5. `AttackGranted`는 Vanguard/CleanSweep의 실제 표시만 기준이며 다른 아군 발동도 해당 공격자의 설정 사용. 표시 없음·미발동·제외 특성은 기존 경로.
6. 같은 공격자의 특성 행동·수호자·끼어드는 추가 공격은 선행 처리 우선 및 지연 경고 한 번. 클립/대여 중복과 무한 대기 없음. 포효·기본 추가 공격은 기존 전용 경로 유지.
7. 긴 지연 중 취소, 재생 중 사망/제거, 전투 재진입 뒤 이전 클립·예약·Hit 신호가 남지 않음. 적/아군 Pull 모두 확인.

위 목록 전체가 통과한 것은 아니다. 이후 직접 확인한 항목은 아래 기록으로 구분한다. P5에서 운영 에셋 값을 변경하면 `DataBaseAssetTests`도 사용자 확인 항목에 포함한다.

### Unity 직접 확인 기록 (2026-11-10)

- 사용자 명시 요청으로 Unity 6000.0.73f1에서 컴파일·Play를 직접 확인했다. MSBuild·Test Runner·새 Test 코드 작성은 하지 않았다.
- 첫 컴파일에서 `CombatUnitAnimationSOEditor.cs`의 네임스페이스 닫는 중괄호 누락으로 CS1513이 발생했다. 누락된 중괄호를 추가하고 Unity Refresh/재컴파일 뒤 오류 0건을 확인했다.
- 기존 Play From Boot 설정(Database, 로드아웃 1, 노드 2, 지정 스테이지 Test 1)을 유지했다. 기본 모드로 Combat 진입·필드/손패 표시를 확인했다. 기본 모드 공격 전체 회귀를 확인한 것은 아니다.
- `CombatUnitAnimation_Cowboy.asset`을 바이트 단위로 백업한 뒤 지정 모드/PullApplied/0초를 임시 적용했다. 아군을 실제로 당기며 카우보이 공격 모션이 재생되고, 완료 후 입력이 다시 열리는 것을 확인했다. 당겨진 아군을 선택해 HP 25/25 유지도 확인했다.
- 지정 모드/PullApplied/3초로 다시 진입했다. 카우보이를 3칸 이동한 뒤 적을 공격했고, 첫 캡처에서 적이 인접 칸으로 당겨진 상태·체력 바 미감소·턴 종료 비활성을 관찰했다. 이후 체력 바가 감소하고 턴 종료와 선택 입력이 복귀했으며 적 선택 정보에서 HP 22/30을 확인했다. 남은 지연 뒤 피해 처리까지 진행되어 멈추지 않는 경로를 확인한 것이다.
- 위 확인은 화면 관찰이다. 정확한 0초/3초 프레임 계측, 내부 실행 횟수, 소리/큐 중복 여부를 계측한 결과로 확대하지 않는다. AttackGranted, 같은 Kind 반복, 미발동/표시 없음, 수호자/추가 공격/포효, 선행 지형 처치, 지연 도중 취소·사망·제거는 아직 미확인이다.
- 재생을 종료해 CombatMapAuthoring 씬으로 돌아왔고 Console 오류 0·경고 0을 확인했다. URP 그림자 아틀라스 해상도 조정 등의 일반 로그는 남아 있다.
- Cowboy 에셋을 백업 원본 바이트로 복구하고 SHA256 일치·해당 에셋 git diff 없음·Unity Refresh를 확인했다. 운영 타이밍 값을 확정하지 않았고 기존 사용자 에셋 변경은 유지했다. 커밋·push하지 않았다.

## P5 — 작업자 값 설정과 Unity 확인 (수동 확인 일부, 운영 값·잔여 확인 대기)

- 작업자가 유닛별 CombatUnitAnimation의 시작 모드·기준 Kind·지연을 조정한다. 카우보이의 PullApplied / 0초 등은 설계 예시이며 실제 에셋 적용은 이 Phase에서 한다.
- 확인: 기본 모드, 지정 Kind 미발동/표시 없음, 적/아군 Pull, 공격 전 버프, 다른 아군 발동, 같은 Kind의 처치/이동 보상 제외, 두 Kind 공존 시 선택한 Kind만 기준, 동일 Kind 반복, 0초/양수/긴 지연, 취소·사망·채널 충돌.
- 카우보이는 시작 타이밍과 올가미 접촉 프레임을 따로 확인한다. 비음수 지연만으로 접촉이 안 맞으면 별도 결정을 받고 클립을 조정한다. 당김 이동을 임의로 늦추지 않는다.
- DB 에셋 변경 시 DataBaseAssetTests를 사용자 확인 항목에 포함한다.

## 제한과 검증

사용자 승인으로 P3·P4를 한 묶음으로 구현했고 후속 요청으로 Unity 컴파일·위 두 Pull 경로를 직접 확인했다. 운영 값 확정과 위에 명시한 잔여 회귀 확인은 남아 있다.

Core·FieldCamera·Architecture 수정, View Test 작성, 전투 View MSBuild, 커밋·push·외부 발송은 하지 않는다. 이번 Unity 직접 확인은 사용자의 명시 요청에 따른 것이며 Test/MSBuild 제한의 해제가 아니다. 향후 깊은 복사/직렬화 복원 등 참조 보존을 바꾸는 결과 경로가 추가되면 대응 계약을 재검토한다.
