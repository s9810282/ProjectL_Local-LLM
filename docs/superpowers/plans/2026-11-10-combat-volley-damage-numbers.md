# 연발 공격의 정수 피해 숫자 — 설계·계획 (2026-11-10)

사용자 요청: Akimbo의 두 투사체는 정상이다. 유닛 피해 숫자를 두 번 나누고, 총 피해 9는 5·4로 표시한다.
이 문서는 2026-11-02 연발 설계 §6의 **숫자 표시** 정책을 변경한다. 실제 피해·체력·피격·사망 및 Core 사건은 그대로다.

## 설계

- 적용 단위는 Akimbo 이름이 아니라 원거리 클립의 `Shots.Count > 1`이다. 단발·근접·코드 모션은 기존 숫자 표시를 유지한다.
- 총량은 결과의 캐릭터 HealthChanged/Died 사건에서 실제 HP 감소량을 읽는다. 기존 `CombatHitFollowUps`의 출처·히트 대상 대응을 재사용하며 별도 근원 추측을 만들지 않는다. 직접 처치(InstantDefeat)는 분할하지 않는다.
- N발이면 `total / N + (접촉 순번 < total % N ? 1 : 0)`. 접촉 순서대로 큰 수를 먼저 표시한다. 9/2=5·4, 8/2=4·4, 1/2=1·0(0은 기존 HUD 규칙대로 숨김).
- 탄별 최초 접촉에서 숫자를 내고, 모든 접촉 뒤 기존 release→Hit→End 순서를 유지한다. 숫자 때문에 체력 사실을 미리 적용하지 않는다.
- 조기 공격은 기존 canRelease가 열릴 때까지 접촉 숫자도 보류한다. 이미 접촉한 수만 합류 뒤 순서대로 표시한다. 별도 타이머·Coroutine은 없다.
- 전용 `CombatVolleyDamageNumbers`가 출처별 사건 참조와 분할 표시 여부를 소유한다. 일반 캐릭터 처리기는 원본 사건으로 중복 숫자를 막는다(위치 보정으로 만들어진 사건과 구별).
- 숫자 준비/출력은 기존 조립에 콜백으로 주입한다. 발사·집계는 HUD와 피해량을 모른다. 결과 시작 때 기존 대응표 구축 뒤 준비하고, 취소 때 참조를 비우며 늦은 콜백은 기존 세대로 거절한다.
- DN1은 유닛 HUD 범위였다. 사용자 후속 요청으로 DN2에서 건물(Structure) 숫자에도 같은 분할 정책을 적용한다. 아래 DN2가 현재 건물 적용 범위다.

## 책임·경계 검토

- SSOT: HP·피해는 Core 결과, 출처 대응은 기존 FollowUps, 발수는 Shots, 접촉 중복 제거는 VolleyReleasePiece, 숫자 분배와 원본 억제는 전용 부품이다.
- SOLID: 숫자 정책을 공격 재생기/Presenter에 넣지 않는다(S). 발수 기반으로 확장하며 Akimbo 분기를 두지 않는다(O). 기존 선택 콜백 기본값을 유지한다(L). 조립은 접촉 콜백만 넘기고 HUD 전체를 넘기지 않는다(I/D).
- FW/JMH: 기존 Presenter 수명과 등록된 유닛 HUD 내부 위젯을 사용한다. 서비스·Builder·Export·UI 등록·Core·Buffer 변경 없음.
- 성능: 결과당 한 번 사건을 색인하고 공격 조립 때 목록을 선택한다. 매 프레임 결과 검색/분할 배열 생성/문자열 생성 없음. 기존 접촉 집계 Tick에서 미표시 접촉만 처리한다.
- 독립성: 분배 규칙 변경은 숫자 부품에, 접촉 시점 변경은 집계에, 표시 모양 변경은 기존 HUD에 머문다.

## DN1 구현·정적 확인

- `CombatAttackPlayback.HitSourceOf`는 기존 FollowUps를 읽기만 한다. Presenter의 `_players.BeginResult`가 공격 후속 표를 만든 다음 숫자 부품이 결과를 읽는다.
- 원거리 조립만 `ContactNumbers`를 요청한다. 단발은 null 콜백이고, 캐릭터 처리기는 원본 사건 기준으로 이미 분할한 숫자만 억제한다. 별도 실행기·서비스·UI 등록·Core 코드 변경 없음.
- 집계가 인덱스별 중복 접촉을 거른 뒤 실제 접촉 순서로 숫자를 낸다. 마지막 숫자 호출 후 기존 release→Hit→End 순서를 유지한다. 숫자 콜백 중 취소 시 상태를 다시 검사한다.
- 조기 공격은 canRelease 이전에 숫자를 내지 않는다. 취소는 기존 재생 세대를 올린 직후 숫자 색인을 비우고, 개별 집계/발사도 기존 취소로 닫는다.
- 정적 확인: 수정한 생성자의 운영 호출자는 Presenter 한 곳, 원거리 조립 호출자는 AttackStart 한 곳이다. Assets/Tests 검색에서 변경한 생성자·집계의 직접 호출은 발견하지 않았고 시험은 수정하지 않았다. `.meta` GUID 단일성·변경 소스 UTF-8/LF·대상 diff 공백 검사를 확인했다.
- 사용자 기존 수정 에셋·CombatMapAuthoring 씬은 건드리지 않았다. 전체 diff 검사에서 해당 씬의 기존 공백 경고가 있어 우리 수정 파일만 별도로 검사했다.

## Phase DN2 — 건물 숫자 연결

사용자 요청: 건물 공격에도 같은 정수 분할 표시를 적용한다. DN1의 사용자 확인 완료는 유지한다.

### 설계·책임 경계

- 기존 `CombatHitFollowUps`는 Structure 사건도 출처/히트 대상으로 대응한다. 이 대응을 그대로 사용해 `CombatVolleyDamageNumbers`의 색인 대상을 확장한다. 분배 공식·접촉 수명·취소·조기 공격 보류는 DN1 한 경로를 공유한다.
- `CombatStructureHitFeedback`에 기존 건물 표시 자격(적 건물, 고유 장애물 제외), 몸 위치 조회, 피격 큐·숫자 출력을 모은다. 숫자만 출력하는 입구를 연발 부품과 공유한다. Core 사실 반영은 기존 Handler에 남긴다.
- 건물 사건 Handler는 마지막 집계 뒤 피격 큐를 한 번 내며, 분할한 원본 사건의 전체 숫자만 억제한다. 실제 HP 반영·파괴·일반 단발/근접 표시 순서(큐→숫자→사실)는 유지한다.
- 기존 Structure 독립 숫자 풀·UI 투영/회수를 사용한다. 숫자마다 별도 대여하므로 파괴 때 건물 모델이 사라져도 기존 표시 수명을 따른다. 새 풀/타이머/서비스/등록은 없다.
- SSOT/SOLID: 피해와 출처 대응은 기존 원본, 정수 분배는 공용 숫자 부품 한 곳, 건물 표시 조건·위치는 전용 피드백 한 곳이다. Handler는 사건 처리만, Presenter는 생성·연결만 맡는다. 기존 Handler 생성자·직접 호출을 유지해 기존 시험의 확인 내용/호출 변경을 피한다.
- FW/성능/독립성: 기존 Presenter의 결과/취소 수명을 재사용하고 등록된 UI 위젯의 풀을 사용한다. 결과 색인은 한 번, 몸 조회는 실제 출력 시점에만 한다. 다른 전투 연출·Core·Framework·FieldCamera는 수정하지 않는다.
