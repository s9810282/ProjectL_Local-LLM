# 토네이도 클릭 도착 범위 — 설계·Task 계획 (2026-11-03)

상태: GH-d 코드 구현·정적 검토 완료. **컴파일 미확인**, Unity 인수 대기. 사용자 요청은 현재 범위 호버를 유지하면서 클릭 시 다음 이동 위치의 범위를 표시하는 것이다.

## 설계

- 호버는 기존 토네이도/하붑/Rider 연막 현재 범위를 유지한다. 토네이도의 비어 있는 영역 칸을 누르면 다음 이동이 끝난 위치의 범위를 고정 표시한다. 고정 중에는 해당 범위가 현재 호버 범위를 대신하며 설명 호버는 계속 동작한다. 통과 경로 전체는 표시하지 않는다.
- 다른 곳 클릭, 취소/포커스 손실/정리, 새 결과·상태, 입력 불허/연출, 공격·배치·아이템·경로 지정 시작에서 고정을 해제한다. 유닛 클릭과 기존 행동 입력을 우선하며 새 공격/이동 명령은 만들지 않는다. 클릭은 기존 입력의 SelectPressed를 사용한다.
- 공개된 `ReadTornadoAreas(Owner.Player)`에서 클릭 칸을 포함하는 활성 Warning 원본만 대상으로 한다. Cooldown에는 아직 난수 방향이 정해지지 않았으므로 미래 범위를 만들지 않는다. 여러 공개 원본이 겹치면 확정된 목적 범위의 합집합을 표시한다.
- Buffer의 StageGimmicks에서 같은 GimmickId/SourceId의 DiagonalDistance를 읽는다. 기존 Core 공개 기하 `TornadoGeometry.Travel`을 호출해 경계에서 잘린 계획 경로를 받고 마지막 중심의 `Footprint`를 표시한다. 실제 `TornadoGimmickRule`도 같은 Travel 함수를 쓴다. View에 방향 선택·경계 절단·반사·난수 로직을 복제하거나 Core 상태를 변경하지 않는다. Warning인데 화살표가 없는 정지 경로는 현재 중심이 다음 중심이다. 전투가 이동 도중 종료되는 경우까지 예측하는 범위는 아니다.
- 목적 칸 수집은 새 CombatTornadoDestinationCells가 담당하고, 환경 범위의 현재/고정 표시 소유자는 기존 CombatEnvironmentHover 하나로 유지한다. 기존 기믹 강조 층/색을 사용하며 별도 UI/서비스/레이캐스트 루프는 만들지 않는다. 생성/연결은 기존 Factory, 입력 전달은 SceneInput이다.
- SSOT: 방향/거리/가시성은 Buffer, 이동 기하는 기존 Core 공개 함수, 고정 선택과 범위 표시 수명은 Hover 객체 한 곳. S/O: 목적 범위 수집을 별도 부품으로 두고 기존 호버/그리기 창구를 재사용한다. L: 기존 유닛 입력/현재 범위/종료 계약 유지. I/D: 작은 칸 목록/기존 입력·표시 계약만 사용하며 새 전역 조회 없음. FW/JMH: 기존 Factory→SceneInput→Hover→SceneDisplay→FieldView 연결, 새 등록/Export/서비스/MonoBehaviour 없음. 기능 독립성: 클릭 목적 범위 변경에 이동 연출·기믹 발동·공격/경로 구현을 수정하지 않는다.

## GH-d 결과

도착 칸 수집 부품과 .meta를 추가했다. 클릭 대기는 칸 하나만 저장하고, 기존 Refresh가 현재 Buffer와 표시 허용 여부를 전달한 뒤 계산한다. 원본 가시성을 먼저 확인하며 Warning/IsActive 조건과 같은 원본 정의를 사용한다. 경계 절단은 Core가 실제 이동에 쓰는 공개 Travel, 영역은 Footprint를 재사용한다. Core/Buffer 파일 수정·InGame DB 조회·Core 상태 쓰기·새 난수 사용 없음.

SceneInput은 기존 Router 처리 전후의 전경 입력 상태를 확인해 기존 동작이 클릭을 쓰면 도착 선택을 하지 않는다. 빈 칸 여부는 기존 CombatCharacterQueries.FindAnyAt으로 확인한다. 클릭 고정 칸은 마우스 좌표와 별개로 유지하며, 현재 Buffer 객체/결과 순번이 달라지거나 표시 불허/전경 활성/정리 시 버린다. 고정하지 않았을 때는 기존 현재 범위와 하붑/DustScreen 합집합 동작을 유지한다. 설명 캐시와 고정 표시 상태는 별개이고 외부 UnHover 뒤에는 기존 포인터 제한을 지키면서 고정 범위만 다시 적용한다.

정적 검토: Router 이후 호출·UI 가림·유닛/행동 우선·Cooldown/배치 제외·정지 Warning·숨김 원본·경계·겹친 원본 합집합·결과/포커스/Stop/Cancel 정리·생성 호출·GUID 고유성·diff 공백을 대조했다. 이동 경로와 현재/목적 영역 계산의 정책을 View에 복제하지 않았다. 기존 Factory 생성/표시 위임 경로와 격자 층을 그대로 사용하여 새 등록/Export/전역 조회가 없다. SSOT/SOLID/FW·JMH/기능 독립성은 위 설계 기준을 유지한다. 새 시험·기존 시험 수정·MSBuild·Unity 실행 없음. **컴파일 미확인**.
