- [x] T6. UnitAuthoringWindow 생성 화면: 원본·짝 Visual·새 enum 이름/숫자·표시 이름·폴더·테이블·출력 경로, 생성·상태·결과 선택 버튼.

## Unity에서 사용자가 확인할 항목

1. Editor 컴파일 성공, 메뉴와 창 열기.
2. 기존 몬스터에서 새 이름·번호로 생성: 컴파일을 거친 뒤 SO 두 개의 동일 키와 각 테이블 단일 등록 확인.
3. 원본 값·GUID 불변, 새 SO GUID 분리, 프리팹·연출 등 공유 참조 보존 확인.
4. 기존 미사용 enum으로 생성할 때 불필요한 소스 변경·재컴파일 없음.
5. 이름·숫자·출력 경로 중복, 짝 Visual 누락, 테이블 모호함, prefab 누락 등에서 명확한 오류와 불완전 등록 방지.
6. 창 닫기·도메인 재로드·중복 클릭 후 중복 생성 없음. 컴파일 오류 후 요청 보존과 재시도.
7. enum 반영 뒤 원본 변경 또는 출력 경로 충돌이 생겼을 때 중단·재검사. 등록 실패 시 생성물 보존·재개, 명시적 취소에서만 작업 소유 에셋·참조 제거.
8. 중단 후 에디터 재시작: 남은 작업 상태를 보여주고 재개 가능. 이미 완료한 단계의 중복 처리 없음.
9. Phase 2에서 능력치·특성·프리팹·아이콘·연출 변경, 저장·Undo·재열기 확인.
10. 실제 DB 에셋을 변경했다면 기존 DataBaseAssetTests 확인. 출현 확인은 별도로 스테이지 배치에 새 SO를 연결한 뒤 Unity 재생으로 수행.

Core enum 변경 허용은 Test 작성·MSBuild 제한의 예외가 아니다. 커밋·push 없음.

## 구현 결과·정적 점검 — 2026-11-10

- 새 C# 6개와 각 .meta: UnitAuthoringAssets, UnitAuthoringOperation, UnitAuthoringPendingStore, UnitAuthoringWindow, UnitAuthoringWindow.Editing, UnitEntityKeySource.
- 직렬화 경로 `key`, `unitVisualData.key`, `unitVisualData.displayName`, `databaseItems`를 현행 SO·Framework 소스와 대조했다. 기존 UnitTraitAuthoringDrawer를 그대로 사용한다.
- 새 파일 UTF-8/LF, 공백, .meta 동반 여부를 정적 검사했다. 기존 Core 인계 문서의 diff 공백 검사도 수행했다. Unity API는 기존 사용처와 공식 문서를 대조했다.
- 컴파일 오류 전 SO 생성 차단, 재로드 후 동일 이름·숫자 확인, 시작·등록 시 재검사 흐름을 검토했다. R1 수정 뒤 일반 실패는 GUID와 완료 단계를 보존하고 명시적 취소만 삭제한다. 강제 종료가 파일 생성·GUID 기록 사이에 발생하는 경우는 자동 삭제하지 않고 경로 충돌로 중단한다.
- SSOT·SOLID·FW·기능 변경 독립성은 설계 §6에 따라 유지했다. 런타임 서비스 등록·Framework/Systems 공개 계약·asmdef·스테이지 도구 변경 없음.
- 실제 EntityKey·SO·테이블·씬·기존 시험은 변경하지 않았다. Test 코드 작성, MSBuild, Unity 컴파일·재생 실행 없음. **컴파일 미확인.** 위 Unity 확인 항목은 모두 사용자 확인 대기이며, 코드 완료와 구분한다.

### 사용자 Unity 확인 — 실행 대기

| 중단/실패 위치 | 기대 결과 |
|---|---|
| Unit 생성 GUID 저장 후 | 재개 시 같은 Unit GUID 유지, Visual만 새로 생성 |
| 두 SO 생성 후 | 재개 전 유효한 값 수정도 유지, 재복제 없음 |
| Unit 테이블 저장 후 / 체크포인트 저장 전 | 현재 참조를 인수하고 중복 추가 없음 |
| 두 테이블 저장 후 / 최종 Complete 저장 전 | 같은 두 GUID·참조를 유지하며 완료만 기록 |
| 완료 기록 뒤 결과 선택 오류 | 생성 완료 상태 유지 |
| 취소 중 한 SO 삭제 후 | 재시작·재개 시 남은 삭제만 실행, 생성 경로 진입 없음 |
| 컴파일 오류 | 자동 후속 생성 없음, 오류 수정 후 재개 가능 |
| 컴파일 성공·재로드 후 요청 키 삭제/개명/번호 변경 | 무한 대기 없이 키 불일치 오류 |
| 완료 이벤트 또는 재로드 미관측 | 컴파일·임포트 중은 대기, 정지 상태의 제한 대기 후 오류 |
| enum 교체 전 종료 | 원본 그대로, 백업/임시 파일만 있을 수 있음 |
| enum 교체 후 종료 | 전체 새 소스와 원본 백업 보존 |
| 교체 직전 다른 작업자의 소스 변경 | 해시 불일치로 중단, 원본 덮어쓰기 없음 |
| StreamingAssets 선택 | enum 변경·생성 전 사전 차단 |
| CreateAsset가 로그만 남기고 실패 | 즉시 생성 오류, 다음 SO 생성·등록 미진행 |

기존 버전 요청은 등록 bool이 없더라도 저장된 GUID와 실제 참조로 재개한다. 소유 GUID가 기록되기 전 강제 종료한 에셋은 계속 자동 인수·삭제하지 않는다. 실제 재현은 하지 않았으며 **컴파일 미확인**이다.
