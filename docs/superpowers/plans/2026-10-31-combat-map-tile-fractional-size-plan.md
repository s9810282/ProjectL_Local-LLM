## 실행 기록

- 시작: 기존 사용자 변경은 보존한다. 에셋 값·프리팹은 수정하지 않는다.
- 구현: `CombatMapTileAlignment`의 정수배 반올림·거절을 제거하고 실수 비율로 넘침을 비교한다. `CombatStageSoTileFit`도 실수 비율을 보관하고 칸 중심으로 타일을 찾으며, 반전 축의 경계 포함 방향을 맞췄다. 경고의 타일 공유 여부도 실제 칸 중심 대응으로 센다.
- 표시: 타일 영역·테두리는 `Rect`로 전달하고, 공용 상자/배치 고스트는 기존 정수 영역을 그대로 Rect로 바꿔 전달한다. DB 툴팁과 도구 도움말을 갱신했다. 데이터 직렬화 형식·에셋 값은 바꾸지 않았다.
- 소수 경계 보완: 처음 수치 대조에서 0.1/0.3 비율의 반전 축 경계가 부동소수점 오차로 런타임/에디터에서 다르게 선택되는 사례를 발견했다. `CombatMapTilesData.TryTileAt`와 에디터 사본이 타일 한 장의 0.0001 이내인 경계에 맞춘 뒤 칸 번호를 계산하도록 보완했다.
- 검증: VS 2022 MSBuild `ProjectL.Systems.csproj`, `ProjectL.Tool.Editor.csproj` Debug 빌드 모두 최종 종료 코드 0. 기존 UI CS0649 경고만 확인했고 변경 파일 오류/경고 없음. 로그는 `Temp/TileSizeFractional-Systems-build.log`, `Temp/TileSizeFractional-Editor-build.log`.
- 수치 검증: 실제 컴파일된 두 어셈블리를 Unity 번들 Mono에서 호출한 임시 harness(`Temp/TileSizeFractional-check.cs/.exe`) **95,628개 확인 통과**. 비율 0.1·0.3·0.5·0.75·1·1.1·1.2·1.25·1.5·2·2.25, 축 교환/각 축 반전, 직사각 타일 맵, 판 안/밖 칸, 기준점 이동·넘침, 정수 비율 회귀, 0/음수/NaN/Infinity 거절, 실수 영역을 대조했다. Fit 객체의 방향/비율은 직접 구성했으며, Of의 Unity Quaternion 계산이나 실제 Transform/씬을 실행한 검증은 아니다.
- 구조 검토: Factory·서비스 등록/Export/조회·수명 변경 없음. 런타임 높이/교체 표의 소유자는 유지했고 Core·FieldCamera·Architecture 변경 없음. 에디터와 런타임 계산 사본은 기존 구조라 두 곳 갱신이 필요하다는 경계를 설계에 기록했다. 타일 외 배치 동작은 영역 표시 형식만 확장했다.
- Unity 에디터 재생·EditMode Test Runner는 미실행. 실제 배경 회전/배율 Transform, 소수 크기의 필드/타일 테두리·높이/바닥 교체, 기존 상자/고스트 표시의 시각 확인은 사용자 인수 때 확인한다. 코드 Phase FT1 종료 보고 지점에서 멈춘다. 커밋·push 없음.
