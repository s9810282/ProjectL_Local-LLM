# 공격 클립 배속 — 설계·계획 (2026-11-10)

사용자 요청: `CombatUnitAnimationSO`에 Attack Speed를 추가하고 발사·이펙트 타이밍도 공격 모션에 맞춘다.

## 설계

- `attackSpeed`는 공격 주 클립/부속 클립의 재생 배율이다. 기본 1, 2는 두 배, 0.5는 절반 속도다. 유한한 양수만 받으며 0·음수·NaN·무한은 데이터 오류로 거절한다.
- SO → 불변 `CombatClipAttackData.AttackSpeed` → 근접/원거리 조립 → `CombatClipPiece` → `CombatClipPlayback`으로 전달한다. 기존 생성자 인자에는 기본 1을 유지한다. 공격 클립이 없는 코드 모션과 피격 클립에는 적용하지 않는다.
- 재생기가 누적하는 **클립 시각**에만 deltaTime × speed를 적용한다. 같은 시각을 `SetTime`과 이벤트 커서에 전달한다. 원본 클립·이벤트 시각은 변경/복사하지 않는다.
- 주 클립·부속 클립·무기 조준 리그는 기존 SetTime을 공유한다. 리그의 조준 구간도 원본 클립 시각을 유지한다. Playable 자체 속도 0과 수동 시각 지정은 유지한다.
- ClipStart/Event/Event2/Event3/End 신호 시각이 함께 변한다. 이 신호에 연결된 발사·이펙트·소리도 따라간다. 실제 Contact/Hit는 기존 투사체 접촉/접촉 집계로 결정되며 피해 숫자도 그 접촉을 따른다.
- `HitDelay`, 큐의 명시적 Delay, 선행 특성 기준 공격 시작 DelaySeconds는 기존 초 단위 계약을 유지한다. 큐는 바뀐 기준 신호 이후 지정한 초만큼 기다린다. 투사체 비행 속도, 파티클·소리 자체 재생 속도, 전투 전체 시간은 변경하지 않는다.
- 기존 SO에 없는 필드는 `attackSpeed = 1f` 초기값을 사용한다. 에셋/애니메이션 일괄 재저장은 하지 않는다. 현재 Editor 코드에 이 SO 필드를 별도로 열거하는 커스텀 인스펙터는 발견하지 않았다.

## 책임·경계 검토

- SSOT: 배속 원본은 공격 SO→불변 공격 값, 클립 시각과 이벤트는 기존 Playback/Timings다. 배속된 이벤트 시각을 다른 곳에 저장하지 않는다.
- SOLID: SO는 입력·검증, 조립은 전달, 재생기는 시간 진행, 클립 채널은 자세 반영을 담당한다(S). 공통 재생기의 선택 배율로 확장하며 유닛별 분기가 없다(O). 기본 1로 기존 피격/직접 호출 계약을 유지한다(L). 좁은 float 인자만 전달하고 Animator/DB를 런타임 재생기가 조회하지 않는다(I/D).
- FW/JMH: 서비스·Builder·등록·Factory·Core·Buffer 변경 없음. 기존 대여·취소·종료 계약을 사용한다. 다른 세션이 수정 중인 조립 실행기/입력/UI 파일은 편집하지 않는다.
- 성능/독립성: Tick에 곱셈 하나만 추가하며 새 할당·검색·타이머는 없다. 이후 속도 조정은 해당 SO에서 끝난다. 투사체·피해·이펙트 수명 코드는 변경하지 않는다.

## AS1 구현·정적 확인

- 기존 소스 6개 수정, 신규 런타임 파일/에셋/씬 변경 없음. SO와 공격 값에 배율을 추가하고 공격 조립 두 곳에서 기존 클립 조각/재생기로 전달했다.
- SO는 `attackSpeed = 1f`와 Inspector Min 0.01을 제공한다. 데이터 생성은 공통 `CombatPresentationValueRules`로 유한한 양수를 검사하며 에셋 이름을 포함해 오류를 낸다. 값/조각/재생기의 직접 생성도 같은 양수 규칙을 사용한다.
- 재생기는 `_time += deltaTime * _playbackSpeed` 후 기존 EndTime 제한과 같은 SetTime/Emit 순서를 사용한다. 커서의 while 소비와 취소 검사를 유지해 한 Tick에서 여러 이벤트를 지나도 기존 순서대로 처리한다.
- 운영 호출 검색: 공격 Data는 SO 한 곳, 클립 조각은 근접·원거리·피격 세 곳, Playback은 클립 조각 한 곳이다. 피격은 새 선택 인자 기본 1을 사용한다. 변경한 생성자의 Assets/Tests 직접 호출은 검색되지 않았고 시험을 수정하지 않았다.
- 조기 공격 지원 코드에 별도 클립 EventTime/EndTime 기반 시계는 발견하지 않았다. 기존 공격 조립으로 연결된다. 무기 조준 리그는 SetTime의 클립 시간으로 보간하므로 조준 시각을 별도로 배속하지 않는다.
- Akimbo의 두 총구 큐는 Cue/Cue2와 Delay 0으로 연결돼 있다. 발사와 같은 클립 신호를 받는 경로를 대조했다. 큐의 명시적 Delay는 기존 초 단위 처리다.
- 대상 diff 공백 검사 및 UTF-8/LF·깨진 문자 없음 확인. 새 서비스/등록·Core/Buffer·UI·다른 세션 수정 파일 편집 없음.
- Test 코드·MSBuild·Unity 재생/컴파일 실행 없음. **컴파일 미확인.** AS1 리뷰 지점에서 중단하며 아래 사용자 확인 대기다.

- 기존 SO의 Attack Speed 기본 1과 기존 재생 유지. Akimbo SO에서 2/0.5 설정 후 각각 빠르게/느리게 재생.
- Akimbo 2배속: 클립 시작 후 첫 발 약 0.4초, 둘째 약 0.633초, 클립 끝 약 0.75초. 각 총구 이펙트와 발사 동기화. 프레임 단위 오차는 기존 재생 방식대로다.
