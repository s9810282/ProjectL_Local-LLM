## 1. 화면 동작

경로가 `A(출발) → B(일반) → C(벽) → D(벽) → E(착지) → F(일반)`이면 다음처럼 표시한다.

1. A→B는 기존 이동.
2. B에서 도약해 C/D에서는 바닥에 내려앉지 않고 E까지 한 번의 호로 이동.
3. E에서 착지한 뒤 E→F는 기존 이동.

떨어진 장애물 구간 사이에 정상 착지 칸이 있으면 도약도 나눈다. 이동 전체를 한 번에 뛰거나, 뛰어넘기 특성을 보유했다는 이유로 모든 일반 칸의 이동 모양을 바꾸지 않는다. 굽은 경로도 Core가 확정한 경유 칸을 따라가며 마지막 도착점만 직선으로 이어 우회 경로를 생략하지 않는다.

## 2. 확인한 현재 구조

| 사실 | 근거 |

## 3. 설계

### LJ-D1 — 도약 구간은 실제 Core 발동으로 정한다

결과 준비 때 원본 사건을 한 번 읽는 불변 `CombatLeapPlan`(가칭)을 만든다. 실제 `Leap / MovementChanged`의 SourceUnitId/TargetCells를 뒤따르는 같은 유닛의 자발적 Moved에 대응한다. 지형/유닛 배치를 View에서 검사해 통과 가능성을 계산하지 않는다.

- 첫 표시 구간은 첫 대응 걸음의 Expected 자리에서 시작한다.
- 연속된 대응 걸음과 바로 다음 자발적 착지 걸음까지 묶는다. 정상 착지 뒤의 일반 걸음은 포함하지 않는다.
- 동일 유닛·배치 연속성·Core 사건 순서를 검사한다. 강제 이동/재배치·사망·필드 이탈·새 행동에서 구간을 끊고, 존재하지 않는 다음 착지 사건을 만들어 내지 않는다.
- Core 결과에서 PositionSwap 전용 재생이 걸음을 소유하면 기존 PositionSwap 보류/순서를 우선한다. 도약과 두 재생기가 같은 위치를 동시에 빌리지 않는다.
- 현재 Core의 같은 발동 표식은 **공개된 지뢰 건너뛰기**도 포함한다. 발동이 실제로 있는 칸은 같은 도약 근거로 취급하고, 숨은 지뢰를 View가 찾아 점프하거나 정보를 노출하지 않는다. 벽/유닛/절벽/지뢰를 구분하는 새 규칙 필드를 View에 만들지 않는다.
- 단순 특성 보유만으로 구간을 만들지 않으므로 장애물 없는 길은 기존 모양 그대로다.

### LJ-D2 — 도약 호 하나를 원본 걸음들에 이어 쓴다

기존 유닛 이동 레인이 원본 걸음을 계속 소비하며, 도약 구간의 시작/끝과 현재 걸음 순서로 전체 호의 진행률을 계산한다. 구간마다 시작 높이·착지 높이·총 시간·최고 높이를 한 번 정하고, 각 걸음에서는 같은 호의 해당 부분만 재생한다.

- 구간 첫 걸음에서 이동 방향을 준비하고, 중간 걸음마다 착지/다시 도약/이동 전 회전을 반복하지 않는다. 곡선 경로의 방향 표시는 실제 경유 순서를 따른다.
- 도약 구간 동안 같은 배치 대여를 유지해 중간 Render가 유닛을 바닥으로 돌리지 않게 한다. 마지막 실제 착지·취소·재배치·사망의 수명 경계에서 반환한다.
- 기존 걸음별 Expected/Final·HP·상태·환경 사건은 원래 순서와 완료 계약으로 소비한다. 다음 중간 사건의 연출을 기다려야 하면 공중 위치를 유지하며, 이를 없애기 위해 중간 사건을 건너뛰지 않는다.
- 원본 Moved/발동을 합성 걸음 한 개로 바꾸거나 결과 끝 사실을 미리 적용하지 않는다. 이동 거리·도착 효과·중단 위치는 원본 Core 사건이 원본이다.
- 중간 피해/사망/추락/토네이도/강제 이동의 원래 표시 수명으로 현재 표시 자세를 넘긴다. 점프 예정 착지 칸까지 먼저 날아간 뒤 과거 사건으로 되돌리지 않는다.
- 일반 걸음의 기존 접촉/자세 대여와 도약의 이어진 대여가 충돌하지 않도록 LJ1에서 `IsActive/CanBegin`·유닛 행동 채널을 대조한다. 다음 원본 걸음과 사실 사건을 진행하면서 다른 자세 대여를 동시에 열지 않는 계약을 구현 전에 확정한다. 필요한 공용 스케줄러 정책 변경이 생기면 구현하지 않고 설계를 다시 검토한다.

### LJ-D3 — 시간·높이는 View 설정 한 곳

전투 연출 설정 `CombatPresentationSettingsData`의 이동 설정에 도약 **구간 전체 시간/높이**를 별도로 둔다(필드명 초안 `leapSeconds`, `leapHeight`). 초기 제안은 0.5초/필드 높이 1이다. 시간은 유한한 양수, 높이는 유한한 0 이상으로 기존 검증 규칙을 재사용한다. 기획 값은 사용자 Unity 확인 후 조정한다.

`CombatEventPresentationValues`에서 같은 값을 전달하고 기존 `CombatStepHeight.Arc`와 불변 구간 모양으로 읽는다. 일반 Hop의 칸당 시간/높이는 유지한다. SO·불변 값·기본 설정 에셋·Inspector 표시 목록(사용 중인 경우)을 함께 확인해 새 값이 편집 가능하도록 한다. 지형/유닛 모델이 높을 때 시각적으로 관통하지 않는지는 Unity 확인 항목이다.

## 6. 구현·정적 대조 기록 (2026-11-02)

### 6.1 LJ1 — 원본 대응·값 전달

- `CombatLeapPlan.Build`는 결과 준비 때 한 번 원본을 읽는다. 실제 Leap/MovementChanged 발동의 출처/자기 대상/중간 칸 하나가 다음 자발적 Moved와 일치해야 한다. 발동만 있는 연출 확인 결과는 걸음을 만들지 않는다.
- 연속된 표식 걸음과 첫 일반 착지 걸음까지만 불변 구간으로 묶는다. 새 행동/추가 공격 출처/끌어오기/다른 대상 이동/복귀/재배치/이동자의 사망·필드 이탈·자리 변화에서 끊는다. 중단 전에 실제로 기록된 마지막 걸음에서 끝나며, 없는 착지 칸을 생성하지 않는다.
- `CombatPresentationSettingsData`가 기본값·조건의 원본이다. `CombatLeapMotionSettings`와 `CombatEventPresentationValues.From` → Presenter → 레인 집합 → 유닛 레인으로 불변 값을 전달한다. `CombatPresentationSettings_Default.asset`에는 새 두 값만 추가했다. 전용 Inspector/직렬화 필드 목록은 없어서 기본 Inspector로 편집한다.
- 편집 위치: `Assets/ProjectL/DataBaseSO/ViewGroup/CombatPresentationSettings/Item/CombatPresentationSettings_Default.asset` → `Combat Presentation Settings Data` → **뛰어넘기 구간 연출** → `Leap Seconds`(구간 전체 보간 0.5초) / `Leap Height`(구간의 가장 높은 표면보다 꼭대기에서 1만큼 높음). 이동 전 회전과 중간 사건 연출 대기는 시간에서 제외한다.

### 6.2 LJ2 — 이어진 배치와 채널 인계

- `CombatLeapStepStyle.Arc`는 구간 시작/끝 높이·가장 높은 경유 표면·설정으로 호를 한 번 만든다. 시간은 원본 걸음 수로 나누고 높이 진행률은 `(걸음 순서 + 걸음 진행률) / 구간 걸음 수`다. 가로는 각 원본 걸음의 두 칸을 이어 굽은 경유 경로를 보존한다.
- 유닛 레인은 중간 걸음의 `FinishStep`에서 배치를 유지하고 다음 걸음에서 같은 호·대여를 쓴다. 다음 걸음의 사실을 그려도 공중 위치를 유지하며, 중간 방향은 바로 맞추므로 이동 전 회전 대기를 반복하지 않는다. 도약의 접촉은 각 원본 걸음 도착 시점에 해제한다. 원본 사건/접촉 묶음/완료 콜백 개수는 바꾸지 않는다.
- 중간 HP 사건은 자세를 빌리기 전에 도약 배치를 잠시 반환한다. 특성 처리기에는 일반적인 유닛 행동 전 콜백을 주입해 해당 유닛만 배치를 반환한다. 자세/서는 자리 대여가 없으면 같은 공중 경유 위치에서 다시 빌린다. 대여가 잠시 반환된 동안만 기존 레인 Tick이 반환을 기다리며, 별도 Update/코루틴/지형 반복 검사는 없다.
- `CombatUnitPresentationWindow.CanResumePlacement`는 다른 자세/서는 자리를 접지 않는 읽기 질의다. 기존 Q-R11(자세와 걸음 배치 동시 대여 금지), 유닛 행동의 서는 자리 규칙, 공용 스케줄러·주체 막기·접촉 Gate는 유지했다.
- 사망/재배치/끌어오기/새 행동 등은 구간 계획에서 미리 끊고 표시 경계에서도 남은 도약을 닫는다. Cancel은 메타데이터와 대여를 함께 버린다. 대응하는 이전 걸음이 없는 중간 도약 시작이나 다음 결과까지 남은 도약 대여는 예외로 알린다.
- PositionSwap은 기존 `TrySuppressStep`이 전체 ActorSteps를 먼저 소유하면 도약 레인을 열지 않는다. 전용 표시가 없는 기존 쌍 경로는 이동자의 실제 착지 걸음을 그대로 쓰고 승객 걸음은 기존 정책을 따른다. PositionSwap 구현은 수정하지 않았다.

### 6.3 LJ3 — 정적 확인과 남은 실행 확인

- 설정 필드/기본 에셋/값 전달, 클래스 네임스페이스·호출부를 대조했다. 새 C# 3개와 `.meta` 3개의 GUID가 Assets/Packages에서 각각 한 번만 나타나는 것을 확인했다. 이번 변경 파일 16개의 UTF-8(BOM 없음)/LF와 해당 경로의 `git diff --check`를 확인했고 충돌 표식·새 파일의 뒤 공백은 없었다. 원본 Core 발동 게시 코드와 기존 순차 재생/자세 대여/취소 코드를 대조한 것이며 실행 시험을 대신하지 않는다.
- SSOT: 구간 대응은 계획, 호는 불변 모양, 현재 진행/대여는 기존 유닛 레인, 화면 사실은 기존 ShownFacts에 둔다. Core 결과나 이동 규칙의 별도 사본은 만들지 않았다.
- SOLID·기능 독립성: 계획·모양·값은 전용 타입, Presenter는 기존 조립/사건 수명 연결, 레인은 진행/회수만 맡는다. 특성 처리기는 Leap 규칙 대신 행동 전 콜백만 호출한다. 공유 위치 채널의 인계 경계는 기존 이동/반응과 함께 확인해야 한다.
- FW/계층: 생성은 기존 Presenter, 설정 조회는 기존 View 표 경로다. 새 서비스/루트 Export/전역 이벤트/수명 등록 없음. 기존 배치 대여의 반환 경로를 쓴다. Core/Buffer/InGameGroup/FieldCamera/Architecture/기존 시험 파일 수정 없음.
- Codex는 Unity 컴파일·실제 재생·기존 시험을 실행하지 않았다. 사용자 확인 범위는 아래 §6.4에 기록하고 나머지 LJ3 항목은 미확인으로 남긴다. 긴 구간의 첫 장애물·큰 유닛/벽 모델의 시각적 관통 여부와 실제 시간 감각은 Unity에서 확인하고 `Leap Height/Seconds`를 조정한다. View DB 기본 에셋을 변경했으므로 기존 `DataBaseAssetTests`도 사용자 확인 대상이다.
- 앞선 드래그 입력 보완은 별도 미확인 상태를 유지한다. 이번 구현으로 입력 문제가 해결됐다고 판정하지 않는다.

**컴파일 미확인.** View 시험 코드 작성·기존 시험 수정·MSBuild·Unity 실행·스테이징·커밋·push는 하지 않았다. 남은 작업은 LJ3 사용자 Unity 확인이다.
