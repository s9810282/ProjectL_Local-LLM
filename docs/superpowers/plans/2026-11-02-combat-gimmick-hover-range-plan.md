# 토네이도·하붑·Rider 연막 호버 범위 Task 계획·GH-a~GH-c 구현 기록

- 갱신일: 2026-11-02
- 상태: GH-a~GH-c 코드 구현 완료. 사용자 Unity 확인 대기·컴파일 미확인.
- 설계 원본: [기믹 호버 범위 설계](../specs/2026-11-02-combat-gimmick-hover-range-design.md).
- 대상: 토네이도와 `HaboobVisual_Default`를 쓰는 하붑 기믹.

- 설명 후속 대상: Rider 연막 `Trail Description` 필드·호버 연결(GH-c, 사용자 "해줘").

## 1. 확정 동작

2026-11-02 사용자 진행 지시로 설계 §2의 다음 기본안을 구현한다.

- 현재 칸을 포함하는 기믹 그룹의 전체 `Cells` 표시. 여러 그룹이 겹치면 합집합.
- 유닛이 같은 칸에 있어도 기믹 범위 표시. 유닛 범위와 별도 층.
- 공격 모드에서도 환경 설명과 같은 조건으로 표시하며 조준 강조는 위에 표시.
- 기존 격자 테두리·채우기 방식, 조절 가능한 전용 색(기본 청록색).

GH-a 종료 보고: 바뀐 파일, 실제 범위 원본, 표시/해제 경로, 기존 범위와의 겹침 처리, 사용자 Unity 확인 항목, **컴파일 미확인**. 여기서 멈춘다.

## 3. 사용자 Unity 확인

1. 토네이도 영역의 가장자리 칸에 호버해도 그 폭풍의 현재 전체 칸이 강조되고, 다른 폭풍으로 옮기면 표시가 바뀐다. 배치 단계에서도 몸이 보이는 영역과 맞는다.
2. 하붑 어느 칸에서든 전체 현재 `Cells`가 강조된다. 십자·떨어진 칸을 포함한 맞춤 모양도 빈 칸을 메우지 않고 그대로 보인다.
3. 같은 칸에 토네이도와 하붑이 겹치면 두 그룹의 합집합이 표시된다. 숨겨진 토네이도의 범위는 나타나지 않는다.
4. 유닛이 기믹 안에 있어도 기믹 범위가 보인다. 유닛 호버·이동 모드·공격 조준은 자기 규칙과 색을 유지하며 기믹 호버를 지워도 남는다.
5. 공격 모드에서도 기믹 범위와 설명을 읽을 수 있고, 조준 칸과 영향 칸이 위에 보인다.
6. UI 위·필드 밖·포커스 손실·입력 정리·종료에서 강조가 남지 않는다. 외부 `UnHover` 뒤에는 기존 포인터 갱신 규칙을 지킨다.
7. 기믹 이동 결과 재생 중에는 강조가 숨겨지고, 재생 완료 후 마우스가 그대로여도 새 영역만 표시된다. 이전 전투나 씬의 범위가 남지 않는다.
8. 설명을 비운 설정에서도 영역 강조가 동작한다. 설명 없는 칸에서 범위 해제가 빠지지 않는다.
9. CellPrefab/GridOutline 모드, 높이 다른 칸, 낮/밤 연기와 겹치는 경우에 범위가 읽힌다. 낙석 경고·지뢰·화약통 범위의 표시/해제가 유지된다.
10. Rider가 이동해 남긴 연막의 어느 칸에서든 같은 Rider의 활성·공개 연막 전체가 강조된다. 떨어진 칸도 포함하고 다른 Rider의 연막은 구분한다.
11. 같은 칸에 여러 Rider의 연막이 겹치면 해당 출처들의 전체 그룹을 합친다. 하붑/토네이도까지 겹치면 모두 합치되 중복 칸은 한 번만 표시한다.
12. 만료·이동 복귀로 연막이 비활성/제거되면 새 결과 뒤 범위에 남지 않는다. 숨겨진 연막은 포함하지 않는다. 특성 설명이 없어도 영역은 표시된다.
13. `TraitVisual_DustScreen`의 `Trail Description`이 연막 칸 호버에 표시되고 숫자 자리가 Buffer 수치로 채워진다. 같은 칸의 동일 문구는 한 번, 서로 다른 문구는 각각 표시된다. 설명을 비우면 연막 설명만 없어지고 범위는 남는다. 기존 특성 아이콘 설명·하붑 설명을 확인하고, `DataBaseAssetTests`도 확인한다.

GH-a/GH-b는 DB 에셋 값을 바꾸지 않았다. 후속 GH-c가 연막 전용 설명 값을 추가했으므로 `DataBaseAssetTests`를 사용자 확인에 포함한다. 테스트 코드 작성·MSBuild 실행 없이 사용자가 Unity에서 컴파일·재생을 확인한다.

## 5. 후속 Phase GH-b — Rider 먼지 연막(확정·코드 구현 완료)

사용자 요청: Rider 특성으로 생성되는 연막도 같은 호버 범위를 표시한다. 하붑·토네이도 기능은 유지한다. 그룹 기준은 사용자 "같은 Rider가 남긴 활성 연막 전체"로 확정한 뒤 아래 Task를 구현했다(설계 §8).

| Task | 작업 | 대상 |
|---|---|---|
| Gb.1 | `TraitTrailFact` 중 활성·플레이어 공개·`DustScreen`인 흔적만 고르고, 확정한 그룹 기준의 칸을 중복 없이 덧붙임 | 새 `Input/Assist/CombatDustScreenHoverCells.cs` + `.meta` |
| Gb.2 | 기존 기믹 수집 뒤 Rider 칸을 같은 목록에 더함. 캐시·해제·빈 설명 처리는 기존 수명 사용 | `CombatEnvironmentHover.cs` |
| Gb.3 | 표시 계약·층/팔레트 설명과 `FieldView` 색상 툴팁에 Rider 대상 포함. 새 층/팔레트 인자/Factory 연결은 추가하지 않음 | `ICombatGimmickRangeFeedback.cs`, `FieldHighlightLayers.cs`, `FieldHighlightPalette.cs`, `FieldView.cs`의 관련 설명만 |
| Gb.4 | 확정한 그룹 기준·변경 독립성·정적 점검·Unity 확인 항목 기록 | 이 설계·계획, 기존 공유 메모 |

사용자 Unity 확인: 이동으로 연막 생성 후 어느 칸에서든 확정한 그룹 전체 강조, 서로 다른 Rider/같은 칸의 출처 겹침, 숨김·만료 흔적 제외, 이동 복귀/만료 뒤 낡은 범위 제거, 하붑·토네이도와 겹침, 유닛·조준 표시 유지. 새 시험·MSBuild는 실행하지 않으며 컴파일 미확인으로 보고한다.

### 5.1 실행 기록(2026-11-02)

- 관련 사실/출처/표시 수명을 조사하고 그룹 기준을 질문한 뒤 사용자 답변으로 확정했다. Gb.1~Gb.4 코드·문서 구현 완료.
- 새 수집 부품 + `.meta`, 환경 호버의 수집 호출 한 줄 추가. 기존 기믹 수집·Factory·렌더러·Core·에셋은 수정하지 않았다. 공통 표시 쪽 변경은 Rider를 포함하는 설명/툴팁뿐이다.
- 활성 여부·특성 키·전체 `Origin` 동등성·플레이어 공개 조건을 코드로 대조했다. 기존 목록을 비우지 않고 덧붙이므로 기믹과 겹쳐도 합집합이 유지된다. 캐시를 내려놓으면 새 Buffer 사실로 다시 수집한다.
- 사용자 확인은 §3의 기존 항목과 Rider 추가 항목이다. 테스트 코드/기존 테스트 변경·MSBuild·Unity 실행 없음. **컴파일 미확인**.
- 관련 추가분은 GH-a의 기존 스테이징에 함께 반영한다. 다른 작업의 `FieldView` 화살촉/넉백 변경은 계속 제외한다.

Unity 확인: Rider 연막 칸에서 이름과 설명이 영역 강조와 함께 표시됨, Buffer 수치가 문구에 들어감, 같은 칸의 동일 문구는 한 번/다른 수치 문구는 각각 표시됨, 빈 설명이면 패널 없이 범위만 보임, 숨김·만료·UI 가림·이동 복귀 뒤 설명이 남지 않음, 기존 특성 아이콘 설명과 하붑 설명 유지. View 에셋 값을 추가하므로 사용자 `DataBaseAssetTests` 확인 항목에 포함한다. 새 시험·MSBuild·Test Runner·Unity 실행 없이 컴파일 미확인으로 보고한다.

### 6.1 실행 기록(2026-11-02)

- Gc.1~Gc.5 코드·문서 구현 완료. 새 `.cs`/`.meta` 없음.
- `TraitVisualData`의 전용 문자열/읽기 프로퍼티, DustScreen 에셋의 기본 문구, 환경 설명의 특성 조회·숫자 치환·동일 문구 중복 제거를 연결했다. 이름은 기존 `DisplayName`, 기존 `Description`은 변경하지 않았다.
- Factory 생성자 호출은 기존 `tables.Traits`를 전달한다. `CombatDisplayTables.Traits`는 기존 필수 조회이며 서비스·Export·Builder 추가 없음. 관련 생성 호출을 검색해 추가 조정할 곳이 없음을 확인했다.
- 범위 수집·강조/숨기기·캐시 수명은 그대로 사용한다. `FieldTrailPresenter`는 담당 설명 주석만 고쳤다. Core·임시 외형·다른 특성 에셋 변경 없음.
- 기본 문구 수치는 코드/SO에 고정하지 않고 Buffer 사실에서 치환한다. 같은 칸에서 동일한 완성 설명은 재사용 HashSet으로 한 번만 붙이고, 문구가 다른 원본은 각각 표시한다.
- 코드/에셋 변경분과 입력 토큰·새 필드명·인코딩·후행 공백을 정적 점검했다. 새 시험·기존 시험 변경·MSBuild·Test Runner·Unity 실행 없음. **컴파일 미확인**.
- 관련 추가분을 기존 스테이징에 반영한다. DustScreen 에셋은 `trailDescription` 추가만 올리고 사용자의 기존 `trailPrefab`·`alwaysEffects` 변경은 제외한다.
