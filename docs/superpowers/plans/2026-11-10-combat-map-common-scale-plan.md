# 전투 배경·타일 공통 배율 Task 계획 — 화면 보존 우선

- 갱신: 2026-11-10. 작성: 전투 View 작업.
- 설계: [공통 배율·기존 표시 보존](../specs/2026-11-10-combat-map-common-scale-design.md).
- 상태: CS4 구형 직렬화 필드·일회성 이전 도구 정리 후에도 사용자가 Unity 확인에서 문제없음을 보고했다. 사용자 확인 완료. Codex가 컴파일·재생·시험을 직접 실행한 것은 아니다.
- 요청 범위: 사용자의 “CS4 까지 쭉 진행해”에 따라 코드 작업과 정적 검토까지 연속 진행했다. 아래 단계별 정지는 최초 계획의 리뷰 지점이며 이번 연속 진행 지시로 대체한다. 데이터 충돌의 임의 수정은 허용하지 않는다.
- View Test 코드·MSBuild 금지. Unity 컴파일/재생은 사용자 확인. 커밋·push·자동 스테이징 없음. 파일 기준 입력과 실제 Unity 검증 증거를 구분한다.

## CS0 — 현재 결과 기준 확정·이전 가능성 조사

1. [ ] 등록/미등록 ViewStage, 타일 세트/변형, 실제 필드 간격, 배경 프리팹과 공유 소비자, 편집 씬의 저장/미저장 상태·override를 읽기 전용으로 목록화한다. 이전 문서의 에셋 수나 현재 보고 값으로 생략하지 않는다.
2. [ ] Combat/Authoring 각각의 기존 배치 결과를 남긴다. 배경/타일 월드 변환, 중심·모서리·범위, 칸→타일 대응과 `SurfaceHeight`, 유닛 발 위치, 카메라와 비교 조건을 기록한다. 저장된 씬 결과와 다시 계산한 결과의 차이도 분리한다.
3. [ ] `tileSize × 원본 배율 × ScaleOffset`과 필드 간격을 축별 대조한다. 제작 규격 2·정사각 간격·균일 양수 배율·TRS 표현·공유 에셋 영향까지 조사하여 무손실 전환 후보/불가능/추가 확인으로 분류한다.
4. [ ] `Test 1`의 1.116297 대 1.5 같은 기존 불일치가 남아 있으면 실제 최신 값을 보고한다. **사용자 확인 없이 1.5로 수정하지 않는다.** 비정사각/소수 다칸/공유 프리팹/미저장 씬 충돌도 같은 정지 조건이다.
5. [ ] 기존 소수 크기 계약과 새 1:1 모델이 충돌하는 대상의 처리 결정을 먼저 받는다. 모든 대상의 “현재 화면 그대로”를 충족하지 못하면 전체 소비 경로 전환을 시작하지 않는다.

산출물: 에셋별 이전 전 결과·후보 결과·차이·변경 예정 파일 목록. 단순 TileSize/ScaleOffset 목록은 조사 완료가 아니다. **CS0 보고 후 멈춘다.**

## CS1 — 공용 규격·배치 계산 준비 (코드 반영)

선행 조건: CS0에서 전환 대상과 충돌 처리가 확정됨. 기존 표시 경로는 이 단계에서 교체하지 않는다.

1. [x] `Tool/Runtime` 공용 제작 규격(2)과 공통 Layout을 마련한다. `s=OutlineCellSpacing/2`의 균일 배율, 방향 보정, 기준 타일 정렬을 공통 입력/결과로 표현한다. 기존 `CombatTileAlignmentMath`의 계산을 재사용/정리한다.
2. [x] 원본 프리팹 배율 재곱셈을 금지하는 입력 검증을 정의한다. 잘못된 숫자·비정사각·비균일·기울기·전환 누락은 에셋/축을 포함한 오류로 드러낸다. 런타임에서 SO를 고치지 않는다.
3. [x] 운영 DB/Buffer 값은 기존 조립 경계가 전달한다. Editor는 `CombatStageSoAssets`와 `FbxCombatStageContext`를 통해 읽는다. 새 서비스/전역 등록/Systems 직접 의존을 만들지 않는다.
4. [x] 새 `.cs/.meta`, 호출 계약·구조를 정적 검토한다. Test/harness를 새로 작성하지 않는다. Unity 컴파일은 사용자 확인 항목으로 넘긴다.

산출물: 공통 계산 경계와 다음 Phase의 적용 계약. **CS1 보고 후 멈춘다.**

## CS2 — 화면 보존 이전 미리보기 (도구 반영·Unity 실행 대기)

1. [ ] 명시적으로 선택한 이전 대상만 읽는 Editor 이전 도구를 준비한다. 기존 값/해시/공유 참조와 새 후보 변환을 보여주며, 미리보기는 원본 SO·프리팹·씬을 쓰지 않는다. 일반 Inspector의 `OnEnable`/`GetData`/자동 임포트에서 이전하지 않는다.
2. [ ] 설계 CS5의 행렬·중심·범위·높이·칸 대응 대조를 도구의 저장 전 검사로 제공한다. 이것은 에셋 이전 기능의 사전 검사이며 별도 View Test 코드를 만들지 않는다.
3. [ ] 원본 루트 배율 1 정리·기존 TileOffset/높이 보존 후보를 만든다. 단순 루트 초기화/자식 배율 일괄 곱셈은 하지 않는다. 공유 프리팹의 다른 소비자에 영향이 있거나 TRS로 보존하지 못하면 저장 불가로 표시한다.
4. [ ] 스테이지별 후보 결과가 이전 결과와 같고 제작 규격도 맞는지 리뷰한다. `TileSize`/타일 방식 `ScaleOffset`을 제거할 준비가 됐는지 모든 읽기·쓰기 사용처와 에셋을 검색한다. 미등록 항목도 누락하지 않는다.

산출물: 사용자가 리뷰할 구체적인 이전 대상과 차이 보고. **원본은 아직 변경하지 않고 CS2 보고 후 멈춘다.**

## CS3 — Combat·Authoring 공동 전환과 승인된 에셋 이전 (코드 반영·에셋 값 변경 0건)

선행 조건: CS2 결과 수락·구현 진행 지시. 화면 보존 실패/처리 미정 대상이 있으면 시작하지 않는다. 런타임만 먼저 바꾸거나 에셋만 먼저 저장해 중간 상태를 배포하지 않는다.

1. [x] `StageViewPropPresenter`·`StageMapTiles`가 새 공통 배치 결과를 적용한다. 필드 구성/카메라 바인딩 순서와 생성 실패 정리·해제를 유지한다.
2. [x] `CombatMapAuthoringPlacement`에 같은 결과를 적용한다. 형제 MapTileRoot와 표시 전용 컨테이너·프리팹 링크를 보존한다. 저장 후 다시 배치할 때도 공통 계산을 쓴다.
3. [x] `CombatStageSoAssets` 읽기/쓰기, `CombatStageSoTiles.cs`의 Layout/Fit/Scene, 스테이지 편집기 SO 입력/복사/저장, `FbxCombatStagePreview` 및 FBX 전투 설정 패널을 같은 계약으로 전환한다. 실행/편집의 타일 간격/높이 계산 사본을 남기지 않는다.
4. [x] `ViewStageDataSO` 타일 크기 입력과 타일 방식 수동 배율 입력을 제거하고 자동 배율을 읽기 전용으로 표시한다. TileOffset X/Z 읽기 전용·Y 편집, 배경 월드 X/Z 역산을 유지한다. 비타일 모드의 `ScaleOffset`은 유지한다.
5. [x] **현재 입력은 값 이전 불필요(0건).** 이후 실제 에셋 값 이전이 필요하면 다음 규칙 적용: 명시적인 이전 실행으로 CS2에서 검증한 대상만 변경한다. 실행 직전 해시/상태가 바뀌면 다시 계산한다. 사용자 미저장 작업은 동의 없이 저장/폐기하지 않는다. 부분 실패 시 이번 변경만 복구하며 이전 완료 표시를 남기지 않는다.
6. [x] 기존 직렬화 필드는 모든 참조·에셋 이전을 확인할 때까지 성급히 삭제하지 않는다. 새 계산에서 사용하지 않는 필드가 남아 있다면 이전 검사용이라는 상태와 제거 조건을 명시하고 이중 원본으로 쓰지 않는다. 미전환 에셋을 기본값으로 새 모드로 간주하지 않는다.
7. [x] `SurfaceHeight` 값/사용 단위와 칸→타일 대응·ReplaceTile 대상·넘침 판정을 유지한다. 타일 배율에 맞춘다는 이유로 유닛 크기·필드·Core 좌표·카메라를 수정하지 않는다.

산출물: 공동 전환 코드·승인된 이전 에셋·이전 기록. **CS3 보고 후 멈춘다. 컴파일/재생 완료와 구분한다.**

## CS4 — 전후 결과 확인·구형 입력 정리

1. [ ] 사용자 Unity 컴파일 확인. 기존 시험 API가 깨지는 부분은 AGENTS 제한에 따라 최소 조정하며 새 View 시험/MSBuild는 실행하지 않는다.
2. [ ] 동일 스테이지/보드/카메라/외형 선택에서 Combat 이전→이후와 Authoring 이전→이후를 비교한다. 둘의 배치 수치도 교차 확인한다. 랜덤 변형과 파티클 시간 차이는 통제하고 조명 차이로 위치 오류를 숨기지 않는다.
3. [ ] 정상 기본값, 90°/180°/270° 회전, 짝·홀/직사각 타일 맵, 기준 타일 변경, 0이 아닌 높이, 배경 X/Z 편집·역산, Undo, SO 저장·재불러오기·씬 재열기·프리팹 저장 후 동일성을 확인한다.
4. [ ] 별도 임시 확인에서 OutlineCellSpacing을 변경하면 배경과 타일에 동일 배율이 적용되는지 확인하고 값을 복구한다. 이때의 의도적인 크기 변화는 **이전 직후 화면 동일** 검증과 섞지 않는다.
5. [ ] 타일 표면 유닛/선택 표시, 지형 바닥 교체, 타일 외형 자체 배율/높이, 낙석 기준 Transform, 배경 펼침 대상, 조명/콜라이더 등 변환의 실제 소비자를 확인한다. 관련 없는 공격 타이밍/입력 기능 전체를 다시 검증하는 범위로 확대하지 않는다.
6. [ ] DB 에셋 이전이 있으므로 기존 `DataBaseAssetTests`를 사용자 확인 항목에 포함한다. 실제 실행 여부/결과를 기록한다.
7. [x] 사용자 Unity 확인 후 불필요한 직렬화 필드와 일회성 이전 도구를 제거했다. 21개 운영/미등록 ViewStage의 해당 항목도 정리했다. 기준 자료는 변경 전 이력으로 보존한다. 정리 후 확인은 아래 최신 기록을 따른다.

완료 조건: 화면 보존·공통 계산·모든 대상 이전이 확인됨. 오류/미확인 항목을 남긴 채 “동일하다”로 보고하지 않는다. **CS4 보고 후 종료한다.**

## 2026-11-10 CS0~CS4 실행 기록

아래는 단계별 이력이다. 당시의 미확인·대기 표기는 문서 끝의 **사용자 확인 및 구형 필드 정리** 기록으로 갱신된다. 개별 시험 실행 로그를 추가로 수집한 것으로 해석하지 않는다.

### CS0 — 파일 기준 확보, Unity 기준 자료는 확인 대기

[에셋별 기준·해시·씬 작업 값](../handoffs/2026-11-10-combat-map-common-scale-baseline.md)에 21개 에셋을 기록했다. 등록 20개/미등록 1개, 공통 TileSize=2, SO 배율=0.75, 등록 필드 간격=1.5다. 이전에 문제가 됐던 Map3GrayBoxP 원본 루트 배율은 사용자 수정으로 1이며 StageTest도 1이다. 현재 입력에서 구형 유효 배율과 새 자동 배율이 같아 원본을 변경하지 않는 전환을 적용했다.

Authoring 저장 씬의 작업 TileOffset Z≈-2와 Test 1 SO의 -1.96은 서로 다른 작업 상태다. 이로 인한 배경 Z 0.03 차이를 새 배율 오류로 취급하거나 한쪽에 맞춰 저장하지 않았다. 열린 Unity의 미저장 상태·메시/콜라이더·카메라 캡처는 파일 조사만으로 검증한 것으로 처리하지 않는다. CS0의 실제 Unity 행렬/화면 비교 요구는 CS2 도구·CS4 확인 항목에 남아 있다.

### CS1 — 공통 계산 코드 반영

- `CombatMapAuthoringMetrics`: 제작 규격 2, 균일 XYZ 배율 `OutlineCellSpacing / 2`, 정사각 간격·원본 루트 배율 1·구형 TileSize 전환 누락 검사.
- `CombatMapPlacementLayout`: 필드 좌표계에서 축 회전과 기준 타일 정렬을 한 강체 보정으로 계산한다. 기존 `CombatTileAlignmentMath` 식을 재사용하며 Transform·SO를 찾거나 저장하지 않는다.
- 기존 Tool.Runtime 어셈블리만 사용한다. 새 서비스·asmdef·Core 변경 없음. 새 스크립트 `.meta` 추가.

### CS2 — 이전 미리보기 도구 코드 반영, 실행 미확인

`ProjectL > 전투 배경 공통 배율 이전 확인`에서 Project 선택 ViewStage를 명시적으로 검사한다. 구형 배치와 새 후보의 배율·행렬·메시 경계·타일 모서리·칸 대응·SurfaceHeight를 보고하고, 열린 Authoring 씬의 작업 값과 현재 표시도 따로 비교한다. 의존 에셋 해시를 포함한 보고서는 클립보드로 복사할 수 있다.

현재 조사한 입력은 수치 이전 없이 새 배율을 사용할 수 있어 **에셋 저장/루트 초기화 실행 기능은 필요하지 않다**. 불일치 입력에 자동 수정·fallback을 제공하지 않는다. 앞으로 다른 제작 규격/루트 배율을 가진 에셋을 도입하면 이 검사에서 충돌을 확인한 뒤 별도 이전 계획을 세운다. 도구 구현 자체가 전체 대상 통과 증거는 아니다.

### CS3 — 소비자 공동 전환 코드 반영

- Runtime `StageViewPropPresenter`, Authoring `CombatMapAuthoringPlacement`, 기존 `CombatStageSoPreview`, `FbxCombatStagePreview`가 같은 배율·배치 계산을 쓴다.
- Runtime 타일은 배경 자식, Authoring 타일은 형제 구조를 유지한다. 프랍 저장 제외/Undo/카메라 억제/실패 해제 경계를 유지한다.
- SO 입력의 TileSize를 숨기고 구형 값은 규격 검사에만 사용한다. 순수 `CombatMapTilesData` 생성자와 범용 `TileFit`의 기존 크기 API는 유지한다. 운영 입력이 만드는 TileSize는 공통 규격이다.
- 타일 방식 ScaleOffset 입력은 자동 배율 표시로 바꾸고 저장 경로에서도 쓰지 않는다. Prefab/MapDefinition은 기존 수동 배율을 유지한다. 일반 SO Inspector는 계산식을, Authoring/기존 도구는 수치와 계산 기준을 표시한다.
- 기존 스테이지 편집기도 등록 Field View를 읽는다. 캐시된 설정을 사용하며 프레임별 에셋 스캔을 추가하지 않는다.
- SurfaceHeight·유닛 크기·외형/회전 선택·타일 생성·바닥 교체 정책은 그대로다. SO/프리팹/씬 에셋을 이번 작업에서 쓰지 않았다.

### CS4 — 정적 검토 결과와 남은 확인

`git diff --check`, 직접 소비자의 구형 배율 쓰기/계산 참조, 새 파일/meta, 외부 경계를 정적으로 검토했다. Test 코드·MSBuild·Unity 컴파일/재생은 수행하지 않았다. **컴파일 미확인.**

사용자 확인 순서:

1. Unity 컴파일 후 21개 ViewStage를 선택해 이전 확인 도구를 실행하고 실패/차이가 없는지 확인한다. 씬 표시와 작업 값의 불일치는 저장 전에 기준을 확정한다.
2. 현재 Authoring 씬에서 `작업 값 다시 적용` 후 위치·크기·그리드·유닛 발 높이를 확인한다. 기존 작업 값을 보존하려면 SO 재불러오기와 혼동하지 않는다.
3. 같은 조건의 Combat에서 배경/타일/유닛/바닥 교체/낙석 기준 위치를 비교한다. 같은 외형·회전과 카메라 구도를 사용한다.
4. 배경 월드 X/Z·타일 Y·기준 타일·회전, Undo, 보정 SO 저장/재열기, 프랍 저장을 확인한다.
5. 별도 임시 설정에서 OutlineCellSpacing을 바꾸고 프리뷰 재적용/Combat 재진입 시 배경과 타일이 함께 바뀌는지 확인한 뒤 복구한다.
6. 기존 `DataBaseAssetTests`를 확인한다(이번 에셋 값 변경은 없으나 DB 입력 검증 계약이 바뀜).

구형 `tileSize` 직렬화 필드와 타일 방식의 옛 `scaleOffset` 값은 이전 검사 자료로 남긴다. 전자는 생산 크기의 원본이 아니며 후자는 타일 배율 계산/저장에 사용하지 않는다. 비타일 ScaleOffset은 영구 유지 대상이다. **Unity 재열기·저장/전후 표시 검증 후에만 불필요한 구형 필드를 제거한다. 현재 CS4 전체 완료로 표시하지 않는다.**

### 설계 기준 재검토

SSOT: 규격은 Metrics, 최종 간격은 등록 Field View, 정렬은 Layout, 높이는 기존 타일 외형 값이 소유한다. SRP: 수치 계산·씬 생성/수명·저장·명시적 이전 검사를 분리한다. OCP/ISP/DIP: 새 표시 표면은 수치 계산 어댑터로 연결하고 DB 탐색을 공통 계산에 넣지 않는다. LSP: 비타일 모드와 기존 수명/API를 보존하며 규격 불일치는 명시적 오류로 알린다. FW 등록·Factory·Buffer·Core 계약은 바꾸지 않는다.

기능 독립성: 다음 배율 공식 변경은 Metrics와 직접 소비자 확인에 한정되고 공격/입력/카메라 구현을 읽거나 고칠 필요가 없다. 프랍 저장 정책은 기존 저장기, 이전 비교는 전용 도구가 소유한다. 배치 변경이 타일 대응/유닛 발/바닥 교체/낙석 위치에 주는 실제 영향은 CS4 통합 확인으로 남긴다. 배치 계산은 생성/재적용 때 O(1), 에셋·경계 스캔은 명시적 이전 검사 버튼에서만 수행한다.

## 2026-11-10 사용자 확인 및 구형 필드 정리 — 최신 상태

사용자가 안내한 Unity 확인을 진행하고 “확인했고 문제 없어”라고 보고했다. 이 확인을 CS4 화면 보존/사용 검증의 사용자 보고로 기록하고, 이어서 요청한 구형 직렬화 필드 정리를 수행했다. 개별 테스트 결과 파일이나 스크린샷을 새로 수집한 것은 아니다.

- `CombatMapTilesInput.tileSize` 직렬화 필드를 제거했다. 운영 Data 생성은 이미 사용하던 `CombatMapAuthoringMetrics.TileSize`를 그대로 쓴다.
- 21개 ViewStage 에셋에서 `mapTiles.tileSize: {x: 2, y: 2}` 한 줄씩만 삭제했다. 작업 시작 시 각 값이 공통 규격인지 확인하고, 나머지 파일 내용은 그대로 보존했다. 사용자 Test 1 보정 수정도 보존했다.
- 에디터의 `SerializedProperty` 조회와 이전 검사 우회 인수를 제거하고 공통 규격으로 작업본을 만든다. 작업본 규격 검증은 유지한다.
- 고정 정사각 입력에서 도달하지 않는 직사각 타일 회전 제한 분기를 제거했다. 불변 타일 Data 생성자와 범용 Fit API는 변경하지 않았다.
- 구형 값을 비교하던 `CombatMapScaleMigrationWindow`와 `.meta`, 전용 `ReadScaleMigrationView`를 제거했다. `ProjectL > 전투 배경 공통 배율 이전 확인` 메뉴도 제거된다. 일회성 비교 때문에 넓혔던 Field View 조회 헬퍼는 다시 private으로 제한했다.
- `ScaleOffset` 및 Authoring `draftScaleOffset`은 비타일 Prefab/MapDefinition에서 실제로 쓰므로 유지한다. 타일 방식의 이전 ScaleOffset 값은 런타임 배율 원본이 아니지만 모드 전환 시 설정을 잃지 않도록 초기화하지 않는다.
- 이전 기준 자료의 값/해시는 이력으로 보존한다. 프리팹·씬·Core·FieldCamera·Architecture·기존 시험 파일은 수정하지 않았다.

정적 확인: 제거한 필드의 직렬화 조회·이전 도구/API 참조가 남지 않았고, 21개 에셋의 이번 수정은 tileSize 한 줄 삭제뿐임을 확인했다. `git diff --check` 통과. **정리 후 컴파일 미확인**이며 Test 코드·MSBuild·Unity 실행은 수행하지 않았다. 커밋·push·스테이징 없음.
