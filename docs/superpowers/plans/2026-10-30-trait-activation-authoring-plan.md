# 사용 가능한 특성 37종의 Activation 연출 작성 계획

> **착수 전 재검토:** 현재 가용성·Kind·Anchor/Point 제약은 [2026-10-31 참조 문서](../viewDocs/trait-effects-and-activation-reference.md)를 따른다. 아래 37종/47줄은 과거 코드의 작성 계획이며 현재 사용 가능 목록이 아니다.

- 날짜: 2026-10-30. 작성: Codex, View 작업.
- 상태: **계획 작성. 코드·SO·프리팹 구현 미착수.**
- 사용자 요청: “사용 가능한 특성 37종에 대해 필요한 Activation 줄과 붙일 연출을 정리하고, 작업 계획부터 세워줘.” 이번 요청을 구현 승인으로 해석하지 않는다.
- 설계 원본: [Activation 연출 작성 설계](../specs/2026-10-30-trait-activation-authoring-design.md). 특성별 작성 Kind·큐·자리는 설계 §4 한 곳에서 관리한다.
- 범위: 우선 36종/45줄(희생 기존 1 + 신규 44), 표식 1종/2줄은 계약 대기. 전체 초안은 37종/47줄.
- 금지: 커밋·push, Core·FieldCamera·Architecture 변경, 옛 Missing Script 에셋 삭제, 새 View 테스트 코드/자동 검증 도구 추가. Phase 끝마다 보고하고 멈춘다.

## 0. 착수 전 확인

- [x] Core 등록/가용성 대조: 42종 중 37종 사용 가능, 5종 보류.
- [x] 현재 에셋 대조: TraitVisual 40종, 누락 2종, 희생 줄 1개, 흔적 2개, Render 등록 효과 3개.
- [x] 시점/자리·UnitAction·ChildAttack·Interception 제약 확인.
- [x] Core 공통 버프·디버프/약점 노출 예고 확인. 현재 계약과 미래 계약을 혼합하지 않음.
- [ ] 설계의 초판 표현과 구현 범위를 사용자 검토로 확정.
- [ ] 실제 구현 시작 때 HEAD·작업 트리·스테이지와 동시 작업 영역 재확인. 현재 조사 기준은 d4809683b이며 기존 미리보기 변경은 별도 작업으로 유지.

## Phase A — 에셋 경계와 입력 준비

### A1. 작성 대상 재대조

- [ ] 설계 §4의 37종과 실제 Core 가용성을 재대조한다. Core 업데이트로 Kind·발동 경로가 바뀌었으면 설계부터 갱신한다.
- [ ] 희생 기존 줄·땅 다지기/먼지 연막 흔적의 GUID·값을 보존하고 변경 전 기준을 기록한다.
- [ ] 사냥꾼의 표식 2줄은 작업 대기 상태로 표시한다. 후속 약점 노출 Kind를 임의로 만들지 않는다.

### A2. 누락된 외형 에셋

- [ ] `TraitVisual_PrecisionShot.asset`·`TraitVisual_ContemptForWeak.asset`와 meta를 만들고 기존 TraitVisual 표에 각각 한 번 등록한다.
- [ ] 등록 키·원본 설명·기획 명칭을 확인한다. 아이콘이나 설명의 추측 값으로 DB 성공을 가장하지 않으며, 선택 필드와 필수 필드를 현행 Validate 계약대로 구분한다.
- [ ] 기능 규칙을 InGame SO에서 View로 읽는 런타임 경로를 추가하지 않는다.

### A3. 입력 리허설

- [ ] 기존 미리보기 창으로 Moment/ChildAttack/Interception 세 문맥의 입력을 수동 대조한다. 일반 줄=Start, 추가 공격=기본 공격, 희생=기존 가로채기 조립이다.
- [ ] 데이터 입력 오류·중복 Kind·미등록 리소스가 명확히 거절되는지 현재 도구/DB 경로로 확인한다. 새 검증 코드는 만들지 않는다.

**완료 기준:** 누락 두 에셋의 정상 조회, 기존 희생/흔적 보존, 표식 대기 유지. 변경 파일·확인 결과를 보고하고 멈춘다. 빈 Activation 47개를 먼저 채우는 작업은 하지 않는다.

## Phase B — 실제 연출 리소스 확보·등록

- [ ] **B1 의미와 모양 확정:** 설계 §5의 9개 표현 계열에 필요한 실제 프리팹/변형을 정한다. 공용으로 쓸 수 있는 것과 새로 필요한 것을 나눈다. 리소스가 없으면 담당 전달 목록을 만들고 해당 작업을 대기한다.
- [ ] **B2 DB 등록:** 필요한 EffectType·EffectDataSO·Render Effect 표 연결과 meta를 추가한다. 현재 세 등록 키(2·3·4)를 다른 뜻으로 재할당하지 않고, 새 키의 충돌·중복·누락을 확인한다. 의미가 맞는 기존 리소스 소비는 허용한다. EffectSystem/Scope/Pool 동작 자체는 수정하지 않는다.
- [ ] **B3 풀과 반환:** 다중 대상 발동의 동시 인스턴스 수를 기준으로 리소스별 풀 값을 정한다. 짧은 파티클의 반복·중단·환경 종료 때 기존 Scope 반환을 수동 확인한다.
- [ ] **B4 표본 재생:** 공격력 부여, 보호막 흡수, 회복, 통과 잔광, 즉사의 대표 리소스를 미리보기에서 본다. 피격/폭발 효과로 다른 의미를 대체하지 않는다.
- [ ] **B5 컴파일/에셋 검사:** 코드 enum 변경이 있으면 Unity 컴파일, DB 변경이 있으면 기존 DataBaseAssetTests 실행 결과를 기록한다. 추가 테스트는 작성하지 않는다.

**완료 기준:** §4에서 참조할 수 있는 실재 리소스와 등록 키의 대응표가 있고, 리소스 미확정 부분을 성공으로 표시하지 않는다. 보고하고 멈춘다.

## Phase C — 36종 45줄 작성

작성 세부 값은 설계 §4를 따른다. 지연 0, UnitAction=None, 공격 표시 덮어쓰기 없음이 기본이고 희생의 기존 행동만 예외다. 아래 묶음 단위로 에셋을 편집하고 확인 결과를 남긴다. 리소스가 준비되지 않은 행은 건너뛴 이유를 기록하며 다른 의미의 임시 이펙트로 채우지 않는다.

| Task | 설계 행 | 대상 | 줄 수 | 확인 초점 |
|---|---|---|---:|---|
| C1 | §4.1 | 피해·방어 우회 10종 | 10 | 실제 수신자, 피해/방어 계산을 View에서 하지 않음, 즉사와 사망 중복 없음 |
| C2 | §4.2 | 공격력·회복 6종 | 8 | 다중 대상, 실제 회복 대상, 가속 축적/소모, 사냥꾼 표적과 Run 보상 구분 |
| C3 | §4.3 | 상태·보호막 6종 | 11 | 증가/감소 공통 DefenseChanged, ShieldReset의 Magnitude 0, HUD 수명 소유권 |
| C4 | §4.4 | 이동·흔적 7종 | 9 | cells/targets 입력, Forced/자발 걸음 중복 없음, 지속 흔적 보존 |
| C5 | §4.5 | 추가 공격·특수 7종 | 7 | 빈 ChildAttack, 기본 공격 유지, 포효 중복 없음, 희생 이동 전 큐와 복귀 |

- [ ] C1 완료·수동 확인.
- [ ] C2 완료·수동 확인.
- [ ] C3 완료·수동 확인.
- [ ] C4 완료·수동 확인.
- [ ] C5 완료·수동 확인. 이 묶음은 신규 6줄 + 희생 기존 1줄 보완이다.
- [ ] 중복 Kind 없이 신규 44줄 + 기존 희생 1줄인지 대조한다. 의도적으로 쓰지 않는 생애주기 줄은 설계 §6과 대조한다.
- [ ] 관련 DB가 정상 생성되는지 기존 에셋 검증을 실행하고 결과를 기록한다.

**완료 기준:** 준비된 리소스로 45줄이 정상 소비되고, 각 줄의 대상/자리/발동 의미가 맞는다. 미리보기의 순간 큐 성공을 실제 HUD·규칙 검증으로 기록하지 않는다. 보고하고 멈춘다.

## Phase D — 운영 연결·읽기 쉬움 확인과 인계

- [ ] **D1 발생 위치:** 운영 전투에서 공격 시작, 맞는 순간 묶음, 피격 뒤 상태 부여, 넉백, 처치 추가 공격, 턴 종료를 대표 사례로 확인한다. 재현할 수 없는 사례는 미확인으로 기록한다.
- [ ] **D2 군집:** 선봉장·사기 증진·결속·넉백 다중 대상에서 큐 수·풀 부족·중복 표시·너무 강한 효과를 확인한다. R11로 늦게 보이는 발동은 기존 제한으로 기록하고 순서를 변경하지 않는다.
- [ ] **D3 경계:** Magnitude 0, 빈 추가 공격, 사망 대상/사라진 출처, 재생 중 중단·재시작, 에셋 수정 뒤 재생을 확인한다. 일반 공격·이동·피격·사망의 기존 모션을 침범하지 않아야 한다.
- [ ] **D4 실제 사실:** 보호막 흡수·공격력 부여/만료·제한·흔적 생성/제거는 Core 사실과 HUD/필드로 확인한다. 미리보기 도구가 합성하지 않는 사실을 자동으로 확장하지 않는다.
- [ ] **D5 인계:** 에셋 위치·리소스 키·대표 재생 방법·확인/미확인·표식 대기·기존 제한을 사용 안내와 이 계획 실행 기록에 남긴다. 공유가 필요하면 문서만 준비하며 외부 전송하지 않는다.

**완료 기준:** 작성된 36종의 표현과 실제 연결 확인 수준이 구분돼 있고, 과도한 반복 효과 없이 읽을 수 있다. 종료 시 Setting 오류·희생 넉백 Core 요청·전체 Reload 조합 미확인 등 기존 제한을 해결했다고 표시하지 않는다. 보고하고 멈춘다.

## Phase E — 표식의 공통 효과 계약 인수 후

- [ ] **E0 진입 조건:** Core 중간 읽기 계약/새 발동 계약을 받은 뒤 사용자와 변경 범위를 확인한다. 현재 계약 2줄을 먼저 구현하지 않는다.
- [ ] **E1 설계 갱신:** 사냥꾼의 표식 → 약점 노출의 실제 TraitKey/Kind·대상·출처·수명/소모 유무를 확인해 설계 §4.6과 줄 수를 수정한다. 새로운 상태를 기존 소모형 표식처럼 표현하지 않는다.
- [ ] **E2 범위 대조:** 기존 상태 외형/사실 처리기의 교체가 필요하면 별도 Core 계약 대응 작업과 소유권을 나눈다. 이 계획에서 HUD 새 읽기 경로를 몰래 추가하지 않는다.
- [ ] **E3 적용/확인:** 확정된 줄만 작성하고 실제 Core 사건·순간 큐·상태 표시가 일치하는지 수동 확인한다.

**완료 기준:** 새 계약과 작성 줄이 맞고 사냥꾼(420)의 표적과 구별된다. 전체 37종 완료 여부는 이 Phase까지 확인한 뒤 판정한다. 현재는 착수 대기다.
