# 특성 시연 도구 — 조립식 구현 Task 계획

- 날짜: 2026-10-31
- 상태: **이번 구현 범위 완료. A~D와 E 예제·대표 수동 검증을 마쳤으며, E2의 공유 HUD 설명 팝업 연결은 사용자 결정으로 후속 보류했다.** 실제 결과와 잔여 확인은 §10~11에 기록한다.
- 설계 원본: [사건 블록 조립 설계](../specs/2026-10-31-composable-trait-preview-design.md), 결정 CP1~CP9.
- 사용자 승인: 설계/계획 작성 뒤 “계획대로 Phase A~E 순차적으로 구현하고 마지막에 검증 및 내용 정리” 요청으로 일괄 구현을 승인했다. 각 Phase 결과를 보고하며 계속 진행한다.
- 진행 규칙: 구현 요청을 받으면 A→B→C→D→E. **각 Phase 완료 후 멈추고** 결과·변경 범위·검증/미검증을 보고한다. 일괄 진행을 명시적으로 요청받으면 그 승인 범위 안에서 진행한다.
- 경계: Core·FieldCamera·Architecture 수정 금지. 커밋·push·외부 메시지 발송 없음. 새 View 테스트·자동 검증 도구 없음. 기존 Setting 종료 오류 유지.

## 1. 선행 조건·남은 의존성

| 항목 | 조사 결과 | 착수/완료 시 확인 |
|---|---|---|
| 기존 전용 씬/Host | 이미 있음. 전체 런타임 생성, 게임 전투 미시작 | 기존 참조·Boot 복원·Play Maximized의 첫 요청 보존 |
| 이동 사건 | Moved Expected/Final·Voluntary 원인 제공 | 한 칸/여러 칸 경로와 끝 방향 수동 재생 |
| 상태 사건 | TraitStateEvent/Final 적용 경로 제공 | Fact 전체 필드 보존, 각 HUD가 읽는 실제 필드 갱신 |
| 가속/공격력 부여 HUD | 기존 UnitStatuses와 두 아이콘 참조 있음 | 실제 버프 등장·설명·제거, 보유 특성 유지 |
| 공격 출처 | AttackGroup/Origin/접촉 계약 제공 | 실제 수신자, 피해 한 번, 같은 Result의 후속 정산 |
| 전체 완료 | Ordered가 사건+표시 완료 뒤 통지 | 묶음 사이 Display 재생성 없음, 현재 묶음 After만 반영 |
| 직렬화 | 기존 Preset은 단일 입력 | 구체 DTO의 저장/복사/정렬/ID 보존과 명시적 가져오기 |
| 외부 Core 작업 | 첫 범위의 선행 요구 없음 | 계약 부족 발견 시 요청 문서에 기록, 내부 Rule 호출 금지 |
| Unity 수동 확인 | 대표 조립/기존 간단 프리셋 재생 완료 | 상세 결과·설명 팝업 잔여는 §10~11 |

가속/공격력 부여 외 상태, Core 규칙 자동 발동, 자유 병렬/스크럽은 첫 계획 범위 밖이다. 이 범위를 넓혀야 하면 먼저 설계와 계획을 갱신하고 사용자에게 확인한다.

## 2. 파일 배치와 변경 책임

구체 파일명은 아래 기준으로 한다. `.cs` 추가 시 `.meta`를 함께 만들고 LF/UTF-8·기존 namespace/Allman 규칙을 따른다. 책임/수명 변경 없는 파일 분할은 가능하다.

| 영역 | 예상 파일/변경 |
|---|---|
| `ViewSystem/Dev/TraitPreview/Scenario/` | 공개 Scenario/Unit/Entry/Block/State 입력 DTO, ScenarioPreset, 내부 CompiledScenario·Compiler·Ledger |
| 같은 경로 `Blocks/` | 이동/공격/상태/발동 작성기, 가속·공격력 부여 상태 변환, 참조/Origin 작성 |
| 기존 Dev/TraitPreview | Session, Host/Bridge, 간단 입력 변환. 기존 두 특수 Builder의 공통 작성 중복 정리 |
| `Factory/Runtime/InGame/View/` | 프리뷰 작성기/변환기 구성 지점. 필요하면 기존 PreviewFactory 옆에 작은 구성 Factory |
| `Editor/CombatPreview/Scenario/` | 목록 편집기, 종류별 블록 상세, 진단 표시, 프리셋 가져오기 |
| 기존 PreviewWindow/PlayStartScene | 모드 선택·명령 연결, pending 요청에 양 입력을 안전하게 전달 |
| `Editor/CombatPreview/Presets/` | 공통 블록으로 작성한 새 조립 예제 프리셋만 추가 |
| 문서 | 현 설계/계획과 기존 사용 안내·제약 표 연결 |

운영 Ordered/이동/공격/상태 HUD는 재사용 대상이다. 기존 서비스 공개/Export/등록/asmdef 수정은 계획하지 않는다. 공용 조립 계약 변경이 꼭 필요하면 영향과 공유 기록을 먼저 확인한다.

## 3. Phase A — 입력·컴파일 계약

- [x] A1 Scene/Host/Session/DTO 계약을 착수 작업 트리에서 재대조하고 기존 사용자 변경을 구분한다. 새로운 외부 의존이 있으면 구현 전에 보고한다.
- [x] A2 Scenario 환경·유닛·Entry·Block의 구체 Serializable 입력과 새 Preset을 만든다. 버전·안정 ID·깊은 복사 규칙을 정의한다.
- [x] A3 재생 묶음의 허용 구성과 상태/발동의 기록 순서·타격 후속 관계를 입력으로 표현한다. 대기는 묶음 사이 항목으로 둔다.
- [x] A4 내부 CompiledScenario/Packet/Wait와 컴파일 전용 Ledger를 만든다. 유닛/공격 그룹/결과 번호를 한 곳에서 발급한다.
- [x] A5 전체 입력 선검사와 묶음·블록·필드별 진단을 연결한다. 잘못된 참조/중복/뒤바뀐 반응 부모·금지된 대기 분리를 차단한다.
- [x] A6 컴파일과 구체 DTO의 직렬화 형태를 확인한다. 새 서비스/전역 상태/SerializeReference가 생기지 않았는지 검토한다.

**완료 기준:** 구체 블록·묶음·대기 입력과 불변 출력 계약이 컴파일되며, 참조와 오류 위치가 명확하다. 실제 시연 완성을 뜻하지 않는다. Phase A 보고 후 멈춘다.

## 4. Phase B — 공통 사건 작성과 상태 투영

- [x] B1 이동 블록을 현재 Ledger 사실에서 한 칸씩 Moved로 만든다. 경로/점유/생존 검증과 최종 방향을 연결한다.
- [x] B2 일반 공격 작성기를 만든다. 접촉·Origin·대상별 최종 HP→피해/사망 생성과 Final 갱신을 한 곳에서 수행한다.
- [x] B3 일반 발동/추가 공격/가로채기 작성기를 공통 공격 입력에 연결한다. 부모 공격과 실제 수신자부터 확정한 뒤 후속을 작성한다.
- [x] B4 가속 held와 출처별 공격력 grant의 초기/변경 공용 변환기를 만든다. 부여 ID 교체/제거, 출처 보존, 합계/능력치의 단일 투영을 연결한다.
- [x] B5 상태 블록은 TraitStateEvent로 생성하고, 초기 상태와 같은 필드를 갱신한다. 가속 소모는 held=0으로 하고 보유 특성은 남긴다.
- [x] B6 같은 묶음 공격의 타격 후속에만 Origin을 연결한다. ChildAttack은 새 공격 그룹, 가로채기는 공격 안 반응으로 배치한다.
- [x] B7 생성 사건·Before/After·공격 출처/HP의 정합성을 검토하고 컴파일한다. Core 내부 규칙/DB 조회가 없는지 확인한다.

**완료 기준:** 다섯 종류의 공통 블록과 특수 발동이 같은 Ledger에서 사건/전후 사실을 생성한다. Core 수식 재구현과 특성별 시나리오 클래스가 없다. Editor 조립/수동 시연은 아직 후속 Phase다. Phase B 보고 후 멈춘다.

## 5. Phase C — 묶음 실행·대기·초기화

- [x] C1 기존 Session을 조립 프로그램 실행으로 확장한다. Display는 시작/초기화 때만 만들고 묶음 사이에는 유지한다.
- [x] C2 Ordered의 전체 완료 뒤 현재 Packet.After를 반영한다. 다음 Packet 시작은 다음 Tick으로 넘기고 runtime/표시 Tick을 중복 호출하지 않는다.
- [x] C3 시간 대기·수동 대기·경계 멈춤/계속·다음 진행을 연결한다. 공격 내부 사건을 임의 분할하지 않는다.
- [x] C4 중단/초기화·실패·SO/입력 변경·늦은 완료를 세대로 차단한다. 대기 중에도 표시 수명을 유지하고 취소 뒤 Initial을 복원한다.
- [x] C5 CompletedCount·Observation/Repeat Interval은 전체 시나리오 기준으로 갱신한다. 연속 0초 항목도 유한하게 진행한다.
- [x] C6 Host/Bridge/첫 Play 요청을 두 입력 모드에 연결한다. Play Maximized의 임시 창 파괴 처리와 기존 씬/Boot 복원 계약을 보존한다.
- [x] C7 컴파일·생성/등록→Export→조회·자원 해제 순서를 대조한다. 수동 조작 입구를 연결한 범위에서 묶음 간 상태 유지·중단을 확인한다.

**완료 기준:** 같은 표시에서 여러 묶음과 대기를 실행하고 전체 반복/취소를 제어할 수 있다. 운영 진행·Buffer에 합성 사실을 쓰지 않는다. Phase C 보고 후 멈춘다.

## 6. Phase D — 조립 Editor·호환 입력

- [x] D1 기존 창에 간단/조립 모드를 추가하고 목록·블록 상세·진단을 독립 부품으로 나눈다.
- [x] D2 추가/복제/정렬/삭제·묶음 붙이기/분리·Undo를 구현한다. 유닛/블록 참조는 이름 선택 UI+안정 ID로 보관한다.
- [x] D3 종류별 필드만 표시하고 지원하지 않는 상태는 선택지에서 구분한다. Kind/Context와 부모 공격 제약, 상태만/발동만 작성했을 때 차이를 안내한다.
- [x] D4 현재 묶음/경계 대기 상태·전후 HP/공격 기여·아이콘 상태 진단과 재생 명령을 연결한다. 전체 Final을 현재 사실로 미리 표시하지 않는다.
- [x] D5 조립 Preset 저장/불러오기를 연결하고 재열기·복사·정렬 후 ID와 입력 값을 확인한다.
- [x] D6 기존 단일 입력을 공통 블록으로 변환한다. Moment/ChildAttack/Interception이 같은 Compiler/Session을 사용하도록 기존 중복 합성 경로를 정리한다.
- [x] D7 기존 네 Preset의 파일/GUID를 유지한다. 명시적인 가져오기만 제공하고 원본 SO·옛 Preset을 자동 덮어쓰지 않는다.
- [x] D8 컴파일·수동 편집→저장→재열기·잘못된 참조 진단을 확인한다.

**완료 기준:** 코드 수정 없이 블록을 조립/저장/재생하고 기존 빠른 확인도 가능하다. Phase D 보고 후 멈춘다.

## 7. Phase E — 예제·수동 검증·사용 안내

- [x] E1 같은 공통 블록으로 가속, 깔끔한 뒷정리, 희생 생존/사망, 첫 공격+추가 공격의 조립 프리셋을 작성한다. 전용 시나리오 코드가 필요하면 설계를 재검토한다.
- [ ] E2 가속의 이동 선행→held/공격 기여 증가→버프 등장/설명→공격 후 held=0→버프 제거·보유 특성 유지까지 확인한다.
- [x] E3 아군 A 공격→B 공격력 grant 획득→B 버프·수치 증가→명시적 소모/제거를 확인한다. 공격 피해가 버프에서 자동 계산되지 않는 안내를 대조한다.
- [x] E4 일반 공격/추가 공격/희생의 출처·피해 1회·타격 후속·사망/복귀를 확인한다. 공격 후속 중 대기 삽입이 차단되는지 확인한다.
- [x] E5 첫 수동 대기·시간 대기·묶음마다 멈춤·계속·중단·반복을 확인한다. 중간 Final이 전체 Final로 덮이지 않고 상태가 다음 묶음으로 이어지는지 확인한다.
- [x] E6 가속 예제를 20회 전체 반복하고, 공격 중·대기 중 중단 및 SO 수정 취소를 확인한다. Scope/유닛/HUD 등 기존 관찰 수치가 누적되지 않는지 기록한다. 내부 모든 자원 누수 부재로 확대 해석하지 않는다.
- [x] E7 기존 네 간단 Preset과 Play Maximized 첫 진입을 수동 회귀한다. 오류/미실행 항목을 기존 Setting 종료 오류와 구분한다.
- [x] E8 사용 안내·블록/묶음 제약 표·예제 입력·지원/미지원 상태·검증 기록을 갱신하고 변경 범위/남은 한계를 보고한다.

**완료 기준:** 대표 조합을 사용자가 코드 없이 편집하고 전후 사건·버프 아이콘을 확인할 수 있다. 새 View 테스트/자동 검증 코드는 없다. Phase E 보고 후 멈춘다.

## 8. 검증 기록 양식

각 Phase에 실제 실행한 것만 적는다. 컴파일 성공과 Unity 시연 성공을 구분한다.

| 항목 | 기록 |
|---|---|
| 작업 트리/변경 파일 | 착수 시 다른 작업과 구분한 범위 |
| 컴파일 | 실행 방식·오류/새 경고·로그 위치 |
| 직렬화/참조 | 저장/재열기·ID·기존 Preset/GUID 보존 |
| 수동 재생 | 프리셋/입력·관찰 결과·반복 횟수 |
| 수명 | 시작/대기/취소/재시작/SO 수정 뒤 결과 |
| 구조 | SSOT/SOLID/FW/조립 독립성·공유 경계 영향 |
| 미검증/이슈 | 신규/기존 이슈, 필요한 후속 |

## 9. 설계 작성 시점의 완료·미완료

- 완료: 기존 합성기/Session/Editor/Factory와 이동·상태·공격 계약 조사, 기존 HUD 필드·아이콘 참조 확인, 조립 구조/경계/Task 작성.
- 미완료: A~E의 코드·씬·에셋 구현과 Unity 컴파일/수동 검증 전부.
- 이번 턴은 문서만 변경하며 테스트 실행 증거를 만들지 않는다.

## 11. 최종 점검과 잔여 의존성

- 새 입력은 6종 프리셋으로 제공한다. 상태/발동을 명시적으로 조립하며 실제 Core 조건·공식·턴 처리는 실행하지 않는다.
- SSOT: 기획 연출은 원본 SO, 컴파일 사실/ID는 Ledger, 실행 상태는 Session 한 곳이다. 초기/변경 상태 같은 변환기를 사용하며 능력치/피해를 별도로 중복 입력하지 않는다.
- SOLID/독립성: Editor는 입력과 명령만, Compiler는 검증·사건 생성, 작성기는 종류별 사건, Session은 실행 수명, Factory는 등록/의존성 연결이다. 상태 변환기 변경은 해당 초기/설정/제거/HUD를 확인하고, 공격 출처·취소 등 공통 계약 변경은 일반/추가 공격·희생·대기를 함께 확인했다.
- FW/JMH: 기존 Runtime 조립→등록→Export→조회·Tick 순서, UnitHUD 동적 등록, Effect Scope 1회 대여와 종료 반환을 유지한다. 새 서비스 키/asmdef/상위 재등록은 없다. 포인터 입력 GameObject는 Host 수명에 하나이며 반복 묶음마다 생성하지 않는다.
- Core·FieldCamera·Architecture·Framework·운영 씬/기획 DB 에셋 변경 없음. 기존 4개 프리셋+meta 해시 일치. 새 cs/meta 누락 0, SerializeReference 0, View 테스트/자동 검증 메뉴 추가 0. 커밋·push·stage하지 않았다.
- E2 부분 확인: 이동·held·유효 공격력·아이콘 획득/제거·보유 특성 유지 확인. 설명 문자열 생성은 기존 CombatUnitStatuses/UnitStatusVisual 경로를 재사용하지만, 공유 HUD.prefab의 descriptionPanel/descriptionText가 fileID 0이라 실제 설명 팝업은 열리지 않는다. 사용자가 “설명 팝업은 후속으로 남김”을 선택해 공유 프리팹 패널 추가/참조 연결은 후속 보류했다. 공유 HUD 프리팹은 수정하지 않았으며, 설명 팝업 검증도 완료로 표시하지 않는다.
- 남은 수동 범위: 공유 HUD 설명 팝업, 모든 Reload/Boot 설정 조합, 임의 대규모 조합·모든 내부 대여/구독의 누수 부재. 기존 Setting 종료 오류·MeshRenderer 종료 참조 오류·맵 분홍색 표시·Gravekeeper 몸 크기 대체 경고는 별도 현상이며 이번 범위에서 수정하지 않았다.

- 최종 UI 입력 모듈 반영 뒤 가속의 2/6·3/6 경계와 아이콘 증감, Undo 시 초기화·전체 재생 완료 1회를 다시 확인했다. 해당 Play의 로그(release-runtime.log)에 재생 예외/컴파일/Refid 오류 줄 0. 최종 Play를 종료하고 원래 Combat 편집 씬 복귀도 확인했다.
