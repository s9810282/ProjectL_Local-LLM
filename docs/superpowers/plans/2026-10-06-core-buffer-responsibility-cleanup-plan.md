# Core/Buffer Responsibility and Bloat Cleanup Plan

**Date and status:** 2026-10-06. D1–D4 decided; Phase C complete; Phase B complete (B1–B11, B9b comments only). Follows the post-E10 review refactoring (environment plan section 18, R1/P3/P1/P2 complete, uncommitted on `feature/Cheon/refactor/core-system`). Commit or push only on explicit request. Stop and report after every phase.

**Goal:** Finish the remaining environment-code cleanups and remove Core gameplay rules that other Buffers re-decide, so that each rule has one owner and Buffers keep only storage duties.

**Principle (same as R1):** a Buffer validates **stale input** (expected value equals current value), **storage invariants** (ID uniqueness, references exist, value ranges, monotonic counters, no duplicate change) and **atomic prepare/install**. A Buffer does not recompute a formula, decide eligibility/policy, or enumerate content kinds. Core states its decision in the proposal; the Buffer compares the proposal's expected values with what it stores.

**Sources:** the post-E10 review; a static audit of `CharacterBuffer`, `BufferSystemGroup`, `CurrentShopData` and `CharacterCombatFactsComparer` (external analysis, re-verified in code); a read-only sub-audit of all other Buffers (re-verified spot checks: `MatchingVictory` ownership, structure HP equality). File/line references are at the time of writing and must be re-checked before editing.

**Verification for every phase:** focused fixtures, then full EditMode (`ProjectL.Tests.Core;ProjectL.Tests.Framework;ProjectL.Tests.CombatViewBoundary`) compared by failed full name against `.utmp/E10-completion/E10-final-full.xml` (16 inherited failures). Restore the Unity-rewritten FMOD catalog byte-for-byte after each run. Behavior-preserving phases must show an unchanged failure set; a phase that intentionally moves a check states which assertions move and where the rule is now tested.
