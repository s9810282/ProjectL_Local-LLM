> **For agentic workers:** Use superpowers:executing-plans for explicitly authorized phases. Stop/report after every phase. No implementation, delegation, commit or push is authorized by this document. Core and View ownership remain separate.

**Goal:** Deliver Core/API/Buffer movement cancellation from pinned develop evidence on the current cost-free controller-turn system, with effects committing movement, per-unit attack commitment, and atomic restoration of placement/movement opportunity plus exact cancellation of recorded distance. Deliver a concrete View handoff; do not implement View.

**Architecture:** One immutable per-unit checkpoint collection in existing combat state; a pure eligibility/reconciliation owner; the existing command transaction and action-availability query; typed result and ordered Returned facts for View. UndoMove is explicit and independent of the input gesture. No old AP ledger, general rollback framework, duplicate live state, origin-click-specific API, new preview lane or Job. UI/input/playback consumers remain View-owned.

**Locality correction:** Decode existing event payloads through the small pure contract in design §5.1a; undo policy consumes normalized evidence. Quantity-only item grants retain their current independence and do not clear checkpoints or gain a combat-store dependency. Actual non-command character/soul changes selectively invalidate matching dependencies within the existing transaction.

## Global constraints

- Preserve one ordinary move and attack per owning-side turn, no move after attack, repeated-cell rejection, category maximum distance and voluntary end-turn with unused actions. A second ordinary move requires a successful explicit undo to restore the opportunity; do not enable successive moves or native closed loops. Zero movement allowance remains disabled movement. No combat costs or refunds.
- Damage, acquisition, trait activation/state changes and other non-allowlisted movement effects commit movement. Do not silently expand cancellation to those effects or weaken their production behavior to make undo available.
- Restore placement/action use and subtract exactly the cancelled move's RecordedDistance from `CharacterStageRecord.DistanceMoved`. Restore the full current category movement allowance; the cancelled distance does not consume it. Preserve HP/stats/traits/XP/resources, damage/kill statistics, turn counters and other characters. Permit distance decrease only through the typed validated undo command; retain ordinary monotonic validation. No distance-based XP implementation in this task.
- Record lifetime follows accepted design section 4.3. Previews and rejected commands do not create/consume checkpoints. Tokens are battle + controller turn + actor + original move command, not View sequence guesses.
- Keep runtime state and publication in existing Buffer owners, rules in pure Core, input in CombatViewBuffer and presentation in View. Respect SSOT, SOLID, FW-001/002/003/004/016 and current UIInputBinding conventions.
- Only an explicit UndoMove request performs cancellation; matching a saved origin never converts an ordinary Move/Attack/item action. Reuse the shared query/token/command contract for any View gesture. Origin-click adoption and input-mode priority are optional Planning/View work, not Core implementation or acceptance requirements.
- Documents English, code/XML comments Korean, UTF-8/LF, paired .meta handling. Preserve GUIDs for actual file restoration/moves after collision checks. Do not restore old enum numbers to different meanings.
- No View/input/UI/scene/prefab/presentation implementation, FieldCamera/Architecture changes, missing-script asset deletion, shop economy or unrelated trait fixes. Existing consumer compilation is required; View implementation and manual acceptance are external and do not block Core completion. No commit/push. Source delivery, integrated compilation, automated tests and manual acceptance are distinct statuses.

## Review focus

1. Recording before pending reactions or final passive reconciliation would allow effectful moves to be undone: U1 final-transition barrier tests and U2 native publication.
2. Actor-only comparisons miss newly relevant passive effects at the original position: U1 hypothetical-return checks, U3 query/execute parity.
3. Generic Moved -> Available or forged checkpoint fields could bypass the one-action rule: U2 direct transaction and metadata provenance tests.
4. Record lifetime and query freshness differ: unrelated movement may preserve B's token while changing CanUndo. U2 QueryRevision/SourceRevision, selective/atomic invalidation and blocked/unblocked tests cover this; inventory-only grants and no-ops preserve both.
5. Repeated cancellations can inflate future XP or underflow/double-decrement distance: U1 exact-delta/cycle tests and U2 source-validated atomic publication; U3 final Core gates.
6. New event types/Kind variants or incomplete wrapper evidence must not be silently ignored or globally expire unrelated actors: U1.2 reader coverage/producer-scope tests before policy integration.
7. Origin coordinates must not select a different actor or change the command meaning: U2 validates actor/token and ordinary-command separation; U3 hands off selected-actor/request cleanup and attack/item input-mode priority as external View acceptance. Core does not own View selection.
