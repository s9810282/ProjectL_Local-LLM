# 전투 지형 외형을 칸 크기에 맞추기 — Phase별 Task 계획

2026-11-17 · CS-a~CS-c 코드·에셋·문서 반영. 사용자 Unity 확인 대기, 컴파일 미확인.

**완료 조건**은 현재 `GridOutline`의 칸 간격 `1.5 × 1.5`에서 Combat과 SO 모드 3D가 각각 적용 전과 같은 화면을 보여주는 것이다. 칸 간격을 바꿨을 때의 동작은 별도로 확인한다. 적용 범위·모드별 단위와 에셋별 정확한 저장값은 [확정 설계 3판 §3·§5](../specs/2026-11-17-combat-terrain-cell-scale-design.md)에 따른다.

각 Phase가 끝나면 변경 파일, 정적 대조 결과, 사용자의 Unity 확인 결과 또는 대기 항목을 보고하고 멈춘다. 설계 변경이 필요한 경우 구현 전에 사용자에게 묻는다. Unity 컴파일·재생·기존 EditMode 시험 확인은 사용자가 맡는다. View 시험 코드 작성과 MSBuild 실행은 작업에서 제외한다.

## CS-a · 현재 화면 기록과 공통 배율 추출

- [ ] **A1. 구현 전 기준 화면 확보 — 사용자 Unity 확인.** 현재 `StageFieldView_Default`의 칸 간격을 확인하고 아래 비교표에 따라 Combat과 SO 모드 3D를 각각 캡처한다. 스테이지·배치·공개 상태, 카메라 위치·각도·배율, 해상도를 기록한다. 토네이도는 점유 칸 수와 연출 시점도 맞춘다. 한 배치에 없는 지형은 해당 지형이 보이는 다른 배치를 사용한다. 캡처 위치와 재현 조건은 §실행 기록에 남긴다.
- [x] **A2. 배율 계산 추출.** `Tool/Runtime/CombatMapAuthoringMetrics.cs`에 `CellScale(cellWidth, cellLength, source)`를 추가한다. 기존 유한성·양수·정사각 검사와 오차 허용값을 옮기고 `cellWidth / TileLength`를 반환한다. 기존 `Scale`은 이 함수를 호출하고 배경 프리팹 루트 검사와 XYZ 균일 벡터 반환을 계속 담당한다.
- [x] **A3. 기존 호출 대조.** `StageViewPropPresenter`와 `CombatMapScaleEditor`가 사용하는 `Scale` 서명, 유효 입력의 결과, 잘못된 칸 간격과 루트 배율의 예외를 확인한다. 현재 간격에서 배경의 XYZ 배율은 각각 0.75다.

**리뷰 지점** — 공통 함수 추출 결과와 기준 화면 확보 상태를 보고한다. 사용자는 기존 배경·타일 배치가 기준 화면과 일치하는지 확인한다.

## CS-b · 런타임·SO 미리보기·에셋을 함께 이전

- [x] **B1. 칸 간격 연결.** `FieldGridMapper`가 생성될 때 받은 필드 로컬 너비·길이로 공통 함수를 사용한다. 간격은 GridOutline 설정 또는 CellPrefab 실측에서 온다. 구성된 격자에서 얻은 배율을 재사용하고 셀 순회나 매 프레임 계산을 피한다.
- [x] **B2. 타일 위 지형의 크기·보정·높이.** `FieldTerrainPresenter`에서 모양별 프리팹 배율과 SO 배율의 곱, SO 위치 보정에 각각 칸 배율을 한 번 적용한다. `Render`와 사건 시점의 `ShowChanged` 양쪽에서 같은 결과가 나오고 풀에서 다시 꺼내도 배율이 누적되지 않는지 확인한다. `SyncSurface → FillSurface`는 OnTile의 올림 높이만 환산해 `Raise`에 넘긴다. ReplaceTile은 타일이 있을 때의 부모 배율 상속, 없을 때의 필드 배치, `Replace`의 바탕 높이를 각각 보존한다.
- [x] **B3. 토네이도 몸체.** `FieldTornadoPresenter.Render → Create`에서 기존 점유 칸 수 비율과 칸 배율을 결합해 몸체 크기와 보정에 적용한다. 최초 표시·이동·재표시가 같은 보정을 쓰는지 확인한다. 방향 화살표 치수와 연출 설정은 기존 값을 사용한다.
- [x] **B4. SO 모드 3D.** `CombatStageSoPreview.RebuildPlacements`의 지형 배율·보정과 토네이도 몸체에 같은 공통 함수를 적용한다. 오브젝트와 공유하는 분기에서는 지형에만 적용한다. `CombatStageSoSpace.RaiseSurfaces`는 환산한 OnTile 높이로 비교와 저장을 모두 수행한다. `PlaceReplacement`와 교체 바탕 높이는 기존 규칙을 따른다.
- [x] **B5. 같은 Phase에서 SO와 툴팁 반영.** `DataBaseSO/ViewGroup/TerrainVisual/Item/`의 Wall·HighGround·Sandstorm·PresenceModifier·Tornado 다섯 SO에 설계 CS4 표의 float 값을 적용한다. 각 축·보정·높이마다 저장값에 0.75를 곱해 이전 값이 복원되는지 대조한다. WeakGround·Cliff는 교체 모드로 확인한다. `TerrainVisualDataSO` 툴팁에 OnTile과 ReplaceTile의 단위를 구분해 적는다.
- [x] **B6. 구조와 변경 범위 검토.** 배경·지형·도구의 제작 규격과 배율 식은 공통 함수 한 곳, 실행 중 칸 높이는 기존 높이 표 한 곳에서 관리하는지 확인한다(SSOT). 각 Presenter는 자기 외형만 처리하고 기존 호출 계약·Factory 조립·Framework 서비스 등록을 보존하는지 확인한다(SOLID·FW·기능 독립성). 지형 높이를 소비하는 유닛·고스트·격자는 결과로 확인한다.
- [ ] **B7. 사용자 Unity 확인.** 컴파일 후 아래 화면 비교표의 두 결과 열을 채운다. 이어서 §칸 간격 변경 확인과 기존 EditMode의 `DataBaseAssetTests`를 실행한다. 보이는 차이가 있으면 지형·화면·재현 조건을 기록하고 B2~B5의 해당 경로 또는 환산값을 수정한 뒤 같은 조건에서 다시 비교한다.

**리뷰 지점** — 런타임·도구·SO를 한 묶음으로 보고한다. 현재 화면 보존은 1.5에서 두 화면의 전후 대조가 모두 일치했을 때 확인 완료로 기록한다.

### 현재 화면 보존 비교표 · 칸 간격 1.5

각 화면에서 **자신의 구현 전 캡처와 구현 후 캡처**를 대조한다. 같은 배치·공개 상태·카메라 구도를 사용한다. SO 미리보기의 벽·고지대는 기본 프리팹을 표시한다.

| 대상 | Combat에서 대조할 항목 | 결과 | SO 모드 3D에서 대조할 항목 | 결과 |
|---|---|---|---|---|
| 배경·바닥 타일 | 맵 외곽과 타일 경계가 전투 격자에 맞는 위치 | 대기 | 같은 미리보기 시점에서 배경 외곽·타일과 선택 칸 테두리의 위치 | 대기 |
| 벽 | 점유 폭·중심, 이웃에 따라 선택된 모양의 회전과 맞닿는 끝 | 대기 | 기본 벽 프리팹의 폭·중심과 타일 위 높이 | 대기 |
| 고지대 | 블록 윗면·이웃 모양의 접점, 유닛 발과 칸 강조가 윗면에 닿는 높이 | 대기 | 기본 고지대 프리팹의 폭·중심·윗면과 그 칸에 배치한 유닛의 발 위치 | 대기 |
| 모래폭풍·PresenceModifier | 각 지형이 드러난 칸에서 중심·폭·바탕과의 높이 차 | 대기 | 각 배치 프리팹의 중심과 칸 경계까지의 폭, 바탕 위 위치 | 대기 |
| 토네이도 | 같은 점유 칸 수와 연출 시점에서 몸체 중심·바닥 위치·외곽 크기 | 대기 | 같은 점유 칸 수에서 정적으로 배치된 몸체의 중심·바닥 위치·외곽 크기 | 대기 |
| 약한 지반·낭떠러지 | 교체 시 타일의 숨김, 약한 지반 외형과 낭떠러지 빈자리, 타일 없는 칸의 기존 배치 | 대기 | 각 종류를 배치했을 때 해당 타일의 숨김과 교체 외형 또는 빈자리, 타일 없는 칸에서의 배치 | 대기 |

### 칸 간격 변경 확인 · 사용자 Unity 확인

- [ ] 같은 배치에서 간격만 `2.0 × 2.0`으로 바꾼다. GridOutline의 게임과 SO 모드 3D 모두 OnTile 외형과 토네이도 몸체의 폭이 1.5일 때의 `2 / 1.5`배인지 확인한다. 고지대는 바탕에서 윗면까지의 높이도 같은 비율로 증가하고 유닛 발이 윗면에 닿아야 한다.
- [ ] 바닥 교체는 실제 타일이 있는 칸에서 부모 배율만 받고, 타일 없는 칸에서는 기존 필드 크기·보정을 쓰는지 확인한다. CellPrefab의 게임 실측 간격과 도구의 기존 1×1 근사는 설계에 명시된 별도 조건이다.
- [ ] 간격을 `1.5 × 2.0`으로 바꾸고 SO 도구에서 **목록 새로고침**을 누른다. OnTile 지형의 배치 유무와 관계없이 3D 창에 정사각 간격 오류와 실제 X·Z 값이 표시되며, 창을 다시 그릴 때 콘솔에 예외가 반복되지 않는지 확인한다. `1.5 × 1.5`를 복원하고 목록을 새로고침해 3D와 칸 선택이 다시 동작하는지 확인한다.
