# 바닥 타일 소수 크기 지원

> **2026-11-10 후속:** 제작 규격 2·필드 간격 기반 자동 배율의 목표는 [공통 배율 설계](2026-11-10-combat-map-common-scale-design.md)에 있다. **이 문서의 소수/다칸 비율 지원은 현재 구현 계약이며 아직 제거하지 않았다.** 새 1:1 모델에서 기존 화면을 보존할 수 없는 항목은 전환을 보류하고 별도 결정을 받는다. 새 설계만으로 기존 유효 데이터를 거절하거나 크기를 바꾸지 않는다.

- 날짜: 2026-10-31
- 요청: TileSize가 필드 칸 간격의 소수 배수여도 사용할 수 있게 한다.
- 이전 타일 맞춤 설계 TA3의 정수배 제한을 이 요청 범위에서 대체한다.

## 결정

1. 타일 한 장의 필드 크기 / 필드 칸 간격을 양의 유한한 실수로 받는다. 0.5·1.25·1.5배도 허용하며 정수로 반올림하지 않는다.
2. 기준 타일 좌하단과 게임 (0,0) 칸 좌하단을 맞추는 위치 규칙은 유지한다. 모든 타일 경계가 필드 칸 경계와 겹칠 필요는 없다. 넘침은 실제 길이로 비교한다.
3. 높이·바닥 교체 대상은 기존처럼 **칸 중심이 놓인 타일 한 장**이다. 칸 하나에 여러 타일이 걸쳐도 겹친 모든 타일을 교체하는 기능은 추가하지 않는다.
4. 편집기도 실수 비율과 칸 중심을 사용한다. 반전된 타일 축의 경계 포함 방향은 런타임의 타일 로컬 좌표 내림과 일치시킨다. 타일 한 장의 0.0001 이내인 경계는 경계에 맞춘 뒤 내림해 소수·회전 계산의 부동소수점 오차를 흡수한다. 필드 영역·선택 테두리는 실수 사각형으로 그린다.
5. 기존 데이터 형식(Vector2 TileSize·정수 anchorTile), 타일 프리팹 배율, Core·카메라·서비스 조립은 유지한다. 타일 전용 보기에서 모든 타일을 직접 편집할 수 있고, 필드 보기의 집기는 기존대로 칸 중심 기준이다.

## 구조 확인

- SSOT: 크기는 기존 TileSize, 칸 간격은 FieldCellSpacing, 런타임 칸→타일은 CombatMapTileSurface/CombatMapTilesData가 계속 소유한다. 에디터는 Systems 참조를 하지 않는 기존 사본 구조를 유지하고 함께 갱신한다.
- SOLID: 맞춤 계산/Transform 적용/높이 표 책임을 유지한다. 새 추상화·서비스·상태는 만들지 않는다.
- JMH/FW: Factory 생성·Group 등록·Export·소비 경로와 수명 계약을 바꾸지 않는다.
- 독립성: 변경은 타일 맞춤과 에디터의 타일 표시 경로에 한정한다. 공용 테두리 좌표만 Rect로 확장하며 유닛 배치·Core 계산·카메라를 수정하지 않는다.
