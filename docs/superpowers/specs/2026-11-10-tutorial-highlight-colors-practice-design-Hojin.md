# 튜토리얼 실습 UI 점멸·진영별 아웃라인 색 분리 설계안

- 작성: 2026-11-10, Codex.
- 상태: **Phase 1~3과 후속 표현 수정 코드 반영. Phase 4 사용자 Unity 확인 대기.** 실습 점멸·카드 정렬은 계획 §9, 점선 크기/설명 박스는 §10, 실습 배경/모델 경계 안정화/흰 점선/HP 제외/모델 폭은 §11, 겹침 내부 선 제거는 §12, 선택 화살표의 모델 경계 제외는 §13, TargetBorder 프리팹 연결 복구는 §14, 실습 안내의 오른쪽 위 배치는 §15(2026-11-11)가 최신 기록이다. 정적 검수 결과는 각 절에 기록한다. 컴파일·Unity 재생·실제 Outline Pass 출력은 미확인이다. 기존 A~D의 Unity 인수 완료를 의미하지 않는다. 구체 색/주기 수치는 아래의 조정 가능한 구현 기본값이다.
- 실행 계획: [실습 점멸·진영별 색 분리 Task 계획](../plans/2026-11-10-tutorial-highlight-colors-practice-plan-Hojin.md). 계획 작성 요청은 구현 Phase의 실행 승인을 뜻하지 않는다.
- 선행 설계: [최신 규칙 튜토리얼 설계](2026-11-10-tutorial-current-rules-refresh-design-Hojin.md) §6.5. 이번 안은 설명에만 정적인 공통색 강조를 적용하던 부분을 대체한다. 진행·성공 판정·입력 제한은 유지한다.

## 1. 요청과 현재 상태

- 사용자 요청: 카드·턴 종료 등 실제 대상 UI의 가장자리에 진한 노란 점선을 추가하고, 아군/적 아웃라인 색을 각각 조정할 수 있게 한다. **기존 튜토리얼 영역 테두리는 흰색이 맞으며, 그 색을 노란색으로 바꾸는 요청이 아니다**(2026-11-10 카드 이미지와 함께 정정).
- 사용자 후속 선택: **설명과 실습 중 필요한 UI를 계속 강조하되, 점선의 깜빡임은 실습에서만 적용한다.** 설명 중에는 고정 점선을 표시한다(2026-11-10 사용자 정정). 일반 전투 전체의 상시 강조는 선택하지 않았다.
- 최초 설정은 `TutorialViewUI → Highlight Style → Color` 한 값으로 UI/모델의 흰색을 공유했다. 현재 `Assets/ProjectL/Prefabs/UI/Tutorial/TutorialUI.prefab`의 TutorialUI 객체 → `TutorialViewUI → Highlight Style` 아래 **UI Border Color / Target Border Color / Ally Outline Color / Enemy Outline Color**로 분리했다. `Model Width`는 기존 공통 모델 외곽선 폭이다.
- 기존 `FocusBorder`는 손패 등을 합친 화면 영역에 흰색 점선을 그린다. 별도 `TargetBorder`는 개별 카드 소개·조작 실습의 실제 카드 배경과 버튼의 네 모서리에 노란 점선을 그린다. **전체 카드 소개(설명의 Hand)는 노란 점선을 표시하지 않는다. 턴 종료 실습은 실제 턴 종료 버튼의 노란 점선을 점멸한다**(사용자 후속 정정). 두 위젯 모두 TutorialUI 내부에 두며 각 카드/버튼 프리팹에는 추가하지 않는다.

## 2. 적용 방식

**기존 공통 강조 표시기를 확장한다.** FocusLocator/Frame은 기존 영역 사각형과 별도로 실제 UI의 RectTransform을 전달한다. 카드의 노란 테두리는 배치용 루트가 아닌 기존 `Button.targetGraphic`에 연결된 카드 배경을 따른다. `TutorialTargetBorderGraphic`은 네 월드 모서리를 TutorialUI 좌표로 투영해 카드의 회전·크기 변화를 따른다. 대상 사각형의 안쪽에 점선을 그리며 스프라이트의 투명 부분을 따라 윤곽을 추적하는 방식은 아니다. UI 색과 점멸은 TutorialUI 스타일 한 곳, 모델은 기존 외형 합성 층을 사용한다.

카드/버튼마다 별도 점선 컴포넌트를 부착하면 대상·색·정리 수명이 여러 프리팹에 나뉘므로 채택하지 않는다. 일반 전투 상시 강조로도 확장하지 않는다. 전투 진입 버튼은 기존 BattleChangerUI의 부모 영역과 실제 ButtonRect를 구분해서 읽는다.

## 3. 조정 항목과 제안 기본값

다음 값은 사용자가 지정한 확정 수치가 아닌 **구현 제안 기본값**이다. 같은 Inspector에서 이후 조정할 수 있다.

| 설정 | 제안 기본값 | 적용 |
|---|---|---|
| UI Border Color | 흰색 `#FFFFFF`, 알파 1 | 기존 튜토리얼 영역 점선 |
| Border Thickness | 4 Canvas 단위 | 흰 영역 테두리 폭(11-11 확대) |
| Target Border Color | 진한 노란색 `#FFCC00`, 알파 1 | 개별 카드·실제 버튼 가장자리. 상단 체력 UI는 제외 |
| Target Border Thickness | 5 Canvas 단위 | 개별 대상의 노란 점선 폭(11-11 확대) |
| Blink Enabled | 켬 | 실습 중 노란 대상 점선만. 설명·흰 영역 테두리에는 적용하지 않음 |
| Blink Period | 1.2초 | 밝음 → 어두움 → 밝음 한 주기 |
| Blink Min Alpha | 0.35 | 완전히 사라지지 않는 부드러운 점멸 |
| Ally Outline Color | 청록 계열 `#39C5FF`, 알파 1 | 강조 대상 아군·메인 캐릭터 |
| Enemy Outline Color | 붉은 계열 `#FF5A4F`, 알파 1 | 강조 대상 적·적 넥서스 |
| Model Width | 0.04 | 모델 공통 폭(11-11 사용자 요청으로 0.015에서 확대) |

- 점선 길이는 16·간격은 8로 확대했다(2026-11-11 사용자 요청). 아군·적 모델 아웃라인은 점멸하지 않는다.
- 영역/대상 UI 색·모델 색을 독립된 필드로 분리하며 기존 직렬화 Color는 UI Border Color로 이전한다. 실제 TutorialUI 프리팹에는 색·폭·점멸 설정을 명시한다. 두 Graphic의 일반 Color가 아닌 루트 스타일이 원본이다.
- 점멸은 실습 표시 중에만 표시 전용 시간으로 동작하며 게임 시간 배율이나 단계 진행 시간에 의존하지 않는다. 자동 다음 진행은 추가하지 않는다. 모양이 그대로면 점선 메시를 매 프레임 다시 만들지 않고 점선 자체의 표시 알파만 갱신한다. 설명으로 전환하거나 점멸을 끄면 점멸 알파 배율을 1로 복원해 설정된 색 그대로 고정 표시한다.

## 4. 설명·실습 표시 대상

- 설명 박스와 실습 안내는 사용자 지정 `Assets/ProjectL/Sprites/TextBox/Box.png`를 사용한다(2026-11-11). 기존 45px 슬라이스·Image=Sliced·Pixels Per Unit Multiplier=2로 모서리를 보존하고, 설명은 기본 560×144·실습은 520×112·본문은 모두 사방 여백 32를 적용한다. 긴 본문은 기존 측정에 따라 높이를 늘린다. 원본 이미지/임포터와 막힌 입력 안내 배경은 유지한다.
- 실습 안내는 오른쪽 위 배경 영역에 배치해 상단 중앙의 플레이어/상대 턴 표시를 가리지 않는다(2026-11-11 사용자 요청, 계획 §15). 기준 Canvas에서 오른쪽 여백은 기존 Screen Margin=24, 상단 여백은 Practice Top Margin=136으로 설정해 설정 버튼 아래에 둔다. 막힌 조작 안내도 같은 오른쪽 기준으로 실습 안내의 실제 높이 아래에 쌓는다. 설명 단계의 대상 옆 배치는 유지한다.
- 설명에서 밝게 드러내는 UI/모델 영역의 바깥에 흰 점선을 표시한다. 영역들이 겹치거나 맞닿으면 다른 밝은 영역 안으로 들어가는 점선 조각은 잘라내 합쳐진 영역 바깥에만 선을 남긴다(2026-11-11 사용자 요청). 밝은 영역을 하나의 큰 사각형으로 늘리지는 않는다. 상단 체력 UI에는 흰 영역 테두리만 사용하며 노란 점선은 표시하지 않는다. 모델 아웃라인은 진영별 색을 유지한다.
- 모델 경계는 설명 시작 때 한 번 측정한 개체 루트 기준 크기를 유지해 Idle 때문에 검은 덮개·흰 테두리·설명 위치가 흔들리지 않게 한다. 현재 카메라/루트 변환과 아웃라인 폭은 계속 반영한다. 애니메이션은 수정하지 않고 기존 holePadding을 유지한다. 강조 해제/단계 전환/실습/숨김/종료/오류에서 경계도 정리하며 개체 재바인딩 때 다시 측정한다.
- 선택 시 머리 위에 뜨는 행동 커서는 모델 경계에 포함하지 않는다(2026-11-11 사용자 요청). 생성자가 커서 루트에 `UnitModelBoundsExclusion` 표시를 붙이고, FieldUnitView는 그 하위 Renderer를 경계 측정에서 제외한다. 화살표가 켜져 있어도 밝은 영역·흰 점선·설명 회피 영역을 위로 늘리지 않는다. 커서 자체의 표시·색·크기·선택 동작은 유지한다.

- 설명은 현재 17단계 정의의 대상 그대로다. 전체 손패 소개는 기존 흰 집합 영역만 표시하고 노란 카드 테두리는 숨긴다. 메인 카드 등 개별 대상에는 흰 영역과 실제 배경의 노란 테두리를 고정 표시한다. 모델은 진영별 색을 사용한다. 마지막 25번의 강조 없음·중앙 배치·클릭 완료도 유지한다.
- 실습 중에는 안내 띠와 점멸하는 노란 대상 UI 점선만 표시한다(Phase 2/3). 흰 영역 테두리·어두운 덮개·전체 클릭 차단막을 켜지 않으며 기존 입력 제한을 따른다. 모델의 일반 선택/호버 표시도 그대로 사용한다.

| 실습 | 플레이어가 조작할 수 있을 때 표시할 UI |
|---|---|
| 12 배치·전투 진입 | 손패의 개별 카드·전투 진입 버튼 |
| 18 이동 | 이동 조작은 필드에서 하므로 전투 중 추가 UI 없음. 배치로 복귀하면 손패·전투 진입 버튼 |
| 22 공격 | 전투 중 공격 버튼과 회복 경로인 턴 종료 버튼. 배치로 복귀하면 손패·전투 진입 버튼 |
| 24 턴 종료 | 턴 종료 버튼 |

- 위 목록은 정의 데이터에서 관리한다. 그래픽/모델 합성 클래스에 단계 번호나 실습 규칙을 넣지 않는다. 전투/배치 상태와 실제 활성 UI를 읽어 해당 구간의 대상만 표시한다. 없는 카드나 꺼진 버튼을 강제로 만들거나 켜지 않는다.
- 실습은 목표 달성까지 강조를 갱신하지만 적 응답·연출·제출 대기처럼 조작할 수 없는 동안에는 점선을 숨긴다. 재시도 가능한 플레이어 입력 시점에는 다시 표시한다. 실습 완료·단계 전환·종료·중단·씬 해제·UI 숨김 때 표시를 정리한다.
- 실습에서 모델을 새로 일괄 강조하지 않는다. 이번 아군/적 색 분리는 기존 설명의 모델 강조에 적용한다.

## 5. 변경 경계와 검수

- **SSOT:** 색/점멸 값은 TutorialUI 스타일, 강조 대상은 단계 정의, 위치는 실제 RectTransform, 진영은 기존 Buffer 읽기 → Locator/Frame, 모델 속성 작성은 UnitModelAppearance 한 곳이다. 적 넥서스도 공개 소유 진영을 사용한다.
- **SOLID:** S는 대상 해석·표시 값·점선 출력·모델 대여를 분리한다. O는 기존 강조 경로를 확장한다. L은 기존 대여 반환/효과 복원·수동 진행 계약을 유지한다. I는 표시 자료에 필요한 진영과 좁은 설정만 전달한다. D는 공개 Buffer/표시 계약에 의존하고 Core 규칙을 복제하지 않는다.
- **JMH/FW:** 기존 Factory/Group 조립과 UIId.Tutorial 등록·UISystem 개폐를 유지한다. 별도 서비스·Canvas·입력 구독·루트 재등록을 추가하지 않는다. 표시 계층의 깜빡임은 Job 완료나 실습 성공 조건에 관여하지 않는다.
- **변경 독립성:** 영역/대상 점선은 별도 Graphic, 점멸은 TargetBorder/Style, 모델 색은 Style/Frame/모델 대여 접점, 실습 표시는 정의/Locator/UIDisplay/UI 수명 접점에 한정한다. BattleChangerUI에는 실제 버튼 영역을 읽는 속성만 추가한다. Core·FieldCamera·Architecture·일반 전투 효과·각 카드/버튼 프리팹은 수정 대상으로 삼지 않는다.
- 실습 표시가 제출 대기/모달/연출 상태를 놓치지 않도록, 구현 계획 2-2에서 기존 전투 입력 사실을 전투 번호·배치/전투 국면·표시 가능 여부로 좁혀 읽는 접점을 구체화한다. 기존 입력 정책을 재사용하고 Factory에서 공급자를 연결한다. 전투 입력 허용 자체나 공개 서비스 등록 구조는 바꾸지 않는다.
- 표시 중 색 변경/진영 변화/재바인딩 시 해당 모델의 강조만 갱신하고, UI 점멸 때문에 모델 대여를 매 프레임 다시 만들지 않는다. 원래 재질과 다른 효과는 기존 합성/복원 경로를 유지한다.
- 새 Test 코드·시험 도우미·MSBuild·EditMode는 수행하지 않는다. 구현 후 정적 대조와 사용자 Unity 확인을 구분한다. **컴파일 미확인**을 보고한다.
- Unity 확인: 전체 카드 소개에는 흰 영역만 표시·개별 카드/실제 버튼의 노란 점선은 배경 가장자리와 정렬·설명은 고정, 턴 종료 실습을 포함해 실습에서만 노란 점멸·설명 복귀 시 알파 복원, UI 위치·클릭/드래그, 적 응답/배치 복귀, 아군·적·넥서스 별 색, Inspector 조정, 단계/씬 전환 정리, 기존 외형 효과 복원, 실제 Outline Pass 출력. 해상도 변경과 점멸 비활성 시 고정 테두리도 확인한다.

후속 Phase 1~4 계획에 따라 실행하되, 사용자 후속 정정에서 직접 요청한 실습 점멸은 Phase 2/3 연결까지 수행한다. 기존 Phase E나 후속 Phase 4의 사용자 Unity 통합 인수를 자동으로 완료 처리하지 않는다.
