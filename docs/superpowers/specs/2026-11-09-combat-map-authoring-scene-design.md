# 전투 배경 씬 작업 설계

> **2026-11-10 후속 설계:** 배경·타일의 제작 규격 2와 `OutlineCellSpacing` 기반 공통 자동 배율, Combat/Authoring 공동 적용은 [공통 배율·기존 표시 보존 설계](2026-11-10-combat-map-common-scale-design.md)가 원본이다. **변경 전후 화면 보존이 필수**이며 기존 불일치를 자동으로 고치지 않는다. 아래 S2~S6의 원본 배율 × SO 배율 설명은 현재 구현/과거 기록이고 새 계약은 아직 미구현이다.

- 작성: 2026-11-09. 전투 View 작업.
- 상태: S1~S5 코드 반영. S5는 Unity에서 `Test 1`의 간격 경고와 배경 X 이동·원복을 확인했다. S4 편집용 격자는 Scene/Game 뷰 표시·토글·씬 재열기를 확인했다. `Prefab`/`MapDefinition` 실물 에셋, FBX 배치 창·Combat Play 구도 비교는 미확인.
- 배경: `2026-11-08-combat-scene-camera-design.md`의 D1~D3는 FBX 배치 창 안에서 전투 구도를 미리 보여준다. 사용자는 프랍을 씬에서 직접 배치하면서 Game 뷰로 구도를 계속 보는 작업 방식을 선택했다.

## 목표와 경계

전용 `CombatMapAuthoring` 씬에서 Play 없이 배경 프랍을 선택·이동하고, 같은 순간 Game 뷰에서 전투 카메라 구도를 확인한다. 씬은 운영 전투 흐름에 등록하지 않는다. Combat·Boot 씬과 Core·FieldCamera·Architecture는 수정하지 않는다. 기존 FBX 배치 창은 유지한다.

## 책임과 원본

| 대상 | 책임 | 원본 |
|---|---|---|
| `CombatCamera.prefab` 인스턴스 | 전투 시점의 위치·회전·가상 카메라 구성 | 기존 공용 프리팹 |
| `Main Camera` | Game 뷰 출력, Cinemachine Brain, URP 및 FMOD Listener 설정 | Boot 씬 출력 카메라 구성 |
| 작업 씬 | 프랍을 편집할 공간과 조명 | 씬 자체 |
| 후속 편집 Inspector | 선택한 운영 `ViewStageDataSO`의 배경·보정 값을 씬 편집 대상으로 연결하고 저장 | ViewStage 테이블에 등록된 SO |

프리팹 인스턴스는 링크를 유지한다. 맵 프리팹에 카메라를 저장하지 않는다. 출력 카메라는 작업 씬 전용이므로 Boot의 인스턴스를 공유하지 않지만, 투영·URP·Brain 구성은 동일하게 시작한다. 작업 씬은 Build Settings에 넣지 않는다.

## Phase 경계

1. **S1 카메라 작업 씬:** 새 씬에 공용 카메라 프리팹 인스턴스, Main Camera, 기본 조명을 둔다. Game 뷰 출력과 프리팹 연결만 확인한다. 이때 런타임 줌 초기값은 아직 재현하지 않는다. 가상 카메라 프리팹의 렌즈를 씬에서 복사해 저장하거나 `zoomMax`를 상수로 중복하지 않는다.
2. **S2 스테이지 연결 Inspector:** 씬의 편집 루트에 `ViewStageDataSO`를 지정하고 등록·맵 참조·보드 맥락을 검증한다. 운영 `StageViewPropPresenter`와 같은 배치·타일 정렬 계약을 호출한다. 원본 프리팹과 미리보기 인스턴스를 구별한다. 공용 설정의 시작 줌·줌 자세는 원본 SO에서 읽어 Game 뷰에 반영한다. 선택/Undo/재열기를 확인한다.
3. **S3 저장 경계:** 씬에서 이동한 프랍의 변경을 원본 맵 프리팹에 명시적으로 적용한다. `StageViewProp` 보정은 SO에 명시적으로 저장한다. 둘 다 Undo와 오염 방지, FBX 배치 창에서의 재열기, Play 결과 비교를 확인한다. 자동 저장이나 원본 암묵적 변경은 허용하지 않는다.

### S3 저장 계약

- 커스텀 Inspector는 위치·회전·배율과 타일 방식의 타일 오프셋·기준 타일을 **씬 작업 값**으로 보유한다. 값을 바꾸면 현재 맵 인스턴스와 표시 타일의 배치만 갱신한다. `ViewStageDataSO`는 **보정 SO 저장** 버튼에서만 쓴다. 타일 방식의 위치 X/Z는 런타임처럼 기준 타일 정렬에 의해 덮인다.
- **프랍 프리팹 저장** 버튼은 선택된 ViewStage의 원본 프리팹과 현재 인스턴스의 출처가 같을 때만 활성화한다. 프리팹 override 중 배경 루트 GameObject·Transform과 옛 Camera·Cinemachine·ImpulseListener의 표시용 변경을 제외한 뒤 Unity의 프리팹 적용 API로 자식 변경·추가·삭제를 저장한다. 표시 타일은 프리팹 인스턴스 밖이어서 적용 대상이 아니다. 적용 뒤에는 표시용 배치·카메라 차단을 다시 건다.
- 두 저장은 서로의 에셋을 쓰지 않는다. Undo는 씬 작업 값·씬 오브젝트·SO 보정에 제공한다. 프리팹 에셋 적용의 Undo는 Unity의 `InteractionMode.UserAction`에 따른다. 저장 전 출처·에셋 경로·모드를 다시 검사하고, 실패하면 씬 인스턴스의 기존 override를 복구한다.
- `Prefab`, `MapDefinition`, `PrefabWithTiles`를 모두 지원한다. `MapDefinition`은 SO의 맵 프리팹을 대상으로 한다. 현재 ViewStage Item 에셋 21개는 모두 `PrefabWithTiles`이고 운영 표 등록은 20개다(`StageViewProp_Test2`는 미등록). 이를 `MapDefinition`으로 취급하지 않는다.

S1 당시 씬에는 원본 프리팹의 가상 카메라 렌즈가 보였고, 런타임은 설정 SO의 `Use Zoom Pose`에 따라 시작 렌즈와 자세를 정했다. S2에서 편집용 Cinemachine 확장이 원본 설정을 읽어 Game 뷰에 시작 구도를 적용했다.

### S2 구체화

- 편집 루트는 선택한 ViewStage와 현재 불러온 ViewStage를 구분해 저장한다. Inspector는 SO 선택만으로 기존 씬 인스턴스를 버리지 않고, 명시적 불러오기에서만 교체한다. 교체 전에는 현재 프리뷰 삭제를 알린다. Undo로 복구할 수 있어야 한다.
- 선택 SO의 운영 표 등록·유일한 전투 Root·필드 칸 수·필드 표시 간격을 `FbxCombatStageContext`에서 검사한다. 맵 원본은 그 SO가 선택한 프리팹이다. 씬 인스턴스는 `PrefabUtility.InstantiatePrefab`으로 링크를 유지하고, 루트에만 런타임의 위치·회전·원본 배율×보정 배율을 적용한다. 원본 프리팹은 바꾸지 않는다.
- PrefabWithTiles의 타일은 `StageBackdropPreview` 컨테이너에서 맵 프리팹 인스턴스와 형제로 만든다. 컨테이너에 함께 회전·이동을 적용하고 `CombatTileAlignmentMath`의 기울기·방향·기준 타일 이동을 호출한다. 그래서 맵 인스턴스의 `Apply All`에 표시 타일이 포함되지 않는다. 타일 외형의 무작위 선택은 편집용 고정 시드여서 Play와 다를 수 있다.
- MapDefinition 방식은 맵 SO의 `Prefab`을 씬 인스턴스로 보여 준다. 운영 `MapAssembler`의 베이크 조명 설치까지 씬에 복제하지 않으므로 조명 결과는 Play와 다를 수 있다. 위치·프랍 편집 수락 기준과 조명 일치 여부를 구별한다.
- 씬의 공용 가상 카메라 Transform·렌즈 원본은 유지한다. Editor 전용 Cinemachine 확장이 설정 SO의 시작 렌즈·Zoom Pose 끝점을 카메라 상태에만 적용한다. 따라서 프리팹 override로 시작 줌 상수를 저장하지 않는다. 설정 SO를 다시 읽는 동작은 Inspector 버튼과 프로젝트 변경 시점으로 제한한다.
- 씬 저장/재열기에서는 선택 SO, 연결된 맵 인스턴스, 표시 타일이 복구된다. 편집 중 프랍 변경은 씬 override이며 S3 전에는 원본 프리팹에 반영되지 않는다. 표시를 위해 옛 카메라를 끈 override와 맵 루트 변환도 인스턴스에 남으므로 Unity의 `Apply All`을 직접 쓰면 안 된다. S3의 명시적 저장에서 프랍 변경과 표시용 override를 구분한다.

## 설계 점검

- **SSOT:** 운영 스테이지는 ViewStage SO, 구도는 공용 카메라 프리팹, 줌 설정은 공용 SO만 원본이다. 작업 씬은 참조와 편집 상태만 소유한다.
- **SOLID:** 씬은 조립, Inspector는 선택·검증, 배치 어댑터는 프리뷰, 저장기는 원본 적용만 맡긴다(SRP). 단계별 기능은 독립 확장한다(OCP). 프리뷰가 런타임 계약의 구체 표현을 바꾸지 않는다(LSP). Inspector 소비 API는 작은 읽기·저장 경계로 나눈다(ISP). 편집 UI는 ViewStage·카메라 읽기 경계에 의존한다(DIP).
- **JMH Framework/FW:** 작업 씬은 운영 시스템 모듈·서비스를 등록하지 않고 Editor 범위에서만 편집한다. Runtime Buffer를 읽거나 Core를 직접 참조하지 않는다.
- **기능 독립성:** 카메라 조립과 스테이지 선택/저장은 별도 Phase다. 카메라 프리팹 변경 시 S1의 참조와 Game 뷰만 확인하고, 저장 로직 변경 시 S3만 검증할 수 있다.
- **성능:** S1은 정적 씬 구성이다. S2 프리뷰는 선택·SO 변경 시 갱신하고 매 프레임 DB 재조립·프리팹 재생성을 피한다.

### S2 구현 경계 재평가

- **책임·SOLID:** 루트 컴포넌트는 선택/출처 참조만, Inspector는 UI·불러오기 순서만, `CombatMapAuthoringPlacement`는 배치, `CombatMapAuthoringCameraSetup`/`Pose`는 카메라 설정을 맡는다(SRP). 새 배경 방식은 배치 경계, 새 카메라 자세는 카메라 경계에서 다룬다(OCP). 프리뷰는 맵 프리팹 계약을 바꾸지 않고 별도 인스턴스로 표시한다(LSP). Inspector는 필요한 ViewStage/카메라 읽기와 프리뷰 생성만 호출한다(ISP·DIP).
- **외부 경계·FW:** 운영 표와 SO 직렬화 필드 읽기는 기존 `CombatStageSoAssets`/`FbxCombatStageContext` 경계를 통과한다. Core·Buffer·런타임 서비스 등록은 추가하지 않았다.
- **유지보수·확장:** 배경 프리팹 원본과 편집 인스턴스, 표시 타일을 분리했다. S3 저장기는 맵 인스턴스의 프랍 변경만 선택해 적용하고 표시용 카메라 비활성화·루트 변환을 제외해야 한다.
- **성능:** Inspector는 선택·프로젝트 변경·Undo 시에만 운영 표와 SO 맥락을 다시 읽는다. 카메라 상태 콜백은 캐시한 설정과 현재 Transform으로만 계산한다. 맵 재생성은 명시적 불러오기에서만 한다.

## S4 — 편집 씬 필드 격자

- 목표: `CombatMapAuthoring`의 Scene·Game 뷰에 전투 필드 격자를 표시해 바닥 타일과 칸 경계를 맞춘다. 격자는 편집용 표시이며 운영 `StageFieldViewDataSO.showGridDecal` 값과 운영 전투 화면은 바꾸지 않는다. 현재 운영 값은 꺼져 있다.
- 좌표 원본은 등록된 전투 Field의 가로·세로 칸 수와 등록된 `StageFieldViewDataSO`의 `GridOutline` 칸 간격이다. `CombatMapAuthoring` 루트의 월드 원점을 필드 중심으로 쓰고, 배경 프리팹·타일 컨테이너의 이동/회전과 독립시킨다. 따라서 바닥 타일 보정을 바꿔도 격자는 움직이지 않아 어긋남을 볼 수 있다.
- 선 재질·기본 선 폭·투영 깊이는 운영 Field View SO에서 읽고, 실제 그리드 위치·마스크·데칼 상자 계산은 런타임 `FieldGridDecal`과 공용 값 계산으로 합친다(SSOT). 편집 씬의 타일 렌더러가 Default 렌더링 레이어를 쓰므로 편집용 데칼은 운영 레이어에 Default도 포함한다. 표시 범위만 넓히며 프리팹 렌더러 속성을 변경하지 않는다.
- 편집용 격자 컴포넌트는 루트에 붙고 데칼 오브젝트와 복제 머티리얼을 메모리에만 만든다. 씬·ViewStage·프리팹 원본에는 데칼 머티리얼의 계산 값을 저장하지 않는다. Inspector에서 표시를 켜고 끄고 운영 설정을 다시 읽을 수 있다. S3 씬처럼 이미 배경이 불러진 경우 격자만 추가하며 프랍 override를 버리지 않는다.
- **경계·SOLID:** Inspector는 조립·조작, SO 어댑터는 직렬화 읽기, 공용 계산은 격자 기하, 편집 컴포넌트는 생성·해제만 맡긴다. Core·Buffer·FieldCamera와 운영 데이터는 바꾸지 않는다. 카메라/프리팹 저장 경로는 격자 기능의 내부 변경에 영향받지 않는다.
- **성능:** 격자는 스테이지 불러오기·설정 새로고침·컴포넌트 활성화 때만 재구성한다. 프레임마다 DB 조회나 셀별 GameObject를 생성하지 않는다. Scene/Game 뷰 확인과 씬 재열기 때 재생성·자원 해제를 검증한다.
- **S4 확인:** `Test 1`의 필드 9×9와 `StageFieldView_Default`의 1.5×1.5 간격으로 9×9 데칼 격자가 Game 뷰 바닥에 표시됐다. 표시를 끄고 다시 켜면 데칼이 사라졌다 복원됐고, 씬을 저장해 재열어도 표시됐다. 생성된 데칼 오브젝트·복제 머티리얼은 씬 YAML에 저장되지 않고 설정·원본 재질 참조만 저장됐다. Unity Console 오류 0. 당시 타일 간격 일치 판단은 S5의 실제 변환 확인으로 정정한다.
- **한계:** 편집 데칼은 운영 표시 스위치와 별도이고 Default 레이어 표면도 받는다. 투영 깊이 밖의 고저차·운영 중 지형 교체는 편집 씬에 재현하지 않는다. 운영 Combat 화면은 기존 `showGridDecal=0`을 유지한다.

## S5 — 배경 수평 위치와 격자 간격 진단

- `PrefabWithTiles`의 기존 정렬은 `positionOffset` X/Z를 상쇄해 타일을 필드에 고정한다. 그래서 위치 X/Z 입력이 맵을 움직이지 않는다. Inspector는 이 무효 입력을 숨기고 실제 배경 맵의 월드 X/Z를 조작 값으로 보여 준다. 사용자가 월드 X/Z를 바꾸면 이동량을 맵 로컬 벡터로 역변환해 기존 `mapTiles.offset` X/Z를 반대 방향으로 갱신한다. 타일·필드 그리드의 월드 위치는 그대로 두고 배경만 지정한 방향으로 움직인다. `positionOffset` Y와 회전·배율·기준 타일은 기존 계약을 유지한다. 운영 `StageViewPropPresenter`와 데이터 형식은 바꾸지 않는다.
- 조작 값은 새 SO 필드를 만들지 않고 `mapTiles.offset`에서 파생한다(SSOT). Inspector에는 실제 배경 위치와 저장될 원본 타일 오프셋을 구별해 표시한다. Undo·SO 저장은 기존 S3 경계를 재사용한다. `Prefab`/`MapDefinition`의 위치 입력은 기존처럼 세 축 모두 `positionOffset`에 쓴다.
- 그리드 칸 간격은 운영 Combat처럼 필드의 `outlineCellSpacing`을 계속 원본으로 쓴다. 타일 중심 간격은 실제 타일 루트 변환의 X/Z 축 길이와 `tileSize`에서 구한다(축 회전·프리팹 루트 배율·SO 배율 포함). 두 값이 다르면 Inspector에 각 축의 실제 간격과 원본을 함께 보이고 경고한다. 편집용 격자를 배경 배율에 맞춰 임의로 늘리거나 SO 배율을 자동 수정하지 않는다. 현재 `Test 1`은 `tileSize=2`, 프리팹 루트 배율 `0.75`, SO 배율 `0.75`여서 타일 간격 `1.125`, 필드 간격 `1.5`다. S4 기록의 `2 × 0.75 = 1.5`는 프리팹 루트 배율을 빠뜨린 계산으로 정정한다.
- **경계·SOLID:** Inspector는 입력·진단 표시만 담당하고, 좌표 변환은 편집 배치 경계에 둔다. 필드 간격은 기존 운영 SO 어댑터에서 읽는다. 타일 정렬 계산·런타임 배치·Core는 수정하지 않는다. 그리드 경고는 맵 배치 값이 바뀔 때 계산하며 프레임마다 에셋을 다시 읽지 않는다.
- **S5 수평 입력 보완:** 월드 X/Z는 `Vector2Field`의 X/Y 보조 라벨로 표시하지 않고 X·Z 입력을 따로 둔다. 180°·90° 회전의 역변환에서 생긴 극소 수치만 0으로 정리해, 한 축을 바꿀 때 다른 축의 원본 타일 오프셋이 부동소수점 오차로 오염되지 않게 한다. 화면 표시의 0 근처 잡음도 숨긴다. 유의미한 회전 교차 성분은 유지하고, 실제 배치 식·저장 계약은 바꾸지 않는다.

### S3 구현·검증 경계

- `CombatMapAuthoringRootEditor.Saving`은 씬 보정값 UI와 명시적 저장 버튼만 소유한다. `CombatMapAuthoringSave`는 SO 보정 저장과 프리팹 적용을 분리한다. 프리팹 저장은 출처를 다시 확인하고 표시용 맵 루트 GameObject/Transform·카메라 override를 걸러낸다. `MapTileRoot`는 맵 프리팹 인스턴스 밖에 둔다. 저장 뒤 표시용 배치와 카메라 차단을 다시 적용한다.
- Unity 6000.0.73f1 Editor에서 `Test 1` ViewStage(StageKey 10001, `PrefabWithTiles`)를 불러와 Game 뷰와 형제 `MapTileRoot`를 확인했다. 보정 Y를 0→0.25로 바꾼 즉시 맵 인스턴스의 Y가 0.25가 되었고 Undo로 0에 복귀했다. SO 저장은 파일 해시 변화를 확인한 뒤 Y=0을 다시 저장하여 원래 해시로 복구했다. 변경 없는 프리팹 저장은 0건으로 처리되어 표시용 override가 적용 대상으로 세어지지 않았다.
- 맵 자식 `B1`의 이름을 임시 변경한 뒤 **프랍 프리팹 저장**으로 1건을 적용했다. 프리팹 diff에는 해당 자식 이름 override 4줄만 추가됐고 표시용 루트·카메라 변경은 없었다. 원본 프리팹을 검증 전 SHA-256으로 복구하고 Unity에서 Refresh·씬 재열기 후 `B1` 이름과 출처 연결을 확인했다. 씬 파일 해시도 검증 전후 같다. Console 오류 0.
- 프리팹 적용 Undo, `Prefab`/`MapDefinition` 실물 스테이지, FBX 배치 창 재열기 및 Combat Play와 구도 비교는 실행하지 않았다. Unity Editor 스크립트는 로드됐으나 Player 빌드 컴파일은 미확인이다.

## S6 — 유닛의 타일 표면 높이 확인

- 편집 씬에 **참고용 유닛 한 개**를 필드 칸 중심에 표시한다. Inspector에서 등록된 유닛 외형과 칸 좌표를 고르며, 기본 외형은 `EntityKey.Unit_MainCharacter`다. 프리뷰 유닛은 배경 프리팹 인스턴스 밖, 편집 루트 아래에 둔다. 따라서 프랍 프리팹 저장 대상이 아니다.
- 유닛 발 기준 위치는 필드 칸 중심의 X/Z에 해당 칸 타일 종류의 `SurfaceHeight`를 더한다. `PrefabWithTiles`에서는 현재 작업 중인 회전·배율·기준 타일을 `CombatStageSoTileFit`/`CombatStageSoTileScene`에 전달하고, 등록된 타일 세트의 높이를 읽는다. 다른 배경 방식과 타일 맵 밖 칸의 높이는 운영과 같이 0이다. 높이 계산에 배경 메쉬의 월드 Y를 더하지 않는다. 유닛 크기는 운영 `fieldUnitScale × 유닛 프리팹 원본 배율`을 사용한다.
- Inspector는 칸과 계산된 높이를 보여 준다. 선택·보정 변경 때만 위치를 갱신하며 에디터 프레임마다 SO를 조회하거나 유닛을 다시 만들지 않는다. 타일 맞춤이 성립하지 않거나 외형이 없으면 유닛을 숨기고 이유를 표시한다. 편집용 유닛의 동작·소리·카메라는 끈다.
- **경계·SOLID/SSOT:** Root는 선택값과 프리뷰 참조만 저장하고, Inspector는 입력만, 전용 편집 배치기는 프리뷰 생성·위치 갱신만 맡는다. 타일 대응은 기존 편집 계산을 재사용하고 높이 원본은 타일 세트 SO 한 곳이다. Core·운영 View·저장 경로는 건드리지 않는다. 이 프리뷰는 타일 바탕 높이만 보여 주며 지형의 ReplaceTile/OnTile 높이와 다칸 유닛의 최고 점유 칸은 재현하지 않는다.

## S7 — Combat 공통 자동 배율과 화면 보존 (설계만, 2026-11-10)

- 목표는 배경과 타일을 별도 수동 배율로 관리하는 것이 아니라, 제작 한 칸 2에 대해 `OutlineCellSpacing / 2`의 공통 균일 배율로 표시하는 것이다. 계산은 런타임과 편집의 공용 경계에 두며, Authoring에서만 다른 공식을 사용하지 않는다.
- 타일 방식의 `TileSize`와 수동 배율 입력은 이전 완료 뒤 제거한다. 자동 배율은 읽기 전용이다. 배경 월드 X/Z는 TileOffset으로 역산하며 별도 SO 원본으로 저장하지 않는다. TileOffset X/Z 읽기 전용·Y 편집은 유지한다. 이 X/Z UI 변경은 먼저 코드 반영됐으며 컴파일 미확인이다.
- **필드·배경·각 타일·프랍·유닛 발 위치·높이·카메라의 현재 결과를 보존해야 한다.** 현재 씬 작업 값/override와 운영 SO의 결과를 각각 기록한다. 기존 간격이 필드와 다른 에셋은 단순 자동 배율로 바꾸면 화면이 달라지므로 먼저 전환 가능성을 검토하고 불가능하면 보류한다.
- 프리팹 원본 배율은 새 자동 배율에 재곱하지 않는다. 루트 배율 정규화·공유 프리팹 영향·옛 높이/오프셋 환산은 명시적인 이전 절차로 처리한다. 관련 편집기/FBX 프리뷰의 읽기·쓰기도 함께 전환한다.
- 상세 책임, 동일성 수락 조건, 충돌 처리와 구현 단계는 [공통 설계](2026-11-10-combat-map-common-scale-design.md)와 [공통 계획 CS0~CS4](../plans/2026-11-10-combat-map-common-scale-plan.md)를 따른다. 기존 목표의 “운영 Combat 수정 없음”은 S1~S6 범위이며, S7은 사용자 요청으로 Combat의 배경 배치 소비 코드도 포함한다. Core·FieldCamera·Architecture와 카메라 구도는 변경하지 않는다.
