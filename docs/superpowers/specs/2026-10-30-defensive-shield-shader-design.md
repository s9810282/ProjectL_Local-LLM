# 보호막 Shader Graph 무드 개선 설계

작성: Codex · 2026-10-30 · 사용자 요청: 제안한 따뜻하고 얇은 보호막을 현재 Shader Graph에 구현.

## 표현과 범위

- 기존 `BuffeEffect/DefensiveShield/Shader/Shild.shadergraph`와 `ShildGround.shadergraph`, 각각의 머티리얼을 수정한다. 에셋 경로·GUID와 기존 프로퍼티 참조명은 유지한다.
- 본체는 샴페인 골드의 얇은 테두리, 거의 투명한 중심, 하단 소실, 상단의 국소 하이라이트와 2~3초 주기의 작은 밝기 변화로 구성한다. 불투명한 하단 덩어리와 강한 노란 발광을 줄인다.
- 바닥은 중심을 채우지 않는 얇고 부드러운 접지 링으로 만든다. 약한 불균일성만 주고 빠른 흐름은 줄인다.
- 생성·해제는 수직 Reveal와 전체 Visibility, 피격은 위치·진행도·강도로 조절할 수 있게 한다. 이 값은 시각화 입력이며 전투 상태를 소유하지 않는다.
- 기본값은 보호막 유지 상태다. 피격은 기본으로 꺼져 있다. 자동 대기 호흡만 Shader Time을 쓴다. 발생 시점이 필요한 효과를 전역 Time으로 반복 재생하지 않는다.
- 일반 Shader Graph 노드를 사용한다. HLSL Custom Function, 신규 텍스처, 신규 런타임 서비스는 추가하지 않는다.

## 구조 검토

- SSOT: 표현 수식은 그래프에, 실제 사용 색·강도는 기존 머티리얼에 둔다. 게임 상태·타이머를 복제하지 않는다.
- SOLID: 본체와 바닥은 기존처럼 독립 그래프다. 조절값을 통해 사용하는 쪽에서 연출을 제어하고 그래프가 Core·DB·다른 기능을 조회하지 않는다. 런타임 인터페이스 추가가 없으므로 LSP·ISP·DIP 계약 변경은 없다.
- FW 계약: 서비스 생성·등록·Export·수명 변경이 없으며 공용 Framework와 Render 서비스는 수정하지 않는다.
- 기능 독립성: 이번 변경은 그래프 2개와 머티리얼 2개, 관련 시각 검증으로 제한한다. 씬·파티클 설정·Core·FieldCamera·Architecture와 다른 공격 VFX는 변경하지 않는다.
- 조립과 구현: 생성/피격/해제 이벤트를 언제 보낼지는 후속 연결의 책임이다. 이번 Phase는 그래프의 입력과 표현을 완성한다.

## 확인 기준

Unity 6000.0.73f1 / 프로젝트의 Shader Graph·URP 17.0.4 소스를 기준으로 그래프를 임포트하고 셰이더 오류를 확인한다. 가능하면 기존 JMHTest 씬의 원본 카메라·파티클을 저장하지 않고 렌더해 전후를 비교한다. 유지/숨김/Reveal/피격의 표현을 각각 확인한다. 생성 이미지 시안은 미술 방향이며 실제 렌더의 검증 증거로 취급하지 않는다.

참고: [Unity Fresnel Effect 노드](https://docs.unity.cn/Packages/com.unity.shadergraph%4017.2/manual/Fresnel-Effect-Node.html). 직렬화·슬롯·렌더 상태는 설치된 17.0.4 패키지 소스를 우선한다.
