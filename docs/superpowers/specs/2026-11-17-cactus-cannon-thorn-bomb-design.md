## 1. 목적과 범위

선인장 캐논의 기존 기본 공격에 **중심 대상 자동 폭탄 부착**을 추가한다. 다음 공격, 연쇄 폭발, 다음 자기 진영 턴 시작으로 폭발하며, 폭발과 넉백으로 다음 폭발의 위치가 바뀌는 전술을 제공한다.

`ThornBomb`를 새 특성으로 등록하고 선인장 캐논의 특성 연결을 교체한다. 사용자는 기존 `ThornField` 가시 장판의 삭제도 요청했다. 기존 기능을 비활성 상태로 방치하거나 폭탄과 병행 운영하지 않는다.

**별도 버튼, 능력 선택 UI, 추가 클릭, 새 입력 명령, 추가 행동 비용은 없다.** 기존 공격 중심 칸의 유닛이 자동 부착 대상이다. 상태 아이콘·부착물·폭발 연출은 결과 표시이며 추가 조작 UI가 아니다.

범위 밖: 새로운 특성 강화 단계와 밸런스 수치, 범용 반응 이벤트 프레임워크, 전체 특성 엔진 재작성, FieldCamera·Architecture 개편, 다른 유닛의 공격 규칙 변경. 옛 Missing Script 에셋 48개는 삭제하지 않는다.

## 3. 확정 게임 규칙

| ID | 사용자 확정 내용 |
|---|---|
| R01 | 기존 기본 공격 피해를 준다. 폭탄은 기존 공격의 중심 칸에 있는 유닛에게 자동 부착한다. 추가 조작은 없다. |
| R02 | 아군·적군 모두 부착 가능하며 대상당 폭탄은 하나다. 아군도 기본 공격 피해를 받는다. |
| R03 | 빈 칸도 공격 가능하다. 부착 유닛이 없으면 폭탄/장판/예약물을 남기지 않는다. |
| R04 | 유닛 공격이 실제 명중하면 체력 피해가 0이어도 기존 폭탄을 기폭한다. 빗나감·도달 실패는 명중이 아니다. |
| R05 | 다른 가시 폭탄에 맞으면 체력 피해가 0이어도 연쇄 기폭한다. |
| R06 | 아군 턴에 부착한 폭탄은 적군 턴을 거쳐 **다음 아군 턴 시작, 행동 전에** 자동 폭발한다. |
| R07 | 부착 당시 선인장 캐논 공격력을 저장한다. 폭발의 기준 피해는 그 값의 50%이며 방어력·상성을 무시한다. |
| R08 | 폭심지와 인접 8칸에 피아 구분 없이 폭발 피해를 준다. 폭심지 대상은 넉백하지 않고, 주변 유닛만 바깥으로 1칸 넉백한다. |
| R09 | A 폭발에 맞은 B의 폭탄은 A의 넉백 처리 뒤, B의 실제 위치에서 폭발한다. 이동이 막히거나 면역이면 남은 위치에서 폭발한다. |
| R10 | 기폭을 유발한 피해로 대상이 죽으면 넉백하지 않고 사망한 칸에서 폭발한다. 자기 폭탄 폭심지는 애초에 넉백 대상이 아니다. |
| R11 | 아군·적군 모두 기본 공격 피해 → 기존 폭탄 및 연쇄 처리 → 공격 중심으로 지정했던 유닛이 살아 있으면 새 폭탄 부착 순서다. |
| R12 | 연쇄 중 **승패가 결정되면 남은 폭발을 중단**한다. R11의 전체 처리는 이 종료 정책 안에서 적용한다. 종료 뒤 새 폭탄도 부착하지 않는다. |
| R13 | 새 특성으로 연결하고 기존 가시 장판 특성은 삭제한다. |
| R14 | **한 폭발의 대상 피해를 모두 적용한 뒤 승패를 판정**한다. 대상별 피해 도중 목표 달성/메인 사망이 관찰돼도 같은 폭발의 나머지 피해는 적용한다. 판정 뒤 종료라면 후속 넉백·연쇄·재부착을 중단한다. |
| R15 | **낙사로 죽으면 폭탄은 터지지 않고 사라진다**(2026-11-17 사용자). 앞서 명중으로 기폭이 예약됐어도 같다. Core는 소멸 사건(`CombatThornBombDiscardedEvent`)을 남긴다. 낙사 판정은 사망 특성의 낙사 제외와 같이 같은 투영의 낙사 사건으로 한다. P09의 낙사 부분을 대신한다. |
| R16 | **기차 즉사로 죽으면 사망 칸(치이기 전 레일 칸)에서 터진다**(2026-11-17 사용자, Phase 4 D1 권장안). 낙사 외의 피해·즉사 사망은 P09대로 사망 칸에서 터진다. 같은 결정으로 기차 즉사도 사망 특성(자폭·공포)을 발동한다(사망 특성 설계 §17). |

R01의 기존 기본 공격 유지에는 현재 Radial 70% 스플래시가 포함된다. 스플래시 명중은 기존 폭탄을 기폭할 수 있지만 새 폭탄을 부착하지 않는다. 주변 폭발 피해에 기본 공격의 70%를 다시 곱하지 않는다.

## 4. 설계자가 제안한 세부값 — 사용자 확정과 구분

아래는 명시되지 않은 경계를 일관되게 완성하기 위한 **검토본의 제안**이다. 문서 승인 전 사용자 확정으로 간주하지 않는다. 구현자가 다른 선택을 해야 하면 먼저 질문한다.

| ID | 제안과 이유 |
|---|---|
| P01 | 비율 계산은 기존 스플래시처럼 정수 절삭한다. 공격력 15 → 기준 피해 7. 공격력 0 → 피해 0이어도 명중 기폭은 성립한다. 최소 1 보정은 새로 넣지 않는다. |
| P02 | 방어·상성만 우회한다. 보호막/보유 방어, 피격 피해 감소, 지형 피해 경감, 아이템의 기존 피해 수신 계약은 유지한다. 방어 무시를 모든 방어 효과 무시로 확대하지 않는다. |
| P03 | 폭발은 기본/추가/반응 공격이 아닌 별도 `TraitExplosion` 피해 원인이다. 공격 명중 시 특성, 공격 횟수, AP를 다시 소비하지 않는다. 가시 폭탄의 연쇄 명중 통지만 별도로 전달한다. |
| P04 | 부착자는 사망·퇴장해도 이미 붙인 폭탄은 유지한다. 출처 ID/효과 키와 수치 스냅샷으로 정산한다. 재부착 직전 공격자가 사망했어도 R11에 따라 대상이 생존하고 전투가 지속되면 부착하며, 투영에 남은 마지막 유효 공격력 사실을 사용한다. |

| P08 | 자동 폭발은 턴 시작의 재구성 → 주기 상태 처리 뒤, 전이 완료/행동 허용 전에 수행한다. 적이 해당 특성을 얻는 경우에도 부착 진영의 다음 자기 턴 시작을 사용한다. |

| P11 | 대상의 폭탄 교체 시 오래된 폭탄의 출처/피해로 먼저 폭발하고 새 부착자의 값으로 새 폭탄을 만든다. 새로운 강화 단계는 만들지 않는다. |

승패 조건 자체는 기존 `BattleOutcomeCalculator`를 유지한다. 현재는 지정 보스 처치/적 본부 파괴 목표와 메인 사망을 검사하며, 메인 사망 패배가 목표 달성보다 우선한다. 대화의 “마지막 적”을 일반적인 전멸 승리 규칙 신설로 해석하지 않는다.

## 5. 선택한 접근과 상태 소유권

### 5.1 비교한 접근

| 접근 | 장점 | 비용/결론 |
|---|---|---|
| 기존 `ThornField`의 이름·상태를 폭탄으로 변경 | 일부 초기 연결 재사용 | 칸 장판과 유닛 부착의 수명/의미가 달라 옛 키·직렬화 의미를 오염시킴. 미선택 |
| 새 `ThornBomb` 등록 + 기존 기능 퇴역 + 필요한 공통 계산만 추출 | 부착·연쇄 규칙을 한 기능 안에서 변경하고 기존 공통 피해/이동 계약 유지 | 상태/표시의 명시적 이전 필요. **사용자 선택** |

범용 트리거 버스나 모든 특성의 통합 리팩터링은 현재 필요가 없다. 새 인터페이스는 실제 기존 능력 평가 경계에 필요한 것만 추가한다.

### 5.2 상태 모델

- 새 `TraitKey.ThornBomb` 번호는 현재 미사용인 **540** 제안. 구현 직전 중복 검사한다. 기존 `ThornField = 40`은 실행/저작 불가한 퇴역 번호만 보존하며 재사용하지 않는다.
- `ThornBombTraitSpec`/Data/Definition은 `DamagePercent = 50`을 전달한다. 인접 8칸, 넉백 1, 다음 자기 턴 규칙은 도메인 규칙 한 곳에 둔다. 각 소비자에 상수를 복사하지 않는다.
- `ThornBombStateSet`은 `NextBombId`와 불변 폭탄 목록을 가진다. 각 `ThornBombSnapshot`은 `BombId`, `SourceId`, `SourceOwner`, `TargetId`, `AttachmentLocalCell`, `CapturedAttackPower`, `DamagePercent`, `DueControllerTurnSequence`를 가진다.
- `CombatCommandState.ThornBombs`가 게시되는 전투 사실이다. Buffer는 수락된 최종 전이만 설치한다. 유닛 특성 RuntimeState/상태 아이콘/이벤트에 별도 원본 폭탄 목록을 만들지 않는다.
- `ThornBombResolution`은 한 계산에만 존재하는 가변 투영이다. 대상 ID → 폭탄 사전, 예약된 BombId 집합, FIFO 큐를 갖는다. 공격/도착 투영은 같은 인스턴스를 공유한다. 최종 불변 상태를 한 번 만든다.
- 큐 항목은 폭탄과 기폭 원인을 보존하되 **살아 있는 대상의 폭발 위치를 미리 고정하지 않는다**. 꺼낼 때 대상의 최신 부착 칸을 읽는다. 사망 시에는 해당 사망의 실제 부착 칸을 health/event 증거에서 한 번 캡처한다. 기존 `AttackKnockbackCalculator.DisplaceCorpse`가 갱신하는 `DeathAnchors`는 시체 효과용 가상 도착점일 수 있으므로 이를 폭탄의 실제 사망 칸으로 재사용하지 않는다. 이 캡처는 계산 중 기폭 증거이며 별도 영속 위치 원본이 아니다.
- `DueControllerTurnSequence = 부착 시 ControllerTurnSequence + 2`. 만료·계산·예약 인자는 기존 턴과 같은 `long`을 사용한다(Phase 2 사용자 승인). 다음 진영 턴은 +1, 다음 자기 진영은 +2. 턴 시작에는 `SourceOwner`와 만료 순번을 함께 확인한다. 같은 턴의 여러 행동으로 감소하지 않는다.
- `With`, 비교/복사, 준비/초기화, 저장된 명령 입력, 미리보기, 되돌리기 증거, 전투 종료 초기화에서 폭탄 사실을 보존한다. 임시 큐는 저장하지 않는다.

### 5.3 기능과 조립

| 책임 | 소유자 | 계약 |
|---|---|---|
| SO → Spec/Definition 및 능력 등록 | 기존 TraitSpecAdapter/TraitRegistry + 전용 ThornBomb 팩토리 | 설정 검증과 조립만 수행 |
| 비율·범위·중심 제외·만료 판정 | `ThornBombRules`, 공용 `ImpactCenterGeometry` | 순수 입력/출력, 상태 변경 없음 |
| 부착/예약/연쇄/최종 상태 | `ThornBombResolution` | 단일 명령 수명. 중복 예약/중복 폭발 방지 |
| 폭발 1회의 피해/넉백 | `ThornBombExplosion` | 동일 projection의 피해·이동 서비스를 호출. 새 명령/가짜 공격자 생성 금지 |
| 일반/추가/반응/스킬 공격과 연결 | 기존 `AttackDeliveryExecutor`와 명중 경계 | 공격 중심 ID를 보존하고 접촉 사실 전달, drain 후 부착 |
| 턴/사망 연결 | 기존 턴 시작·사망 정산 경계 | 만료/사망 사실만 전달. 폭탄 산식/큐 내부를 모름 |
| 결과 공개 | 기존 transition/evidence/Buffer | 폭탄 변경과 체력/이동 결과를 원자적으로 공개 |
| 부착 표시/폭발 재생 | 전용 View 소비자 + 기존 playback 조립 | Buffer/결과 읽기만 수행. 입력이나 Core 규칙 없음 |

기존 `TraitRegistration`은 `EffectRuleFactory`를 필수로 받는다. `ThornBombEffectRule`은 좁은 `IEffectThornBombRule` 능력으로 부착 설정을 제공하고 기존 무상태 effect snapshot을 재사용한다. `ThornBombAttackApplication`만 이 능력을 읽어 중심 후보와 부착 절차를 만든다. 공용 공격 실행기는 해당 연결 함수를 호출하며 특성 키/설정 해석을 직접 하지 않는다. 이 한 기능을 위해 전체 registry/codec 구조를 재작성하지 않는다.

## 6. 실행 계약

### 6.1 기존 공격과 자동 부착

1. 기존 공격 선택/벽/사거리/병과 자격으로 전달을 확정한다. 도달 가능한 실제 공격 중심 칸의 캐릭터 ID와 로컬 칸을 보존한다. 구조물/빈 칸은 후보 없음이다.
2. 기존 직접 피해와 스플래시를 실행한다. 성공한 실제 접촉에서만 기존 폭탄을 예약한다. 피해 0도 포함하며 단순 원장 존재나 예측 범위로 명중을 판정하지 않는다.
3. 원래 공격의 넉백·필수 도착 효과를 끝낸다. 폭탄 큐가 있으면 같은 투영에서 연쇄를 처리한다. 다른 유닛의 공격도 여기서 기존 폭탄을 기폭할 수 있다.
4. 승패 미확정이고 원래 중심 대상이 살아 있는 필드 유닛이면 새 부착을 준비한다. 희생 대행 등으로 중심 대상의 **옛 폭탄이 아직 남아 있다면**, 교체 사유로 그 폭탄을 예약하고 연쇄를 먼저 drain한다. 이후 승패·생존을 다시 검사하고 새 폭탄을 부착한다. 옛 폭탄을 조용히 덮어쓰지 않는다. 빈 칸에 나중에 들어온 다른 유닛을 다시 찾지 않는다. 대상이 이동했다면 같은 ID의 이동 후 위치를 따른다.
5. 기존 공격 완료/추가 공격의 고유 수명을 유지한다. 폭발 자체로 `AttackDeliveryExecutor`를 재귀 호출하지 않는다. 추가 공격이 별도로 실제 발생하면 그 공격의 명중 경계를 그대로 통과한다.

새 부착 시 공격력은 `CombatEffectiveStatsCalculator.AttackPower`로 부착 시점의 유효 사실에서 한 번 읽는다. 기본 공격 시작 때의 공격력을 잘못 저장하거나 폭발 시 재조회하지 않는다.

### 6.2 한 폭발과 연쇄

1. 승패가 확정됐으면 잔여 큐를 중단하고 새 부착을 금지한다.
2. 폭탄을 활성 상태에서 제거하고 처리 중으로 확정한다. 자기 폭발로 자신을 재예약할 수 없다.
3. 현재 부착/사망 칸을 중심으로 3×3의 맵 내부 칸과 대상 ID를 한 번 수집한다. 대상별 중복 피해는 없다.
4. 각 유효 대상에게 `floor(CapturedAttackPower × DamagePercent / 100)`를 입력으로 넣는다. 방어·상성 산식은 건너뛰고 기존 보호/피격 경감/HP 적용 경계를 사용한다. 피해 0인 접촉도 다른 폭탄을 예약한다. 대상 순서는 EntityId 오름차순 제안이며, **이번 폭발의 대상 피해를 모두 적용할 때까지 승패에 따른 조기 중단을 하지 않는다**. HP 변경과 증거 기록은 정상 처리하고, 지연하는 것은 승패에 따른 중단 결정뿐이다.
5. 이번 폭발의 전체 피해 적용이 끝나면 기존 `BattleOutcomeCalculator`로 승패를 판정한다. 종료라면 후속 넉백·잔여 폭발·재부착을 중단한다. 메인과 목표 보스가 같은 폭발로 함께 죽으면 두 피해를 모두 적용한 상태에서 기존 메인 사망 우선 정책에 따라 패배한다.
6. 전투가 계속되면 살아 있는 주변 대상만 중심 바깥으로 1칸 이동한다. 사망 대상과 중심 점유자는 넉백하지 않는다. 기존 면역·막힘·낙사·도착 효과를 처리하고 이동 중 종료는 기존 경계에서 확인한다. 폭발 피해 묶음의 중단 지연을 다른 공격·이동·턴 전체로 확대하지 않는다.
7. 이 폭발의 이동/도착이 끝난 뒤 FIFO의 다음 폭탄으로 진행한다. B가 이미 다른 효과로 더 이동했다면 꺼내는 시점의 실제 위치를 사용한다.

재귀 호출 대신 큐를 사용하고 폭탄마다 한 번만 처리한다. 한 계산 중 연쇄 폭발은 새 폭탄을 생성하지 않는다. 대기 중 같은 대상에 다시 명중해도 같은 BombId를 중복 처리하지 않는다.

### 6.3 공통 기능 재사용의 정확한 범위

- `ImpactBoltTraitRule.TryResolveStep`의 중심 제외/방향 계산을 `Domain/Movement/ImpactCenterGeometry`로 추출한다. 발리스타와 폭탄이 이 함수를 호출한다. 폭탄이 발리스타 특성을 장착하거나 발리스타의 전용 Rule을 직접 소유하지 않는다.
- `AttackForcedMovement`의 충돌·한 칸 이동·지형/도착 실행을 기존 `MovementProjection`을 받는 좁은 공통 실행 경계로 옮긴다. 공격 전용 ledger/시체 처리/공격 순서는 기존 호출자가 유지한다. 폭탄 호출을 위해 가짜 `CommandAttackPlan`을 만들지 않는다.
- `CombatDamageApplication`의 공유 인스턴스를 사용한다. 폭발 1회에 고유 AttackGroup을 배정하고 모든 대상에게 같은 그룹을 사용한다. 다음 폭발에는 새 그룹을 배정한다. 피해 출처는 저장된 부착자, 물리 출처는 폭심지다.
- 새 `CombatDamageKind.TraitExplosion = 8` 제안은 `IsAttack`에 포함하지 않는다. enum 검증·피해 수신 자격·아이템·통계 증거의 누락을 점검하고 실제 해당 계약만 수정한다. 공격 횟수/명중 특성 연쇄를 새로 열지 않는다.
- 상태/기능 분기를 여러 caller에 복제하지 않는다. existing protocol adapter의 명시적 매핑 한 항목, 입력 검증, 생존/만료 조건은 정당한 분기다. 모든 `if`를 없애기 위한 Dictionary/delegate/인터페이스 증식도 금지한다.

### 6.4 미리보기·AI·되돌리기·게시

- 실제 실행과 미리보기는 같은 폭탄 규칙/연쇄 해석기를 사용하되 원본과 분리된 상태를 쓴다. 미리보기를 취소해도 BombId/만료/원본 상태가 변하지 않는다.
- 기존 공격 미리보기 결과만으로 부족한 연쇄별 중심·피해·넉백·부착 결과는 순서 있는 `ThornBombExplosionPreview` 읽기 계약과 `AttackPreview.ProjectedThornBombs`의 완료된 예상 부착 상태로 추가한다. 같은 유닛이 여러 번 맞고 밀릴 수 있으므로 대상 ID 하나로 결과를 덮어쓰지 않는다.
- AI는 이 계산 결과를 기존 평가 경계에서 소비한다. AI 안에 폭탄 피해/연쇄 전용 근사 산식을 복제하지 않는다.
- 이동 자체는 부착 ID/만료/공격력을 바꾸지 않는다. 이동 중 사망으로 폭발이 발생하면 비가역 효과로 기록해 기존 undo 차단 계약을 따른다. 조용히 폭탄 상태만 되돌리는 경로를 만들지 않는다.
- `CombatThornBombAttachedEvent`, `CombatThornBombDetonatedEvent`를 전용 파일에 둔다. 부착/소모 사실과 BombId/대상/출처/중심/기폭 이유/AttackGroup을 제공한다. HP·넉백은 기존 health/movement 증거가 원본이며 폭탄 이벤트에 독립 HP 원본을 복제하지 않는다.
- 최종 상태와 이벤트 증거는 같은 전이에서 검증 후 게시한다. 잘못된 대상 중복, 음수 공격력, 잘못된 마감/출처/로컬 칸은 예외로 거부하며 정상적인 빈 칸/막힘/이미 예약됨과 구분한다.

### 6.5 View

- 기존 일반 공격 입력·투사체는 유지한다. 부착은 명중/연쇄 재생 후 중심 대상의 표시 앵커에 연결하고, 이동을 따라간다.
- 전용 `CombatThornBombEventHandler`와 부착 표시 presenter가 신규 이벤트를 소비한다. 최종 Refresh를 먼저 적용해 폭탄이 너무 일찍 사라지거나 새 폭탄이 먼저 보이지 않게 한다.
- 재생 순서는 A 폭발 → A 피해/넉백 → B의 이동 후 위치에서 폭발 → 재부착이다. 사망 대상의 오브젝트가 반환돼도 이벤트 중심 좌표로 폭발을 재생한다.
- 결과 읽기 모델에 근거한 상태 표시만 추가한다. 별도 독립 화면·팝업·패널은 만들지 않는다. 기존 유닛 표시의 세부 위젯으로 조립한다.
- 풀/렌더 scope는 Cancel·전투 종료·씬 해제에 한 번 반환한다. View에 턴 시계/피해 계산/기폭 결정/상태 원본을 두지 않는다.

## 7. 기존 가시 장판 삭제 계약

삭제 대상은 `ThornField`의 실행 기능과 전용 authoring/data/spec/definition/state/effect/field snapshot·표시·DB 연결이다. 공용 파일 속 전용 부분은 해당 부분만 삭제한다.

1. 선인장 SO를 새 authoring으로 이전한 후 가시 생성/수명/접촉 피해/방어 감소 부여/소모 이벤트를 제거한다.
2. `CombatCommandState.ThornFields`, `StageSnapshot.ThornFields`, `OwnedCharacterStatsSnapshot.ThornFieldDescription`, 이동 context/undo 원본 및 복사·검증을 정리한다. 빈 배열을 받는 무의미한 호환 API를 영구 유지하지 않는다.
3. `ThornMovementTileRule`, `FieldThornPresenter`, `ThornFieldVisual` SO/Query/Factory/키, 설명 바인딩과 전용 TraitVisual을 제거한다. Catalog·ViewGroup·씬·프리팹의 GUID 역참조를 먼저 제거한다.
4. `TraitKey.ThornField = 40`은 기존 퇴역 정책에 맞춰 번호 보존만 한다. 가용성은 `Retired`, 실행 등록/저작 생성/데이터 재해석은 금지한다. 새 폭탄 번호로 재사용하지 않는다.
5. `ThornHeart` 반사, 일반 출혈/방어 감소, 타 특성·기믹 및 공유 피해/이동 코드는 이름이 비슷해도 삭제하지 않는다. 기존 장판이 부여했던 상태 타입이 다른 기능에 쓰이면 공유 타입은 유지한다.
6. 옛 문서는 이력으로 남긴다. 수정 범위의 현재 안내만 새 설계로 연결한다. Missing Script 48개는 이번 삭제와 분리한다.
7. 기존 시험의 단순 생성자/API 컴파일 보정과 행동 검증 변경을 분리한다. 타인 시험의 장판 기대값을 없애거나 시험을 삭제하기 전 사용자에게 구체 목록으로 확인받는다. 이 문서는 그 변경의 선승인이 아니다.

| 장판을 폭탄으로 교체 | 칸 상태가 attack/movement/undo/DB/View에 퍼져 있음. 초기 삭제는 실제 상태 계약 변경 | 옛 칸 상태를 제거하고 부착 상태를 명령 상태 한 곳에 소유 | 초기 회귀는 넓음. 이후 폭탄 수치 변경은 authoring/spec/순수 규칙/설명에 한정; 다른 특성 내부를 읽을 필요 없음 |
| 밀린 뒤 연쇄 폭발 | 강제 이동은 공격 plan/ledger와 연결되어 있어 복사하면 지형 처리 불일치 위험 | 방향 순수 함수와 실제 이동 실행만 공유하고 공격 결과 정산은 유지 | 폭탄은 이동 요청/결과 계약을 이해. 발리스타 전달·투사체 내부를 몰라도 됨. 공통 경계 변경 시 발리스타 회귀는 여전히 필요 |
| 부착 표시/연출 변경 | 화면 공용 이벤트 handler에 타입별 분기를 늘리면 무관 기능 이해 비용 발생 | 전용 소비자 + 기존 event type 등록/Factory 주입 | 해당 presenter/handler/표현 설정 수정. Core 턴·다른 VFX 내부는 불필요. 취소/공유 playback 회귀는 유지 |

**SSOT:** 게시된 전투 상태 한 곳, 계산 중 투영 한 곳, View 읽기 모델/이벤트는 파생 사실. 상태 복사본을 별도 원본으로 쓰지 않는다.

**SOLID:** SRP는 순수 규칙·해석·공통 HP/이동·표시·조립 분리로 점검한다. OCP는 기존 능력/이벤트 등록 지점을 사용하며 전역 특성 분기를 확장하지 않는다. LSP는 기존 공격/넉백/취소 계약을 지켜 발리스타를 회귀 확인한다. ISP는 폭탄이 필요한 입력과 피해/이동 경계만 전달하고 새 거대 world 인터페이스를 만들지 않는다. DIP는 View가 Core 구현이나 InGame SO 대신 공개 사실을 소비하고, 조립부가 구현을 연결하도록 한다.

**FW/JMH:** FW-001~003의 등록·수명·단일 Build를 유지한다. 새 내부 해석기를 Framework 서비스로 등록하지 않는다. FW-004의 변경 경계를 지키며 Buffer를 View가 쓰지 않는다. FW-005~009 입력/UI 경로는 기존 공격을 유지한다. FW-011/014의 scope·pool 반환을 재사용하고 FW-012 DB 요구를 함께 이전한다. FW-013 이벤트 계약과 FW-015 순서/정렬은 기존 공개 메커니즘을 지킨다. FW-016의 초기화→계산→게시→재생 수명을 우회하지 않는다. 생성/등록은 기존 TraitRegistry 및 View Factory, 상위 노출은 기존 Group/Context, 소비자는 기존 주입 경로이며 루트 서비스 재등록은 없다.

**성능:** 명령당 사전/큐 한 세트, bomb당 1회 예약, 폭발당 칸 9개·대상 ID 중복 제거. 보드 점유 조회를 사용하고 매 피해마다 전장 전체를 반복 정렬하지 않는다. 순서 결정은 배치 수집 시 한 번, 비율 계산은 폭탄 단위로 한 번. 보드 조회 최적화의 이익은 아직 측정하지 않았으며 전장/AI 캐시 전면 개편을 포함하지 않는다.

위 효과는 코드 연결 조사에 근거한 설계 예상이다. 성능 향상·런타임 안정성은 아직 검증되지 않았다.

## 9. 승인·검증·인계

- 문서 작성은 구현 완료가 아니다. 설계/계획 검토 후 Phase 단위로 진행하고 각 Phase에서 멈춰 보고한다.
- Core 요청은 Core 작업자에게 인계한다. 다른 영역을 수정할 포괄 권한으로 해석하지 않는다. Core 구현을 이 세션에서 수행하려면 해당 Phase에 대한 명시적 지시가 필요하다.
- View Test 코드를 작성하지 않는다. 전투 View MSBuild를 실행하지 않는다. 이 문서 작업에서 컴파일·Unity·테스트를 실행하지 않았다.
- 사용자 Unity 확인: 기본/아군/빈 칸/0피해/넉백 후 연쇄/사망/자동 만료/동시 폭탄/종료 중단/미리보기 일치/취소·해제·재진입. 세부 인수표는 구현 계획의 V01~V18을 따른다.
- DB 이전 시 `DataBaseAssetTests`는 사용자 실행 항목이다. 실제 테스트 변경·폐기는 §7.7의 소유권 규칙을 따른다.
- 설계가 기존 호출 계약과 충돌하면 이를 우회 구현하지 않고 변경 이유·범위를 보고하고 먼저 묻는다.

## 10. Phase 2 연결 계약 보완 (2026-11-17)

사용자가 승인한 두 이동 의존성 보완: 공용 강제 이동 실행기는 IMovementTileRule 목록을 인자로 받고, MovementProjection은 생성 시 전달받은 같은 목록을 공통 완료 정산까지 보관한다. 개별 기믹은 이 목록을 연결하며 폭탄의 사망/연쇄 규칙을 구현하지 않는다. 작업 결과·검증 수준은 구현 계획 §4의 실행 기록을 원본으로 한다.

## 11. Phase 4 실제 변경 범위 (2026-11-17)

**Phase 4에서 줄인 결합**

- 처치 연쇄 초기 근거 식은 `KillChainAttackCalculator` 한 곳에 둔다. 폭탄은 폭발 중 사망만 알리고(`ThornBombResolution.KilledIds`), 처치 연쇄가 자기 식에서 그 사망을 뺀다.
- 미리보기 결과 재조립은 구조체 복사 생성자다. `AttackPreview`에 필드를 더할 때 이 함수를 따로 고칠 필요가 없고, 빠뜨리면 컴파일러가 잡는다.
- 장판 제거로 빈 인자가 된 피해 적용·강제 이동 입구의 인자를 걷었다.

**남은 결합과 위험**

- **기차 경로(해결, 2026-11-17):** 기차 즉사도 낙석처럼 `MovementProjection` 완료 정산으로 끝낸다. 그래서 폭탄(R16)과 사망 특성이 같은 사망 경계를 탄다. 낙사는 소멸 사건으로 사라진다(R15).
- **부착물 프리팹 칸:** 여전히 모든 TraitVisual SO에 있는 칸이다. 다만 "부착물을 붙이는 특성"의 원본(`TraitVisualData.RequiresAttachment`)과 부트 DB 검사로, 줄·프리팹이 빠지면 DB 생성에서 멈춘다(D2 해결).
- **폭발 연출:** 이펙트는 가시 폭탄 TraitVisual 줄의 발동 줄(`TraitActivationKind.ThornBombDetonated`, View 조회용 열쇠)이 정한다(D3 해결). 연출 수정은 그 줄만 고친다. 소리는 특성 발동 줄에 칸이 없어 없고, 소리 창구가 열리면 연결한다.
- **폭발 미리보기:** Core가 폭발 칸(`BlastCells`)과 밀기 직전 점유 칸을 주고, View는 그대로 그린다(D4 해결).

성능은 정적 판단이다. 측정하지 않았다. 폭발이 없는 공격에서 폭탄 기능이 추가로 할당하던 것(생존자 목록·사망 관찰 정렬·미리보기 배열 복사)을 없앴다. 폭발 1회의 대상 수집은 전장 캐릭터를 한 번 훑는다. §8의 "보드 점유 조회"는 쓰지 않았다(전장 규모가 작아 남김).
