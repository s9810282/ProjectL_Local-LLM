## 1. 착수 전 구조와 작업 범위

Q는 `CombatInputRouter`에서 기존 조준 표시를 정리한 뒤 `CombatPathInput.BeginPlanning()`으로 들어간다. 이동할 행위자·시작 칸을 고정하고, 시작 칸 또는 상하좌우 이웃에서 경로를 편집한다. 좌클릭 누름으로 정확한 경로를 확정하며, 놓기로 제출하지 않는다. 기존 되돌리기·경계 히스테리시스·거절 접두 경로·재진입 규칙을 유지한다.

범위 요청 `CombatViewPreviewData.MoveRange`와 Core 처리/응답 `CombatPreviewResult.MoveRange`는 이미 존재한다. View 이동 입력이 아직 요청·표시하지 않는다. `CombatViewBuffer`는 최신 미리보기 요청 하나만 보관하므로 범위·경로·복귀를 동시에 요청할 수 없다.

필드의 `Range`와 `MovementDraft` 층도 존재한다. `FieldHighlightLayers.DrawOrder`는 범위보다 경로를 위에 둔다. CellPrefab/GridOutline은 같은 강조 상태를 읽으므로 새 표시 모드·별도 강조 저장소는 필요 없다.

`PlacementGhost`는 View DB의 유닛 프리팹을 풀에서 빌리고, 재질·색·충돌·그림자를 고스트용으로 설정한다. 하지만 `CombatSceneDisplay.ShowGhost/HideGhost`는 배치 상태도 바꾸며, `HideOriginal`은 필드·손패의 원본을 숨긴다. 이동에는 이 배치 의도를 호출하지 않는다. `FieldUnitView`에는 반투명 기능이 없다.

이번 작업은 플레이어 Live 이동 입력의 표현 확장이다. Core 계산·Buffer 스키마·Flow/Job/Plan·FieldCamera·Architecture·공용 Render 구현과 셰이더는 변경하지 않는다. RecordInputOnly에 검증 없는 이동 입력/범위를 추가하지 않는다. 별도 이동 고스트 프리팹 테이블도 만들지 않는다.

## 2. 동작 결정

### D1. 표시 시작과 종료

| 시점 | 범위 | 원본 모델 | 고스트 |
|---|---|---|---|
| Q 수락, 시작 칸 대기 | 범위 요청, 응답 전에는 없음 | 기존 표시 | 없음 |
| 경로 편집 시작 | 받은 범위 유지 | 약간 투명 | 현재 커서에 표시 |
| 경로 견적 응답 대기 | 받은 범위 유지 | 반투명 유지 | 중립색 |
| 현재 경로 승인/거절 | 받은 범위 유지 | 반투명 유지 | 현재 견적에 대응하는 유효/무효색 |
| UI 위·필드 밖·좌표 매핑 실패 | 받은 범위 유지 | 반투명 유지 | 숨김 |
| 좌클릭 확정 후 견적 대기 | 받은 범위 유지 | 반투명 유지 | 동결한 확정 위치, 대기색 |
| Move 명령 제출 성공 | 제거 | 원래 표시 복원 | 반환 |
| 취소·공격 전환·복귀·입력 불가·행위자 변경·포커스 상실·Detach | 제거 | 원래 표시 복원 | 반환 |

확정 후 대기 중에는 경로와 고스트 확정 위치를 함께 동결한다. 새 입력으로 경로가 바뀌지 않는 기존 `_frozen` 계약을 유지한다. 제출은 취소와 다르며 이미 제출한 명령을 취소하거나 결과 확인을 대신하지 않는다. 실제 이동 연출은 기존 사건 재생이 맡는다.

### D2. 이동 범위는 Core 응답으로 표시한다

- Q 수락 시 현재 활성 행위자의 `MoveRange`를 한 번 요청한다.
- 성공 응답의 `Destinations[].TargetAnchor`를 `Range` 층에 표시한다. 출발 칸은 기존 활성 행위자/경로 표시가 담당한다.
- 실패 또는 목적지 0개면 범위를 비운다. 실패를 성공으로 꾸미거나 View에서 대체 범위를 계산하지 않는다. 범위 실패만으로 새 런타임 Fault 정책을 만들지 않는다.
- 이동 거리·AP·점유·지형을 View에서 재계산하지 않는다. 범위는 목적지 후보 안내이며 특정 우회 경로의 승인이나 기믹 처리 후 최종 도착을 보증하지 않는다.
- 확정은 기존 정확한 경로의 Core `MovePreview`와 일치하는 `MovementPreviewContext`만 사용한다. 범위 응답으로 Move context를 만들어 제출하지 않는다.
- 범위 사본은 해당 Q 지정 수명 안에서만 유효한 표시용 파생 캐시다. 제출·취소·전투/행위자/시작 위치 또는 결과 상태 변경 때 버리고 다음 Q에서 새로 요청한다. 매 프레임 재요청하지 않는다.

### D3. 단일 미리보기 슬롯의 요청 순서

`CombatPathInput`이 범위 요청 순서를 조정하고 내부의 `CombatMovementRangeRequest` 하나가 범위 요청 번호·지정 수명·요청 당시 사실 대조와 응답 1회 소비를 소유한다. 같은 상태를 PathInput에 중복 저장하지 않는다. `CombatMovementInteraction`은 기존 경로 초안·견적·동결·제출의 소유자로 유지한다.

1. Q는 기존 경로/복귀 표시와 소유 요청을 정리하고 새 지정 수명을 시작한다.
2. 범위 요청을 게시하고, 범위 응답을 받을 때까지 **경로 견적 게시만 유예**한다.
3. 유예 중에도 시작 칸 판정·포인터 샘플링·경로 편집·되돌리기를 기존 Draft에서 계속 처리한다. 별도 초안이나 포인터 이력 큐를 만들지 않는다. Phase 2 고스트도 실제 커서를 따라간다.
4. 이때 클릭 확정하면 정확한 초안을 동결하지만 제출하지 않는다. 이전 context를 재사용하지 않는다.
5. 일치하는 범위 응답을 표시한 뒤 유예를 해제한다. 최신 초안만 한 번 견적 요청하며, 경로가 0걸음이면 요청하지 않는다. 동결 초안이면 그 초안의 응답을 기다려 기존 제출 경로를 사용한다.
6. 이후 경로 변경은 기존 최신 요청 방식으로 견적을 갱신한다. 범위는 표시 캐시로 남으며 다시 슬롯을 차지하지 않는다.

범위 유예는 입력 허용 정책이 아니다. `allowed=false`로 넘겨 Draft가 취소되는 방식은 사용하지 않는다. Interaction의 견적 게시 경로에 좁은 유예/재개 계약을 추가하며 실제 허용 판단은 기존 `CombatInputPolicy.CanEditPath` 한 곳에 둔다.

응답 수락에는 범위 요청 번호, 현재 입력 슬롯의 Kind/EntityId/번호, 응답 UnitId, 전투 ID, Q 지정 수명, 활성 행위자·시작 위치와 요청 당시 결과 상태를 대조한다. 이미 소비한 동일 응답은 다시 처리하지 않는다. 취소 후 늦은 응답·이전 Q 응답·다른 행위자 응답은 무시한다. 범위/경로/복귀 정리는 자기 요청 번호가 현재 슬롯과 일치할 때만 `ClearPreview`한다.

요청 슬롯을 다른 입력이 선점했다면 반복 재게시로 서로 덮어쓰지 않는다. 현재 지정의 유효성을 다시 확인하고 소유권을 잃은 지정만 정리한다. 정상 E/Return/EndTurn 경로는 기존 Router의 취소 순서를 따른다.

### D4. 이동 표시 책임

새 내부 `CombatMovementPlanningPresenter`는 씬 연결마다 하나를 만들며 이동 범위·고스트·원본 흐림의 표시 수명을 조정한다. Buffer와 Core 서비스는 받지 않는다. `CombatSceneDisplay`는 기존 이동 표시 계약의 어댑터로 값/의도를 전달한다. 범위와 고스트의 개별 Unity 구현은 기존 FieldView/PlacementGhost/FieldUnitPresenter에 둔다.

`ICombatMovementFeedback`에 범위 표시/해제, 실제 편집 시작의 행위자 식별, 포인터 갱신/숨김, 편집 표시 종료를 필요한 만큼 추가한다. 시작 때 행위자 ID·외형 키·표시 방향을 값으로 전달한다. bool만 가진 기존 `SetPathPlanning`으로 대상 유닛을 추측하지 않는다. 가짜 Display 등 모든 구현을 함께 갱신한다.

범위와 공격은 같은 `Range` 층을 재사용한다. 이동 취소를 끝낸 뒤 공격이 표시하는 기존 Router 순서를 보존한다. 늦은 이동 콜백이나 비활성 이동 정리가 새 공격 범위를 지우지 않도록 이동 표시 소유 수명과 해제 여부를 검사한다. `FieldHighlightState` 밖에 별도 칸 강조 상태를 만들지 않는다.

### D5. 커서 고스트

- 기존 `PlacementGhost`의 풀과 프리팹을 재사용한다. 이 작업에서 클래스·씬 참조의 이름/GUID는 바꾸지 않는다.
- 이동용 호출은 배치 활성 상태·손패 숨김을 변경하지 않는다. 배치와 이동은 기존 입력 Layer/Router에서 상호 배타적이다. 전환 때 이전 표시를 먼저 정리한다.
- 필드 평면과 교차한 **연속 커서 월드 위치**를 사용한다. 칸 끝점과 별개이며, 같은 칸 안에서 커서가 움직여도 갱신한다. 기존 `GhostWorldOffset/GhostScale`을 사용한다.
- 월드 방향은 `FieldUnitPresenter.ModelRotation`의 기존 계산을 재사용한다. 진행 경로 방향으로 회전시키는 추가 기능은 이번 범위가 아니다.
- 고스트 위치 갱신은 `ShowDraft`의 경로/후보/응답 동일값 생략과 분리한다. 고스트 색은 현재 초안 revision의 견적만 반영한다. 옛 경로의 유효색이 새 후보에 남지 않아야 한다.
- 필드 밖/UI 위에는 고스트를 숨기고, 기존 경로의 재진입 조건을 충족한 때 다시 표시한다. 숨김/재표시는 편집 수명 종료와 구분해 원본 흐림은 유지한다. 포인터가 불가 후보 칸에 있으면 무효색, 새 견적이 아직 없으면 중립색이다.
- Collider를 비활성화하고 그림자를 끄는 기존 고스트 준비를 유지한다. HUD/체력 라벨은 실제 유닛에만 붙인다. 렌더러/재질 검색과 핸들 생성은 인스턴스 준비 때 하며 포인터마다 Instantiate/검색/배열 생성을 하지 않는다.

### D6. 원본 모델 반투명과 설정

원본은 실제 위치에 그대로 두고 모델 렌더러만 흐리게 한다. GameObject·Collider·HUD·체력 라벨·실제 위치·Core 회전·점유는 변경하지 않는다.

표현 설정의 원본은 기존 `StageFieldViewData`다. 다음 조정값을 추가한다. 수치는 구현 기본안이며 Phase 2 Unity 리뷰에서 화면을 보고 조정할 수 있다.

| 설정 | 기본안 | 검증/용도 |
|---|---|---|
| `movementOriginalOpacity` | 0.65 | 원래 모델 알파에 곱하는 값. 유한한 (0, 1] |
| `neutralGhostTint` | (0.8, 0.8, 0.8, 0.5) | 견적 대기 중 중립 고스트 색. 유한한 성분, 알파 [0, 1] |

유효/무효 고스트 색·크기·높이는 기존 설정을 재사용한다. 이동 범위 색도 기존 `Range` 색을 사용한다. 런타임 상태나 다른 값에서 계산 가능한 표시 필드를 SO에 추가하지 않는다.

`FieldUnitPresenter`가 흐리게 할 대상 ID를 관리하고 `FieldUnitView`가 모델 재질/색의 적용·원상 복원을 담당한다. 같은 View를 다시 Render해도 임시 흐림이 유지되고, 대상 교체·풀 반환·새 ID 바인딩·Release에서는 남지 않아야 한다. 적 이동 연출의 회전 override와 독립적으로 동작한다.

**머티리얼 착수 점검:** 현재 기본 필드 에셋의 `ghostMaterial`은 비어 있다. 운영 플레이어 외형의 모든 모델 재질과 셰이더를 추적해 투명 지원과 실제 색 프로퍼티를 확인한다. Alpha 키가 있다는 사실만으로 반투명이 된다고 가정하지 않는다.

- 투명 지원 재질은 기존 `IColorSystemService/IColorHandle`로 원래 RGB와 알파를 보존하며 표시 배율만 적용한다.
- Opaque 재질은 기존 셰이더가 제공하는 투명 모드의 변형 재질을 **View 소유 자원**으로 준비해 슬롯별로 임시 적용하고, 원본 shared material 에셋은 수정하지 않는다. 원래 텍스처·색·머티리얼 슬롯을 유지한다. 변형은 첫 사용 시 캐시해 재사용하며 소유 View 최종 파괴/해제에서 정리한다.
- 고스트에 필요한 투명 재질은 View 소유 에셋으로 준비하고 기존 `ghostMaterial`에 연결한다. 기존 배치 고스트도 영향을 받으므로 배치 회귀를 확인한다.
- 지원되지 않는 셰이더의 변경이나 공용 Render 기능 수정이 필요하면 구현하지 않고 Phase 2 리뷰에 근거와 대안을 제시한다. 반투명을 전체 숨김이나 불투명 색 변경으로 대체해 완료 처리하지 않는다.

Renderer당 ColorHandle은 하나만 소유한다. 기존 소유자를 확인하고 중복 발급하지 않는다. `Dispose`만으로 Renderer의 표시가 복원된다고 가정하지 않고 원래 재질/색 값을 명시적으로 적용한다. ColorSystem 내부 수정은 하지 않는다. 파괴된 Renderer를 건드리지 않으며 정리 실패 시 남은 대상의 복원을 계속 시도한다.

### D7. 취소·완료·정리

이동 표시 종료는 멱등적이어야 한다. 범위/경로 요청 정리, 강조 해제, 고스트 반환, 원본 복원을 각각 시도하고 한 정리 실패가 나머지를 막지 않게 기존 실패 수집 방식을 적용한다. 해제 뒤 콜백은 표시를 다시 빌리거나 만들지 않는다.

범위·고스트를 위해 `CombatResultPlayback`의 결과 확인, Gate의 명령 대기, 정상 전투 종료의 마지막 결과 소비를 바꾸지 않는다. 포기 대기/승패 종료로 새 입력이 차단되면 편집 표시만 종료한다. 정상 이동 사건 재생은 원본 흐림을 복원한 뒤 기존 경로로 진행한다.

## 4. SSOT·SOLID·JMH/FW 검토

- **SSOT:** 가능 여부/비용/점유는 Core, 실제 위치/행위자는 Buffer, 초안과 동결은 기존 Interaction, 범위 순서는 PathInput·범위 요청 정체성과 소비 수명은 그 내부 Request 객체, 강조 상태는 FieldHighlightState, 외형/표현 설정은 View DB, 재질/흐림 상태는 FieldUnitView다. 범위 캐시와 포인터/색은 표시용 파생값으로만 둔다.
- **S:** 입력은 입력/요청 수명, PlanningPresenter는 표시 조정, Ghost/UnitView는 Unity 적용을 맡는다. ViewSystem과 SceneDisplay에 계산·편집 상태를 추가하지 않는다.
- **O/L:** 기존 표시 계약과 인스턴스 재사용을 확장한다. `Clear/Cancel/Detach` 멱등성, 견적 revision/context 일치, 취소 후 제출 금지, 클릭 확정 계약을 유지한다.
- **I/D:** PathInput은 좁은 이동 Feedback으로 의도를 전달하고 구체 Renderer/Presenter를 조회하지 않는다. 표시기는 Buffer/Core 서비스 없이 받은 값과 기존 View DB/Color 서비스를 사용한다.
- **JMH:** 런타임 상태와 DB 분리, Build 후 조립 불변, 검색은 준비 단계, 역할 분리·대여 자원 반환·과도한 추상화 금지를 적용한다. 새 전역 서비스/모듈/이벤트 버스/입력 구독/Coroutine은 없다.
- **FW-004/005~007:** 실제 상태 경계를 우회하지 않고 입력은 기존 Submit/Router/Buffer 경로를 유지한다. Configure를 다시 수행하거나 action map을 임의 조작하지 않는다.
- **FW-011/014 및 Color 수명:** 기존 Pool 계약과 렌더 자원의 반환 경로를 따른다. Color의 구체 복원 동작은 자체 검증하고 Dispose에 없는 보장을 기대하지 않는다. 고스트 반환 뒤 대여 참조를 폐기한다.
- View 계획 확장 항목 X1/X3/X5/X6을 이 작업의 책임·취소·요청·재진입 검증으로 연결한다.

## 5. 동시 작업과 리뷰 경계

조사 시 적 행동 간격 작업이 `CombatSceneDisplay/CombatSceneEventPresenter/CombatSceneRoot` 등에 진행 중이다. 해당 변경을 보존하며 같은 파일 구현을 동시에 진행하지 않는다. Phase 착수 직전에 최신 작업 트리를 다시 읽고 현재 변경과 충돌 여부를 확인한다. Phase 2는 적 이동 회전이 FieldUnitPresenter/View에 추가됐으면 그 변경을 인수한 뒤 독립적인 흐림 상태만 추가한다.

최초 요청은 **구현 계획 작성**이었다. 이후 사용자가 병행 가능한 독립 로직·전용 테스트 준비만 진행하고 공통 연결은 다른 세션 종료 뒤 하도록 지시했다. 이에 새 Request 코드와 테스트/각 meta만 추가했다. 독립 .NET 검증 증거와 연결 주의사항은 Task 계획 §0A·§4.2를 따른다. 기존 입력/표시/계약·공통 FakeDisplay·씬·SO·재질은 변경하지 않았다. 공통 연결은 아직 착수하지 않으며 각 Phase 완료 뒤 보고하고 멈춘다. 설계 변경·타 작업자 영역 변경이 필요하면 구현 전에 사용자에게 확인한다.


### 2026-10-13 Phase 2 리뷰 결정

명시적 Phase 1·Phase 2 진행 지시로 범위와 편집 고스트/원본 흐림 연결을 반영했다. 최신 구현·검증·대기는 Task 계획 §4.4가 원본이다. 실제 URP 픽셀 검사에서 URP/Lit·Unlit과 고스트는 알파 혼합/복원됐지만 운영 모델의 Standard 슬롯은 원본부터 오류색이며 반투명이 되지 않았다. D6 범위를 넘는 View 소유 URP/Lit 변환을 제안했고 사용자는 **“여기서 멈추고 기존 재질을 별도로 정리”**를 선택했다. 이번 구현은 기존 셰이더 모드만 유지하며 해당 슬롯 변환이나 공유 원본 재질 변경은 추가하지 않는다. 전체 운영 슬롯 반투명과 원본 GameView 확인은 미완료로 남긴다.
