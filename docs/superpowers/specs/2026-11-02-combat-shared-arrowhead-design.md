# 이동·넉백·토네이도 공용 화살촉 설계 (2026-11-02)

- 요청: 토네이도 이동 방향과 충격 화살 넉백 예상 방향의 `Arrow.prefab` 대신 유닛 이동 경로 끝의 삼각형 화살촉을 사용한다.
- 사용자 확정: **경로 띠 없이 삼각형 화살촉만** 사용한다.
- 범위: View 표시·설정·조립. 기존 이동 경로 설계 MA3의 모양을 공용화하고, 넉백·토네이도 설계의 프리팹 표시 부분을 대체한다.
- 상태: **Phase 1·높이 설정 Phase 2 코드·에셋·정적 점검 완료. 컴파일 미확인**, Unity 확인 대기. 실행 기록은 [Task 계획](../plans/2026-11-02-combat-shared-arrowhead-plan.md)을 따른다.

## 1. 표시와 설정

1. `FieldArrowhead`가 MeshSystem의 반지름 1·꼭짓점 3인 Circle을 한 번 만들고, 위치·회전·배율과 ColorSystem 색만 갱신한다. 이동 경로도 이 부품을 사용하여 메시 규격·자세 계산의 원본을 하나로 둔다.
2. 이동 경로는 기존 머티리얼·길이·너비·꼭지 오프셋과 띠 이음을 그대로 사용한다. 삼각형은 +Z를 가리키고 위를 보는 평면이다.
3. 넉백은 `StageFieldView_Default > Knockback Preview`에서 `Knockback Arrow Material / Length / Width / Lift`를 설정한다. 기본 길이 0.5·너비 0.8은 현재 이동 경로 화살촉과 같다. 기존 밀림·막힘·면역 색과 높이 0.25, 점유 칸 앞 가장자리의 배치 기준을 유지한다.
4. 토네이도는 `TornadoPresentation_Default`에서 `Direction Arrow Material / Length / Width / Lift`를 설정한다. 기본 길이 0.5·너비 0.8. 높이 `Direction Arrow Lift`는 칸 표면 위 월드 단위 띄움이며 기본 0.05다(2026-11-02 사용자 후속 요청). 기존 폭풍 옆 칸의 배치 기준·방향을 유지한다. 기존 Arrow 재질 `Bullet.mat`을 두 설정에 연결하여 토네이도 색과 넉백 색 덮어쓰기 성질을 유지한다.
5. 넉백·토네이도 배치 기준은 삼각형 앞뒤 범위의 가운데로 해석한다. 이동 경로는 기존처럼 도착 칸이 꼭지 기준이다. 새 경로 띠는 추가하지 않는다.
6. 머티리얼 누락, `_BaseColor` 부재, 유한한 양수가 아닌 길이·너비는 구성 오류로 거절한다. 넉백의 맨 설정에서 머티리얼이 없으면 표지만 생략하는 기존 시험용 계약은 유지한다. 운영 DB는 머티리얼을 필수로 검사한다.
7. 높이는 두 설정 모두 유한한 0 이상 값이다. 토네이도는 SO → 불변 Data → 방향 배치로 전달하고 기존 코드 상수를 제거한다. 넉백은 기존 `Knockback Arrow Lift`를 계속 사용한다. 공용 화살촉 부품·이동 경로·Factory·Core는 이 높이 추가로 수정하지 않는다. 높이는 각 기능 설정 한 곳에서 소유하며 새 서비스 등록·수명 변경이 없어 SSOT·SOLID·FW 계약과 기능 독립성 경계를 유지한다.

## 2. 책임·조립·수명

- 공용 화살촉은 게임 상태·격자·넉백 원인·토네이도 규칙을 모른다. 부모 로컬 좌표·방향·표현 설정만 받는다. 독립 서비스로 등록하지 않는다.
- 이동 경로는 `FieldMovementPathLine`, 넉백 재사용 목록은 `FieldKnockbackMarkers`, 토네이도 인스턴스는 `FieldTornadoPresenter`가 소유한다. 넉백·토네이도는 그림자를 끄고 이동 경로는 기존 그림자 설정을 유지한다.
- 토네이도에 필요한 Mesh·Color 인터페이스는 기존 `CombatDisplayServices`에서 운영·특성 미리보기 Factory가 전달한다. Global/루트 등록을 추가하지 않는다.
- 해제는 Color 핸들 → Mesh 핸들 → GameObject 순서이며, 한 핸들 해제가 실패해도 나머지 자원을 거둔다. 구성 실패·반복 해제·토네이도 전체 해제도 소유 자원을 남기지 않는다.
- 옛 `Arrow.prefab`과 `.meta`는 보존한다. 새 `.cs`에는 `.meta`를 만든다. Core·FieldCamera·Architecture는 변경하지 않는다.

## 3. 구조 점검

| 기준 | 적용 |
|---|---|
| SSOT | 삼각형 메시 규격·자세 계산·자원 해제는 공용 화살촉 한 곳. 기능별 재질·크기는 독립된 저작 값이며 다른 기능 설정을 읽지 않는다. |
| SRP | 공용 부품은 그리기, 넉백은 목록·상태별 색, 토네이도는 방향 표시 시점·자리, Factory는 주입 담당. |
| OCP | 같은 삼각형이 필요한 표시가 공용 부품을 조합할 수 있다. 게임별 분기를 부품에 추가하지 않는다. |
| LSP | 기존 표시·취소·해제 계약 유지. `IsAimed`는 실제 화살촉 표시 여부를 반환한다. |
| ISP | Mesh·Color 인터페이스만 전달한다. 전체 서비스 묶음을 표시 부품에 넘기지 않는다. |
| DIP·FW | 기존 Global Context에서 제공받은 Mesh·Color 서비스 사용. FW-010 구체 DTO, FW-011 핸들 반환 준수. FW-001~003 등록·Builder 변경 없음. |

독립성 비교: 이전에는 같은 모양을 쓰려면 프리팹 복제나 기능별 삼각형 계산이 필요했다. 변경 뒤 삼각형 형상 수정은 공용 부품, 넉백 색·배치는 넉백, 토네이도 경고 시점·배치는 토네이도만 수정한다. 공용 부품 변경 때는 세 사용처를 함께 확인한다. 재질·크기 편집은 각 기능 창구에 머무르며, 이동 경로 설정을 넉백·토네이도가 조회하지 않는다.

## 4. 검증

Test 코드와 MSBuild는 작성·실행하지 않는다. 정적 참조·에셋 GUID·수명·diff를 점검한다. Unity에서 컴파일, 이동 경로 직선·꺾임·높이 차, 넉백 직선·대각선·막힘·면역·복수 대상, 토네이도 경고 표시·해제·재진입, 특성 미리보기 진입, `DataBaseAssetTests`를 사용자가 확인한다. **컴파일 미확인**.
