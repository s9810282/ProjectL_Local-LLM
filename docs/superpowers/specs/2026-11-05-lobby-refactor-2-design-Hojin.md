## 1 원칙

- **범위:** 호진이 만든 로비 코드다(평가 범위 124개 파일). 다른 사람이 뒤에 고친 줄도 이 파일들 안이면 고친다. 고친 뒤 그 사람에게 변경을 정리해 넘긴다(2026-11-05 사용자 기준).
- **보호 영역은 그대로다.** Framework·GlobalSystem 내부·Core·Factory 공용 조립·`ServiceKeys` 계약은 바꾸지 않는다. 연결 줄만 바꾸고, 바꾸면 담당자 공유 문서에 적는다.
- **함께 쓰는 부품은 스테이지 맵 동작도 바꾼다.** `ViewSystem/Common`의 `PopupViewScope`·`PopupInputSession`·`ScreenUIPointerBlocker`가 그렇다. 고칠 때 스테이지 맵 쪽 호출을 함께 확인하고, Unity 확인 목록에 스테이지 맵 항목을 넣는다.
- **순서:** 동작 결함(C10) → UI 규약·SSOT → 구조 → 정리 → 성능 → 재평가. 앞 묶음일수록 실제 버그에 가깝다.
- 새 시험 코드와 MSBuild는 없다. 보고에는 "컴파일 미확인"을 쓴다. Phase마다 Codex 검수를 받는다.
- **이번에 다루지 않는 것(§5):** 앞서 내린 결정이나 외부 조건에 묶인 낮음 다섯이다. 이것들은 재평가 뒤에도 남는다.

## 2 중간 6개 설계

### 2.1 M-01 로비 입력 콜백의 예외를 오류 경계로

- **문제:** 시설 누름·뗌, 아티팩트 끌기, 덱 닫기·카드 클릭이 InputSystem·EventSystem 콜백에서 돌고, 예외가 `RuntimeFaultBoundary`에 닿지 않는다.
- **설계:**
  - 새 `ViewSystem/Common/FaultReportingUIInputReceiver`(`IUIInputReceiver` 감싸개)를 만든다. 안쪽 호출의 예외를 잡아 경계에 보고하고, 이미 정지했으면 부르지 않는다.
  - 새 `ViewSystem/Lobby/FaultReportingLobbyReceiver`(`ILobbyInputReceiver` 감싸개)도 같은 꼴로 만든다.
  - 연결 자리는 셋이다.
    - 로비 입력: `LobbyViewInput.Connect`가 `Interaction` 대신 감싸개를 슬롯에 건다.
    - 덱: `LobbyDeckPopupController`가 Presenter를 감싸 화면에 건다.
    - 아티팩트: `ArtifactPopupController.InputReceiver`가 같은 꼴로 보고한다. 지금 `CloseReceiver`가 쓰는 꼴을 공용 감싸개로 바꿔 둘이 같게 한다.
  - `LobbyInteraction.OnSelectReleased`의 "Cancel 뒤 다시 던짐"은 그대로 둔다. 감싸개가 받아 보고한다.
- **바뀌는 동작:** 지금은 예외가 Unity 로그로만 남고 게임이 계속된다. 바꾸면 F1로 멈춘다(FW 계약대로).

### 2.2 M-02 시설 실행 판정을 하나로

- **문제:** 출발만 "막힘 아님 + 로비 Layer"를 보고, 덱·아티팩트는 Layer를 보지 않는다. 도착하는 순간 설정창이 Layer를 독점하고 있으면 팝업 열기가 F1이 된다.
- **설계:**
  - `LobbyViewScope`에 `CanRunFacility()`(막힘 아님 + `IsLobbyLayer`) 하나를 둔다. `CanDepart`는 이것을 쓴다.
  - `LobbyFacilityActions.CanExecute`는 세 시설 모두 이 판정을 먼저 거친다.
  - `LobbyInteraction.Tick`은 도착 완료를 **소비하기 전에** 로비 Layer인지 본다. 설정창 등이 Layer를 가져간 동안에는 이동 완료를 남겨 둔 채 기다린다(Q-R2-1 A). 설정창을 닫으면 다음 Tick에 시설이 열린다.
  - 시설 팝업이나 출발 처리 때문에 막힌 경우는 지금처럼 가던 이동을 버린다(2026-11-05 R2-a Codex 검수 뒤 정정, 계획 §3.2).
  - 판정 원본은 Scope 하나이고, 입력에는 대리자 하나로 넘긴다. 지금 넘기는 `isBlocked`·`isLobbyLayer` 둘은 그대로 둔다. 호버는 Layer만 보기 때문이다.

### 2.3 M-03 외형 없는 아티팩트는 예외로

- **문제:** `LobbyViewServices.FindArtifactVisual`이 `TryGet` 실패 때 null을 돌려준다. 쓰는 쪽은 `?.`로 넘어가 빈 칸으로 그린다.
- **설계(Q-R2-2 A):**
  - 조회를 `GetArtifactView`(없으면 `KeyNotFoundException`, 메시지에 아티팩트 ID)로 바꾼다.
  - `ArtifactBoardRefresher`의 null 캐시와 `?.` 셋, `ArtifactPopupView`의 `ModelPrefab == null` `continue`를 걷는다. 외형 항목의 프리팹·이름은 DB 생성 때 이미 필수다.
  - View는 InGame DB를 읽지 않는다(데이터 경계). 그래서 InGame 정의와 짝을 맞추는 검사는 런타임에 넣지 않는다. 없는 ID가 Buffer로 오는 순간 예외가 나는 것이 원본 하나다.

### 2.4 M-05 가림 판정은 화면 공간 UI만

- **문제:** `ScreenUIPointerBlocker`가 월드 공간 Canvas의 Graphic까지 가림으로 본다. 그래서 방 프리팹의 시설 안내 글자 위에서 호버·클릭이 막힐 수 있다.
- **설계(Q-R2-3 A):**
  - 레이캐스트 결과의 모듈이 `GraphicRaycaster`이고, 그 Canvas가 `RenderMode.WorldSpace`가 **아닐 때만** 가림으로 본다. 이름(Screen UI)과 뜻을 맞춘다.
  - Canvas는 `GraphicRaycaster`마다 처음 한 번 찾아 사전에 둔다. 포인터 이동마다 `GetComponent`를 하지 않기 위해서다.
  - 스테이지 맵(`StageMapPointerBlocker`)도 이 부품을 쓴다. 지금 `StageSelect.unity`에는 월드 공간 Canvas가 없지만, 노드 프리팹에 있는지는 구현 때 확인한다.

### 2.5 M-09 아티팩트 모델 자세 식 하나로

- **문제:** 칸 평균 중심·높이·회전·배율 식이 배치 표시(`ArtifactPopupView`)와 드래그 표시(`ArtifactDragDisplay`)에 두 벌 있다.
- **설계:**
  - `ArtifactBoardMapper`에 `ModelPose(cells, rotation, prefab)`(→ 로컬 위치·회전·배율) 하나를 둔다. 두 표시가 이것을 부른다.
  - 회전 각도(`index × 90°`) 도우미도 여기 하나로 둔다. N-40의 아티팩트 두 곳을 함께 정리한다.
  - 로비 판의 회전 리터럴(N-40의 셋째)은 §3.2에서 정리한다.

### 2.6 M-12 로비 루트 참조 원본을 하나로

- **문제:** `ArtifactPopupView.lobbyRoot`(저작 참조)가 `LobbySceneRoot.worldRoot`와 같은 객체를 따로 가리킨다. 비어도 예외가 나지 않는다.
- **설계(Q-R2-4 A):**
  - `lobbyRoot` 직렬화 칸을 걷는다. 로비 연결이 `ArtifactPopupView.Configure`(또는 Factory `Create`)에 로비 월드 루트를 넘긴다.
  - 넘긴 값이 null이면 예외로 막는다.
  - 씬 YAML에 남는 옛 칸 값은 다음 저장 때 사라진다. 프리팹·씬을 손댈 것은 없다.

## 3 낮음 88개 — 작업 묶음

중간과 함께 고치는 것은 그 자리에서 다룬다. 나머지는 기준별로 묶었다. "고칠 방향"은 문제 목록에 있다. 설계에서 정한 것만 적는다.

### 3.1 R2-a 정확성(C10) — 중간 넷과 함께

- **N-04:** 팝업이 닫히면 늘 막힘을 푼다. Layer 조건은 쓰는 순간의 판정(§2.2)에 둔다.
- **N-05:** `PopupInputSession.Begin`이 수명을 확립하지 못하면 실패 결과를 돌려주고, 열기를 멈춘다. 공용 부품이라 스테이지 맵 팝업에도 적용된다.
- **N-06:** 열기·닫기 도중 연결이 바뀌어 원인 예외를 버리는 갈래에서도 경계에 보고한다.
- **N-08·N-11:** 실패 사유 문구에 빠진 열거 값을 채운다. 보드 설정 표의 실패 셋을 원인별 문구로 나눈다.
- **N-09:** 우클릭 회수는 `_hasPointer`일 때만 한다.
- **N-10:** 아티팩트 UI의 화면 좌표 판정이 Overlay Canvas를 전제하므로, `Validate`에서 Overlay인지 검사한다.
- **N-12:** `LobbyViewScope.Start`가 준비 완료 여부를 돌려준다. `Attach`는 성공일 때만 배경음을 처리한다.
- **M-04(Q-R2-5 C):** 코드는 그대로 둔다. 다음 두 가지를 덮어쓰는 줄 주석과 `boardCenter` 툴팁에 적는다. 판 크기 검사는 넣지 않는다(§4.1).
  - 바닥은 4×4 판에 맞춘 고정 아트이고 판 루트 원점에 놓인다.
  - `boardCenter`는 격자 위치만 옮긴다.
- **M-06(Q-R2-6):** 아티팩트 도메인 정지 사실을 View가 읽는 좁은 계약으로 낸다. 팝업에 안내 한 줄을 보이고 편집 입력을 막는다. 출발은 1차 결정(D11·Q-LJ2 A)대로 막지 않는다.

### 3.2 R2-b UI 규약·SSOT

- **M-10:** 로비·아티팩트 입력의 누름·뗌·강제 취소 해석과 선택 소유자 보존을 `ViewSystem/Common` 부품 하나로 둔다.
- **M-07·M-08:** 실행 순서가 숫자 사본에 기대는 곳은 기준 값 하나에서 식으로 구한다.
  - Job 우선순위: 호출 Job과 확인·전환 Job이 한 상수를 읽는다.
  - 씬 노드 순서: "View 해제 = 이탈 검사 + n" 꼴로 둔다.
- **N-40~N-52 중 로비 몫:**
  - 회전 도우미(§2.5)
  - 판 안쪽 판정 `LobbyBoardData.Contains` 하나
  - 팝업 UIId는 `_view.ID`에서
  - 아티팩트 입력 가능 판정은 이름 있는 판정 하나씩
  - 덱 입력·카드 칸 판정은 한쪽이 원본
  - 출발 요청 단계: `IsPending`을 전이 표에서 구함
  - Buffer 번호 발급 하나
  - 아티팩트 명령·프리뷰 Job 하나로
  - 유한 값 판정 공용
  - 걸음 회전 주석
  - 씬 루트 검사는 `LobbySceneRoot.Validate` 하나
  - 입력 Layer 창구 재사용
- **N-82:** 덱 UI가 플래그를 내리기 전에 호버 해제를 보낸다.
- **N-83:** 아티팩트 보유 목록 슬롯의 누름·끌기 시작을 한 경로로 모은다.

### 3.3 R2-c 구조(C2·C4·C8·C9)

- **M-13·N-54 (시설 종류):**
  - 시설 실행 계약 `ILobbyFacilityAction { CanOpen; Open(); }`을 두고, 종류 → 항목 표로 받는다.
  - 판의 도착 칸은 (종류 → 칸·방향) 목록 하나다. 시설 수는 열거 값 수에서 구한다.
- **M-14 (팝업 집합):** 로비 팝업을 Start·Tick·Dispose 공통 항목의 순서 있는 목록으로 둔다. 씬 루트 찾기·출력 복원은 각 팝업 Factory가 맡는다.
- **N-01·N-55~N-59 (넓은 계약·큰 클래스·DB 계층):**
  - 서비스 묶음을 쓰는 쪽별로 나눈다(씬 표시·입력·출발·덱·아티팩트).
  - 이동 시작·소리는 말 표시 쪽으로 옮긴다.
  - 덱 표시 계약 `ILobbyDeckDisplay`를 둔다.
  - 아티팩트 표시 계약을 표시·판정·수명으로 나눈다.
  - 방 프리팹 검사는 한 곳에 둔다.
  - `LobbyFacilityView`의 런타임 캐시는 View 쪽으로 옮긴다.
- **N-61:** 출력 마스크 층 이름을 설정으로 빼고, 생성은 아티팩트 Factory로 옮긴다.
- **N-73·N-75·N-02·N-03 (캡슐화):**
  - `LobbyViewInput.Tick()`을 둔다.
  - 출발 단계는 읽기 계약·쓰기 계약으로 나눈다.
  - 보드 좌표 변환기는 하나만 만든다.
  - 드래그 표시 준비는 `Configure` 한 입구에서 한다.
- **M-11·N-13·N-14 (수명):**
  - 컨트롤러는 "현재 호스트만" 감싼 판만 쥔다.
  - 씬 표시 시작의 부분 정리를 한 꼴로 맞춘다.
  - `Detach`에서 지난 연결을 바로 놓는다.
- 이 묶음이 가장 크다. 시설·팝업을 늘릴 계획이 없으면 M-13·M-14·N-54는 미룰 수 있다(Q-R2-8).

### 3.5 R2-e 성능(C7·C11)

### 4.1 Q-R2-5 확인 결과 (M-04 바닥 위치)

- **들어온 커밋:** `ArtifactPopupView.Render`의 바닥 처리는 처음 구현 때부터 지금 꼴이다. 바닥을 판 가운데 칸 자리에 놓은 뒤 바로 `localPosition = Vector3.zero`로 덮어쓴다. 처음 구현 커밋은 `5376b174d`(호진, 2026-10-06 "[호진] 아티팩트 3D 팝업 구현")다. 그 뒤 판에서 바뀐 적이 없다(`git log -S`). `boardCenter` 설정 칸도 같은 커밋에서 처음 생겼다.
- **바닥 아트가 맞춰진 기준**(아티팩트 팝업 계획 §3.4·§3.7):
  - 10-06 배치면 정렬 때 실제 메시를 재서 바닥 안쪽 배치 면 한 변 7.161을 4 × 1.79에 맞췄다.
  - 10-17 공간 모델 교체 때 자식 배율·위치를 손으로 맞춰 "배치면 한 변 7.16·중심 (0,0,0)·높이 0"으로 뒀다.
  - 곧 바닥은 4×4 판에 손으로 맞춘 고정 아트이고, 판 루트 원점에 놓는 것을 전제로 정렬됐다.
- **지금 데이터:**
  - `ArtifactPopupConfig_Default.boardCenter`는 (0,0,0)이다. 그래서 덮어쓰는 줄은 지금 화면에 아무 차이를 만들지 않는다.
  - 판 크기를 바꾸는 Core `ExpandBoard`는 부르는 곳이 없다. 판은 늘 4×4다.
- **판단:**
  - 바닥이 `BoardCenter`·판 크기를 따르지 않는 것은 고정 아트를 원점에 두려는 처음 의도로 보인다. 따라갈 필요가 없어서 넣지 않은 쪽에 가깝다.
  - 다만 의도가 코드에 적혀 있지 않다. 주석 "중앙에 하나만 표시합니다"(N-76)는 덮어쓰기와 맞지 않는다. `BoardCenter`를 바꾸면 격자만 옮겨지고 바닥은 그대로라는 사실도 툴팁에 없다.
- **고른 안(Q-R2-5 다시):**
  - **C 코드는 그대로 두고 의도만 적음(새 권장).** 덮어쓰는 줄과 `boardCenter` 툴팁에 다음 두 가지를 적고, N-76의 낡은 주석도 함께 고친다. 크기 검사는 넣지 않는다(판 크기를 바꾸는 길이 없어서).
    - 바닥은 4×4 판에 맞춘 고정 아트이고 판 루트 원점에 놓인다.
    - `boardCenter`는 바닥 위 격자 위치만 옮긴다.
  - A 처음 권장: C에 더해 바닥 아트가 맞는 판 크기(4×4)를 설정 검사에 둔다.
  - B 바닥이 판 크기·중심을 따라가게 바꾼다(필요가 생기기 전까지는 하지 않음).
- C로 하면 M-04는 "의도가 적힌 기반 선택"이라 재평가에서 낮음이 하나 남을 수 있다. 주석이 실제 동작과 맞으면 감점 사유가 약해진다.
