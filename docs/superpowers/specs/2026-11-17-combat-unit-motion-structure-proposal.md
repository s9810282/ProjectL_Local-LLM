# 전투 유닛 동작 구조 — 동작 키 + 단계 목록 (제안 초안)

- 날짜: 2026-11-17
- 상태: **대신함(2026-11-17).** 사용자 "기존 구조 기준"으로 고정 칸(공격·피격)을 유지하고 칸 안을 다시 짜는 [클립 칸 다시 짜기 설계](2026-11-17-combat-unit-clip-slot-redesign-design.md)가 대신한다. Q-MS1~Q-MS5는 정하지 않는다. 아래는 그때 기록(§1 블렌드·§2 대조는 새 설계의 바탕).
- 계기: 새 클립 연결(설계 [new-clips-wiring](2026-11-17-combat-unit-new-clips-wiring-design.md)) 중 넣을 칸이 없는 클립이 계속 나옴(Gravedigger `Recovery`, 카우보이 `PullBack`) → 사용자 "생길 때마다 새로 넣자는 게 아니라 근본적인 구조를 생각해볼 필요가 있다".
- 바탕 설계: [유닛 애니메이션 클립 설계](2026-10-19-combat-unit-animation-clip-design.md)(AC1~AC19 — Idle = 컨트롤러, 사건 클립 = 묶음 SO + 코드).

## 1. 왜 Animator 상태 기계가 아니라 코드가 클립을 바꿔 끼우나(사용자 질문 답, 11-17)

10-19 클립 설계의 나눔(AC9, 사용자 결정): 사건과 무관하게 늘 도는 Idle은 컨트롤러, 전투 사건이 시작시키는 공격·피격은 묶음 SO + 코드.

1. **맞는 순간을 전투 재생이 쥔다.** 공격 클립 `ClipEvent`가 대상 피격 시작·발사·소리·이펙트·흔들림의 기준 시점이다. 재생기가 연출 시계로 클립 시각을 넣고(`SetTime`) 같은 Tick에 이벤트를 낸다. Animator 전환·Unity 이벤트는 Unity 업데이트·전환 시간에 매여 시계가 갈린다(AC2: Unity 이벤트 끔, 시각은 DB가 클립에서 읽음).
2. **유닛마다 다른 클립을 데이터 한 곳에서 고른다.** 컨트롤러마다 공격·피격 상태·파라미터·전환을 만들지 않고 묶음 SO 칸만 채운다(원본 하나).
3. **취소·되돌리기.** 취소·풀 반환 때 위층을 빼고 쉬는 자세로 되돌린다.
4. **부속 클립(말·무기·올가미)을 몸과 같은 시각으로** 레이어 섞개에서 돌린다.
5. **전투 규칙(템포 `attackSpeed`·시작 맞춤·원거리 발사 목록)을 코드가 적용한다.**

- 치르는 값: Animator 창·미리보기로 전투 흐름을 그대로 볼 수 없음, 프리팹 Animator 설정(켜짐·컨트롤러)을 실행 중 코드가 넘겨받음(캐논 셋은 Animator가 꺼져 있어도 전투는 돌지만 미리보기는 안 돔 — 사용자 확인 중), Animator 블렌드 트리·전환을 사건 클립에 못 씀.
- 블렌드: 지금은 Idle ↔ 사건 클립을 바로 갈아 끼움(가중치 0/1, 설계 §2·AC9 "끊김이 보이면 섞는 시간 값 하나로 나중에"). 섞는 그래프(`AnimationMixerPlayable`)를 우리가 들고 있어 크로스페이드는 `UnitClipChannel` 한 곳 + 값 하나로 가능. 정할 것: 끝의 쉬는 자세 되돌리기(계획 P17)를 페이드 뒤로, 페이드아웃 동안 그 유닛 다음 연출 대기 여부. 사건 클립끼리 섞기(공격 중 피격)는 클립 대여가 유닛당 하나라 위층 둘이 필요. 컨트롤러에 공격 상태를 두고 `CrossFade`로 부르는 혼합안은 맞는 순간 시각을 다시 Animator가 쥐어 권하지 않음.

## 2. 지금 구조가 늘어나는 이유(코드 대조, 11-17)

| 자리 | 지금 | 문제 |
|---|---|---|
| 묶음 SO `CombatUnitAnimationSO` | 이름 있는 칸 둘(공격 `attackClip`·부속, 피격 `hitClip`·부속) + 공격 시작 칸 셋 | 새 순간 = 새 칸 + 검사 + 에디터 |
| 공격 시작 `CombatAttackAnimationStartMode` | 0 기본·1 지정 선행 발동 시작(카우보이 끌어오기 310)·2 휩쓸기 시작(SoulEater 죽음의 손) | 경우마다 열거 값 + 코드 갈래(`CombatAttackAnimationStartData`·`CombatPreAttackPresentationStarts`) + 에디터 UI |
| 공격 처리 `CombatAttackStart.TryBegin`·`TryBeginArea`·`TryBeginDeferred` | 공격 칸을 직접 고름. 스킬(사건 51)은 시전자 공격 클립을 빌림 | 스킬 전용 클립 자리 없음 |
| 피격 처리 `CombatCharacterEventHandler`(:314·:360·:389) | 피격·넉백 피격·연발 앞 탄 피격이 모두 피격 칸 | 순간별 클립 구분 불가 |

## 3. 제안

1. **동작 키(Motion key) 하나로 부른다.** 게임 순간의 작은 어휘 — 공격, 피격, 스킬(스킬 키), 특성 발동(발동 종류) — 를 값 하나(`CombatMotionKey` 가칭: 종류 + 번호)로 정한다. 사건을 재생하는 코드는 "이 유닛에 이 키의 동작이 있나"만 묻는다. 없을 때 넘어가는 키는 규칙 하나(스킬 X → 공격, 끌어오기 공격 → 공격 등). 이미 있는 순간의 새 클립 = 데이터 한 줄.
2. **동작 = 단계 목록(선행 → 본 → 후속).** 단계마다 몸 클립 + 부속 클립. 맞는 순간·발사 이벤트는 본 단계에만. 단계 잇기는 재생기 한 곳이 맡고, 공격·피격·스킬 조립 코드는 지금처럼 시작·이벤트·끝 신호만 본다 → PullBack·Recovery가 생겨도 조립 코드 무변경.
3. **묶음 SO = 동작 줄 목록.** 고정 칸 대신 "키 + 단계 + 설정(템포·시작 맞춤·섞는 시간)" 줄 목록. 지금 공격·피격 칸은 공격 줄·피격 줄로 옮김(에셋 옮기기 도구 또는 `FormerlySerializedAs` + 읽기 호환 — 정할 것). 검사는 단계마다 같은 규칙(본 단계만 이벤트 셋, 부속 규칙, 루트 곡선).
4. **시작 모드 갈래를 줄로 흡수.** 카우보이 = 끌어오기 발동 키 줄 [PullBack(선행), CowBoy_Attack(본)] + 발동 시작 맞춤. SoulEater 휩쓸기도 같은 모양 → `CombatAttackAnimationStartMode` 갈래 축소.
5. **섞는 시간도 재생기 한 곳.** 단계 사이·Idle 오갈 때 크로스페이드를 줄 설정 하나로(§1 블렌드).
6. **Idle은 컨트롤러 그대로**(AC9).

고려했지만 권하지 않음: 컨트롤러를 클립 창고로(상태 이름 = 키) 쓰고 재생기가 꺼내 틀기 — Animator 창에서 보이는 장점은 있으나 검사가 에디터 전용이 되고 원본이 둘(SO 설정 + 컨트롤러 상태)로 갈림.

## 5. 같이 볼 것

- **SoulEater(27) = Gravedigger 모델(사용자 확인).** 지금은 ShotGun 프리팹 + 옛 Boomber 클립을 빌린 임시 설정(11-16). Gravedigger 새 프리팹(`Prefabs/Characters/New/Playerable/Gravedigger/Gravedigger.prefab`)은 Sniper처럼 Animator만 있어 부품(크기·레이어·몸 상자·이벤트 컴포넌트·랙돌, 근접이라 총구 불필요)을 넣어야 함 — 새 클립 연결 계획 §5.8의 Sniper 방식(Library 가져오기 결과에서 번호 읽기)으로 코드 없이 가능. 클립 `Gravedigger_Attack`(1.25초)·`_Hit`(1.17초)·`_Recovery`, 죽음의 손 휩쓸기 맞춤(시작 모드 2)을 새 클립에서도 유지해야 함.
- **라이더 셋의 말 클립**은 이미 부속 클립으로 공격·피격에 연결됨(EnemyShabow·Boomber·CowBoy, 카우보이는 올가미까지). 컨트롤러 Idle 층도 있음. 이동 중 말 동작 클립은 없음(전투 이동은 코드).
