# 충격 화살 VFX 설계

작성: Codex / 2026-10-31. 최초 와류 시안 제작 뒤 사용자가 “우리 무드에 맞게”, “충격화살이라는 거랑 거리가 먼 디자인”이라고 지적하여 물리적인 충격 화살로 표현을 수정했다. 현재 표현 원본은 아래 충격 화살 방향이다. 과거 와류 제작 결과는 계획 실행 기록으로만 남긴다.

## 범위와 표현

- 대상: `Assets/ProjectL/Script/Render/Effect/AttackEffect/Arrow/`.
- 기존 `Arrow.prefab` GUID를 유지해 비행 효과로 재구성한다. 기존 FBX의 ArrowObject 실루엣을 재사용하고 본체에 목재·금속 색을 부여한다.
- 비행: 두껍고 각진 강철 촉, 짙은 목재, 베이지 깃이 주인공. 촉 뒤의 짧은 아이보리 압축 공기선과 가는 직선 속도선만 둔다. 청록 나선·공전·마법 조각을 제거한다. 크고 빛나는 외피로 본체를 덮지 않는다.
- `ArrowImpact.prefab`: 0.1초 이내 강한 아이보리 타격 섬광 → 0.25초 내 빠르게 확장하는 낮고 불규칙한 충격 링 → 지면 방향 충격선·짧은 균열·밖으로 밀려나는 황토 먼지와 작은 돌. 전체는 0.6초 이내 단발 재생 후 빈 상태가 된다. 얼음·번개·불꽃의 원소 효과는 넣지 않는다.
- 화살은 로컬 +Z가 진행 방향이다. 비행 프리팹은 위치 이동을 소유하지 않는다. 착탄 프리팹의 +Y는 지면 법선이다.
- Unity 기본 ParticleSystem, 편집 가능한 Shader Graph, Mesh 에셋만으로 효과를 구성한다. 입자 수명에 따른 투명도·크기는 ParticleSystem 곡선이 소유한다. 셰이더가 그 값을 다시 시간으로 계산하지 않는다.
- 기존 씬, Core, FieldCamera, Architecture, 전투 타임라인, 공용 서비스·등록, DB는 변경하지 않는다.

## 프리팹과 수명 계약

- 비행 프리팹 루트에 ParticleSystem을 두고 하위 효과를 재귀 Play/Stop할 수 있게 한다. 본체도 Mesh 파티클로 표시해 StopEmittingAndClear 시 잔존하지 않는다.
- 비행 본체·압축 공기선·속도선은 일정한 크기/불투명도로 반복하며 회전시키지 않는다. 모든 위치는 Local이다. 긴 비행에도 과거 위치로 떨어진 조각이 남지 않는다.
- 착탄은 Loop off, Burst 기반, 작은 maxParticles. 재사용 시 `Stop(true, StopEmittingAndClear)` 후 `Play(true)`한다. 호출자는 비행과 착탄 프리팹 생성·회수와 피격 위치/방향을 소유한다.
- 독립 Editor 미리보기 창에서 비행 위치 이동과 착탄 호출을 시연한다. 창은 PreviewScene 자원을 소유하고 닫을 때 해제한다. 열린 작업 씬을 저장·변경하거나 Play 모드에 진입하지 않는다.

## 구조 점검

- SSOT: 입자 수명/크기/색 곡선은 프리팹, 공통 색 곱과 투명도 전달은 Shader Graph, 형태는 Mesh. 게임 규칙 값을 VFX에 복제하지 않는다.
- SRP: 비행/착탄 프리팹의 표현과 Editor 미리보기의 조립·이동 시연을 분리한다. OCP: 효과 교체는 프리팹 내부에서 끝난다. LSP/ISP/DIP: 새 서비스/인터페이스를 추가하지 않으며 현재 Framework 계약을 변경하지 않는다.
- FW-010~012/014: 이번 단계는 독립 에셋 제작이며 Render 서비스·Pool을 우회해 게임에 등록하지 않는다. 실제 대여/반환·취소 연결은 Phase 2에서 기존 연출 계약을 확인한 뒤 결정한다.
- 변경 독립성(공동 인계 §4.6): 압축선·착탄 링·먼지 변경은 해당 Mesh/ParticleSystem/Material만 영향. 미리보기 이동시간 변경은 Editor 창만 영향. 전투 적용·취소 계약 변경은 Phase 2의 조립 지점과 영향 검증으로 분리한다.
- 정리: 기존 사용 중인 머티리얼의 사용자 변경은 백업한다. 불필요한 기존 레이어는 Arrow 프리팹에서 제거한다. 외부 또는 미저장 씬에서 참조할 수 있는 기존 Shader/FBX 에셋은 참조 확인 없이 삭제하지 않는다.

## 검증 기준

1. Unity 실제 임포트·컴파일, ShaderUtil 오류 0, 참조 누락 0.
2. 비행 0.3초/반복 경계/장시간에 본체와 압축선이 유지되고 총 입자 수가 제한된다.
3. 착탄 초기/확산/소멸을 네이티브 URP 렌더로 확인한다. 1초에는 모든 파티클이 사라지고 재시작이 가능하다.
4. StopEmittingAndClear는 비행의 본체·꼬리까지 비운다. Editor 창 해제 후 PreviewScene이 남지 않는다.
5. 처음부터 수정된 JMHTest 씬과 기존 사용자 변경 파일을 보존한다. 범위 밖 파일은 변경하지 않는다.
