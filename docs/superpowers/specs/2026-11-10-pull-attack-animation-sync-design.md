# 공격 시 선행 특성 연출 기준 공격 애니메이션 시작 시점 설계 (2026-11-10)

상태: **결과 조사·설계 완료, P1~P4 코드 반영·컴파일 미확인. P5 미착수**. 사용자가 P3·P4 동시 구현·일괄 리뷰를 승인했다. 파일명은 링크 유지를 위해 보존한다. 대상은 공격 시 선행 발동하는 특성이다. 모든 특성의 인과관계 추적, ClipPull 전용 이벤트, 당김 지연, 공격 클립 선행 시간 제안은 이번 설계에서 제외한다.

## 1. 요구와 범위

작업자는 CombatUnitAnimationSO에서 **기준 TraitActivationKind 하나와 지연 d**를 지정한다. 같은 공격의 유효한 선행 발동 중 지정 Kind와 일치하는 첫 실제 연출 시작을 t0로 삼는다.

    지정 Kind의 선행 연출 시작 t0 ── 특성 연출 진행
                         └─ d초 ─ 공격 클립 시작 ─ 타격 준비
    공격 피해 표시                  선행 필수 처리 + 타격 준비 완료 후

d=0이면 함께 시작하고 d=0.3이면 특성 연출 시작 0.3초 뒤 클립을 시작한다. 당김 자체의 시작 지연이나 클립 시작 후 이동 지연이 아니다.

### 1.1 현재 지원 대상으로 확인한 발동

| 특성·발동 종류 | 생산 위치 | 범위 |
|---|---|---|
| Pull / PullApplied | PullAttackCalculator.ExecuteSteps | 실제 끌어오기 실행. 적·아군 모두 포함하고 피해 없는 당김도 포함한다. |
| Vanguard / AttackGranted | TraitAttackNotifications.Apply | 공격 행동 알림으로 생성하는 선행 공격력 부여. 발동자가 공격자와 달라도 포함한다. |
| CleanSweep / AttackGranted | TraitAttackNotifications.Apply | 공격 행동 알림으로 생성하는 선행 공격력 부여. |

이는 View가 발동 조건·확률·효과량을 재계산하는 규칙 표가 아니다. **현재 재생 시작 기준으로 지원할 공개 발동 종류의 목록**이다. 실제 발동 여부는 Core가 낸 사건만 따른다. 카우보이 유닛 키 분기 없이 같은 타이밍 조정기를 쓴다.

### 1.2 제외

- 이동·턴·피격·사망·처치가 원인인 발동, 도발의 행동 대상 선택 알림.
- HunterTargetSelected/StatusRemoved 같은 상태 재선택·정리. 공격 계산 중 앞에 나타나도 공격 시 발동하는 특성으로 취급하지 않는다.
- Hunter/Rampage/MoraleBoost의 처치 보상 AttackGranted, 이동으로 발생한 Acceleration의 AttackGranted. **AttackGranted라는 종류 하나만으로 대상 여부를 판정하지 않는다.**
- 공격 후 발동, 독립된 추가 공격 시작, 대신 맞기 반응을 부모 공격의 선행 특성으로 편입하지 않는다. 기존 연출은 유지한다.

새 선행 특성이 추가되면 생산 위치와 요약/사건 연결을 확인하고 지원 목록 한 곳에 추가한다. 조정기에 특성별 타이밍 로직을 추가하지 않는다. 이 명시적인 적용 범위를 없애고 모든 앞쪽 발동을 자동 지원하는 것은 별도 확장이다.

## 2. 현재 데이터로 가능한 연결

**결론: 위 범위는 현재 운영 결과의 객체 참조와 사건 순서로 정확히 연결할 수 있다. 신규 Core ID·관계 DTO를 구현 선행 조건으로 요구하지 않는다.** 이전의 모든 특성 연결 요구는 과도한 범위였다.

### 2.1 생산자에서 Buffer까지 확인한 근거

| 경계 | 확인한 코드 | 결과 |
|---|---|---|
| 공격 전 발동 생성 | CombatAttackCalculator.cs의 actionEventStart 이후 TraitAttackNotifications.Apply, PullAttackCalculator.ExecuteSteps | 해당 공격의 선행 발동을 사건에 먼저 넣는다. |
| 공격 사건 위치 | 같은 계산기의 attackEventIndex는 사전 이동 이후, 피해 실행 이전. 마지막에 이 위치로 CombatAttackEvent/CombatRoarEvent를 삽입 | 최종 목록에서 발동이 해당 공격 사건보다 앞에 있는지 확인할 수 있다. |
| 공격 요약 수집 | CombatAttackCalculator.cs 211~240의 traitRows.Add(value) | 사건에 들어 있던 동일 발동 객체를 수집한다. ResultOrigin이 null인 Vanguard/CleanSweep도 수집된다. |
| 결과 조립 | AttackResultFactory.Build의 traitActivations.Concat(ledger.Reactions), AttackResult.cs 60~69 | 컬렉션은 복사하지만 발동 객체는 재생성하지 않는다. Interception은 별도 반응이므로 범위에서 제외한다. |
| 사건 보관 | CombatEffectsEvent와 CombatCommandTransition, CombatResult의 생성자 | 배열만 복사해 발동/사건 객체 참조를 보존한다. |
| 합성·공개 | CombatCommandComposition.WithEvents/Merge, CombatStateBuffer.cs 260~265 | 기존 Attack과 사건을 전달한다. 최종 결과가 만들어진 뒤 그 목록으로 색인하므로 앞삽입에 따른 인덱스 이동도 문제없다. |
| 끌어오기 이동 대응 | PullAttackCalculator가 같은 AttackPullSnapshot을 CombatPullEvent와 AttackResult.Pull에 전달 | 발동과 연관된 실제 이동 연출 시작도 동일 결과 안에서 대응시킬 수 있다. |

주요 경로:

- Core 생산자: Assets/ProjectL/Script/Systems/RuntimeSystem/InGameSystem/CoreSystem/CoreCaculator/Application/Combat/
- Core 값: 같은 CoreCaculator/Contracts/Combat/, Contracts/Results/AttackResult.cs
- Buffer 공개: Assets/ProjectL/Script/Systems/RuntimeSystem/BufferSystems/Combat/CombatStateBuffer.cs

**원인과 순서의 구분:** HunterApplication.Reconcile은 공격 사건 앞에서 실행될 수 있고, 당김 중 사망이 발생하면 TraitKillSettlement의 처치 보상도 앞에 나타날 수 있다. 요약에 속하며 앞에 있다는 사실만으로 공격 시 선행 발동인지 판단하지 않는다. §1 지원 목록과 함께 사용한다.

### 2.2 연결 절차

1. 최종 결과의 CombatEffectsEvent를 순회해 발동 객체 참조 → (사건 인덱스, 발동 인덱스)를 만든다. 비교는 명시적 참조 동일성이다.
2. 같은 결과의 공격 출처 사건에 실린 AttackResult.TraitActivations를 읽는다. CombatResult.Attack 요약을 별도 공격으로 중복 등록하지 않는다.
3. §1 지원 대상이며 동일 발동 객체가 사건 목록에 정확히 한 번 있고, 그 사건 인덱스가 해당 공격 출처보다 앞인 경우만 선행 연결로 만든다.
4. 같은 발동이 두 공격에 연결되거나 사건에 중복으로 등장하면 모호한 데이터다. 가까운 다음 공격·값 비교·AttackGroup 단독으로 보정하지 않는다. 새 모드에서 필요한 대상 연결이 깨졌으면 결과/발동/공격 위치를 명시해 검증 오류로 보고한다.
5. 공격의 런타임 키는 결과/재생 세대 + 출처 사건 인덱스다. 명령마다 1로 시작하는 AttackGroup을 전역 ID처럼 사용하지 않는다.
6. Pull의 이동 시작 통지는 같은 결과에서 AttackResult.Pull과 참조가 같은 CombatPullEvent를 찾아 연결한다. 대상·시작/도착 칸·경로는 추가 교차 확인 근거다. 이동을 다시 계산하거나 다시 실행하지 않는다.

위 절차로 **선행 발동 자격과 공격 소속을 먼저 확정**한다. 그다음 공격자의 CombatUnitAnimationSO가 지정한 Kind와 일치하는 발동만 시작 기준 후보로 선택한다. Kind 설정은 자격을 넓히지 않으며, 같은 Kind의 이동·처치 보상을 선행 발동으로 만들지 않는다.

일반 공격과 AttackResult가 있는 포효는 같은 요약 대응을 사용할 수 있다. ChildAttack만 있는 추가 공격을 독립 루트 AttackResult로 오인하지 않으며 기존 재생 경로를 유지한다.

### 2.3 보장 범위와 유지보수

이는 **현재 인메모리 생산·Buffer 전달 경로의 확인된 성질**이다. 직렬화 복원·깊은 복사 등 다른 결과 공급 경로에까지 보장한다고 확대하지 않는다. 향후 발동 객체를 재생성하면 대응 어댑터와 확인 항목을 갱신해야 한다. 그때 안정 ID/관계 사실이 필요하면 좁은 범위로 Core에 요청한다.

도발은 이번 범위 밖이므로 요약 누락을 이 기능의 차단 사유로 삼지 않는다. 기존 광범위 Core 요청은 [경계 인계 §66](../handoffs/2026-09-24-view-core-data-boundary-handoff.md)에 정정·철회 기록을 남긴다. 외부 발송은 없었다.

## 3. 작업자 입력

입력은 공격 클립을 가진 **CombatUnitAnimationSO**가 소유한다. 공유 CombatAttack_Melee에 유닛별 시점을 넣지 않는다. 공격 클립 하나에 기준 Kind 하나와 지연 하나를 설정한다. 여러 Kind별 설정 목록이나 우선순위 규칙은 이번 범위에 넣지 않는다.

| 제안 필드 | 의미 |
|---|---|
| attackAnimationStartMode | AfterPreAttackPresentation(기본, 기존 순차 경로) / FromSelectedTraitPresentationStart(지정 Kind의 선행 연출 시작 기준) |
| attackAnimationStartKind | TraitActivationKind 형식. 현재 선택 가능한 값은 PullApplied와 AttackGranted다. TraitKey나 유닛 키를 설정하지 않는다. |
| attackAnimationStartDelaySeconds | 지정 Kind의 연출 시작 기준, 유한한 0 이상 지연 초 |

- 지연은 특성 연출 시작 기준이며 클립 길이로 제한하지 않는다. 코드 모션 전용 유닛은 이번 범위에서 새 모드를 지원하지 않아 설정 시 공격 클립 존재를 검사한다.
- 기본 모드는 기존 스케줄러의 공격 허용 경계를 따른다. 기다리지 않던 곁들임·상시 효과의 종료를 새로 기다리지 않는다.
- Kind·지연은 지정 Kind 모드에서만 검사·사용한다. 해당 모드에서 미정/정의되지 않은 값 또는 지원 목록에 없는 Kind를 지정하면 에셋과 필드를 명시한 설정 오류다. 기본 모드의 미사용 Kind·지연 때문에 기존 에셋을 깨뜨리지 않는다.
- 선택 가능한 Kind는 §1 지원 발동 목록에서 중복을 제거해 얻는다. 에디터 선택지와 런타임 검사에 별도 사본 목록을 두지 않는다. 인스펙터에는 지정 Kind 모드일 때만 기준 Kind와 지연을 편집하도록 표시한다.
- 같은 공격에서 **지정한 Kind와 일치하는 첫 유효 연출**의 시작만 t0로 기록한다. 다른 Kind의 선행 연출은 정상 재생하되 이 타이머를 열지 않는다. 같은 Kind의 후속 발동·다른 표시 단계가 타이머를 재설정하거나 클립을 다시 시작하지 않는다.
- 지연 중 특성 연출이 끝나도 t0+d를 기다린다. 원래 공격 사건에 도달할 때까지 지정 Kind의 유효한 선행 연출 시작이 없으면 기존 공격 경로를 따른다. 이는 정상적인 미일치이며, 소속 연결 오류를 숨기는 대체 경로와 구분한다.
- Kind는 공격자 자신의 보유 특성으로 제한하지 않는다. 예를 들어 다른 아군의 Vanguard 발동도 해당 공격의 선행 발동으로 확인됐다면 AttackGranted 설정의 후보가 된다.

### 3.1 작업자 설정 예시와 기대값

| 설정 | 기대 동작 |
|---|---|
| 지정 Kind / PullApplied / 0초 | 같은 공격에 연결된 당김 연출 실행 시작과 함께 공격 클립을 한 번 시작한다. |
| 지정 Kind / PullApplied / 0.3초 | 당김 연출 실행 시작 0.3초 뒤 공격 클립을 시작한다. |
| 지정 Kind / AttackGranted / 0.2초 | 확인된 Vanguard·CleanSweep 선행 연출 중 먼저 실제로 시작한 연출의 0.2초 뒤 클립을 시작한다. |
| PullApplied 선택, 같은 공격에 AttackGranted도 있음 | 앞선 버프 연출은 기준이 아니다. 당김 연출 시작을 기다린다. |
| AttackGranted 선택, 처치 보상만 존재 | 선행 자격이 없어 기준으로 사용하지 않는다. 다른 유효 후보가 없으면 기존 공격 재생이다. |
| 지정 Kind가 발동하지 않거나 실제 표시가 없음 | 기존 공격 재생. 아직 발생하지 않은 발동을 기다리지 않는다. |

예시 값은 설계 설명이며 SO 에셋에 적용한 값이 아니다.

## 4. '특성 연출 시작'의 연결

특성 사건을 읽은 시각이나 결과 수신 시각을 기준으로 쓰지 않는다.

- 큐·글자·유닛 행동은 기존 연출 실행이 시작될 때 통지한다. ActivationStart와 StateApplied의 차이를 반영한다.
- **Pull은 특성 큐가 비어 있어도 당김 이동 자체가 연출이다.** CombatPullEvent에 연결된 기존 이동 레인이 실행을 시작할 때(선행 회전 포함) 통지한다. 빈 TraitVisual 때문에 기준이 사라지지 않게 한다.
- 시작 기준을 제공하는 작은 어댑터가 발동과 실행을 연결한다. 공통 시점 조정기는 선택된 Kind와 소속이 확인된 후보를 받고 유닛/특성 키별 동작으로 분기하지 않는다.
- 표시 없는 발동은 t0를 만들지 않는다. 같은 공격의 다른 유효 발동이 **지정 Kind와 일치하고** 실제 표시가 있으면 그 시작이 기준이다.
- 큐 내부의 개별 지연은 기존 큐 설정이다. 모든 파티클이 보이기 시작하는 픽셀 시점을 추적하는 기능은 아니다.

## 5. 재생 책임과 Gate

1. 지원 발동 분류는 §1의 적용 목록 한 곳이 소유한다. 효과 수치·발동 계산은 하지 않는다.
2. 결과 대응기는 참조·인덱스로 소속을 정한다. 요약은 연결에만 쓰고 특성 효과를 중복 재생하지 않는다.
3. 기존 특성 표시·이동 레인은 실행 시작만 통지하고 원래 연출을 수행한다.
4. 시점 조정기는 지정 Kind 후보의 첫 t0·예약·시작 여부를 소유하며 기존 재생 시간축을 사용한다. 기준 Kind와 지연은 공격자 클립 설정에서 읽은 불변 값이다.
5. 기존 공격 조립은 클립을 한 번 시작한다. 원래 공격 사건이 오면 같은 실행에 합류한다.

조기 클립의 타격 신호는 준비 상태로 보관하고 선행 필수 처리와 합류한 뒤 공격 피해를 해제한다. 선행 당김·지형 피해·처치 보상은 원래 사건 순서로 처리한다. 이를 공격 피해 Gate에 가두면 교착이 생길 수 있다. 조기 실행 합류 예외는 해당 공격 자신에게만 적용하고 다른 실행의 잠금은 유지한다.

특성 행동과 공격 클립이 같은 공격자 Pose/Clip을 빌리면 기존 행동을 우선한다. 자원이 반환되면 한 번 시작하고 설정 시각보다 늦어진 사실을 진단으로 남긴다. 사망·제거·취소·세대 변경 시 예약·준비 신호와 대여를 정리한다.

피해 없는 아군 당김은 현재 IsMovementOnly의 클립 생략 분기와 합류를 조정하되 피해·피격을 만들어 내지 않는다. 공격 후 추가 공격·가로채기 등은 새 시작 기준으로 삼지 않으며 기존 계약의 회귀 확인만 한다.

### 5.1 P3·P4 구현 경계

- `CombatPreAttackPlayback`: 첫 시작 예약·지연·합류·예약 폐기. 기존 Presenter의 Tick에서만 진행한다.
- `CombatDeferredAttackSource`: 조기 실행의 출처 수명을 보관하고 원래 공격 사건 합류 때 실제 Gate에 연결한다. 피해 대상 판정이나 재생 시계를 복제하지 않는다.
- `CombatPieceRunPlayer`: 조기 실행을 기존 실행 목록에서 진행/회수하고 합류 때만 행동 슬롯에 올린다. 선행 당김·지형 처리를 조기 행동 슬롯으로 막지 않는다.
- 기존 Release/Volley 조각: 타격 준비와 합류 허용을 모두 기다린 뒤 Release → Hit. Hit 큐와 수호자 복귀는 이 신호를 따른다. 원거리 발사와 물리 Contact는 기존 클립·투사체 시간이며 피해 해제와 다른 시점이다.

수호자 반응이 있거나 선행 구간에 다른 행동/출처·공격자 자신의 사실·공격자 채널을 사용할 특성 행동이 있으면 원래 공격 사건까지 시작을 미루는 보수적인 대여 정책을 사용한다. 뒤에 올 특성 행동을 조기 Pose/Clip 대여 때문에 생략시키지 않기 위해서다. 실제 사용 중인 채널도 기다리며 지연 진단은 예약당 한 번이다. 이 경우 d는 최단 대기 시간이고 클립 시작이 더 늦을 수 있다. 수호자 나가기 시간도 유지한다.

적용 출처는 일반 `CombatAttackEvent`다. 포효 요약 대응은 관계 검증만 하며 포효의 전용 코드 모션과 추가 공격 경로는 기존대로 둔다. 기본 모드/일치하는 실제 시작 없음은 기존 순차 경로, 소속 오류는 예외다. 사망/제거 직전·대여 상실·전투 취소 시 해당 예약 실행을 폐기하고 대여를 반환한다. 예약이 남아 있으면 최종 사실 갱신과 다음 결과를 기다린다.

## 6. 시각적 한계

시작 지연은 0 이상이므로 특성 연출보다 먼저 공격 클립을 시작하지 못한다. 당김이 즉시 시작되고 올가미 접촉 프레임이 늦다면 시작 동기화만으로 접촉 전체가 맞지 않을 수 있다. 이때 클립 조정 또는 별도 선행 정책을 논의하며 당김을 임의로 늦추지 않는다. 기존 ClipEvent·HitDelay·공유 소리 큐를 이 설정 때문에 자동 변경하지 않는다.

공통 영향은 공격 Gate·대여·취소다. 관련 일반 공격/추가 공격 회귀 확인은 필요하다. 적용 기준은 [설계 인계 §4.6](../handoffs/2026-09-30-combat-view-design-session-handoff.md)을 따른다.

## 8. 상태

범위를 좁힌 정적 조사는 완료했다. **현재 범위는 Core 확장 없이 View 설계가 가능하다.** 작업자 입력은 CombatUnitAnimationSO의 시작 모드·기준 Kind·지연으로 확정했다. 이전 광범위 요청은 철회했고 새 외부 요청은 없다.

2026-11-10 사용자 지시로 P1·P2를 반영했다. 지원 목록은 `CombatPreAttackTraitKinds`, 소속 대응은 `CombatPreAttackTraitMap`, 실행 소속 키/위치는 `CombatPreAttackSourceKey`·`CombatPreAttackTraitBinding`이 담당한다. SO 입력은 `CombatAttackAnimationStartData`로 전달하고 `CombatPreAttackPresentationStarts`가 실제 큐·텍스트·유닛 행동·Pull 이동의 시작을 선택 Kind에 연결한다. 기본 모드만 있는 결과에는 새 색인 검사를 추가하지 않는다.

이어서 사용자 승인으로 P3·P4를 함께 연결했다. 지정 모드에서는 첫 실제 시작 + 지연으로 조기 클립을 열고 원래 공격 사건이 같은 실행에 합류한다. 타격 준비가 빨라도 피해/Hit는 합류 뒤다. 기존 에셋 값은 이번 구현에서 변경하지 않아 기본 모드는 유지된다. 세부 변경·확인 항목은 [계획 P3·P4 실행 기록](../plans/2026-11-10-pull-attack-animation-sync-plan.md#p3p4-실행-기록-2026-11-10)에 남겼다.

후속 사용자 요청으로 Unity를 직접 확인했다. 커스텀 인스펙터의 닫는 중괄호 누락(CS1513)을 수정하고 Unity 컴파일 오류 0건을 확인했다. 임시 PullApplied/0초 아군 당김에서 공격 모션·HP 유지·입력 복귀, PullApplied/3초 적 당김에서 선행 이동 후 피해 반영(선택 시 HP 22/30)·입력 복귀를 관찰했다. 종료 후 Console 오류·경고는 0건이었다. 프레임 단위 시각 계측이나 전체 회귀 통과를 의미하지 않는다. 임시 Cowboy 에셋은 원본 바이트로 복구했다. P5 운영 값 확정과 AttackGranted·중복 통지·충돌·취소/사망 등 잔여 확인은 계획의 Unity 직접 확인 기록을 따른다. MSBuild·Test Runner는 실행하지 않았다.
