# 공격 범위의 캐릭터 쪽 Outline 열기

> 2026-11-02 후속 결정: 캐논의 조준 지점 피해·폭발 영역(`Affected`)은 원점 쪽 생략 없이 닫힌 경계로 그린다. 같은 색으로 합쳐진 호버와 채움 가장자리도 같다. 전체 공격 선택 범위·이동/호버 범위의 기존 정책은 유지한다. 판별·전달 기준은 [독립 공격 영역 설계 §2](2026-11-02-field-outline-style-and-independent-impact-design.md#2-캐논의-독립-피해폭발-영역), 구현 상태는 같은 작업의 [OS2 계획](../plans/2026-11-02-field-outline-style-and-independent-impact-plan.md)이다.

- 날짜: 2026-11-01
- 사용자 결정: 캐릭터 앞에 사각형으로 보이는 범위에서 캐릭터 쪽 변 전체를 숨겨 나머지 세 변만 그린다.
- 계획: [AO1](../plans/2026-11-01-attack-outline-opening-plan.md).

## 동작과 범위

1. 현재 선택한 공격자의 공격 범위·끌어오기 확장 범위·공격 영향 범위의 Outline에 적용한다. 범위 칸 자체와 채움/그라데이션은 바꾸지 않는다. 독립된 호버 칸 표시, 이동 범위, 배치 구역, 레일, 다른 유닛을 호버한 범위에는 적용하지 않는다. 같은 색 채움에 합쳐져 그 범위 전체를 다시 그리는 호버는 원래 층의 열린 변을 함께 따른다(검토 보완: 숨긴 변을 다시 덮어 그리지 않게 함).
2. 선택한 공격자의 점유 칸은 기존 ActiveActor 강조 상태에서 읽는다. 범위와 공격자 점유 칸의 경계 상자를 비교해 공격자가 완전히 바깥에 있는 축 중 더 멀리 떨어진 축을 고른다(월드 거리, 동률은 X). 해당 방향의 범위 맨 바깥 격자 변을 연다. 공격자를 둘러싼 범위와 공격자 표시가 없는 경우에는 한쪽을 임의로 고르지 않고 기존 고리를 유지한다.
3. Merged의 사각형은 캐릭터 쪽 한 변과 그 변에 연결되는 둥근 모서리를 생략한다. 계단/분리 모양은 선택한 경계선에 닿는 부분만 생략하며 다른 외곽·구멍을 새로 열지 않는다. EachCell도 전체 범위의 해당 바깥 변에 닿는 칸만 열며 내부 칸 사이 선은 유지한다.
4. 숨길 변의 방향과 격자 경계선 번호를 나타내는 선택 DTO를 AreaOutlineData → GridOutlineCreateData로 전달한다. 기본값은 숨기는 변 없음이다. 메시의 닫힌 고리와 UV 계산을 유지하고 해당 띠의 삼각형만 생략한다. 열린 양 끝을 이어 닫는 선을 만들지 않는다.
5. 범위 전체에서 방향/경계선을 한 번 구한 뒤 깊이·지형 높이별로 나눈 핸들에 같은 값을 전달한다. 높이별 부분 범위의 중간 경계를 실수로 새로 열지 않는다. 둥근 모서리는 해당 경계선에서 모서리 반지름 이내이면서 그 방향을 향하는 조각만 생략한다.
6. 캐릭터가 움직여 같은 범위의 숨길 변만 바뀌어도 다시 그린다. 성공한 갱신 뒤에만 칸/색/숨긴 변을 기억한다. 기존 핸들 대여·반환 수명은 유지한다.

## 구조 점검

- SSOT: 공격자 위치는 기존 Buffer에서 파생된 ActiveActor 칸, 범위는 기존 응답 칸이다. 위치나 규칙을 새로 저장하지 않는다. 열린 변은 표시 파생값이며 DTO 기본값은 닫힌 고리다.
- SOLID: 캐릭터 쪽 결정은 FieldAttackOutlineOpening, 일반 격자 선의 생략은 Render 메시 부품이 맡는다(SRP). 기존 호출자는 기본값으로 유지한다(OCP/LSP). DTO에 필요한 방향·경계선만 추가한다(ISP). 입력/Factory에 메시 구현을 노출하지 않고 기존 AreaOutline 계약을 쓴다(DIP).
- JMH/FW: 서비스 등록·Export·Builder·입력·이벤트는 바꾸지 않는다. 기존 구체 렌더 DTO와 핸들 수명(FW-010~012)을 유지한다. RenderSystem/Core는 렌더 메시 영역이며 CoreSystem 전투 계산 영역은 수정하지 않는다.
- 기능 독립성: 선택 원점/숨길 변 판단을 거대한 FieldOutlineRenderer에 구현하지 않고 작은 표시 부품에 둔다. Renderer는 기존 전달 지점과 캐시 비교만 바꾼다. 미래 판단 변경은 이 부품과 관련 시험에 한정되며, 남는 공유 경계는 AreaOutline DTO/격자 메시 생성과 기본값 회귀다. 공용 셰이더·FieldCamera·Architecture·씬·SO는 수정하지 않는다.

## 검증

- 네 방향·한 칸/직사각형·가로세로 간격이 다른 칸·축소/둥근 모서리·EachCell·분리된 높이 핸들을 대조한다.
- 소스가 없거나 범위 안이면 기본 고리 유지, 소스만 이동하면 열린 변 재계산, 기본 DTO/다른 표시의 인덱스 유지, 구멍·내부선 보존을 검사한다.
- 관리 빌드와 관련 EditMode 시험, 가능한 Unity 새로고침을 구분해 기록한다. 실제 전투 화면 인수와 자동 검증 결과를 혼동하지 않는다.

## AO2 — 채움 가장자리도 같은 방향으로 열기

- 사용자 추가 결정: 기존 Outline 선과 채움 가장자리의 진한 띠를 둘 다 캐릭터 쪽에서 없앤다. AO1에서 채움을 유지한 범위를 이 결정으로 확장한다.
- 방향/격자 경계선은 AO1의 FieldAttackOutlineOpening 하나를 Outline과 채움이 함께 사용한다. 채움 종류·깊이별 기존 재질 사본에 그 값을 전달하고, 캐릭터만 움직여 열린 변이 바뀌면 메시 재생성 없이 재질 값만 갱신한다.
- 채움의 모양/겹침 구멍 마스크는 유지한다. 투명도 전이의 거리 계산에 한해 열린 바깥쪽 이웃이 이어진 것처럼 처리한다. 해당 변을 거리의 원인에서 빼되 나머지 세 변과 둥근 모양 마스크는 유지한다. 외부 이웃 텍스처를 읽거나 실제 칸을 추가하지 않는다.
- 셰이더의 숨겨진 _OpenEdge 기본값은 0(닫힘)이다. 값 이름·재질 필수 속성·값 전달은 기존 소유자 FieldCellFillStack에 둔다. 원본 SO/재질 값·RGB·팔레트 전체 알파·Core·입력·Factory·핸들 수명은 바꾸지 않는다.
- SSOT/SOLID/JMH·FW/독립성: 열린 변 정책을 복제하지 않고 기존 표시 판단과 렌더 경계를 재사용한다. 채움 기능의 변경은 채움 셰이더·재질 전달에 한정하며 Outline 메시를 재구현하지 않는다. 기존 AO1 회귀와 실제 셰이더를 RenderTexture로 그린 GPU 픽셀 대조를 함께 확인한다.

## AO3 — 중앙 캐릭터 인접 변과 넓은 전이 폭 회귀 수정

- 사용자 화면: 범위 중앙의 캐릭터에 붙은 테두리가 남고 칸마다 작은 채움 사각형이 보인다. 운영 재질은 사용자가 전이 폭 0.4·중앙 비율 0으로 조절한 상태이며 이 설정을 보존한다.
- AO1의 바깥 한 변만 여는 조건은 중앙 캐릭터/호버 범위를 처리하지 못했다. 기존 바깥 변 생략에 더해 범위 원점 유닛이 점유한 칸의 경계 상자에 닿는 Outline/채움 띠를 제거한다. 중앙 캐릭터의 선택·호버 테두리가 같은 경계를 다시 그리지 않게 한다. 범위 바깥 테두리와 다른 구멍은 보존한다.
- 선택한 캐릭터의 원점은 기존 ActiveActor 상태, 호버 범위 원점은 호버 요청의 EntityId로 완료 표시 스냅숏에서 읽은 점유 칸이다. Field는 호버 범위 수명과 함께 표시 원점 칸을 보관·해제한다. 다른 캐릭터를 호버했을 때 현재 선택 캐릭터를 잘못 원점으로 쓰지 않는다. Core 규칙/Buffer를 수정하지 않는다.
- 채움 모양을 깎는 합집합 SDF는 유지한다. 전이 거리는 합집합 구성 상자의 min을 쓰지 않고 실제 노출된 변·볼록 원호·오목 꺾임까지의 거리로 계산한다. 모든 이웃이 이어진 내부에는 경계가 없으므로 중앙 진하기로 유지된다. 기존 국소 SDF가 폭 0.45까지 이음매 없이 쓸 수 있다는 AO1 이전 가정은 철회한다.
- 두 수정은 기존 원점/열린 변 판단 부품과 렌더 DTO/재질에 한정한다. SSOT는 기존 캐릭터 사실과 표시 상태, 기능 책임은 원점 전달/판단/메시/셰이더로 구분한다(SOLID). 새 서비스·Factory·입력 명령·등록·자원 수명 변경은 없다(JMH/FW). 공용 경계 확장 때문에 선택 원점과 호버 원점이 다른 경우, 중앙 구멍, 넓은 폭의 GPU 회귀를 함께 검증한다.
