# 적 행동 간격과 이동 방향 연출 설계

- 작성: View 작업, 2026-10-13
- 상태: 2026-10-13 사용자 설계 승인·M1/M2 진행 지시. Phase별 구현·검증 상태는 Task 계획을 따른다.
- Task·실행 기록: [적 연출 Task 계획](../plans/2026-10-13-enemy-presentation-plan.md)

## 1. 요청과 현재 동작

사용자 요청은 적 행동·턴 사이의 딜레이, 이동 방향으로 몸을 돌린 뒤 이동, 마지막 이동 목적지에서 플레이어 측으로 돌아보기다.

2026-10-13 후속 사용자 요청 “아군 유닛도 이동 시 회전 들어가야함”으로 E4~E6의 회전 대상은 아군·적의 자발적 이동 모두로 확장한다. 행동·턴 딜레이는 적 전용을 유지한다. 아군은 도착 후 기존 배치 방향(`ModelRotation(Owner.Player, facts.Rotation, mapper)`)으로 복귀한다. 과거 M2 기록의 아군 회전 제외는 이 요청으로 대체한다.

사용자 확정 기본값은 행동 간 0.2초, 턴 전환 0.4초, 회전 0.1초다. 기존 `CombatSceneRoot.movementStepSeconds`와 별도 설정으로 둔다. 사용자가 현재 Combat 씬의 한 칸 이동 시간을 0.12초에서 **0.2초**로 바꾼 작업은 보존한다.

현재 `OrderedCombatPresentation`은 결과의 불변 사건을 순서대로 재생하며 이동 완료와 비이동 사건의 완료 콜백을 기다린다. `CombatSceneEventPresenter`는 이동 위치만 보간한다. `FieldUnitPresenter.RenderFacts`는 표시할 때마다 `ModelRotation`을 적용하므로 적은 항상 플레이어 측을 본다. 각 칸 도착 때의 `RenderEvents`도 이 방향을 다시 적용한다. 비이동 사건은 현재 즉시 완료한다.

## 2. 제안 동작 기준

### E1. 시간 설정

Combat 씬의 `CombatSceneRoot` Inspector에 다음 세 값을 둔다. 원본은 씬 설정 하나이며 Presenter 생성 때 값만 전달한다.

| 필드 | 기본값 | 의미 |
|---|---:|---|
| `enemyActionGapSeconds` | 0.2 | 같은 적의 이전 행동과 다음 행동 사이 간격 |
| `enemyTurnGapSeconds` | 0.4 | 적이 포함된 턴 전환의 간격 |
| `movementTurnSeconds` | 0.1 | 아군·적 공통 이동 전 방향 전환과 마지막 도착 후 방향 복귀 시간(옛 `enemyTurnSeconds` 직렬화 값 인수) |

0이면 해당 연출 시간을 생략한다. 음수·NaN·무한대는 연결 시 거절한다. 프레임 시간은 기존 View Tick을 사용하며 Coroutine·Task·별도 Update·실시간 타이머를 만들지 않는다.

### E2. 행동 경계

- 경로 전체를 이동 행동 하나로 본다. 칸마다 행동 딜레이를 넣지 않는다.
- 이동 후 공격, 같은 적의 공격 후 다음 공격 등 **다음 행동 시작 전** 0.2초 기다린다. 첫 행동 앞에는 행동 딜레이를 추가하지 않는다.
- 공격 사건의 시작을 지연하되 공격의 피해·특성·사망 등 후속 사건마다 별도 딜레이를 넣지 않는다. 기존 사건 순서를 보존한다.
- 적 여부는 이미 표시 중인 사건 사실의 `Owner`로 판정한다. 이동은 `Expected.Owner`, 공격은 공격자 ID에 대응하는 표시 사실을 사용한다. 최신 Buffer나 InGame DB를 조회하지 않는다.
- 이동 도착에서 방향 복귀가 끝난 뒤 다음 행동 간격을 시작한다. 사망·필드 이탈한 대상에는 복귀 회전을 시도하지 않는다.
- 거절 결과, 환경 메타데이터, 강제 이동·체크포인트 복귀는 새로운 적 AI 행동으로 세지 않는다.

### E3. 턴 경계

- 적→적, 적→플레이어, 플레이어→적 전환에는 0.4초를 한 번 적용한다. 플레이어→플레이어는 적용하지 않는다.
- 적 `TurnEnded` 뒤 간격을 먼저 적용하고, 이어지는 `TurnStarted`에서 같은 전환의 간격을 중복 적용하지 않는다. 플레이어 턴 종료 뒤 적 `TurnStarted`로 들어갈 때는 적 시작 앞에서 적용한다.
- 처음 전투에서 적 턴이 시작할 때도 시작 앞에 0.4초를 적용한다.
- 턴 종료/시작이 다른 `CombatResult`에 나뉘어도 중복 적용 여부를 씬 연결 수명 동안 유지한다. 행동 이력은 턴 전환에서 비운다.
- `NightEnded`는 같은 전환의 딜레이를 다시 넣지 않는다. 정상 전투 종료의 기존 마지막 결과 소비를 유지한다.
- 턴 간격과 행동 간격을 같은 경계에 합산하지 않는다. 턴 경계에서는 0.4초만 적용한다.

### E4. 이동 회전

1. 자발적으로 이동하는 아군·적의 이동 시작 칸에 위치를 유지한다.
2. Expected/Final 칸 중심의 **월드 위치 차이**로 진행 방향을 구하고 0.1초 동안 회전한다.
3. 회전 완료 후 기존 한 칸 이동 시간을 사용해 위치를 보간한다.
4. 다음 칸에서도 같은 방향이면 회전을 생략한다. 경로가 꺾이면 위치를 유지한 채 새 방향으로 회전한 뒤 이동한다.
5. 마지막 이동 칸 도착 후 0.1초 동안 해당 Owner의 기존 `ModelRotation` 방향으로 복귀한다. 완료 뒤 다음 행동으로 진행한다.

회전은 기존 프리팹 전방(+Z)과 필드 기준을 따른다. 필드가 회전돼 있어도 월드 진행 방향과 기존 정면 계산이 같은 Mapper를 사용한다. 회전 없는 동일 위치 사건은 0벡터로 LookRotation하지 않는다.

임시 회전값은 FieldUnitPresenter의 개체 ID별 표시 override로 유지한다. `RenderFacts`가 중간 환경/체력 사건을 다시 그려도 정면으로 되돌아가지 않아야 한다. 이 값은 **표현에서만 유효한 파생값**이며 Core의 `Rotation`과 Buffer 사실을 수정하지 않는다. 일반 표시 때의 정면 계산은 기존 `ModelRotation` 한 곳을 재사용한다.

HUD는 기존 카메라 방향 보정과 월드 위치를 유지한다. 체력 숫자가 회전 직후 뒤집히지 않도록 회전 표시 경로에서도 기존 숫자 방향 보정을 적용한다. 풀 반환·새 ID 바인딩에서는 임시 회전이 남지 않아야 한다.

### E5. 최종 칸과 완료 계약

Core 사건 순서를 유지한 채 현재 이동 행동에서 같은 행위자의 마지막 `Moved`를 식별한다. 중간 환경/체력 사건이 있어도 경로를 매 칸 종료하지 않는다. 다음 공격·턴 경계는 새 행동의 경계다. 강제 이동이나 다른 개체의 이동을 같은 경로로 합치지 않는다.

`OrderedCombatPresentation`은 마지막 걸음 후 씬 표시의 **이동 종료 연출 완료**를 기다린다. 좁은 이동 시퀀스 표시 계약으로 최종 칸 복귀 요청/완료를 전달하고, 씬 어댑터가 실제 회전을 맡는다. 이동 한 걸음 완료와 경로 종료 회전 완료를 혼동하지 않는다. 기존 첫 이동 소리 1회 계약을 유지한다.

결과의 완료 콜백은 회전·행동 대기·턴 대기가 모두 끝난 뒤 기존 경로로 한 번만 호출한다. 기존 `CombatResultPlayback`과 Flow의 결과 확인 경계가 다음 계산을 막도록 하며 새 차단 상태를 Buffer·Job·LifeCycle에 추가하지 않는다.

### E6. 취소와 실패

- Cancel/Detach/오류 정지는 대기 중 완료 콜백, 진행 중 회전, 위치 보간, 행동/턴 이력을 함께 비운다.
- 남아 있는 살아 있는 표시의 임시 방향 override를 제거하고 기존 정면으로 복구한다. 이미 반환/파괴된 View를 다시 만들거나 빌리지 않는다.
- 취소 중 완료 통지를 호출하지 않는다. 취소 뒤 늦은 통지는 기존 세대 검사로 무시한다.
- 정상 전투 종료는 Cancel로 마지막 결과를 건너뛰지 않는다.
- 새로운 연결·재전투에서 이전 턴 대기/적 ID/회전이 이어지지 않아야 한다.

## 3. 책임과 변경 범위

| 담당 | 변경 |
|---|---|
| `CombatSceneRoot` | 직렬화 시간 세 값·읽기 프로퍼티·유효값 검사 |
| `CombatSceneDisplay` | 설정 주입·좁은 이동 시퀀스 계약 전달 |
| `OrderedCombatPresentation` | 이동 행동 마지막 걸음 판정·경로 종료 표시 완료 대기 |
| `CombatEnemyPresentationPacing`(신규 순수 C#) | 행동/턴 경계와 중복 딜레이 방지 이력 |
| `CombatSceneEventPresenter` | 기존 Tick에서 대기·회전/이동 단계 진행, 완료/취소 수명 |
| `FieldUnitPresenter`·필요 시 `FieldUnitView` | ID별 임시 방향 적용/복구, 현재 표시 회전 조회·보간, HUD 방향 유지 |
| 이동 시퀀스 표시 계약 | 경로 종료 요청/완료. 구체 씬 표시를 Ordered에서 직접 참조하지 않음 |
| `Assets/Scenes/Combat.unity` | 기존 0.2초 이동값을 보존하면서 새 세 설정만 추가 |
| `Assets/Tests/EditMode/Framework/` | 시간 경계·완료 순서·실제 회전·취소 회귀 |

Core·Buffer·전투 진행 Job/Plan·FieldCamera·Architecture·Render 내부와 유닛 DB는 변경하지 않는다. 새 C#에는 `.meta`를 함께 만든다.

## 4. SSOT·SOLID·JMH/FW 점검

- **SSOT:** 기획 규칙·위치·Core 회전은 기존 Core/Buffer 사실, 일반 유닛 방향은 `FieldUnitPresenter.ModelRotation`, 연출 시간 입력은 SceneRoot, 행동/턴 간격 이력은 Pacing 한 곳, 표시 회전 override는 FieldUnitPresenter 한 곳이다. 최신 Buffer를 중간 연출에 재조회하지 않는다.
- **S:** Ordered는 순서/완료, Pacing은 표시 간격 경계, SceneEventPresenter는 실제 재생 수명, FieldUnitPresenter는 View 적용을 담당한다. ViewSystem·Job·LifeCycle에 연출 상태를 넣지 않는다.
- **O/L:** 이동 종료 표시를 기존 순차 연출의 완료 계약으로 확장한다. 0초·취소·동기 완료에서도 한 번 완료, 취소는 미완료라는 기존 보장을 유지한다.
- **I/D:** Ordered는 좁은 표시 계약을 통해 종료 회전을 요청한다. Core 서비스나 MonoBehaviour 구현을 받아 분기하지 않는다. 새 범용 연출 서비스/이벤트 버스는 만들지 않는다.
- **JMH:** Framework 개발 지침의 역할 분리, 런타임 상태와 DB 분리, Build 후 구조 불변, 대여 자원 수명, 과도한 추상화 금지 기준을 적용한다. 새 서비스/모듈/Builder/전역 구독은 없다.
- **FW-004/011/014:** 기존 상태 경계를 우회하지 않고, 회전 때문에 새 View를 빌리지 않는다. 표시 재사용·풀 반환에서 임시 연출을 정리한다.
- 기존 입력 바인딩과 결과 확인/정상 이탈 계약을 바꾸지 않는다.

## 5. 리뷰 지점

§2의 첫 적 턴 대기, 행동 경계(경로 전체 1회), 적이 포함된 양방향 턴 전환, 도착 후 복귀 회전까지 완료를 기다리는 동작을 구현 전에 확인한다. 이 문서는 새 기능 설계안이며 기존 회전/이동 기능을 완료 상태로 되돌리지 않는다.
