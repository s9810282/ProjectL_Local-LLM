## 2 화면

단계와 칸은 Core 값을 그대로 쓴다. 다음 위치는 Core도 이동 순간에 정하므로 경고 때 보여 줄 수 없다(U13).

| 시점 | 화면 |
|---|---|
| 전투 진입·재연결 | 현재 범위에 구름 하나를 둔다. 경고 프리팹이 있고 단계가 `RelocationWarning`이면 경고도 켠다 |
| Warning 사건 | 구름은 그대로 둔다. 경고 프리팹이 있으면 켠다 |
| Relocation 사건 | 구름을 새 범위로 옮기고 경고를 끈다. 칸마다 이펙트 1회 |
| 결과 끝 | Buffer 최종 상태로 다시 맞춘다 |

어느 사건도 다음 사건을 막지 않는다.

## 3 구조

### 3.1 사건 줄(HB1)

`CombatEventTypeTable`에 `CombatHaboobEvent` 줄을 더하고 새 처리기 칸 `Haboob`을 둔다(인계 §1.2 기능별 처리). 주체·근원이 없어 묶음 밖 장벽이 된다. 새 `Playback/Handlers/CombatHaboobEventHandler.cs`가 사건 값으로 표시를 맞춘다.

### 3.2 구름 외형(HB2)

구름은 범위 전체를 덮는 프리팹 하나다(Q-HB1, 토네이도와 같은 꼴). 자리는 `Cells`의 바깥 사각형 가운데이고, 높이는 덮는 칸 표면의 최댓값이다. 배율은 프리팹 배율 × (바깥 사각형 ÷ 기준 칸 수)다. 재질은 프리팹이 갖는다(인계 §8.2).

판정·호버는 Core `Cells`를 그대로 쓴다. 외형은 값으로 정해진 모양을 그리는 것이라 판정에 영향을 주지 않는다.

### 3.3 하붑 표시(HB3)

> 2026-11-02: 구름 인스턴스·경고 인스턴스·`PlayRelocation`은 §9.1과 계획 HP-17·HP-19가 대신한다. 수명 꼴(`Show`·`Render`·정리 목록)은 그대로다. 입구 인자는 칸 목록이다.

새 `Display/Map/FieldHaboobPresenter.cs`: 구름 인스턴스 하나, 경고 인스턴스 하나(선택).

- `Show(HaboobGimmickState state, mapper)`: 사건 시점에 칸·단계대로 맞춘다.
- `PlayRelocation(state, mapper)`: 칸마다 이펙트를 낸다. `CombatEffectWindow`를 쓴다.
- `Render(StageGimmickStateSet set, mapper)`: 결과 끝과 진입. 상태가 없으면 지운다.

표시 정리 목록(`Clear`, `Release`)에 더한다. 재연결 때는 `Render`만 한다. 전투가 바뀌면(`BattleInstanceId`) 이 경로로 비운다.

### 3.4 값(HB4)

> 2026-11-02: 지금 칸은 구름 이펙트·위치 보정·회전 보정·이동 소리 프리셋·이름·설명이다(§10). 아래 표의 프리팹·기준 칸 수·경고 프리팹·이동 이펙트는 만들지 않았다.

새 View 표 `HaboobVisual`(`ThornFieldVisual` 꼴, 설정 하나). 낙석과 표를 나눠 서로의 값을 건드리지 않게 한다.

| 칸 | 뜻 |
|---|---|
| 구름 프리팹 | 필수 |
| 기준 칸 수 | 프리팹이 덮는 바깥 사각형 한 변, 기본 4 |
| 경고 프리팹 | 선택, 비면 표시 없음 |
| 위치 보정 | 칸 표면 기준 |
| 이동 이펙트 | `EffectType`, Empty면 없음 |
| 이름·설명 | 호버 설명 |
| 이동 소리 프리셋 | 기본 -1 |

연결 줄(`ViewTableKey`·`ViewDataBase`·`ViewDataBaseFactory`·표시 Factory)은 민형님 공유 문서에 적는다.

### 3.5 안내·설명(HB5)

- `CombatActionNotice`: `HaboobDesignationBlocked` 안내를 더한다. Core가 막힌 칸을 범위에서 빼므로 칸을 누를 때 미리보기로 이유를 물어 안내한다(계획 Q-HP1 A). 문구 초안은 "공격자와 지정한 칸이 모두 먼지구름 안이거나 모두 밖이어야 합니다."이다. 투사체가 막힌다는 뜻으로 쓰지 않는다. 현강님 줄이라 변경을 공유한다.
- `CombatEnvironmentText`: 구름 칸 호버 설명을 더한다(인계 §1.2). 정적 모래폭풍 지형과 다른 기믹으로 설명한다(인계 §6.1).
- 이동 뒤 호버·범위·미리보기가 새 구름 기준으로 다시 그려져야 한다(인계 §6.3). 구현 때 지금 입력 흐름을 확인하고, 옛 응답이 남으면 다시 요청하게 고친다.

### 3.6 소리(HB6)

`CombatEventSounds`에 Relocation 갈래와 슬롯 칸(연결 대기 null)을 더한다. AudioSystem 요청은 사운드 작업자 안내에 적는다.

### 3.7 표시 규칙(HB7)

- 구름은 유닛과 칸 강조가 보이게 반투명으로 만든다. 충돌체를 두지 않아 포인터를 막지 않는다.
- 프리팹 레이어는 메인 카메라가 그리는 값으로 맞춘다(§10, `Smoke.prefab` = 0).
- 벽·낭떠러지 칸에도 놓는다. 칸 표면 높이를 따른다.
- 칸 프리팹 모드와 GridOutline 모드 모두 `FieldGridMapper`만 쓴다.

## 9 2026-11-02 사용자 결정

### 9.1 구름 = 칸마다 Smoke 이펙트(HB8)

사용자 "임시 구름 프리팹이 아니라 Smoke 이펙트를 하붑 칸마다 하나씩". 민형님 `Render/Effect/EventEffect/SmokeEffect/Smoke.prefab`을 쓴다.

- `Cells`의 칸마다 이펙트 하나를 켜 둔다. 칸이 곧 외형이라 맞춤 모양도 칸대로 보이고, §6의 맞춤 모양 차이와 §8의 프리팹 모양 사본이 없어진다. 기준 칸 수·배율·경고 프리팹·이동 이펙트 칸은 만들지 않는다.
- `Smoke`는 Looping이라 스스로 끝나지 않는다. 표시가 칸마다 손잡이를 쥐고 빠진 칸만 거둔다. 거두면 방출이 멎고 입자는 수명(5초)만큼 남는다.
- 그래서 규칙은 사건 순간에 바뀌고 연기는 천천히 따라온다. 인계 §6.2가 전환은 View 선택이라고 한 범위 안이다.
- 프리팹에는 등록이 없어 `EffectType`·이펙트 표 항목을 더한다. 프리팹 값(레이어 18·입자 크기·그림자)은 재생을 본 뒤 정한다.

세부 값은 [계획 §1.1](../plans/2026-11-01-combat-haboob-view-plan-Hojin.md).

### 9.2 턴 주기: Core 그대로

사용자가 처음 말한 "2턴 뒤 생기고 2턴 뒤 사라짐"은 기획서 6쪽·Core(시작부터 있음, 2 카운트마다 이동)와 달랐고, Core 주기를 확인한 뒤 "Core에 따라 만든다"로 정했다. 경고 사건은 칸이 그대로이고 지금은 화면 변화가 없다. 화면 쪽 남은 판단은 [계획 §2.1](../plans/2026-11-01-combat-haboob-view-plan-Hojin.md#21-화면에서-정할-것재생-뒤).

### 9.3 검토 범위(HB-c)

묶음 끝 검토는 내부 구현, 연결부, 화면에 보이는 것까지 본다(계획 Hc.5).

### 9.4 구름 이동: 화면에서만 미끄러짐(HB9)

사용자 "Core에서는 순간이동이지만 화면에서는 먼지 구름이 이동하는 것처럼" → "도착까지 대기". 인계 §6.2가 전환 모양을 View 선택으로 둔 범위 안이고, Core 변경은 없다.

- **판정:** Core 그대로다. 칸·거절·호버 설명은 사건 순간에 새 칸이다. 이동 중에 판정용 칸이나 접촉을 만들지 않으며, 구름이 유닛 위를 지나가도 아무 일도 없다.
- **모양(2026-11-02 사용자 재생 뒤 바뀜):** 칸마다 쥔 연기의 뿜는 곳만 새 칸으로 옮기고, 이미 나온 입자는 뒤에 남아 수명대로 사라진다. 옮겨 가는 동안 나온 입자가 길을 따라 떨어져 연기를 흘리는 모습이다. 처음의 "입자까지 한 덩어리로 옮기기"(Local)는 재생에서 부자연스러워 `Smoke.prefab` 시뮬레이션 공간을 World(`moveWithTransform: 1`)로 바꿨다. Core가 같은 모양을 평행 이동만 하므로(`HaboobGimmickRule.SelectCells`) 뿜는 곳들은 같은 거리를 움직인다.
- **시간:** 거리와 상관없이 정해진 시간(기본 1초)이고, 경로는 직선이며 천천히 출발해 천천히 멈춘다.
- **기다림:** 이 사건은 구름이 도착해야 끝난다. 뒤 사건(낙석)과 입력은 그 뒤에 온다. 입력이 열릴 때 화면의 구름과 판정 칸이 같다. 이동이 있는 턴 끝마다 약 1초가 는다.
- **칸이 그대로인 이동, 경고:** 움직이지 않고 바로 끝난다.
- **재시작·재연결·재생 취소:** 이동 없이 지금 칸에 바로 맞춘다.

남는 점: 입력이 열린 뒤에도 옛 자리와 길에 연기가 최대 5초 남고, 새 칸은 도착 뒤 서서히 짙어진다. 판정은 이미 새 칸이다(§9.1 셋째 줄과 같음). 세부는 [계획 §1.2](../plans/2026-11-01-combat-haboob-view-plan-Hojin.md#12-2026-11-02-구름-이동hb-d).

## 10 구현 메모(2026-11-02)

- 구름: `FieldHaboobPresenter`가 칸 → 이펙트 손잡이 표를 가진다. 그대로인 칸은 두고, 빠진 칸은 거두고, 새 칸과 밖에서 멈춘 칸은 다시 낸다. 값은 표 `HaboobVisual`이다.
- 사건: 경고와 칸이 그대로인 이동은 `CombatHaboobEventHandler`가 `Final.Cells`로 맞추고 기다리지 않는다. 칸이 바뀌는 이동은 표시가 손잡이를 새 칸 이름으로 바꾸고 조각 `CombatHaboobMovePiece`가 연기를 옮기며, 도착하면 사건이 끝난다(§9.4, 계획 §7.6). 소리는 출발 순간에 한 번이다.
- **레이어:** `Smoke.prefab`은 레이어 18(`Blending`)이었고 메인 카메라 Culling Mask(0·20·21·30·31)에 없어 화면에 나오지 않았다. 재생 중 Default로 바꾸면 보이는 것을 사용자가 확인했고, 사용자가 프리팹을 0으로 저장했다. 18을 카메라에 더하는 길은 첫 낮·밤 전환이 마스크를 고정 레이어 + 전환 레이어로 덮어써(`ScreenTransitionOutput`) 민형님 영역까지 고쳐야 해서 쓰지 않았다. 그 결과 이 연기는 `EffectOcclusionOutlineFeature`의 이펙트 레이어에서 빠진다.
- 화면 값: 재생 뒤 사용자가 괜찮다고 해 나머지(입자 크기·Prewarm·칸 테두리·경고 표시)는 시작 값 그대로다.
- 거절 안내: 칸 조준에서 목록에 없는 칸을 누르면 그 칸의 공격 미리보기를 한 번 묻고, 답이 `HaboobDesignationBlocked`면 하붑 안내를 낸다. 다른 이유는 지금까지처럼 일반 문구다. 답 전에 호버 요청이 슬롯을 덮으면 일반 안내를 낸다. 조준 목록이 비었을 때도 칸으로 묻는다. 이 안내만 2초 보인다.
- 호버: `CombatEnvironmentText`가 `Cells`에 든 칸마다 표의 이름·설명을 보인다. 2026-11-02 사용자 요청으로 같은 칸에서 하붑 그룹의 현재 `Cells` 전체를 강조한다. 범위·겹침·수명 정책과 구현 원본은 [기믹 호버 범위 설계](2026-11-02-combat-gimmick-hover-range-design.md), 실행은 해당 계획 GH-a다(컴파일 미확인).
- 이동 뒤 다시 그리기: 코드 변경 없음(계획 HP-12).
