# 기본·겹침 강조의 테두리 방식 분리와 독립 공격 영역 (2026-11-02)

- 사용자 요청: StageFieldView에서 기본 강조와 겹친 강조의 Merged/EachCell을 따로 고른다. 캐논은 조준 지점의 피해·폭발 영역만 네 변을 모두 그린다.
- 사용자 확인: 표시 종류별 설정이 아니라 **깊이 0 / 깊이 1 이상**의 두 설정이다. 캐논의 전체 공격 선택 범위까지 닫는 변경은 아니다.
- Task·진행 기록: [구현 계획](../plans/2026-11-02-field-outline-style-and-independent-impact-plan.md).
- 기존 동작 근거: 현재 FieldCellShape·FieldCellFillStack·FieldOutlineRenderer와 [열린 경계 설계](2026-11-01-attack-outline-opening-design.md). 이전 문서의 빌드·시험 수행 기록은 이번 작업의 검증 방식으로 사용하지 않는다.

## 1. 기본·겹침 방식

| 값 | 적용 대상 | 기본값 |
|---|---|---|
| 기존 `cellOutlineStyle` | 깊이 0의 테두리·채움, 레일·배치 구역, 겹치지 않은 호버 | Merged |
| 새 `overlapCellOutlineStyle` | 깊이 1 이상의 테두리·채움, 해당 깊이에 놓인 호버 | Merged |

- 깊이는 FieldCellFillStack 한 곳에서 정한다. 아래 §1.1의 후속 사용자 결정에 따라 종류별 깊이를 통일하고, 테두리·채움은 그 결과로 방식을 고른다. 채움이 없는 표시 설정에서는 기존처럼 깊이 0이다.
- 네 조합(Merged/Merged, Merged/EachCell, EachCell/Merged, EachCell/EachCell)을 지원한다. 현재 운영 에셋은 Merged이며 새 값도 Merged로 명시해 기존 화면을 유지한다. 설정은 다음 Combat 구성 때 읽는다.
- `cellOutlineScale`·`overlapInsetScale`·두 모서리 반지름은 추가 분리하지 않는다. 기존 크기 식(기본 방식이 EachCell이면 cellOutlineScale, 아니면 1을 시작 크기로 하여 깊이마다 overlapInsetScale을 곱함)을 유지한다. 새 값은 **칸의 연결 방식**만 가른다.
- 모양 원본은 FieldCellShape 한 곳이다. 테두리·채움·호버 덩어리 수집은 깊이에 맞는 방식을 조회한다. 높이로 나눈 테두리도 원래 깊이를 유지한다.
- 아래 채움의 구멍은 **다음 깊이의 방식**으로 깎는다. 셰이더의 현재 판 연결 값과 구멍 연결 값을 나눠 혼합 조합에서도 위 판과 빈 자리가 일치하게 한다. 새 구멍 연결 속성의 미지정 기본값은 현재 판 방식을 따라 기존 직접 재질 사용을 보존하며, 운영 표시기는 두 값을 명시한다.
- 겹친 Merged 덩어리가 아래의 다른 종류/개별 칸 사이를 잇는 경우는 기존 모양 합성 규칙을 따른다. 새로운 받침 클리핑·크기 자동 조정은 넣지 않는다. 기존 깊이 2 이상 덩어리 중첩 경고는 겹침 방식으로 판단한다.

### 1.1 후속 결정 — 모든 채움 강조의 깊이 통일 (OS1b)

- 사용자: "나머지도 똑같이 해야지". 호버 공격 범위에 한정했던 전체 크기 통일을 모든 채우는 강조에 적용한다. 같은 종류의 일부 칸이 아래 강조와 겹치면 그 종류의 **전체 칸**을 같은 깊이에 놓는다. 따라서 겹치지 않은 나머지 칸도 크기·모서리·Overlap Cell Outline Style이 같다.
- 현재 표시하는 칸과 기존 그리기 순서에서 아래 종류 → 위 종류의 겹침 관계를 만든다. 아래부터 한 번 깊이를 정해, 위 종류의 깊이는 겹치는 아래 종류의 최대 깊이 + 1이다. 다른 칸에서 아래 종류가 올라가도 위 종류가 그 아래로 내려가지 않는다. 서로 겹치지 않는 종류끼리는 깊이를 올리지 않는다.
- 기존 호버 공격 범위의 명시적 받침 관계는 유지한다. 받침이 보이면 직접 겹치는 칸이 없어도 그 위 깊이에 둔다. 배치 구역은 그리는 동안 다른 채움과 같은 계산에 참여한다. 평소에만 보이는 채움/행동 중 채움의 필터는 기존 표를 따른다.
- 호버는 한 칸이다. 같은 색 아래 판에 합쳐지면 아래 종류의 통일된 깊이를 따르고, 별도 색이면 그 칸 맨 위 판 바로 위에 둔다. 호버로 아래 종류 전체를 새로 올리지 않는다.
- 종류별 깊이를 통일하면 한 칸에서 깊이 0과 2만 있는 식의 빈 깊이가 생길 수 있다. 아래 판의 구멍 지도는 고정된 다음 깊이가 아니라 **그 칸에 실제로 있는 바로 위 종류**를 담는다. 종류별 모양 배열(안쪽 거리·반지름)을 같은 깊이 결과에서 파생해 셰이더에 전달하고, 실제 위 판 모양만큼 비운다. 깊이가 비어도 아래/위 색이 섞이지 않는다.
- 종류·깊이 지도와 별도로 깊이별 구멍 지도를 유지하되 이는 표시 파생 캐시다. 구멍 지도는 RFloat에 위 종류(하위 8비트)와 **그 위 판 자체 지도**의 같은 높이 이웃(상위 8비트)을 담는다. 구멍 선택이 다른 옆 칸이나 받침 밖에서도 실제 위 판 모양과 일치하게 한다. 이미 필수인 RFloat 형식을 재사용한다. 기존 Build/Release 수명으로 만들고 돌려주며, 셰이더의 새 선택 값이 꺼진 기존 직접 재질 사용은 기존 고정 구멍 모양을 따른다.
- 대상은 기존 채움 목록이다. 채우지 않는 레일·행위자·경로선 등의 표시를 새 채움으로 바꾸지 않는다. Core 규칙/Buffer·입력·Factory·겹침 방식 입력 값은 추가 변경하지 않는다.
- SSOT/SOLID/JMH·FW/독립성: 깊이와 겹침 관계는 기존 FillStack의 표시 책임 안에서 한 번 계산한다. Outline은 결과만 소비하고, 셰이더는 전달받은 실제 위 판 모양만 사용한다. 새 서비스/조립 없이 기존 핸들 수명과 반환 경로를 유지한다. 캐논 닫힘 정책과 별도 Phase로 검토한다.

## 2. 캐논의 독립 피해·폭발 영역

- 캐논 공격 미리보기의 `Affected` 영역은 유닛 쪽 변 생략을 적용하지 않고 닫힌 테두리로 그린다. 채움 가장자리도 같은 닫힘 정책을 따른다.
- 기준은 기존 공격 미리보기가 공개한 실제 전투 병과 사실이다. 개별 유닛 키·프리팹 이름으로 분기하거나 InGame DB를 읽지 않는다. 캐논으로 전직한 메인 캐릭터도 포함한다.
- 닫힘 여부는 공격 영향 표시의 수명에 묶인 표현 정보 하나로 전달한다. FieldAttackOutlineOpening이 Outline과 채움에 같은 결정을 제공하며, 같은 색으로 합쳐진 호버도 이를 따른다. 영향 해제·교체·필드 Reset 때 함께 비운다.
- OS2 전달 확정: 공격 성공 응답을 표시하는 기존 호출자가 `ProjectedCategory.Key == CategoryKey.Cannon`을 한 번 판단해 `ShowAffectedCells`의 선택적인 `closeOutline` 값(기본 false)으로 전한다. SceneDisplay는 전달만 하고, 공격 피드백은 Field의 영향 표시 입구로 칸과 닫힘을 함께 넘긴다. FieldHighlightState의 `IsAffectedOutlineClosed`가 표시 수명의 유일한 보관 위치다. 일반 층 갱신/영향 지우기/Reset은 기본 열린 정책으로 되돌린다. 같은 칸에서 닫힘만 달라져도 다시 그릴 변경 목록을 만든다.
- 전체 공격 선택 범위·호버 공격 범위·이동 범위의 기존 열린 경계 정책은 유지한다. 일반 공격 영향 영역도 현재 동작을 유지한다. 다른 독립 공격이 필요하면 같은 표시 정책의 판별 지점을 확장한다.
- 이 항목은 별도 Phase다. Core·Buffer 계약과 공격 규칙 변경은 필요하지 않다.

## 3. 구조 점검

| 기준 | 적용 |
|---|---|
| SSOT | 두 입력 값은 StageFieldViewData, 깊이는 기존 FillStack, 모양·깊이별 방식은 FieldCellShape, 열린 경계는 FieldAttackOutlineOpening만 소유한다. |
| SOLID S | DB 검증·모양 계산·채움 재질 전달·메시 표시의 기존 책임을 유지한다. 캐논의 표시 정책을 셰이더나 일반 메시 생성기에 넣지 않는다. |
| SOLID O/L | 기존 enum·렌더 DTO·핸들 계약을 재사용한다. 기존 기본 조합과 미지정 셰이더 값의 동작을 유지한다. |
| SOLID I/D | 소비자는 깊이별 모양 조회와 기존 상태 읽기 계약만 사용한다. 새 서비스나 전체 Context 의존성을 추가하지 않는다. |
| JMH/FW | Factory·Builder·등록·Export·입력 바인딩은 변경하지 않는다. 구체 DTO 갱신(FW-010), 기존 핸들/재질 반환 수명(FW-011), DB 값 검증을 유지한다. |
| 변경 독립성 | 방식 변경은 DB·FieldCellShape·테두리/채움 소비자·필드 전용 셰이더에 한정한다. 캐논 변경은 영향 표시와 열린 경계에 한정해 별도 Phase로 검토한다. 조립·전투 계산·FieldCamera·Architecture는 수정하지 않는다. |

대표 시나리오: 겹침 방식을 바꾸기 위해 공격 입력·유닛 조회를 수정하지 않는다. 캐논의 닫힘 기준을 바꾸기 위해 깊이별 모양·메시 생성·조립을 수정하지 않는다. 남는 공통 경계는 Field 상태, Outline/채움의 같은 모양과 열린 경계 전달이다.

## 4. 검증과 제한

- View Test 코드를 작성하거나 시험을 실행하지 않는다. MSBuild도 실행하지 않는다. 정적 참조·diff·직렬화 기본값을 확인하고 **컴파일 미확인**으로 보고한다.
- 사용자가 Unity에서 네 방식 조합, 호버의 깊이 전환/같은 색 합침, 아래 채움 구멍과 위 판의 일치, 지형 높이 분리, 다음 Combat 재진입을 확인한다.
- OS1b 인수: 공격 모드 범위·피해 영역·위험 범위·넉백 도착 등 채우는 종류가 일부만 겹쳐도 전체 크기/방식이 같은지, 연쇄 겹침에서 위아래 순서가 맞는지, 빈 깊이가 생긴 칸의 색이 섞이지 않는지, 겹침 해제 시 원래 깊이로 돌아오는지 확인한다.
- DB 에셋 변경은 사용자 `DataBaseAssetTests` 확인 항목에 포함한다.
- 캐논 Phase 인수: 피해·폭발 영역 네 변/채움 가장자리, 일반 공격의 열린 변, 캐논 전체 선택 범위 유지, 영향 해제 후 일반 공격으로 전환을 확인한다.
