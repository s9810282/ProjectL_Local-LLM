# 전투 진입 보드 순차 등장 설계

- 날짜: 2026-11-02 (R9 갱신: 2026-11-03)
- 상태: R1~R9 코드 구현 완료. 최신 R9는 맵 선로 양끝 5칸 표시 연장이다. R4 기본 동작 사용자 확인 완료. R5~R9 컴파일 미확인, Unity 재생 확인 대기.
- 계획: [전투 진입 보드 순차 등장 계획](../plans/2026-11-02-combat-board-reveal-plan.md)
- 기준: 사용자가 제공한 Master of Piece의 `Battle Encounter — Transition & Board Reveal` 우측 AFTER GIF. 이번 범위는 보드 등장과 그 뒤 적 등장이다.

## 1. 사용자 확정 사항과 제안

사용자는 로딩 중 화면 구성을 끝내고 **로딩 종료 직후 아군 측에서 적 측으로 보드가 순차 등장**하기를 요청했다. **지형은 각 타일과 함께 등장**한다. 아군은 손패에서 배치하므로 별도 진입 연출을 추가하지 않는다. **적 유닛은 보드가 완성된 뒤 기존 소환 연출로 등장**한다.

다음은 설계에서 제안한 구현 정책이다. 2026-11-02 사용자의 “Phase 차례대로 전체 진행해” 지시로 이 설계·계획 범위의 R1→R2를 진행했다. 사용자가 직접 정한 요구와 구분해 기록한다.

- 같은 깊이의 타일은 함께 시작하고, 다음 줄은 앞줄이 완전히 끝나기 전에 시작한다. 아래에서 상승하고 최종 높이를 살짝 넘은 뒤 안착한다.
- 적들은 보드 완성 뒤 동시에 기존 소환 상승 동작을 시작한다. 적 사이의 추가 등장 간격은 넣지 않는다.
- 격자·배치 구역 강조는 보드가 완성된 뒤 표시한다. 유닛 HUD는 해당 적의 소환 종료 후 표시한다.
- 전투 입력과 자동 진행은 로딩 대기부터 적 등장 완료까지 기다린다. 손패에서 유닛을 꺼내는 입력도 완료 후 연다.
- 생성 타일이 없는 배경은 이 연출을 건너뛰고 기존 화면 구성을 유지한다.

## 2. 현재 코드와 연결 지점

경로는 `Assets/ProjectL/Script/Systems/` 기준이다. 기존 설계 문서의 오래된 실행 상태 대신 아래 현재 소스를 연결 근거로 삼는다.

| 위치 | 확인한 책임 | 이번 연결 |
|---|---|---|
| `RuntimeSystem/GlobalSystem/LoadingSystem/LodingSystem.cs` | 씬 Enter와 AfterLoad 노드 뒤에 BeginReveal을 호출한다. 로딩 표현이 숨겨지고 End가 끝나야 IsLoading이 false가 된다 | Global Context 경유로 기존 로딩 서비스를 읽는다. AfterLoad에서 연출을 시작하지 않는다 |
| `RuntimeSystem/InGameSystem/ViewSystem/Combat/CombatLoadedScene.cs` | 씬 로드 노드에서 루트와 배경을 준비한다 | 생성 타일의 씬 수명 유지 |
| `Combat/Display/Map/StageMapTiles.cs` | 각 타일을 만들고 `Transform[,] placed`를 반환한다 | 모든 실제 타일의 참조와 완성 위치를 연출 준비에 전달 |
| `Combat/Display/Map/StageViewPropPresenter.cs` | 타일 생성 후 배경 정렬과 칸별 높이·타일 표를 만든다 | 정렬이 끝난 타일만 연출 대상으로 제공 |
| `Combat/Display/Map/CombatMapTileSurface.cs` | 필드 칸과 바닥 타일 대응 및 최종 높이 | 지형의 소속 타일 확인에 재사용. 애니메이션으로 높이 표를 갱신하지 않는다 |
| `Combat/Display/Map/FieldTerrainPresenter.cs` | OnTile 지형은 지형 루트 아래, ReplaceTile 외형은 원래 타일과 같은 부모 아래 배치 | 지형 원본 ID·칸·실제 Transform을 준비 시점에 제공 |

| `Combat/Display/CombatSceneDisplay.cs` | Install에서 필드·표면·지형·유닛의 첫 구성을 완료 | 첫 구성이 끝난 뒤, 로딩 화면이 걷히기 전에 시작 자세·표시 억제 준비 |
| `Combat/Presentation/Pieces/CombatRisePiece.cs` | 기존 소환의 아래에서 회전하며 올라오는 동작 | 적 진입에서도 동일 조각 재사용 |
| `Combat/Playback/Support/CombatAbilityMotionSettings.cs` | View DB의 기존 SummonRise 값 묶음 | 적 진입용 소환 값을 따로 복제하지 않는다 |
| `Combat/CombatViewSystem.cs` | 씬 연결, 입력 연결, Tick·해제의 조정 | 진입 연출의 준비·Tick·완료·취소 연결만 담당 |
| `RuntimeSystem/LifeCycleSystem/LifeCycles/Combat/CombatProgressFacts.cs`, `Plans/CombatPlan.cs` | 결과 대기를 P < S로 판단한다. 일반 처리에서 IsPresenting은 별도 진입 애니메이션을 뜻하지 않는다 | 결과 번호와 독립된 진입 대기 사실을 명시적으로 전달 |

표의 `Combat/`는 `RuntimeSystem/InGameSystem/ViewSystem/Combat/`를 뜻한다. 조립은 기존 `Factory/Runtime/InGame/View/` 경로에 둔다.

## 3. 시작과 진행 순서

```text
로딩 화면이 가림
  → 기존 타일 생성·배경 정렬·높이 표 확정
  → 기존 Install로 지형·유닛·필드 표시 구성
  → 완성 자세 수집, 타일·지형 시작 자세와 적·격자 표시 억제 준비
  → 로딩 화면 걷힘 완료
  → 아군 측부터 타일과 지형 순차 상승·안착
  → 격자 표시, 적 소환 상승 시작
  → 모든 적 등장 완료
  → 진입 대기 해제, 전투 입력·정상 진행
```

진입 상태는 `CombatBoardEntryPresentation` 한 곳이 소유한다(새 클래스 이름은 제안). 상태는 `WaitingForLoading`, `Board`, `Enemies`, `Complete`로 구분하고, 준비 전·해제 뒤에는 진행하지 않는다. 다른 객체는 여기서 파생한 대기 여부만 읽는다.

- 준비는 로딩 중 끝내므로 완성된 보드가 잠깐 보였다가 내려가는 프레임이 없다. 지형 배치가 tile.localPosition을 읽으므로 **지형 첫 배치를 마치기 전에 타일을 내리지 않는다.**
- 로딩 완료 조건은 해당 Combat 연결의 첫 구성이 성공했고, 오류가 없으며, `IsLoading == false`인 것이다. LoadingProgress 1, AfterLoad, MonoBehaviour.Start 또는 고정 지연 시간으로 대신하지 않는다.
- 첫 로딩 완료 Tick에서 추가 지연 없이 시작한다. 보드·적의 완료 전환에서 같은 프레임 시간을 두 단계에 중복 적용하지 않는다.
- 초기 전투 진입 한 번에만 실행한다. 일반 Refresh, 턴 변경, 후속 소환 사건에는 보드 연출을 다시 실행하지 않는다. 같은 배경 프리팹을 쓰더라도 새 전투 씬 수명에서는 새로 준비한다.

## 4. 타일과 지형의 움직임

### BR1 타일 순서와 자세

- 대상은 `StageMapTiles.Build`가 만든 실제 타일이다. 필드 칸을 순회해 타일을 중복 애니메이션하지 않는다. 필드 밖의 배경 타일도 생성된 보드의 일부로 포함한다.
- 배경 정렬 후 각 타일의 완성 위치를 필드 로컬 좌표로 투영한다. 통상 아군이 있는 작은 필드 Y 쪽에서 큰 Y 쪽으로 진행한다(필드 Transform에서는 local Z 증가). 타일 배열 row나 화면 아래쪽을 방향 기준으로 사용하지 않는다. 배경 회전·반전·소수 타일 크기도 같은 변환을 따른다.
- 줄 배치는 필드 방향으로 투영한 실제 타일 중심의 깊이를 사용한다. 같은 깊이는 같은 지연을 받는다. 전체 깊이에 비례해 시작 시간을 분배하고, 깊이 차이가 없는 보드는 모두 즉시 시작한다.
- 사용자 정의 아군 배치 칸이 여러 곳에 흩어진 경우까지 적 위치를 추정해 진행 방향을 바꾸지 않는다. 이번 방향은 필드의 아군 쪽 기준축이다. 별도 방향 저작이 필요하면 후속 설계로 다룬다.
- 저장한 완성 자세에 필드 위 방향 변위만 더한다. 회전·크기·프리팹 후보 선택은 유지하고, 완료·취소 시 원래 자세를 정확히 복원한다.

### BR2 지형 동반

- 지형의 `source.Cell`에서 기존 칸↔타일 표로 대응 타일을 찾고, 그 타일과 동일한 시작 시점과 높이 변위를 적용한다.
- OnTile과 ReplaceTile 외형 모두 포함한다. ReplaceTile은 숨긴 바닥 타일을 대신해 움직이고, 원래 타일은 계속 숨긴다. 외형 프리팹이 없는 교체 지형은 기존 빈 공간을 유지한다.
- 지형을 비활성 바닥 타일의 자식으로 옮기지 않는다. 현재 부모·회전·배율·풀 반환 구조를 유지하고 실제 지형 Transform에 같은 월드 변위를 적용한다.
- 하나의 큰 타일에 여러 칸의 지형이 대응하면 모두 같은 변위를 받는다. 한 칸 아래에 여러 작은 타일이 있어도 기존 칸 중심 대응을 그대로 사용한다.
- 생성 타일 밖의 지형은 완성 위치의 필드 깊이로 시작 시점을 산출한다. 없는 타일을 만들거나 칸 높이를 추정해 추가하지 않는다.
- 1차 지형 대상은 기존 `FieldTerrainPresenter`의 Terrain 분류 외형이다. Object 분류 장식, Structure 개체, 철도·기차와 움직이는 환경 기믹까지 자동 편입하지 않는다. 이들을 함께 움직여야 하는 맵은 별도 대상 정책을 확인한다.

### BR3 표시와 설정

- 연출 전과 각 줄의 시작 전에는 해당 타일·지형의 표시를 억제한다. 원래 활성/표시 상태를 기록하고 연출이 억제한 부분만 복원한다. `FieldTileReplacement`의 SetActive 소유권을 가져오지 않는다.
- 칸 높이·유닛 위치의 규칙 사실은 완성된 보드 값이다. 연출 자세는 View의 일시적인 표시값으로만 보관한다.
- 보드 전용 설정은 View 연출 설정 표에 별도 직렬화 값 묶음으로 둔다. 경과 시간·대상 Transform을 SO에 쓰지 않는다.
- 초기 조정값 제안: 전체 줄 시작 분배 시간 1.0초, 한 줄 동작 0.4초, 시작 깊이 1.5, 정점 초과 높이 0.15. 깊이·높이는 필드 로컬 단위이며 배율을 반영한다. GIF의 정확한 추출값이 아니며 Unity에서 조정한다.
- 시간·깊이·높이는 유한한 0 이상으로 검사한다. 시간 0과 한 줄 보드도 즉시 완료가 가능해야 한다. 설정을 끈 경우 첫 구성 완료 자세를 유지한다.

## 5. 적 등장과 기존 소환 재사용

- 대상은 첫 화면에 실제로 그려지는 `Owner.Enemy`인 필드 캐릭터다. 손패·사망·필드 밖 캐릭터 및 Structure를 소환 대상으로 새로 취급하지 않는다.
- 적 인스턴스는 로딩 중 기존 표시 경로에서 준비하되 모델과 해당 유닛 HUD의 표시를 억제한다. 기존 단일 `_hiddenEntityId`(배치 고스트용)를 적 전체 숨김에 재사용하지 않는다.
- 보드 완료 뒤, 적의 자세 채널을 빌려 `CombatRisePiece`와 기존 `SummonRiseDelaySeconds/Seconds/Depth/Turns`를 사용한다. 시작 자세를 적용한 뒤 표시 억제를 풀어 완성 자세가 먼저 비치지 않게 한다.
- 소환 동작과 값의 원본은 기존 조각·View DB에 둔다. 진입용 조립은 적마다 Pose를 빌리고 상승 조각을 함께 실행한 뒤 전원의 완료를 기다린다. 조각 실행·대여·취소는 기존 `CombatComposition`/`CombatPieceRun` 기반 실행을 재사용한다.
- 기존 `CombatSummonEventHandler`는 전투 중 실제 소환 사건의 사실 반영과 강조까지 담당한다. 진입을 위해 가짜 `CombatSummonEvent`나 결과를 만들거나 해당 처리기의 ApplyFacts를 호출하지 않는다. 전투 중 소환 처리 순서는 유지한다.
- 적이 0명이면 즉시 적 단계를 마친다. 이미 준비된 필수 적 표시의 자세 대여 실패는 성공으로 넘기지 않고 해당 EntityId를 포함한 구성/수명 오류로 보고한다.

## 6. 입력과 진행 대기

현재 `IsPresenting`과 `HasUnpresentedResult`는 결과 확인 번호 P < S에서 나온다. 보드·초기 적 등장은 전투 결과가 아니므로 이 식을 변경하거나 결과 번호를 조작하지 않는다.

- 진입 소유자에서 파생한 `IsEntryPresentationPending`을 좁은 진행 계약 `ICombatProgressView`로 노출하고, `CombatProgressReader`가 사실 값으로 읽게 한다. 이름은 제안이며 상태 원본은 복제하지 않는다.
- `CombatPlan`은 이 값이 참이면 새 명령·미리보기·자동 진행·정리·이탈을 기다린다. 승패 또는 포기에서 기존 제출 정지를 먼저 하는 우선순위는 유지한다. 기다림을 위한 새 Job이나 Core API는 추가하지 않는다.
- 입력 사실과 정책에도 같은 진입 대기를 전달해 Layer 연결·손패 배치·전투 버튼·포인터 선택/호버·미리보기·포기 요청·전투 카메라 조작을 막는다. 기존 일반 결과 연출 중 허용 정책을 일괄 변경하지 않는다.
- `CombatViewSystem.Tick`은 진입을 진행하는 동안 일반 결과/가용성/미리보기 소비에 들어가지 않는다. 적 단계의 조각 Tick은 진입 소유자가 한 번만 호출한다.
- 첫 구성 성공(`Shown`), 씬 연결(`IsAttached`), 진입 완료를 서로 다른 사실로 유지한다. `SuspendSubmissions`는 정상 종료용이므로 진입 대기에 사용하지 않는다.
- 전역 Option의 열기·닫기 정책은 바꾸지 않는다. 진입 연출은 기존 게임 Tick 시간을 따라 일시정지되며, 재개 후 같은 시점에서 이어진다.

| 지형 생성·반환·바닥 교체 | 기존 FieldTerrainPresenter, FieldTileReplacement |
| 진입 단계·전체 완료·로딩 종료 관측 | 새 진입 연출 부품 |
| 타일·지형의 시간별 표시 자세 | 새 보드 연출 부품 |
| 적 등장 조립 | 새 진입용 적 등장 부품, 기존 소환 조각·설정 재사용 |
| 객체 생성·설정·좁은 의존성 연결 | 기존 View Factory의 진입 연출 조립 부분 |
| 씬 연결·Tick·오류·취소 호출 | CombatViewSystem 및 연결 수명 |

Factory가 만든 진입 부품을 표시와 함께 명시적으로 전달한다. 조정자에 타일 정렬·보간·적별 조각 생성을 넣지 않는다. 준비된 대상은 초기 수집 후 재사용하고 Tick에서 씬 탐색·DB 조회·대상 목록 재생성을 하지 않는다.

씬 이탈, 첫 설치 실패, 표시 해제, 런타임 오류 정지에서는 먼저 진입을 취소한다. 남은 Transform 자세·연출이 건드린 표시 상태·적 Pose 대여를 복구한 뒤 기존 표시를 반환하고 배경을 없앤다. 지형이 배경 자식인 기존 해제 순서도 유지한다. 하나의 복구 실패가 나머지 자원 정리를 막지 않게 하며, 실패를 모아 기존 오류 경계로 보낸다. 종료된 수명의 완료 콜백으로 입력을 다시 열지 않는다.

## 8. 설계 원칙 점검

기준은 [View 설계 인계 §4](../handoffs/2026-09-30-combat-view-design-session-handoff.md#4-반드시-지킬-설계-원칙), JMH Framework 개발 지침, Framework 프로그래머 가이드다.

| 항목 | 적용 |

| SSOT | 보드 규칙·칸 높이는 Buffer/기존 높이 표, 바닥 숨김은 기존 교체 부품, 소환 동작·값은 기존 Rise 조각/DB, 진입 진행은 새 소유자 한 곳 |

UI는 새 화면을 만들지 않는다. 기존 필드 표시·유닛 HUD 내부 표시만 준비/복구하며, 기존 등록 UI를 외부에서 직접 열고 닫는 경로를 추가하지 않는다. Framework 등록 경로는 View Factory 생성 → 기존 ViewGroup의 CombatViewSystem 등록 → 기존 InGame/루트 수명 → 내부 부품 Tick 전달을 유지한다.

## 9. 구현 경계와 인수

- Core 로직·InGame 규칙·Buffer 쓰기·FieldCamera·Architecture는 수정하지 않는다. LifeCycle의 Combat 진행 계약/Plan은 View 소유 골격 범위에서 필요한 진입 대기만 추가한다.
- 타일 없는 맵의 동작, Object/Structure 등 별도 표시의 동반 여부, 한 전투 안 재시작 경로가 구현 중 위 정책과 다르게 필요해지면 설계를 먼저 갱신하고 확인한다.
- 전투 View Test 코드와 MSBuild는 추가/실행하지 않는다. 기존 시험은 계약 변경으로 컴파일이 깨지는 호출·대역만 최소 대응한다. 다른 사람이 쓴 시험의 실행 기대 변경은 먼저 묻는다.
- 수동 인수: 로딩 종료 직후 시작, 완성판/적 사전 노출 없음, 아군→적 방향, 지형 동반, 교체 바닥 숨김, 소수·대형 타일, 적 기존 소환, 입력·자동 진행 대기, 재진입·중단 복구, 전투 중 기존 소환/지형 붕괴 유지.
- 컴파일 미확인. Unity 컴파일·재생 확인은 사용자가 한다. 에셋 값을 변경하는 구현 Phase에서는 DataBaseAssetTests를 사용자 확인 항목에 포함한다.

## 10. 구현 기록 (2026-11-02)

- `CombatBoardEntryPresentation`이 로딩 대기·보드·적·완료 단계를 소유한다. `CombatBoardEntryFactory`는 필요한 부품만 조립하고, `CombatSceneDisplay.Install`의 완성 화면 구성 뒤 준비한다. 연결 수명은 `ICombatEntryPresentation`으로 Tick·Cancel·대기 여부만 받는다.
- `StageViewPropPresenter`가 정렬된 실제 생성 타일 목록을 제공한다. `StageMapTiles` 생성 알고리즘은 변경하지 않았다. `FieldTerrainPresenter`는 이미 그린 외형의 칸과 대응 타일을 제공한다.
- 보드는 원래 localPosition·Renderer.enabled를 보관하고 필드 위 방향 변위만 적용한다. 부모·회전·크기·바닥 타일 activeSelf·표면 높이 표는 변경하지 않는다.
- `CombatEntryEnemyAppearance`는 초기 필드 적에 기존 Rise 조각과 Pose 대여 실행을 조립한다. 기존 소환 사건 처리기·Core 사건은 변경하지 않았다. 유닛 HUD 억제는 기존 HUD 사용 여부와 별개이며 완료·취소 때 해제한다.
- 격자·채우기·궤적용 내부 `FieldVisualRoot`를 만든다. Global 풀 아래의 AreaOutline 핸들은 기존 Update 계약에 빈 칸을 보내 숨기고, 다시 표시할 때 기존 상태로 그린다. Render 서비스 계약은 변경하지 않았다.
- 로딩 상태는 `Global.LodingServiceCommand.LodingService`로 받는다. 진입 중 결과 재생 Tick은 건너뛰고, 같은 대기 사실을 진행 Plan·입력 정책에 전달한다. 완료 후 입력 Layer를 다시 맞춘다.
- 정상 완료·오류 정지·Install 실패·Clear·Release·Detach에서 복구한다. 복구 오류는 모아 전파하며 정상 입력 재개는 현재 연결의 Tick만 수행한다.
- 설정 기본값은 §4 BR3과 같다. 기존 씬·설정 에셋은 수정하지 않았다. 컴파일·실제 시간감·씬 재생·EditMode 확인은 미실행이며 계획의 Unity 인수표가 남는다.

## 11. 모드와 증가 묶음 확장 (사용자 요청, R3)

- 기존 방식은 enum `Default = 0`으로 보존한다. 새 `Coner = 1`은 사용자가 요청한 철자를 그대로 사용한다. 기존 에셋은 Mode를 바꾸기 전까지 Default다.
- Coner는 필드 좌표의 좌하단(작은 local X·Z)에서 우상단(큰 local X·Z)으로 진행한다. 생성 타일 중심의 `X + Z`가 작은 순서로 대각 방향을 정한다. 같은 값은 Z, X 순으로 정렬해 매번 같은 결과를 낸다. 카메라 화면 좌표나 타일 프리팹 자체 회전은 사용하지 않는다.
- 사용자는 `1→2→3`을 **한 차례에 함께 시작하는 타일 묶음 크기 증가**로 확정했다. Coner의 첫 묶음은 1개이며, k번째 묶음(0부터)의 개수는 `floor(1 + k × ConerBatchGrowth)`다. 증가량 1은 1·2·3, 2는 1·3·5, 0.5는 1·1·2·2, 0은 계속 1개다. 마지막 묶음은 남은 개수만 시작한다.
- `ConerBatchGrowth` 기본값 1, 유한한 0 이상. Default에는 적용하지 않는다. 실제 생성 타일을 한 번만 세며, 같은 타일을 따라가는 여러 지형은 묶음 크기에 추가하지 않고 같은 시작 지연을 받는다.
- `SweepSeconds`는 첫 묶음 시작부터 마지막 묶음 시작까지의 시간이다. 전체 묶음 사이에 균등 분배하고, 묶음 하나면 즉시 시작한다. 따라서 증가량을 바꿔도 보드 총 시간은 일반적으로 SweepSeconds + TileSeconds로 유지된다. SweepSeconds=0이면 모두 동시에 시작한다.
- 타일 없는 지형은 생성 타일 묶음 개수에 넣지 않는다. 완성 위치의 같은 대각 방향 진행률을 보드 범위에 맞춰 0~1로 제한하고 SweepSeconds를 곱한 지연을 사용한다. 대응 타일이 있는 OnTile/ReplaceTile은 반드시 해당 타일의 묶음을 따른다.
- 순서·시작 시간표 계산은 별도 `CombatBoardRevealSchedule`에 둔다. `CombatBoardReveal`은 준비된 지연으로 기존 상승·안착·복구를 실행한다. 적 소환·로딩·입력·Factory 수명은 수정하지 않는다.
- SSOT: 모드/증가량은 기존 보드 설정 한 곳, 묶음 계산은 시간표 한 곳. S/O: 시간표와 자세 실행 분리. L: Default와 기존 결과/진입 계약 유지. I/D: 기존 대상·필드 Transform·설정만 전달. FW/JMH: 새 등록·서비스·UI·타이머 없음. 기능 독립성: 모드 변경은 설정·시간표·그 소비 지점 안에서 처리한다.

R3 코드 반영: `CombatBoardRevealMode`와 `CombatBoardRevealSchedule`을 추가하고 기존 보드 설정/준비만 연결했다. 실제 타일 Transform 기준으로 시간표를 한 번 만들고 지형은 같은 시간표 항목을 공유한다. 준비 이후 Tick은 모드별 정렬이나 묶음 계산을 반복하지 않는다. 컴파일·Unity 재생은 미확인이다.

## 12. 배경 구역 동반 등장 (사용자 요청, R4)

사용자가 `NewStageTest.prefab`의 X·Z 위치 기반 구역 정리를 요청해 `DayMap/BackGroundProp`의 기존 직속 182개를 16×16 단위의 `RevealArea_X…_Z…` 빈 GameObject 29개로 묶었다. 기존 배치·회전·크기와 내부 계층은 유지했다. 이어 사용자가 이 구역의 등장 연출 연결을 요청했다. 아래는 §4 BR2의 1차 대상 제한에 추가되는 배경 장식 전용 범위다.

- 등록 규칙: 배경 프리팹의 `DayMap/BackGroundProp` 바로 아래에서 이름이 `RevealArea_`로 시작하는 Transform만 등록한다. 별도 Inspector 연결 없이 이번 29개 구역에 적용한다. 경로·접두사 규칙은 대상 수집 부품 한 곳에 둔다. 해당 경로나 구역이 없는 배경은 등록된 구역이 없는 정상 선택 기능이다.
- 수집 시점: `StageViewPropPresenter.Show`에서 타일 생성·배경 정렬을 끝낸 뒤 한 번 수집한다. 구역 중심과 모든 실제 생성 타일 중심을 필드 로컬 X·Z로 바꾸고, 평면 거리가 가장 가까운 타일을 각 구역의 기준으로 삼는다. 같은 거리면 기존 생성 타일 목록의 앞 항목을 사용한다. Y 높이는 선택에 쓰지 않는다.
- 구역의 빈 부모를 하나의 Body로, 가까운 타일을 Timing 대상으로 기존 `CombatBoardRevealTarget`에 등록한다. 타일과 똑같은 Delay·상승·초과·안착 값을 사용하고, 자식 장식은 부모를 따라 움직인다. 타일 시간표와 Coner 묶음 크기에 구역 수를 추가하지 않는다. 필드 밖 구역도 가까운 가장자리 타일을 따른다.
- 실제 생성 타일과 구역을 부모·자식으로 겹치면 변위가 중복되므로 구성 오류로 거절한다. 구역은 같은 부모의 직속 자식만 수집해 구역끼리 중복 이동하지 않는다.
- 로딩 중 숨김 준비 → 타일·지형·구역 동반 등장 → 격자 → 적 소환 → 입력 재개 순서를 유지한다. 구역까지 기존 보드 부품이 완료/취소를 처리하므로 별도 진행 플래그·타이머·완료 콜백을 만들지 않는다.
- 취소/오류/씬 해제에서 구역의 원래 localPosition과 Renderer 표시도 기존 복구 목록으로 돌린다. 생성 타일 없음/Enabled=false는 기존 건너뛰기 정책을 유지한다. 프리팹의 Day Camera 및 DayMap/Lights는 등록 경로 밖에 있어 연출 대상으로 추가하지 않는다.
- SSOT: 묶음·시간은 기존 타일 시간표/보드 설정, 구역 기준점은 프리팹 Transform 한 곳. S/O: 대상 수집·Factory 조립·연출 실행을 분리하고 실행 내부는 변경하지 않는다. L/I/D: 기존 대상 계약을 재사용하고 수집 결과만 주입한다. FW/JMH: 새 등록 서비스·MonoBehaviour·UI·Buffer 쓰기 없음. 기능 독립성: 배경 등록 규칙 변경은 수집 부품, 연결은 Presenter/Factory/준비 입구에 한정한다.

R4 코드 반영: `CombatBackdropRevealTargets`와 .meta를 추가하고 Presenter의 정렬 후 수집/해제, Factory의 대상 전달, 진입 Prepare의 대상 추가를 연결했다. 프리팹 구역 29개와 기존 182개 오브젝트의 부모 연결을 정적으로 대조했다. 기존 시간표·상승·취소 부품과 프리팹 자체는 이번 연결에서 수정하지 않았다. 컴파일·Unity 재생은 미확인이다.

## 13. 적 Nexus 낙하와 착지 이펙트 (사용자 요청, R5)

사용자는 배경 장식 건물이 아니라 **Structure인 적 Nexus**를 지정했다. 기존 배경 프리팹·구역은 그대로 두고, 살아 있는 `Owner.Enemy`의 `EntityKey.Structure_Headquarters`만 대상으로 한다. 대상은 설치 때 전달받은 Buffer의 Structures와 현재 표시를 대응하며 InGame DB나 Core 로직은 읽거나 쓰지 않는다.

- 순서: 로딩 중 완성 배치/숨김 → 보드·배경 상승 → 격자 표시 → 적 Nexus 낙하 → 착지 `FallingRocks` 자연 종료 → 기존 적 유닛 소환 → 입력 재개. Nexus가 없는 전투는 해당 단계를 즉시 건너뛴다. 여러 대상이 있다면 함께 떨어진다.
- `CombatEntryNexusAppearance`는 기존 자세 창구의 대여를 통해 완성 자세 위에서 가속 낙하(`t²`)한다. 회전·크기는 유지하고, 끝에는 완성 자세를 정확히 복구한다. 모델과 HUD는 로딩 중부터 숨기며 모델은 높은 시작 자세 적용 후 공개하고 HUD는 착지 후 공개한다.
- 이펙트 자리는 공중의 현재 위치가 아닌 **높이 표를 반영한 완성 배치의 점유 칸 지면 중심**이다. 기존 `FieldUnitPresenter.CenterOf`가 놓은 자세의 원점을 사용한다. 물리 충돌 검사나 바닥 높이 재계산을 추가하지 않는다. 낙하 완료 때 `EffectType.FallingRocks`를 한 번만 기존 `CombatEffectWindow`로 재생하고 손잡이가 자연 종료될 때까지 기다린다. 해당 이펙트는 Render 표에 등록돼 있고 프리팹의 파티클 3개는 비반복·링 버퍼 없음이다.
- 설정은 기존 전투 연출 SO의 별도 `Nexus Drop`: Enabled=true, Height=10(월드 단위), Seconds=0.6을 초깃값으로 제안한다. 설정 검증은 새 설정 타입 한 곳이다. Board Reveal을 끄거나 생성 타일이 없으면 기존 전체 진입 건너뛰기 정책을 유지한다. Nexus Drop만 끄면 Nexus는 기존 즉시 표시를 유지한다.
- 수명: 기존 진입 객체가 Nexus 단계도 소유한다. 설치 실패/오류/이탈은 자세 대여·Renderer·HUD·착지 이펙트를 반환한다. 표시의 EntityId가 바뀐 뒤 옛 복구가 새 개체를 수정하지 않도록 확인한다. 새 타이머 MonoBehaviour·서비스·Core 사건은 만들지 않는다.
- SSOT: Structures는 Buffer, 자세는 기존 대여, 접촉 높이는 기존 필드 배치, 단계는 기존 진입 소유자, 튜닝은 설정 타입이 원본이다. S/O: Nexus 동작·설정·Factory 조립 분리, 기존 타일/적 소환 알고리즘은 변경하지 않는다. L/I/D: 기존 Pose/이펙트 계약을 사용하며 필요한 창구만 주입한다. FW/JMH: Global Render → 기존 서비스 조립 → 같은 CombatEffectWindow를 공유하고 루트 Export/등록을 추가하지 않는다.
- 기능 독립성: 낙하 곡선/설정 변경은 Nexus 부품에 한정한다. 전체 순서 변경은 Entry, 의존성 연결은 Factory가 맡는다. 공유 경계인 Install/Cancel/입력 대기는 함께 검토한다. 배경 구역/타일 시간표나 전투 중 공격·소환은 수정 범위가 아니다.

R5 코드 반영: `CombatNexusDropSettings`/`CombatEntryNexusAppearance`를 추가하고 기존 설정 SO·초깃값 에셋, 표시 대상 수집, Install의 Structures 전달, Entry 순서와 Factory만 연결했다. Nexus의 위치는 직접 Transform 쓰기 대신 기존 자세 대여로 변경한다. 표시 대여와 착지 이펙트는 기존 취소 경계에 포함되며 원래 대기 계약을 유지한다. 컴파일·Unity 재생은 미확인이다.

## 14. 기믹·선로와 유닛 상시 이펙트의 공개 시점 (사용자 확정, R6)

사용자는 기믹을 **보드 완성 후 한꺼번에 표시(2번)**하도록 확정했고, 기차 기믹의 기찻길도 포함하도록 요청했다. 이어 유닛 특성의 상시 이펙트가 먼저 보이는 문제를 지적했다.

- 순서: 보드·일반 Terrain·배경 순차 등장 → 격자와 **모래바람/토네이도/낙석 경고/선로** 공개 → Nexus 낙하·착지 이펙트 → 적 소환 완료 → **유닛 상시/상태 유지 이펙트** 재생 → 입력 재개. 일반 Terrain의 타일 동반 등장과 Nexus FallingRocks 시점은 유지한다.
- `CombatEntryDeferredDisplay`가 진입 동안의 표시 보류를 맡는다. Factory가 같은 객체를 SceneDisplay와 Entry에 전달한다. 초기 Refresh 전 Begin으로 보류를 시작하며, 기존 진입의 보드/유닛 완료 경계에서 각각 공개한다. 이 부품은 시간이나 게임 진행 상태를 갖지 않는다.
- 기믹: SceneDisplay의 최종 사실 그리기는 위 부품의 Render를 통한다. 보류 중에는 불변 StageGimmickStateSet, 토네이도 영역의 고정 목록과 현재 Mapper만 보관한다. CombatDisplayValues나 가변 Buffer를 보관하지 않는다. 보드 완료 때 기존 각 Presenter.Render를 한 번 호출하고 임시 참조를 비운다. 이후 전투의 그리기/이동/발동 경로는 그대로다.
- 선로: 기존 로딩 중 Install과 Paths 준비를 유지하고 설치 루트의 표시만 억제한다. 보드 완료 때 Rail/RailTile과 보드 밖 연장 구간을 함께 공개한다. 열차는 기존 발동 전 비활성 상태를 유지한다. 프리팹의 장식 Rail은 기존 배경 구역 연출 대상이며 런타임 기차 선로와 구분한다.
- 상시 이펙트: `CombatShownFacts.SyncPersistent` 입구만 보류해 최초 파티클 자체를 생성하지 않는다. 기존 표시 사실·HUD·피격/착지 등 일회성 이펙트는 그대로 사용한다. 유닛 등장 완료 후 보류를 해제하고 현재 표시 사실로 SyncPersistent만 호출한다. 유닛 전체 Render나 Buffer 최신값 재조회는 하지 않는다.
- 취소/실패/해제는 미공개 기믹 스냅샷과 상시 효과 보류를 버리고 선로 표시를 복구한다. 취소 시 새 기믹이나 상시 이펙트를 재생하지 않는다. 기존 표시의 Clear/Release가 인스턴스와 효과 창구를 정리한다. 연출 꺼짐/타일 없음/두 번째 Install은 보류를 걸지 않아 기존 즉시 표시를 유지한다.
- SSOT: 진행 단계는 Entry, 실제 기믹 인스턴스는 기존 Presenter, 상시 효과의 대상과 활성 집합은 기존 ShownFacts/PersistentEffects가 소유한다. S/O: 보류 부품과 조립을 분리해 기존 기믹/특성 동작 알고리즘을 변경하지 않는다. L/I/D: 기존 Render/Sync 계약과 작은 공개 경계만 확장한다. FW/JMH: 새 System·Service·MonoBehaviour 타이머·UI 등록 및 Core 쓰기 없음. 같은 Global Render 창구를 사용한다.
- 기능 독립성: 공개 시점 변경은 Entry와 보류 부품, 특성 효과 내용 변경은 기존 효과 출처에 머문다. 공통 경계인 첫 Install/완료/취소/재진입과 진입 이후 기믹·특성 동작은 인수 대상이다. 기존 다른 작업자의 Inspector 특성 값 전달 변경을 보존한다.

R6 코드 반영: 초기 화면의 기믹 Render는 보류 부품을 통하고, 선로는 기존 설치 루트의 표시 API만 추가했다. ShownFacts의 상시 효과 동기화는 보류 중 생성하지 않으며 정상 진입 완료에만 명시적으로 다시 맞춘다. 취소는 미공개 스냅샷/보류를 버린다. 기존 타일·Nexus·적 소환 동작은 수정하지 않고 진행 경계에 공개 호출을 추가했다. 컴파일·Unity 재생은 미확인이다.

## 15. 선로 순차 낙하 (사용자 요청, R7)

외부 연장 생성/순서 정책은 아래 §16의 사용자 결정으로 대체한다. 아래 외부 조각 관련 내용은 R7 당시 구현 이력이다.

- 사용자 요청: 타일이 모두 깔린 뒤 기찻길을 0번 쪽부터 반대편까지 차례로 하늘에서 떨어뜨린다. R6의 선로 즉시 공개를 이 연출로 교체한다.
- 순서: 보드·배경 안착 → 격자/일반 기믹 공개와 선로 낙하 시작 → 모든 선로 착지 → Nexus 낙하/착지 효과 → 적 소환 → 상시 효과/입력 재개. 선로 없음 또는 Railway Drop 비활성은 해당 단계를 건너뛴다. 전체 Board Reveal 비활성/생성 타일 없음은 기존 전체 건너뛰기 정책을 유지한다.
- 선로 한 조각은 기존 RailTile과 Rail 한 쌍이다. 가로는 작은 X에서 큰 X, 세로는 작은 Y에서 큰 Y로 진행한다. 0번 쪽 바깥 연장 끝부터 반대편 연장 끝까지 같은 순서에 포함한다. 여러 직선은 각자의 첫 조각부터 동시에 시작하며 열차 Reverse 설정과 독립적이다.
- `FieldRailwayPresenter`는 설치 때 직선별 조각 쌍을 순서대로 보관하고 읽기 전용 목록을 제공한다. 위치·높이·크기는 기존 설치 결과가 원본이다. 열차 경로/발동/피해/애니메이션은 수정하지 않는다. 설치 해제 때 목록도 비운다.
- `CombatEntryRailwayAppearance`는 로딩 중 설치된 조각의 완성 localPosition/Renderer 상태를 수집하고 숨겨 높은 시작 위치에 둔다. 보드 완료에 첫 조각을 공개하고 조각 순번 × 간격 뒤 각 쌍을 공개하여 t² 가속 낙하한다. 회전·크기·부모는 유지한다. 대기 조각이 한 프레임 먼저 보이지 않도록 루트 공개 전에 개별 숨김을 준비한다.
- 설정 SSOT는 기존 전투 연출 SO의 별도 Railway Drop: Enabled=true, Height=10(월드 단위, 필드 위쪽), Seconds=0.45(조각별 낙하 시간), SegmentGapSeconds=0.08(시작 간격). 유한한 0 이상이며 간격 0은 동시 시작, 시간 0은 각 시작 시각에 즉시 착지다. Nexus 등 기존 사용자 설정값은 보존한다.
- 단일 진행 소유자는 기존 Entry다. 정상 완료/취소/실패/해제에서 원래 자세와 Renderer 상태를 복구한다. 새 이펙트나 소리는 추가하지 않는다. 준비 목록은 설치 이후 읽고 재설치/부분 실패의 정리는 기존 소유자와 연결한다.
- SSOT: 순서/조각은 설치 결과, 수치는 설정, 진행은 Entry 한 곳. S: 선로 설치·낙하 실행·Factory 조립 분리. O: 전용 실행 부품과 단계만 확장. L: 기존 진입 공개 계약/기차 발동 유지. I: 낙하는 읽기 전용 조각과 설정만 소비. D: Factory가 의존성을 전달하고 서비스 로케이터를 만들지 않는다. FW/JMH: 새 서비스 등록/Export/MonoBehaviour/타이머/Buffer 쓰기 없음. 기능 독립성: 낙하 변경에 기차의 이동/피해 재생기를 수정할 필요가 없다.

R7 코드 반영(2026-11-03): 설치 결과를 `RailwaySegmentVisual` 쌍의 직선별 읽기 전용 목록으로 제공하고 Factory가 새 낙하 부품에 전달한다. 목록은 설치 전 Factory에서 복사하지 않고 설치 후 Prepare에서 읽는다. Entry에 Railway 단계를 추가했으며 보드/선로 경계에서 같은 deltaTime을 두 번 소비하지 않는다. 설정 에셋에 Railway Drop만 추가하고 기존 Board Reveal/Nexus Drop 수치를 보존했다. 원래 위치와 Renderer 상태의 복구·설치 목록 정리를 소스로 대조했다. 컴파일·Unity 재생은 미확인이다.

## 16. 맵 내부 선로만 생성 (R8, 2026-11-03)

아래 맵 내부 전용 정책은 후속 §17에서 양끝 5칸 표시 연장으로 확장됐다.

- 사용자가 진입 순서가 매우 느리다고 보고했다. 현재 RailwayVisual의 OutsideCells=230으로 양 끝에 460조각이 추가된다. R7이 이를 낙하 시간표에 포함해 간격 0.08초 기준 36.8초를 더하며, 보드 첫 칸 전에도 18.4초를 기다린다.
- 사용자 결정: 외부 조각을 묶어 기다림만 줄이는 대신, 맵 크기에 맞게 생성한다. 실제 `RailCells`를 검증한 `RailwayTrackLayout.Track.Cells`에만 RailTile/Rail을 한 쌍씩 만든다. 보드 밖 연장 생성과 그 등록을 제거한다. 직선별 첫 칸부터 +X/+Y 순서와 RailTile/Rail 동반 낙하는 유지한다.
- 직선의 선로 칸 N개는 `(N-1) × SegmentGapSeconds + Seconds` 동안 낙하한다. 여러 직선은 함께 시작하며 가장 늦게 끝나는 직선을 기다린다. 별도 시간 상한/보정값은 추가하지 않는다.
- OutsideCells는 기존 열차 경로의 보드 밖 이동 여유에도 사용되고 있다. 선로 생성만 제거하며 열차의 이동 시작/종료, 속도, 접촉 예약을 바꾸지 않는다. OutsideCells/TravelPaddingCells의 Inspector 설명을 실제 역할에 맞춘다. 값과 공개 프로퍼티는 유지한다.
- SSOT: 생성 대상은 기존 Layout의 맵 내부 RailCells 한 곳, 시간은 기존 설정/진행 부품이다. S/O: 설치 대상 변경은 Presenter의 생성 부분에 한정하며 낙하 구현은 그대로 사용한다. L: 기존 진행/취소/열차 경로 계약 유지. I/D: 새 의존성/계약 없음. FW/JMH: 기존 Factory/서비스 등록/Export/조회 유지. 기능 독립성: 이 수정에 투사체·Nexus·타일·열차 이동 내부를 변경할 필요가 없다.

R8 반영: 외부 생성 호출과 ExtendEnd를 제거했다. 설치/등장 목록은 검증된 맵 내부 선로만 가진다. 열차 조립과 경로 계산 구간이 HEAD와 같은지 대조했다. 설정 에셋·사용자 낙하 높이/시간 값은 수정하지 않았다. 컴파일·Unity 재생 미확인이다.

## 17. 양 끝 5칸 표시 연장 (R9, 2026-11-03)

사용자 최종 요청에 따라 직선의 첫 칸에서 반대 방향으로 5칸, 마지막 칸에서 진행 방향으로 5칸을 더 만든다. 별도 `RailExtensionCells`가 표시 연장 개수의 원본이며 기본값과 RailwayVisual_Default 에셋은 5다. 0은 맵 내부만 생성한다. 기존 OutsideCells/TravelPaddingCells는 열차 이동 여유로 유지하며 표시 개수로 사용하지 않는다.

첫 외부 끝부터 순서대로 생성/등록하고 기존 낙하 부품을 사용한다. 총 조각은 N+10, 현재 0.08초 간격에서 추가 시간은 0.8초다. 실제 RailCells·열차 경로·접촉 계산은 늘리지 않는다. 설정/생성/진행의 책임을 유지하고 새 서비스/등록/Export/의존성을 추가하지 않는다(SSOT·SOLID·FW/JMH·기능 독립성). 코드와 정적 검토 완료, **컴파일 미확인**. Task/인수는 계획 R9에 기록했다.
