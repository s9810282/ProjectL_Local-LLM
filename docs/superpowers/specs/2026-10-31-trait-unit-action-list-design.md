# 특성 UnitAction 목록과 희생 보호 대상 물러나기

사용자 요청: Activations의 UnitAction을 List로 바꾸고, 희생 수호자가 대신 맞으러 나갈 때 기존 피격 대상도 약간 뒤로 물러나게 한다. 기존 단일 행동 설계의 View 확장이다. Core·실제 이동·피해 규칙은 변경하지 않는다.

## 1. 실행 의미

리스트는 서로 다른 유닛의 동시 행동 묶음이다. 수호자 나가기와 보호 대상 물러나기를 동시에 시작하고, 모두 끝난 뒤 공격 뼈대를 시작한다. 사용자에게 동시/순차 선호를 질문했으며 기본안은 동시다. 순차 연출 타임라인이나 같은 유닛의 다단 동작은 이번 범위가 아니다.

| 항목 | 희생 기본 연결 | 의미 |
|---|---|---|
| Unit Actions[0] | 기존 Source / GuardFront 설정 그대로 | 수호자가 보호 대상의 원래 자리 앞, 공격자 쪽으로 나감 |
| Unit Actions[1] | Targets / AwayFromAttacker / 거리 0.3 / Walk / Face Attacker | 보호 대상이 자기 원래 자리에서 공격자 반대쪽으로 물러나며 공격자를 바라봄 |
| 두 행동의 나가기 시간 | 기존 수호자 OutSeconds를 보호 대상에도 초기값으로 사용 | 동시에 자리를 잡음. 이후 각 값은 독립 편집 가능 |
| 복귀 | 수호자 피격·사망·그 출처의 후속 정산 뒤 | 생존 유닛은 원래 서는 자리로 복귀. 죽은 유닛의 자리는 기존 대여 계약대로 쓰지 않음 |

보호 대상이 같은 공격의 다른 직접 타격도 받으면 수호자 후속과 보호 대상 자신의 후속이 모두 끝난 뒤 돌아온다. HoldSeconds는 가로채기에서 사용하지 않는 기존 정책을 유지한다.

## 2. 입력과 마이그레이션

- `TraitActivationVisual.unitAction` → `List<CombatUnitActionInput> unitActions`. 런타임에는 읽기 전용 `UnitActions` 목록으로 값 사본을 만든다.
- Actor=None인 입력은 행동 없음으로 유지한다. null 항목은 구성 오류이고, 한 줄에 같은 활성 Actor 역할을 두 번 넣으면 검증 오류로 알린다. Source와 Targets는 함께 쓸 수 있다.
- 현재 저장소에서 단일 unitAction 필드를 가진 SO 3개(희생·깔끔한 뒷정리·2연발)를 목록으로 변환한다. 모든 기존 필드값·큐·공격 표시·GUID를 보존한다. 희생에만 두 번째 항목을 추가한다.
- 필드명을 자동으로 단일 객체→리스트 변환할 수 있다고 가정하지 않는다. YAML 입력을 명시적으로 마이그레이션하며 런타임에 숨은 구 필드와 새 목록을 동시에 보관하지 않는다. 외부 브랜치의 구 형식 에셋은 병합 시 같은 변환이 필요하다.
- 기존 enum 숫자는 보존하고 `CombatUnitActionPlace.AwayFromAttacker=3`을 추가한다. 가로채기 없는 일반 발동에서는 공격자 기준점이 없으므로 경고 후 Stay로 처리한다.

## 3. 재생·소유권

- `CombatActivationRows`가 발동 줄의 행동 목록을 한 번 읽어 보관한다. 일반 발동 처리기는 목록을 순회해 기존 유닛 실행으로 각각 보낸다. 추가 공격 발동에서는 목록 전체를 경고 후 건너뛰는 기존 공격 우선 정책을 유지한다.
- `CombatGuardLead`는 Source를 GuardianId, Targets를 ProtectedId에 매핑한다. 각 항목은 같은 공격 composition에 들어간다. 새 전역 재생기나 독립 MonoBehaviour를 만들지 않는다.
- 기존 Guard 항목에 실제 행동 유닛을 구분하는 파생 값 `Unit`을 둔다. 수호자/보호 대상의 식별자 원본은 기존 Interception이다.
- 나가기 시작 전 보호 대상·공격자의 기준 위치를 포착한다. 보호 대상이 먼저 물러나도 수호자의 목적지가 그 뒤를 따라 바뀌지 않게 한다.
- 공격 시작은 설정된 최장 시간 추정 대신 모든 나가기 조각의 실제 완료를 기다린다. 이를 위한 작은 완료 대기 조각은 행동 조립 내부에 둔다.
- 각 유닛의 Stand 채널은 공격 실행이 한 번씩 소유한다. 같은 공격 안에서 같은 유닛이 여러 가로채기에 등장하면 기존 정책처럼 첫 행동만 채택한다. 일반 발동의 중복 유닛은 기존 유닛 실행 충돌 경고 경로를 따른다.
- 복귀는 실제 행동 유닛의 원래 자세로 한다. 보호 대상 행동도 수호자의 후속 정산을 기다리고, 자신에게도 후속이 있으면 함께 기다린다. 취소·중단·실패는 기존 composition/lease 해제를 따른다.
- 몸/접촉 위치 조회는 기존 StandingBody 경로를 사용한다. 피해 수신자는 Core가 정한 수호자 그대로다.

## 4. 구조 점검

| 기준 | 적용 |
|---|---|
| SSOT | 행동 입력은 unitActions 목록 한 곳, 자리 계산은 CombatUnitActionPlaces 한 곳, 실제 수신 관계는 Interception 한 곳 |
| SRP/SOLID | 입력·캐시·가로채기 매핑·행동 조립·순수 자리 계산을 기존 책임대로 확장. 기능별 조건은 관련 파일에 한정 |
| 조립과 기능 독립성 | 목록/매핑은 특성 경계, 이동 계산은 Places, 완료/복귀는 Composer. Core·UI 등록·카메라·운영 진행은 수정하지 않음 |
| Framework/FW | 기존 서비스/Export/Factory 등록 그래프 유지. 새 Stand 소유자·매 Tick 전역 검색·별도 게임 상태 없음 |
| 직렬화 | 기존 에셋의 값을 목록으로 이전하고 같은 meta/GUID 보존. 새로운 enum 값은 기존 번호를 바꾸지 않음 |

## 5. 확인

새 View 테스트/자동 검증 도구는 만들지 않는다. 컴파일·에셋 필드 대조·가능한 수동 Play로 확인한다. 희생 생존/사망, 두 유닛 나가기·대기·복귀, 목록 순서 변경에도 수호자 목적지 유지, 취소 후 위치 복원, 목록 없는 일반 발동/추가 공격을 확인 대상으로 둔다. 사용자가 Unity를 조작 중이면 자동 조작을 중단하고 미확인으로 남긴다. 기존 Setting 종료 오류는 별도 사용자 결정대로 유지한다.
