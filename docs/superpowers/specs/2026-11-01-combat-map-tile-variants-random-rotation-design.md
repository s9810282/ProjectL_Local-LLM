# 바닥 타일 프리팹 후보·Random 회전 설계

- 날짜: 2026-11-01
- 상태: 사용자 진행 승인으로 R1·R2 구현·자체 검토 완료. 실행 증거와 남은 시각 인수는 계획과 [최종 검토](2026-11-01-combat-map-tile-variants-random-rotation-review.md)를 따른다.
- 요청: 종류(Enum)별 여러 타일 등록, ViewStageDataSO의 바닥 타일 Rotations에 Random 추가, 후보가 여러 개면 무작위 선택, 맵 툴 대응.
- 사용자 확정: **SurfaceHeight는 Enum별 하나를 공유**한다(2026-11-01 답변).
- 앞 단계: [소수 크기 지원](2026-10-31-combat-map-tile-fractional-size-design.md). 소수 크기·기준점·칸 중심 대응·높이·바닥 교체 규칙을 유지한다.
- 계획: [variants-random-rotation-plan](../plans/2026-11-01-combat-map-tile-variants-random-rotation-plan.md).

## 1. 확인한 현재 경로

| 소유자 | 현재 책임 | 바뀌는 부분 |
|---|---|---|
| CombatMapTileSetSO.Entry | kind + prefab 하나 + surfaceHeight | prefab 하나를 prefabs 후보 배열로 확장 |
| CombatMapTileVisual | 종류별 불변 프리팹·높이 | 후보 개수/인덱스 조회와 공유 높이 |
| CombatMapTilesInput / CombatMapTilesData | 칸별 종류·Rotation4 배열 검사/조회 | 바닥 타일 전용 회전 입력 타입 |
| StageMapTiles.Build | 배경 아래 타일 생성·회전 적용 | 칸별 후보/Random 회전 확정 |
| CombatMapTileSurface | 칸 중심의 타일 높이·Transform 표 | 높이가 종류별 공유이므로 현재 책임 유지 |
| CombatStageSoAssets | SerializedObject로 세트/회전 읽기·쓰기 | 후보 배열 읽기, Random 값 보존 |
| CombatStageSoTileScene / CombatStageSoPreview | 에디터 타일 외형·높이/3D 배경 | 같은 미리보기 추첨 결과 소비 |
| CombatLayoutWindow.SoTiles | 종류/회전 편집·정보 표시 | 후보 수/목록, Random 지정/표시, 다시 뽑기 |

현재 회전 타입 Rotation4는 **Core.Contracts의 공용 타입**이다. 여기에 Random을 추가하면 실제 4방향 회전을 쓰는 유닛·Core 계약까지 바뀌므로, 바닥 타일의 입력 옵션을 별도로 둔다.

## 2. 결정안

### TV1 종류별 후보와 높이

```text
CombatMapTileSetSO
  tiles[]
    kind
    prefabs[]       // 후보 1개 이상
    surfaceHeight   // 이 종류의 모든 후보가 공유
```

- 같은 kind는 현재처럼 한 줄만 등록한다. 서로 다른 종류가 같은 프리팹을 참조하는 것은 허용한다.
- 후보 1개면 그 프리팹을 쓴다. 후보가 여러 개면 **칸마다 독립적으로 등록 항목 중 하나를 같은 확률로 선택**한다. 후보를 한 번씩 모두 써야 하는 분배·가중치·인접 중복 방지는 추가하지 않는다.
- 후보 목록이 비었거나 null 항목이 있으면 종류·후보 인덱스·에셋 이름을 담은 구성 예외다. 종류 중복/미정의 값과 유한 높이 검사는 유지한다.
- 데이터는 후보 배열을 소유하고 외부에 수정 가능한 배열을 내보내지 않는다. 후보 개수와 인덱스 조회를 제공한다.
- 같은 종류의 후보는 같은 타일 크기·피벗·윗면 높이로 제작한다. 프리팹별 높이를 별도로 저장하거나 메시에서 자동 추측하지 않는다.

### TV2 회전 입력 옵션

- 새 View 전용 `CombatMapTileRotation : byte`를 둔다: **R0=0, R90=1, R180=2, R270=3, Random=4**.
- 바꾸는 직렬화 대상은 `ViewStageDataSO.stageViewPropData.mapTiles.rotations`다. 지형/오브젝트 외형 회전과 Core Rotation4는 범위 밖이다.
- 기존 0~3 값과 byte 기반 배열 형식을 유지한다. 회전 배열을 비우면 기존처럼 모두 R0이며, Random은 명시적으로 지정한다.
- 정사각 타일의 Random은 0°·90°·180°·270° 중 하나, 직사각 타일의 Random은 **0°·180° 중 하나**다. 수동 90°·270°의 직사각 금지 규칙은 유지한다.
- 결과 각은 프리팹 원래 회전 앞에 타일 루트 기준 Y 회전으로 곱한다. 배경 회전/배율과 화면 방향 변환은 기존 소유자가 처리한다.

### TV3 선택 시점과 수명

- SO.GetData/검사는 후보와 회전 옵션을 읽고 검사할 뿐 **추첨하지 않는다**. DB 조회·저장 검사 때문에 결과가 바뀌지 않는다.
- 런타임은 MapTileRoot를 만드는 `StageMapTiles.Build` 한 번마다 새 표시용 시드를 잡고, 각 칸의 프리팹/실제 회전을 확정한다. 같은 인스턴스의 갱신·높이 조회·타일 숨김/복구에서는 다시 뽑지 않는다.
- 후보 선택과 Random 회전은 서로 다른 추첨 경로를 사용한다. 고정 회전/후보 하나는 그대로 쓴다.
- 이 시드는 전투 규칙/타임라인 난수와 분리한다. UnityEngine.Random의 전역 상태나 Core 난수/Buffer를 사용·수정하지 않는다.
- 결과를 ViewStageDataSO에 덮어쓰지 않는다. 새 전투/배경 재생성에서는 다시 선택할 수 있으며, 이전 전투와 반드시 다른 결과가 나와야 한다는 뜻은 아니다.

### TV4 런타임과 맵 툴의 같은 선택 규칙

- 두 어셈블리가 이미 참조하는 `ProjectL.Tool.Runtime`에 맵 타일의 작은 순수 계산 도우미 `MapTileRandomSelection`을 둔다. Core/Systems/Unity 객체 참조 없이 **표시 시드 + 타일 좌표 + 종류 값 + 후보 수/회전 가능 범위**로 후보 인덱스와 Random 회전 결과를 계산한다.
- 도우미는 후보 추첨과 Random 각 추첨만 담당한다. SO 검사, 입력 Enum 해석, 프리팹 생성, Transform, 높이, 선택 UI를 맡지 않는다. 새 Framework 서비스/Builder/인터페이스는 만들지 않는다.
- 같은 입력에서는 같은 결과를 낸다. 후보와 회전은 별도 구분값으로 선택해 한쪽 옵션 변경이 다른 쪽 추첨 순서를 밀지 않게 한다. 딕셔너리 순회 순서에 의존하지 않는다.
- Systems가 Editor를 참조하거나 Editor가 Systems 내부 구현을 우회 호출하지 않는다. 도구가 기존에 복제한 좌표/맞춤 계산은 이번 범위에서 이관하지 않는다.

### TV5 맵 툴 동작

1. 세트를 읽어 **종류별 후보 목록·개수·공유 높이·사용 칸 수**를 보인다. 후보 등록은 기존처럼 TileSet Inspector에서 한다.
2. '타일' 보기 및 2D/3D의 '타일 회전' 도구에 **Random 지정**을 추가한다. 단일/복수 선택·Ctrl+A·Undo/Redo·초안·저장/재열기를 지원한다.
3. 저장 옵션과 미리보기 결과를 구분한다. Random을 0°로 표시하지 않고 `Random`과 필요 시 현재 예시 각을 함께 보인다. 작은 타일 칸은 `?` 표식+범례를 쓰고 툴팁/칸 정보에 전체 Random 문구와 예시 각을 표시한다. 칸 정보에는 현재 예시 프리팹도 확인할 수 있게 한다.
4. **미리보기용 시드는 창이 소유**한다. Repaint, 마우스 이동, 카메라 조작, 2D/3D 전환, 같은 데이터의 재구성에서는 바뀌지 않는다. 같은 시드·좌표·종류에 대한 결과를 모든 표시가 공유한다.
5. `랜덤 다시 뽑기`는 미리보기용 시드/캐시만 바꾼다. SO·작업본·Undo에 추첨 결과를 기록하지 않는다. 실제 전투의 시드와 같다고 약속하지 않는다.
6. 90° 돌리기/R/Shift+R은 **Random으로 지정한 칸은 그대로 두고 고정 회전 칸만 돌린다**. 고정 각 버튼을 누르면 Random에서 해당 각으로 바뀐다. Random 지정 버튼은 역으로 옵션을 Random으로 바꾼다. 직사각 타일의 허용 각 검사도 이 구분을 따른다.
7. 저장 시 회전 값 4를 그대로 보존한다. Random을 모듈로 4로 바꿔 R0으로 잃는 경로(앞쪽 띠·각 표시·회전 단축키·저장)를 모두 확인한다.
8. 종류별 높이는 후보와 무관하다. 미리보기 재추첨 때문에 유닛 높이/바닥 교체 대상/필드 격자가 바뀌지 않는다.

### TV6 기존 에셋과 작업 트리

- 단일 `prefab`을 `prefabs[]`로 바꾸는 것은 scalar→array라 FormerlySerializedAs만으로 이전할 수 없다. **타일 세트 에셋의 기존 참조 하나를 후보 한 항목으로 명시적으로 이전**한다. 이전 전후 kind·GUID/fileID·높이를 대조한다.
- 조사 시 저장소 TileSet은 `CombatMapTileSet_Temp.asset` 한 개, 종류 4줄이다. 구현 시 다시 검색해 실제 대상 목록을 확정하고, 신규 세트가 있으면 함께 검사한다. 에셋 파일/스크립트 GUID는 유지한다.
- 임의로 새 프리팹 후보를 배정하거나 ViewStageDataSO의 타일 배치/회전 값을 일괄 Random으로 바꾸지 않는다. 기존 배치는 그대로 재현된다.
- 현재 사용자 수정 중인 `CombatMapTileKind.cs`는 Tile1부터 BoundaryConer까지 0 기반 값으로 바뀌어 있다. **이 수정은 유지하고 재번호를 매기지 않는다.** 기존 에셋의 종류 숫자도 그대로 보존한다. 옛 Test 이름/1 기반 설명은 현재 Enum 기준으로 문구만 정리한다. 숫자를 보존하는 이전은 옛 이름의 의미까지 복원하는 작업이 아니므로 종류별 실제 후보 배정은 사용자 확인 대상이다.
- 다른 사용자 에셋/프리팹 변경, Core, FieldCamera, Architecture, 옛 Missing Script 에셋에는 손대지 않는다. 스테이징/커밋은 이번 구현에 포함하지 않는다.

## 3. 구조·계약 검토

| 기준 | 적용 |
|---|---|
| SSOT | 후보/높이는 TileSet, 회전 옵션은 ViewStageDataSO, 추첨 규칙은 공용 계산 도우미, 살아 있는 외형은 생성한 Transform이 소유. 검사 때 추첨/추첨 결과 역저장 없음 |
| SRP | 입력 검사·불변 후보 데이터·선택 계산·생성 적용·편집 표시를 분리. StageViewPropPresenter에 선택 UI나 선택 알고리즘을 추가하지 않음 |
| OCP | 후보 개수가 늘어도 생성 분기나 종류별 switch를 늘리지 않음. 새 필드는 이번 요구 범위로 한정 |
| LSP | 상속/다형 계약 변경 없음. 고정 후보/고정 회전은 기존 결과를 유지 |
| ISP | 계산 도우미에는 좌표/시드/개수만 전달. DB/Framework/전체 화면 상태를 전달하지 않음 |
| DIP | 런타임·Editor 모두 기존 하위 Tool.Runtime의 계산만 사용. 새 상호/상향 어셈블리 참조 없음 |
| JMH/FW | 생성은 기존 StageMapTiles, 배경 수명은 StageViewPropPresenter/씬 연결, Export/루트 Builder/서비스 조회/해제 순서 변경 없음 |
| 기능 독립성 | 후보 선택 변경은 도우미+타일 생성/미리보기 안에 머무름. 높이는 공유 사실이라 CombatMapTileSurface/FieldSurfaceHeights를 수정하지 않음. Core Rotation4 소비자의 수정/회귀를 동반하지 않음 |

대표 변경 시나리오: 지금은 종류에 후보를 추가하려면 단일 프리팹 계약 자체를 바꿔야 한다. 구현 뒤 후보 추가는 TileSet의 배열 편집으로 끝난다. Random 허용 각 정책을 바꿀 때는 타일 선택 규칙·옵션 검사·해당 도구 안내만 확인한다. 공통 좌표계·씬 해제 계약을 바꾸는 경우에는 여전히 타일/지형 통합 회귀가 필요하다.

## 4. 인수 기준

- 후보 하나+고정 회전: 기존 외형/참조/높이/위치 유지. 후보 여러 개: 선택 결과가 반드시 해당 종류 후보 중 하나이며, 칸별로 선택한다.
- Random은 정사각/직사각의 허용 각에서만 나온다. 고정 R0~R270, 빈 배열의 R0, 알 수 없는 값 거절을 확인한다.
- 동일 미리보기 입력은 표시 종류가 달라도 결과가 같고 Repaint로 흔들리지 않는다. 다시 뽑기는 SO를 dirty로 만들지 않는다.
- Random 저장/재열기·Undo/Redo·초안·Resize가 값 4를 유지한다. 섞인 선택의 회전 단축키는 TV5.6을 따른다.
- 배경의 90° 회전/반전·소수 크기, 칸 높이·지형 바닥 교체/복구, 전투 재진입/씬 해제를 대조한다.
- 입력 형식 변경으로 에셋을 이전할 때 실제 GUID/fileID·종류 숫자·높이와 참조 누락을 검사한다. 가능한 컴파일/수치 검증과 Unity 에디터/재생 확인은 구분해서 기록한다.
