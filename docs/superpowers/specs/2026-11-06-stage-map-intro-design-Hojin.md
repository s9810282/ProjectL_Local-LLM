# 스테이지 맵 진입 연출 설계 — 노드 낙하·연결선 그리기·카메라 왕복

- 작성일: 2026-11-06
- 상태: 사용자 승인에 따라 **구현 계획 Phase 1(MI1~MI8) 코드 작성·정적 검토 완료**. **컴파일 미확인**, 사용자 Unity 확인 U1~U9 대기. 시간 설정의 초기 제안값은 Unity 확인에서 조절한다.
- 구현 작업·확인 기록: [맵 진입 연출 구현 계획](../plans/2026-11-06-stage-map-intro-plan-Hojin.md).
- 선행 작업: [노드 낙하 설계](2026-11-06-stage-node-drop-design-Hojin.md), [구현 계획과 확인 기록](../plans/2026-11-06-stage-node-drop-plan-Hojin.md).
- 이 문서는 선행 Phase 1에 없던 후속 기능이다. 기존 계획에 Phase 2가 있었던 것으로 소급하지 않는다.

## 1. 사용자 확인 내용과 제안의 구분

### 확인한 방향

1. 플레이어 쪽에서 사람이 선을 긋듯 **선 끝이 이동하고 지나간 부분이 남는 표현**을 원한다.
2. 최종 구상은 **선이 뻗는 동안 노드가 낙하**하는 것이다. 앞서 논의했던 '모든 노드 낙하 후 선 그리기'는 이 구상으로 바뀌었다.
3. 카메라는 처음 플레이어가 보이는 위치에서 보스 노드까지 보여 준 다음 처음 위치로 돌아온다.
4. 노드 낙하·연결선·카메라 복귀가 끝날 때까지 사용자 카메라 이동과 노드 선택을 막는다. 차단은 후속 기능에서 제거·교체할 수 있는 임시 정책으로 분리한다.
5. 사용자에게 보인 미리보기는 갈림길의 선이 동시에 뻗고, 선 도착과 노드 착지가 맞으며, 카메라가 전개를 따라가다가 보스에서 머문 후 돌아오는 방식이었다. 사용자가 '네 맞아요'로 이 흐름을 확인했다.
6. 2026-11-06 검수 후 사용자가 두 보완을 요청했다. 연결선은 **이미 드러난 점선의 위치·길이·간격을 고정한 채 순차 노출**하고, 낙하 높이는 **현재 운영 에셋의 20 월드 단위를 유지**한다. 높이 30 제안은 폐기한다.

### Codex 제안으로 두는 세부 결정

- 재생은 기존 낙하처럼 **각 Run의 챕터 최초 표시 때 한 번**이다. 전투 복귀·상점/회복 종료·재그리기 때 반복하지 않는다.
- 미리보기 조작 상태의 전개 7초를 초기 설정 제안으로 사용한다. 숫자 자체를 별도로 확정한 것으로 기록하지 않는다.
- 초기 대기 0.6초, 보스 정지 0.9초, 복귀 2.2초를 제안한다. 실제 게임 화면에서 조절한다. 개별 낙하 시간은 현행 0.8초를 유지하며, 낙하 높이는 위 사용자 확정값을 따른다.
- 노드가 화면에 들어왔다는 사실로 재생을 시작하지 않는다. 동일 시간표가 노드·선·카메라를 구동한다.
- 개발 전투 직행 등으로 현재 노드가 시작 노드가 아닌 첫 표시에서는 현재 노드에서 전방으로 도달 가능한 구간만 연출한다. 그 밖의 노드·선은 기존 표시 정책에 따른 최종 상태로 준비한다.

## 2. 목적과 범위

맵이 플레이어부터 만들어지는 모습과 보스까지의 전체 진행 방향을 한 번에 보여 준다. 사용자는 카메라가 돌아온 후 맵을 조작한다.

수정 범위는 StageMap View, 그 설정 SO/Data, 기존 View Factory의 조립 및 관련 가이드·공유 문서다. 선의 순차 노출은 StageMap View가 소유하는 임시 메시로 처리한다(§6). Core·Buffer 구현·FieldCamera·Architecture·공용 Camera/Render/Loading·셰이더·전투 본부 구현·공용 프리팹은 수정하지 않는다. 연결선의 원본 메시·머티리얼·프리팹 에셋도 유지한다. 새 UI 화면·UIId·입력 Layer·공용 서비스 등록은 만들지 않는다.

이번 범위에는 경로 선택 규칙 변경, 손/펜 오브젝트, 손떨림·잉크 텍스처, 새 사운드, 카메라 회전·줌·흔들림, 연출 건너뛰기 버튼, 저장 데이터에 재생 이력을 보존하는 기능은 포함하지 않는다.

## 3. 검토한 표현 방식

| 방식 | 특성·비용 | 결정 |
|---|---|---|
| 낙하와 선 그리기를 맞추고 카메라가 전개를 따라 왕복 | 지금 나타나는 구간을 화면에서 확인할 수 있다. 셋이 같은 시간 기준을 써야 한다 | **미리보기로 확인한 방식** |
| 낙하가 전부 끝난 뒤 선을 그리고, 완성된 맵을 카메라로 왕복 | 기존 낙하와의 결합은 작지만 대기 단계가 길고 화면 밖 낙하를 놓칠 수 있다 | 앞선 순차 구상. 최종 요청에 따라 채택하지 않음 |
| 한 갈래씩 끝까지 그린 다음 다른 갈래로 이동 | 한 사람이 펜 하나로 그리는 인상이 강하다. 분기 사이 시선 이동과 전체 시간이 길어진다 | 동시에 갈라지는 미리보기 확인에 따라 채택하지 않음 |

내부 구현은 **공통 시간표 + 기능별 재생 부품**을 제안한다. 독립 타이머 셋을 나중에 맞추거나 Scope 한 곳에 선 변형·카메라 보간·낙하 수식을 모두 넣는 방식은 동기화·변경 범위를 키우므로 쓰지 않는다.

## 4. 화면에서 보이는 흐름

1. 로딩 중 실제 맵과 현재 플레이어·보스 위치를 읽고, 대상 건물과 선을 숨기고, 카메라 시작 구도를 준비한다.
2. 로딩이 끝나면 시작 구도를 0.6초 보여 준다. 이때도 맵 조작은 잠긴다.
3. 플레이어에서 선 끝이 전방으로 움직인다. 갈림길에서는 각 선이 동시에 시작한다. 각 다음 노드는 그 선이 도착할 때 착지하도록 조금 앞서 낙하를 시작한다.
4. 선은 바닥에 남고 이미 드러난 점선의 위치·길이·간격은 변하지 않는다. 선 끝이 점선의 빈 구간을 지나면 다음 점선이 나올 때까지 새로 보이는 부분은 없지만 진행 시간은 계속 흐른다. 공중의 건물 Transform을 따라 들리거나 휘지 않는다. 건물이 착지하면 기존 FallingRocks를 한 번 재생한다.
5. 카메라는 선의 전개 진행도에 맞춰 맵 진행 축을 따라 보스 쪽으로 이동한다. 기존 각도·배율은 유지한다.
6. 보스까지 전개되면 0.9초 머문 뒤 2.2초 동안 부드럽게 처음 구도로 돌아온다. 복귀 중 새 낙하·선 재생을 반복하지 않는다.
7. **건물 착지·선 완성·카메라 복귀·착지 효과 정리**를 모두 만족하면 진입 연출을 완료한다. 기존 효과 자연 종료 또는 마지막 착지 후 게임 시간 3초 상한을 유지한다. 효과 대기는 카메라 정지·복귀와 동시에 진행한다.
8. 임시 차단을 풀고 보류 팝업 복원 → 기존 증강/선택 UI 처리 → 호버를 기존 순서로 재개한다.

보스까지의 화면 이동 시간은 기존 낙하의 짧은 전개 시간과 별개로 충분히 확보한다. 개별 낙하의 모양·현재 높이·시간은 유지하면서 **노드별 착지 예약 시각**을 넓히는 방식이다.

## 5. 시간표와 분기·합류 규칙

### 기준 데이터

- 연결 관계·역할·현재 노드·RunId는 기존 Buffer에서 읽는다. 표시 위치는 실제 배치된 노드 루트에서 얻는다. View가 InGame DB를 다시 읽거나 Core 진행을 바꾸지 않는다.
- 현재 노드에서 `NextNodeIds`를 따라 도달 가능한 전방 노드와 간선을 수집한다. 현재·클리어 건물·시작 장식·플레이어 마커의 표시 정책은 `StageNodeView`가 결정한다. 선은 이 건물 숨김과 별도로 유지한다.
- 맵의 실제 위쪽 축과 진행 축을 사용한다. 진행 방향 거리 `s`는 현재 노드에서 해당 노드까지의 월드 위치 차이를 맵 진행 축에 투영한 값이다.
- 보스가 전방의 마지막 지점이며 `sBoss > 0`인 구간에서 `q(node) = s(node) / sBoss`로 진행도를 구한다. 각 대상 간선은 `q(to) > q(from)`이어야 한다. 누락 노드·중복 보스·도달 불가능한 보스·비유한 좌표·0 길이·역방향 간선은 대상을 명시한 구성 오류로 처리한다.
- 현재가 보스이고 전방 간선이 없으면 연출할 구간이 없으므로 즉시 최종 표시한다. 이 경우 분모 0으로 계산하거나 불필요한 왕복을 만들지 않는다.

### 공통 시각

`H = 시작 대기`, `R = 전개 시간`, `D = 사용 중인 개별 낙하 시간`으로 둔다. 높이가 0이거나 낙하가 꺼져 있으면 시간표의 유효 `D`는 0이다.

- 낙하 대상 중 가장 작은 `q`를 `qMin`으로 두고, `P = max(0, D - qMin * R)`를 계산한다. 낙하 대상이 없으면 `P = 0`이다. 이 파생 여유 시간은 SO에 저장하지 않는다.
- 전개 시작 `T0 = H + P`, 노드 도착 `A(node) = T0 + q(node) * R`, 플레이어의 출발 시각은 `A(player) = T0`다.
- 건물 낙하는 `A(node) - D`부터 `A(node)`까지 진행한다. 앞부분이 너무 짧아도 초기 대기 이전으로 낙하가 잘리지 않는다. `D = 0`이면 예약 착지 시각에 바로 배치한다.
- 각 선의 시작은 `A(from)`, 끝은 `A(to)`다. 완성 상태의 시작/끝 좌표는 고정하고, 노출 경계를 0→1로 선형 이동한다. 한 선 안에서는 노출 경계의 속도가 일정하지만, 가로 길이가 다른 모든 선의 월드 속도를 같게 강제하지 않는다.
- 합류 노드의 도착 시각은 한 개다. 여러 진입선은 모두 같은 시각에 도착하고, 건물 낙하·착지 효과는 노드별 한 번만 실행한다. 출발선은 그 시각부터 이어진다.
- 카메라 전진은 `T0`부터 `T0 + R`까지다. 개별 선이 화면에 보이는지·카메라가 도착했는지를 낙하 시작 조건으로 삼지 않는다.

이 결정은 선행 낙하의 **플레이어와의 평면 직선거리별 지연**을 **맵 진행 축 기반 공통 시간표**로 바꾸는 제안이다. 앞으로 퍼지는 인상은 유지하면서, 가로 위치가 다른 같은 진행 지점의 노드도 동시에 착지한다. 설계 승인 후에만 변경한다.

## 6. 선과 카메라의 표시 책임

### 연결선

현재 `StageLinkView`는 XY Quad 프리팹의 local Y를 선 길이로, local X를 폭으로 사용한다. 운영 `StageMapConnection.mat`는 `AreaOutline.shader`의 UV.x 기준 점선을 사용하며 현재 `_DashEnabled = 1`, `_DashCount = 10`, `_DashFill = 0.48`, `_FlowSpeed = 0`이다. 연결선 메시의 UV.x는 길이 방향으로 0→1이다. Transform 길이만 줄이면 짧아진 구간에도 점선 10개가 모두 배치되어, 전개 중 이미 보인 점선의 위치·간격이 달라진다.

이를 막기 위해 **완성 배치 고정 + StageMap 전용 임시 메시의 정점·UV 구간 절단**을 사용한다. 공용 셰이더의 노출 속성 추가나 공용 머티리얼 값 변경은 필요하지 않다.

- 표시 부품은 시작/끝의 고정 지면 좌표와 최종 Transform·원본 Mesh·Renderer 표시 상태를 보관한다. 완성 중점 `(start + end) / 2`와 전체 길이·회전·높이는 전개 동안 고정한다. 원본 Quad의 출발/도착 정점과 UV 대응을 준비 때 확인하며, 지원하지 않는 메시 구성은 대상 선을 명시한 오류로 처리한다.
- 대상 선마다 원본 Mesh를 복사한 임시 Mesh를 한 번 준비한다. 진행률 `p`에서 출발 쪽 정점은 그대로 두고, 도착 쪽 두 정점을 각각 원본 출발→도착 정점 사이의 `p` 위치로 옮긴다. 도착 쪽 UV도 원본 출발→도착 UV 사이의 `p` 값으로 보간한다. 표면의 노출 경계만 움직이므로 지나간 위치의 UV와 점선 무늬는 고정된다.
- 길이 방향 UV를 잘라낸 구간에 다시 0→1로 정규화하지 않는다. `_DashCount`를 진행률에 곱해 조정하는 방식도 쓰지 않는다. 이 셰이더는 개수를 정수로 반올림하므로 패턴이 단계적으로 바뀔 수 있다. 원본의 점선 설정은 읽기 기준이며 View에 같은 상수를 복제하지 않는다.
- `p = 0`이면 Renderer를 숨겨 길이 0의 흔적을 막는다. `0 < p < 1`에서는 임시 메시를 표시한다. 원본 전체 Bounds는 부분 메시도 포함하므로 유지할 수 있으며, 새로 드러난 부분이 잘못 컬링되지 않아야 한다. 정점/UV 작업 배열은 준비 때 재사용 가능하게 만들고 매 Tick마다 Mesh·배열을 생성하지 않는다.
- `p = 1`, 연출 생략, 취소에서는 원본 Mesh와 최종 표시 상태를 복원하고 임시 Mesh를 해제한다. 완성 직전/직후 점선 무늬·색상·폭이 튀지 않아야 한다. 원본 `sharedMesh`의 정점·UV, 공유 머티리얼 값에는 쓰지 않는다.
- 호버는 기존 색상·폭만 다루고, 그리기는 임시 메시의 노출 구간과 숨김만 다룬다. 연출 동안 호버는 차단하고, 완료 뒤에는 원본 메시로 기존 호버를 재개한다. 별도 MaterialPropertyBlock을 덮어써 ColorHandle의 값을 지우지 않는다.
- 선의 GameObject·ColorHandle·임시 Mesh의 소유권은 `StageLinkView`에 남긴다. `StageLinkDrawPresentation`은 진행률 전달과 완료/취소 조정만 하며 자원을 중복 생성·해제하지 않는다. 임시 Mesh는 View가 직접 생성한 Unity 자원으로, Framework에서 대여한 Mesh/Effect/Color 자원과 구분한다.
- Clear 순서는 연출 참조 해제→원본 Mesh 재연결→소유한 임시 Mesh 해제→ColorHandle 반환→선 GameObject 파괴다. 부분 준비 실패·반복 취소·늦은 이전 세대 정리에서도 자기 임시 Mesh만 해제하고 새 표시나 원본 에셋은 건드리지 않는다.
- 같은 맵 재그리기·재사용 경로에서도 새 선과 재사용 선의 대상 수집/최종 복원 계약이 동일해야 한다. 최초 로딩 Reveal 전에 건물과 선 모두 준비되어야 한다.

### 카메라

현재 `StageMapCameraDrag`가 Catalog 핸들 한 개와 기준 구도·진행축 offset을 소유한다. 자동 왕복도 **동일한 소유자**의 좁은 제어 창구를 사용한다.

- 생성·바인딩·최초 구도 반영·노드 범위 설정 뒤 시작 구도와 offset을 한 번 보관한다. 초기 구도는 실제 플레이어가 화면에 보이는지 확인하고, 필요한 진행축 보정은 로딩이 덮인 준비 단계에 끝낸다.
- 보스 목표 offset은 실제 보스 위치를 기존 맵 평면·진행축 계산에 넣어 구한다. 기존 허용 범위의 끝이 작성 구도를 포함하려고 넓어진 경우가 있으므로 단순히 최대 offset을 보스로 간주하지 않는다.
- 자동 연출은 시작 offset→보스 offset을 전개 시간에 맞춰 이동하고, 복귀에는 시작/끝 속도가 0인 보간을 사용한다. 회전·렌즈·맵 가로 구도는 바꾸지 않는다. 끝에는 보관한 offset을 정확히 복원한다.
- 자동 조작 소유권을 얻을 때 진행 중 드래그를 끝낸다. 종료·취소 때 연출 소유권을 먼저 반환한 뒤 일반 조작으로 넘긴다. 드래그의 내부 기준 offset도 함께 맞아야 첫 수동 입력에 카메라가 튀지 않는다.
- `CinemachineVirtualCamera`나 출력 Camera의 Transform을 연출이 직접 덮어쓰지 않는다. 별도 Catalog 핸들을 빌려 같은 카메라에 경쟁하는 쓰기를 만들지 않는다.
- 카메라 핸들이 아직 준비되지 않았으면 로딩 준비 상태에서 기다린다. AfterLoad에서 이루어지는 기존 핸들 대여를 로딩 완료 뒤로 옮겨 상호 대기를 만들지 않는다.
- 에디터 Alt 구도 조작도 진입 연출 중에는 차단한다. 자동 소유 중 `PreviewCameraFraming`의 적용을 보류하고, 구도 설정의 사용자 저장값 자체는 변경하거나 되돌리지 않는다.

## 7. 수명과 재생 이력

- `StageNodeDropHistory`의 Run/챕터 이력을 **맵 진입 연출 전체의 이력 한 개**로 일반화한다. 낙하·선·카메라별 HashSet을 만들지 않는다. 기존 클래스 이름/참조 변경 시 `.meta` GUID를 유지한다.
- 실제 연출 표시/카메라 변경을 시작하기 직전에 최신 Run/맵/Scope 세대를 검사하고 시작 이력을 기록한다. 로딩 준비·초기 대기만으로는 기록하지 않는다.
- 시작 전 취소는 다음 진입에서 재시도하고, 시작 후 취소는 같은 Run/챕터 재진입에서 최종 표시만 한다. 새 Run은 기존 `RunId` 비교로 이력을 초기화한다.
- 이미 본 챕터는 낙하·선 그리기·자동 왕복을 모두 생략한다. 일반 복귀의 현재 플레이어 표시/카메라 정책은 기존 경로에 맡기고 왕복용 스냅샷을 다시 적용하지 않는다.
- 최초 배치 준비는 `StageMapLoadingPreparation`의 Complete 조건이며 연출 재생 완료와 다르다. 준비가 낙하·카메라 종료나 `IsLoading == false`를 기다리면 안 된다.
- 공통 진행은 scaled time으로 계산한다. 설정 창을 열면 낙하·선·카메라·보스 정지·효과 대기 상한이 함께 멈춘다. 설정 입력은 임시 맵 차단의 대상이 아니다.
- 큰 deltaTime으로 여러 착지를 한 Tick에 처리해도 각 효과는 한 번만 재생한다. 실제 효과를 생성한 Tick의 앞선 시간까지 효과 대기 경과로 재사용하지 않는다.
- 이탈·오류·Run/맵 교체·재그리기·재연결은 세대를 무효화한 뒤 하위 연출을 취소한다. 효과 반환→건물/선 복원→카메라 자동 소유 해제→표시 파괴/핸들 반환 순서를 보장한다. 한 정리의 예외로 다른 정리를 건너뛰지 않는다.
- 현재 살아 있는 Scope의 취소에서는 시작 카메라 구도를 복원한다. 이미 새 Scope에 소유권이 넘어갔거나 핸들이 해제된 경우에는 이전 연출이 카메라에 다시 쓰지 않는다.
- 준비·재생·정리 예외는 기존 `RuntimeFaultBoundary`에 보고한다. 실패를 정상 완료로 처리해 조작을 허용하지 않는다.

## 8. 임시 입력 차단

연출 부품이 입력 서비스를 직접 잠그거나 해제하지 않는다. `StageMapIntroInteractionPolicy` 한 곳이 전체 연출의 진행 상태를 읽어 **추가로 차단할지** 결정하고, 기존 준비·팝업·요청 대기·Layer·오류 조건과 조합한다.

| 입력/행동 | 진입 연출 중 |
|---|---|
| 노드 누름·뗌·최종 진입 요청 | 차단 |
| 노드 호버 설명·윤곽선·선 강조 | 차단 |
| 배경 드래그 시작·이동, 휠 이동 | 차단 |
| 에디터 Alt 이동·회전·돌리·휠 | 차단 |
| 새 선택 팝업·보류 상점/회복 복원 | 기존처럼 보류 |
| 설정 창 열기·닫기 | 허용, 게임 시간 정지/복원 |
| 시스템이 소유한 카메라 자동 연출 | 실행 |

차단 시작 때 기존 누름·드래그를 정리하고, 차단 중 새 누름은 Blocked로 소유한다. 완료 뒤 놓기만 해서 노드 진입이나 드래그가 시작되지 않으며 새 누름부터 허용한다. 휠 입력은 축적하지 않는다. 설정/팝업/Layer 해제의 기존 전체 Cancel도 유지한다.

선행 구현의 '연출 중 배경 드래그를 보존하는 TickHover 분기'를 새 정책과 함께 정리한다. 매 프레임 포인터 전체를 초기화해 Blocked 소유권을 잃는 방식으로 바꾸지 않는다.

후속 기능에서는 이 추가 차단 정책과 조립 지점을 교체한다. 낙하 수식·선 변형·카메라 시간표 안에 입력 제한 조건을 흩어 놓지 않는다. 준비 실패·화면 미연결·팝업 독점 같은 원래 안전 조건은 임시 차단 제거와 무관하게 유지한다. 자동 카메라와 수동 카메라의 소유권 전환은 후속 기능에서 결정하며, 정책 제거를 같은 핸들에 두 제어자가 동시에 쓰는 것으로 구현하지 않는다.

## 9. 부품과 설정

아래 이름은 구현 계획 작성자가 조정할 수 있지만 책임·상태 소유자는 바꾸지 않는다.

| 부품 | 책임·수명 |
|---|---|
| 기존 StageMapViewSystem / 일반화한 IntroHistory | Run/챕터 최초 시작 이력 한 개, Effects의 기존 System 수명 유지 |
| StageMapIntroTimeline | 배치 좌표·연결에서 한 번 만드는 불변 예약 시각. 초기 여유 시간·합류 시각 계산 |
| StageMapIntroPresentation | Scope 수명의 유일한 경과 시간·준비/재생/완료/취소 상태, 하위 Tick과 완료 조합. 표시 수식은 소유하지 않음 |
| 기존 StageNodeDropPresentation의 역할 정리 | 예약 시각을 받아 건물 낙하·착지·효과 완료 관리. 자체 챕터 이력·거리 지연 계산 제거 |
| StageLinkDrawPresentation / StageLinkView | 전자는 선별 진행률·완료/취소를 조정. 후자는 고정 배치·임시 메시의 정점/UV 노출·원본 복원 및 GameObject/ColorHandle/임시 Mesh 소유 |
| StageMapCameraTour | 전진·정지·복귀 보간, 동일 카메라 소유자의 제어 창구 사용 |
| StageMapIntroInteractionPolicy | 전체 진행에 따른 제거 가능한 추가 입력 차단 |
| 기존 StageMapSceneFactory | 설정·의존성·부품 생성과 주입 |
| 기존 StageMapViewScope | 준비/연결/해제 호출, 기존 입력·팝업 조건과 연출 완료 연결. 각 연출 수식은 구현하지 않음 |

하위 부품은 공통 시간표의 해당 값과 필요한 대상/계약만 받는다. 전체 Services·Buffer·다른 연출 객체를 통째로 넘기지 않는다. 매 프레임 그래프 탐색·씬 검색·배열 재생성을 하지 않는다.

`StageMapView_Default`의 View 설정에 `Map Intro`를 추가하는 안을 제안한다.

| 설정 | 초기 제안값 | 조건 |
|---|---:|---|
| Enabled | true | 전체 진입 연출 사용 여부 |
| Start Hold Seconds | 0.6 | 유한한 0 이상 |
| Reveal Seconds | 7 | 유한한 양수. 실제 값은 Unity 인수 때 조절 |
| Boss Hold Seconds | 0.9 | 유한한 0 이상 |
| Return Seconds | 2.2 | 유한한 0 이상. 0이면 복귀 시작 때 즉시 시작 구도로 복원 |

기존 `Node Drop`의 Enabled·Height·Seconds는 개별 낙하 표현 설정으로 유지한다. **사용자가 확정한 Height = 20을 보존**하며 운영 SO 값을 30으로 덮어쓰지 않는다. `Wave Spread Seconds`는 새 공통 전개 시간과 역할이 겹치므로 **새 구현에서 제거**하고 생성자·SO·에셋·가이드를 함께 맞춘다. 사용하지 않는 두 시간 필드를 함께 노출하지 않는다.

- 전체 Enabled가 꺼져 있으면 최종 표시, 효과/왕복/최초 시작 기록 없음.
- 개별 Node Drop이 꺼져 있으면 건물은 최종 상태로 준비하고 선·카메라는 정상 전개한다. 노드 낙하가 없어도 전체 이력은 실제 선/카메라 시작 때 기록한다.
- Height 또는 Seconds가 0이면 해당 예약 도착 때 즉시 착지하고 기존 착지 효과를 재생한다.
- 건물 낙하 대상이 없어도 선·카메라 대상이 있으면 해당 연출은 진행한다. 전체 시각 변화 대상이 없을 때만 즉시 완료하고 기록하지 않는다.
- 현재 위치·클리어 건물은 기존대로 숨기고 효과도 재생하지 않는다. 경로 위의 숨긴 건물 때문에 선 진행이나 합류 시각을 없애지 않는다.

SO 입력→불변 View Data 변환/검사와 운영 에셋 값을 함께 변경한다. 런타임 진행·재생 이력은 SO에 저장하지 않는다.

공통 수명 변경까지 독립 확인이 가능한 것처럼 주장하지 않는다. 특히 기존 낙하와 카메라 입력의 공유 계약을 바꾸므로 그 회귀는 이번 인수 범위다.

## 11. 구현 계획에 포함할 확인 항목

- 챕터 1·2 최초 진입: 로딩 Reveal 이전 완성 건물/선 노출 없음, 플레이어에서 시작, 분기 동시 전개, 합류 착지/효과 한 번, 선 끝과 착지 일치.
- 연결선 순차 노출: 동일한 선의 25%·50%·75%·100% 진행에서 이미 나타난 점선의 지면 위치·길이·간격이 같고, 앞부분이 늘어나거나 사라지지 않음. 점선 빈 구간에서도 시간표는 이어지며 선 도착/착지 시각은 변하지 않음. 대각선·맵 회전/비균일 스케일·긴/짧은 선에서도 최종 원본과 일치.
- 선 자원: 완성·생략·취소·재사용·부분 준비 실패 후 원본 메시 복원, 임시 Mesh 누적 없음, 공용 메시/머티리얼 값 불변, 새로 드러난 부분의 컬링 정상, ColorHandle/호버 복원 정상.
- 카메라: 전개 구간이 보이며 보스까지 이동, 보스 정지, 정확한 시작 구도 복원, 이후 첫 드래그·휠에 튐 없음. 회전/비균일 스케일 맵과 작성 구도 포함.
- 완료 조건: 낙하만 끝났거나 선만 끝났거나 카메라가 아직 돌아오는 동안 조작이 열리지 않음. 효과 상한 경고·회수는 기존 계약대로 한 번.
- 입력: 일반 드래그·휠·노드 클릭·호버와 에디터 Alt 우회 차단. 차단 중 누른 채 완료 후 뗌에 동작 없음. 완료 후 새 입력 정상.
- 설정 창: 시작 대기·낙하·선·보스 정지·복귀·효과 대기의 정지/재개. 정지 중 취소는 즉시 정리.
- 재진입: 같은 Run/챕터 생략, 다음 챕터와 새 Run 재생, 시작 전/후 취소 구분, 개발 중간 노드 첫 진입과 현재 보스 처리.
- 생명주기: 씬 이탈·재그리기·오류·재연결에서 선/노드 복원, 효과 반환, 늦은 이전 세대의 카메라/표시 쓰기 없음.
- 설정: 운영 낙하 높이 20 유지, 전체 꺼짐, 낙하만 꺼짐, 높이/시간 0, 보스 정지/복귀 0, 전개 시간/배치 깊이 변화로 초기 여유 시간 발생, 대상 없음.
- 기존 팝업 복원·선 호버 폭/색·카메라 구도 도구·FallingRocks 반복 크기 유지. SO 변경 후 기존 `DataBaseAssetTests`는 사용자 Unity 확인 항목이다.

View 테스트 코드·시험 도우미 작성, MSBuild·Unity 실행, 커밋·push를 하지 않는다. 구현 후 정적 확인과 사용자 Unity 확인을 구분해 **컴파일 미확인**을 보고한다. 기존 도구로 재현 불가능한 예외 경로는 미재현으로 기록한다.

## 12. 다음 단계와 현재 상태

사용자는 검수 후 두 항목 보완에 이어 이 설계를 기준으로 구현 계획 작성을 요청했다. 이에 따라 위 계획에 작업 계약과 Phase를 정리했다. 계획 작성 요청을 게임 코드 구현 승인으로 확대하지 않으며, 시간 설정의 제안값을 Unity에서 확정한 것으로 기록하지 않는다.

- 2026-11-06 별도 문맥의 구현 계획 관점 검토 완료: 시간표/합류, 카메라 소유권/로딩, 현재 노드 이후 부분 그래프, 설정/이력 이전, 임시 차단 분리, 취소/정리를 확인했다. 구현 계획을 바꿀 중요한 미결정 질문 없음. 정적 설계 검토이며 컴파일·실행 증거가 아니다.
- 2026-11-06 후속 정적 검수에서 기존 UV 점선에 Transform 길이 증가를 적용하면 이미 그려진 패턴도 늘어나는 문제 1건과, 현행 높이 20/문서 제안 30의 차이를 확인했다. 사용자의 보완 요청에 따라 §1·§2·§4~§6·§9~§11에 고정 패턴의 순차 노출, 임시 메시/UV와 자원 소유·복원, 높이 20 유지 및 확인 항목을 반영했다. 문서 보완이며 구현·실행 검증 완료를 뜻하지 않는다.
- 2026-11-06 사용자 요청에 따른 구현 계획 작성: 단일 Phase의 MI1~MI8에 시간표·고정 점선 노출·낙하 이전·카메라 왕복·수명·입력·인계를 배정했다. 자세한 계약과 사용자 Unity 확인 항목은 계획이 소유한다.
