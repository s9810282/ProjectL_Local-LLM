## 현재 구현 근거

- `CombatEntryNexusAppearance`는 `height * (1 - t * t)`로 필드 위쪽 축에서 완성 위치까지 가속 낙하하고, 착지 때 `EffectType.FallingRocks`를 지면에 재생한다. 착지 이펙트의 자연 종료를 기다리되 최대 3초의 대기 상한이 있다.
- 운영 `CombatPresentationSettings_Default.asset`의 `nexusDrop`은 높이 30, 낙하 시간 0.8초다. 클래스 초기값 10·0.6초와 구분한다.
- `StageNodeView`는 현재 위치·클리어 노드의 건물을 숨긴다. `StageMapViewReader`는 기존 Buffer의 현재 노드를 읽으며, 선택 전에는 시작 노드를 현재 위치로 쓴다.
- `StageMapViewScope.RefreshDisplay`에서 배경·노드·현재 마커·카메라 범위를 구성한다. 전투 복귀 때 Scope가 다시 만들어지므로 최초 재생 기록은 그보다 긴 수명에 있어야 한다.
- 기존 `IBufferQuery.RunProgressReadSink.RunId`로 새 Run을 구분할 수 있다. Core나 Buffer를 수정할 필요가 없다.
- Stage 진입은 맵 생성 Job을 등록하고, 실제 맵 Buffer와 노드 표시는 이후 Tick에서 준비된다. 로딩은 씬 준비 작업이 없으면 AfterLoad 뒤 바로 Reveal하므로, `IsLoading` 조회만으로는 최초 배치·숨김 완료를 보장하지 못한다.
- `EffectScope.Play`는 완료 손잡이를 반환하지 않는다. 효과의 자연 종료 시에는 기존 `ParticleStopNotifier` → EffectScope → 풀 반환 경로가 효과 객체를 받침에서 풀 루트로 옮긴다.
- `StageMapInteraction`의 포인터·누름·뗌은 선택 UI의 표시 여부와 별도로 수신된다. `RestoreNoncombat`도 최초 표시 직후 직접 호출되므로 선택 UI의 열기 조건만 바꾸어서는 입력·팝업을 함께 보류할 수 없다.
- `OptionUI.Open`은 `Time.timeScale = 0`으로 게임 시간을 멈추고, 운영 `FallingRocks.prefab`의 파티클은 `useUnscaledTime = 0`이다.

## 접근 방식과 제안

권장: 스테이지 전용 낙하 부품을 추가하고, 기존 Render Effect 서비스를 통해 본부와 동일한 `FallingRocks`를 사용한다. 낙하 수식은 동일하게 적용하며 설정은 스테이지 View 설정에 둔다. 스테이지 속도를 조절할 때 전투 본부의 수치가 함께 바뀌지 않는다.

대안: 전투 본부 연출을 공용 낙하 실행기로 추출해 양쪽에서 사용한다. 중복된 수식은 줄지만 전투 개체의 자세 대여·HUD·이펙트 완료 계약까지 분리해야 해 변경 및 사용자 확인 범위가 커진다. 이번 노드 연출에는 권장하지 않는다.

전투 본부 클래스를 그대로 호출하는 방식은 전투 개체 ID·자세 대여·필드 Mapper에 의존하므로 제외한다. 두 기능이 사용하는 Effect 종류·프리팹은 기존 Render DB 한 곳을 원본으로 유지한다.

## 화면 동작 제안

1. Stage 전용 `ILodingPreparation`으로 유효한 Run·맵·현재 노드가 준비되기를 기다린다. 로딩 화면이 걷히기 전에 최종 노드 배치·현재 플레이어 위치·카메라 범위를 확정하고, 낙하 대상 건물을 숨긴 뒤 준비를 완료한다. 실제 낙하와 최초 재생 기록은 로딩 종료 후 시작한다.
2. 대상은 기존 정책상 표시되는 일반·보스 노드 건물이다. 현재 위치·클리어 건물을 다시 켜지 않는다. 시작 지점 장식, 플레이어 마커, 배경과 연결선은 낙하시키지 않는다.
3. 플레이어가 서 있는 현재 노드에서 각 대상 노드까지의 맵 평면상 실제 월드 거리를 사용한다. 노드 번호·목록 순서·그래프 연결 단계로 정렬하지 않는다.
4. 가장 가까운 거리를 `dMin`, 가장 먼 거리를 `dMax`라 할 때 시작 지연은 `(distance - dMin) / (dMax - dMin) * waveSpreadSeconds`다. 거리가 같거나 대상이 하나면 지연은 0이며, 같은 거리의 노드들은 함께 시작한다.
5. 시작할 차례가 되면 각 건물을 자기 착지 위치 위에서 보여 주고 맵의 위쪽 축 반대 방향으로 낙하시킨다. 노드 자리와 연결선의 기준 Transform은 고정하고 건물 외형만 움직인다.
6. 착지 때 건물의 원래 위치·회전·크기를 정확히 복원하고, 해당 노드 지면에서 `FallingRocks`를 한 번 재생한다.
7. 모든 건물 착지와 착지 이펙트 종료 후 선택·호버·기본 윤곽선·팝업 열기를 허용한다. 마지막 착지 후 게임 시간으로 최대 3초가 지나면 남은 효과를 회수하고 기다림을 끝낸다. 보류한 비전투 팝업 복원은 현재 문맥을 다시 읽어 실행한다. 설정 메뉴는 기존처럼 열 수 있으며, 열려 있는 동안 낙하·파티클·완료 대기가 함께 멈춘다.

초기 튜닝 제안: 낙하 높이 30 월드 단위, 노드별 낙하 시간 0.8초, 가장 가까운 대상과 가장 먼 대상의 시작 차이 0.6초. 세 값과 사용 여부를 스테이지 View SO에서 조정한다. 시간·높이 0은 즉시 처리하고, 음수·비유한 값은 구성 오류로 거절한다.

## 로딩 준비 계약 — 검수 보완 1

- `StageMapViewSystem.Initialize`에서 기존 `RegisterScenePreparation(SceneIndices.Stage, ...)`로 Stage 전용 준비 작업을 등록한다. 씬 진입마다 새 Pending 작업을 만들고, Factory가 현재 씬 Scope의 준비 창구와 연결한다.
- 준비 작업은 기존 Buffer를 읽어 유효한 RunId·챕터 맵·현재 노드가 준비됐는지 확인한다. Stage Job이 아직 데이터를 만들지 않은 정상 대기는 Pending이며, 빈 값을 준비 완료로 취급하거나 View가 Core의 맵 생성 API를 대신 호출하지 않는다. 구성 오류·유효하지 않은 데이터·런타임 오류는 기존 오류 경계에 보고하고 Failed로 종료한다.
- 준비 완료 조건은 배경·최종 노드·마커·카메라 범위 구성과 낙하 대상 수집·숨김까지 성공한 것이다. 준비 작업과 일반 Scope Tick은 같은 준비 창구를 사용하여 노드를 이중 생성하거나 준비한 외형을 다시 켜지 않는다. 연출을 생략하는 재진입도 최종 맵 준비는 완료해야 한다.
- 준비 작업은 **`IsLoading == false`를 기다리지 않는다.** 준비 완료가 먼저 Reveal을 허용하고, 별도의 연출 Tick이 `IsLoading == false`를 확인한 뒤 낙하를 시작한다. 준비와 재생이 서로 기다리는 구조를 만들지 않는다.
- 준비 중에는 첫 노드가 생성되는 순간부터 연출 대상 외형의 Renderer 표시를 억제한다. 최종 배치 후 실제 대상이 아닌 외형은 기존 표시 정책으로 복원한다. 노드·플레이어 위치 사실과 GameObject의 현재/클리어 활성 정책은 기존 소유자가 유지한다. 로딩 표현이 없는 개발 진입에서도 완성 건물이 먼저 나타났다 숨는 프레임을 만들지 않는다.
- 준비가 성공하면 준비 작업의 임시 참조·대여·구독을 정리한다. 준비된 표시와 낙하 상태는 씬 Scope의 연출 부품이 계속 소유한다. 취소는 반복 가능하며, 씬 이탈·Scope 교체·Run/맵 문맥 상실 시 그 준비 작업은 Cancelled로 끝나고 새 연결에 영향을 주지 않는다.

## 이펙트 완료 판정 계약 — 검수 보완 2

- 스테이지 전용 효과 부품이 EffectScope와 착지 받침을 관리한다. 낙하 부품에는 재생·완료 조회·취소에 필요한 좁은 창구만 넘긴다. `EffectScope`에 존재하지 않는 완료 조회나 반환값을 가정하지 않는다.
- 효과 하나마다 그 효과만 자식으로 두는 고정 받침을 사용한다. `Play` 성공 후 받침에서 효과가 풀로 반환되어 `childCount == 0`이 되면 그 재생의 자연 종료로 판단한다. 받침에는 다른 장식이나 노드 외형을 자식으로 넣지 않는다. 이는 기존 전투 `CombatEffectFollower.IsFree`와 같은 반환 관찰 방식이다.
- 받침과 완료 조회에는 씬 연결/재생 세대를 함께 묶는다. 재사용된 받침의 이전 조회는 새 효과를 가리키지 않는다. 같은 EffectScope를 재사용하더라도 현재 소유 세대만 `StopAll`을 호출할 수 있어야 하며, 이전 Scope의 반복 정리가 새 연결의 효과를 회수하지 않는다.
- 모든 노드가 착지하고 각 효과가 자연 종료되면 완료한다. 마지막 착지 이후 3초의 게임 시간 상한을 넘기면 경고를 한 번 남기고 현재 소유 효과를 `StopAll`로 반환한 뒤 완료한다. 효과가 없는 정상 생략 경로는 이 대기를 만들지 않는다.
- `ParticleStopNotifier.Play`의 콜백을 교체하거나 빌린 효과 객체를 직접 파괴하지 않는다. 정상 종료·시간 상한·오류·씬 이탈 모두 효과 반환을 완료한 뒤 자신이 만든 받침을 정리한다.

## 입력 차단과 팝업 복원 계약 — 검수 보완 3

- 준비 대기부터 낙하·착지 효과 대기까지의 진행 상태는 연출 부품 한 곳이 소유한다. Scope는 이 상태에서 노드 입력·표시·팝업 허용 여부를 파생하며, 별도의 동기화용 완료 플래그를 복제하지 않는다.
- `CanShowSelection`만 막지 않고 `StageMapInteraction`의 노드 호버·누르기·떼기 수신과 최종 `RequestEntry` 경로에서도 같은 허용 조건을 확인한다. 차단 시작 시 기존 노드 누름·호버를 지우고, 차단 중 누른 입력은 종료 뒤 떼더라도 확정하지 않는다. 연출 완료 후의 새 누름부터 선택을 받는다.
- 호버 설명의 즉시 알림과 Tick의 기본/호버 윤곽선도 함께 차단한다. `StopInput`은 씬 해제용 영구 정지이므로 임시 연출 차단에 사용하지 않는다. 기존 입력 Layer·설정 창 수명과 카메라 드래그·휠 정책은 유지한다.
- `InterceptEntry`, `CanOpenDeckEdit`, `OpenTraitGrowthWhenIdle`, `RestoreNoncombat`와 개발 도구 진입 조건에 연출 대기를 반영한다. 설정 메뉴의 공용 열기·닫기는 기존 경로를 유지한다.
- `StageMapSelectionPresentation.CanOpenScreens`는 부모 화면 수명의 계약으로 유지한다. 초기 StageSelect 열기 예약을 보존한 채 `CanShowSelection`으로 열기를 보류하고, 연출을 숨기기 위해 그 예약까지 지우는 `HideSelection`을 호출하지 않는다.
- 최초 표시 직후 또는 진입 결과 관찰에서 요청된 `RestoreNoncombat`은 연출 중 단순 return으로 버리지 않고 현재 Scope에 복원 요청으로 보류한다. 완료 후 팝업을 열 수 있는 시점에 RunId·맵 키·현재 선택·처리 대기·상점/회복 상태를 다시 읽고 유효한 요청만 한 번 소비한다. 진행 사실을 복사해 저장하지 않는다.
- 완료 후에는 보류한 비전투 팝업 복원과 기존 증강/팝업 열기 조건을 먼저 처리하고, 팝업이 없을 때 기존 선택 화면 예약을 소비한다. 이탈·재연결·Run/맵 교체 시 이전 복원 요청을 폐기한다. 연출 생략 경로도 같은 완료 처리를 거친다.

## 시간과 일시정지 계약 — 검수 보완 4

- 노드별 시작 지연, 낙하 진행, 마지막 착지 후 3초의 대기 상한은 모두 `Time.deltaTime`에 해당하는 게임 시간을 쓴다. 기존 호버 UI의 `Time.unscaledDeltaTime`을 연출 시간으로 재사용하지 않는다.
- 운영 `FallingRocks`는 기존의 scaled time 설정을 유지한다. 설정 창이 `Time.timeScale = 0`으로 멈추면 낙하와 파티클, 대기 제한이 함께 멈추고, 닫힌 뒤 남은 시간부터 이어진다. 일시정지 중 파티클이 끝나지 않았다는 이유로 시간 상한 경고나 강제 반환이 발생하지 않는다.
- 일시정지 중 처음 준비가 완료돼도 실제 낙하 시작·착지 효과 발행·최초 재생 기록 확정은 재개 이후에 한다. 낙하 시간 0의 즉시 처리도 일시정지를 우회하지 않는다.
- 일시정지와 무관하게 씬 이탈·오류·취소는 즉시 정리한다. 정리는 시간 진행이나 파티클의 자연 종료를 기다리지 않는다.

## 최초 재생과 수명

- 이번 Run의 `RunId`와 챕터 맵 키를 기준으로 이미 시작한 연출을 View 전용 기록 한 곳에서 관리한다. 게임 진행 사실을 복제하거나 Buffer에 쓰지 않는다.
- 씬 이탈·전투 복귀·같은 맵 다시 그리기·상점/회복 종료로 기록을 지우지 않는다. 새 RunId를 만나면 이전 Run 기록을 비운다. 새 Run의 각 챕터는 다시 한 번 재생하는 것으로 제안한다.
- 기록은 대상 준비 성공 후 로딩이 걷히고 일시정지가 아닌 상태에서 실제 연출을 시작할 때 남긴다. 준비 실패나 시작 전 취소는 재생한 것으로 기록하지 않는다. 시작 후 중단한 경우 재진입에서는 최종 배치를 바로 보여준다.
- 저장 파일이나 기기 간의 재생 이력 보존은 이번 범위에 없다. 런타임을 새로 시작하면 현재 세션에서 처음 보는 챕터를 재생한다.
- 재그리기·표시 교체·Supersede·오류 정지·씬 이탈은 외형 복원과 효과 반환을 노드 파괴보다 먼저 수행한다. 취소는 반복 호출 가능해야 하며 이전 Scope의 정리가 새 Scope 자원을 회수하지 않아야 한다.

## 구성과 변경 경계

- 전용 낙하 부품: 대상별 원래 자세, 지연, 낙하 진행, 착지 완료와 표시 복원만 담당한다. 기존 `StageNodeView`는 표시 대상과 외형 참조를 제공한다.
- 최초 재생 기록: System과 함께 살아 있는 전용 부품에 둔다. 씬 Scope에는 기록을 복제하지 않는다.
- 조립: 기존 `StageMapSceneFactory`에서 연출·효과·로딩 준비의 의존성을 연결한다. `StageMapViewScope`는 준비·Tick·취소 순서, 선택 가능 여부와 보류한 팝업 복원을 조정한다. 거리 계산·낙하 수식·파티클 완료 관찰을 Scope에 넣지 않는다.
- 서비스 수신: `StageMapViewSystem.PostBindService`에서 기존 Global → Render → CoreGroup Effect 서비스, Global → Loading 조회, Buffer의 Run 읽기를 받는다. 루트 서비스 재등록은 하지 않는다.
- 로딩 등록: System의 기존 Initialize 경로에서 Stage 씬 준비 작업을 등록한다. 준비 상태의 완료·실패·취소는 `ILodingPreparation` 계약을 따르며 공용 Loading 구현을 수정하지 않는다.
- 효과: 스테이지 전용 EffectScope 하나를 System 수명에 재사용한다. 효과 부품이 고정 착지 받침, 완료 관찰과 소유 세대 검사를 맡고, 현재 소유 효과를 `StopAll`로 반환한다. 전투의 EffectScope와 공유하지 않는다.
- 설정: `StageMapViewDataSO`가 직렬화 입력을 소유하고 `GetData()`가 읽기 전용 낙하 값을 새로 만든다. 운영 `StageMapView_Default.asset`에 값을 명시한다.
- Core·Buffer 구현·FieldCamera·Architecture·전투 본부 구현·Render 공용 구현을 수정하지 않는다. 새로운 UI 화면·UIId·서비스 등록도 없다.

## 구현과 확인 범위

설계 승인 후 Task 계획을 작성하고 한 Phase에서 구현·정적 검토·인계한 뒤 멈춘다. 테스트 코드·도우미를 만들거나 MSBuild를 실행하지 않는다. 컴파일 미확인으로 보고한다.

사용자 Unity 확인 항목: 챕터 최초 진입의 거리 순서·동시 거리·착지 표현, 전투 복귀와 팝업 종료 시 재생 생략, 다음 챕터의 최초 재생, 새 Run의 재생 복원, 연출 중 입력/윤곽선 차단과 완료 뒤 복원, 로딩 종료 전 진행 방지, 이탈·오류·재그리기 때 외형과 효과 정리, 높이/시간/전파 시간 0, 챕터 1·2, 기존 현재/클리어 숨김. DB 에셋을 변경하므로 `DataBaseAssetTests`도 사용자 확인 항목에 포함한다.

검수 보완에 따른 추가 확인:

- 첫 Run처럼 맵 생성 Job이 뒤늦게 완료되는 진입에서, 배치·숨김 준비 전 로딩이 걷히지 않는지와 준비/로딩 사이 상호 대기가 없는지. 로딩 표현 없는 개발 진입에서 완성 건물이 먼저 노출되지 않는지.
- 착지 효과의 자연 종료, 마지막 착지 후 게임 시간 3초 상한, 취소 후 풀 반환, 씬 재연결 뒤 이전 받침/완료 조회/정리가 새 효과에 영향을 주지 않는지.
- 낙하 중 누르고 완료 뒤 떼기, 준비 중 호버, 완료 직후 새 클릭, 상점·회복 복원 보류, 증강·덱 팝업과 선택 화면의 복원 순서.
- 준비 완료 직전·낙하 중·착지 효과 대기 중 설정 창을 열고 닫기. 열린 동안 위치·파티클·대기 시간이 함께 멈추는지, 재개 시 연출이 이어지는지, 일시정지 상태의 취소도 즉시 자원을 정리하는지.
