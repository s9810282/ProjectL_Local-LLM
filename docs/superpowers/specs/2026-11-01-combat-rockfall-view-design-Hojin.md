## 1 지금 코드에서 확인한 것

| 사실 | 근거 | 설계에 주는 영향 |

## 2 화면

칸·맞은 유닛·피해는 Core 값을 그대로 쓴다. 시간표를 View에 적지 않는다.

| 시점 | 화면 | 다음 사건 |
|---|---|---|
| 전투 진입·재연결 | 경고 단계면 `WarnedCells`에 경고 칸 표시를 켠다. 옛 폭발·충돌은 다시 재생하지 않는다 | - |
| Warning 사건 | 터널 자리에서 터널 방향으로 `Boom`이 터지고, 떨어질 칸마다 테두리·채우기·느낌표를 켠다 | 막지 않음 |
| Impact 사건 | 경고 칸 표시를 치우고 칸마다 돌이 떨어진다. 착지 때 이펙트·카메라 흔들림, 돌은 사라진다(U10) | 착지까지 막음 |
| 그 뒤 체력·속박·사망 | 있는 피격 반응·사망 연출·HUD | Q-RF2 |
| 결과 끝 | Buffer 최종 상태로 다시 맞춘다 | - |

## 3 구조

### 3.1 사건 줄(RF1)

`CombatEventTypeTable`에 `CombatRockfallEvent` 줄을 더하고 새 처리기 칸 `Rockfall`을 둔다(인계 §1.2 기능별 처리). 주체·근원이 없어 묶음 밖 장벽이 된다.

새 `Playback/Handlers/CombatRockfallEventHandler.cs`:

- Warning: 터널 이펙트를 내고 `Final.WarnedCells`로 경고 칸 표시를 켠다.
- Impact: `Expected.WarnedCells`로 낙하 조립을 시작하고, 모든 돌이 착지하면 사건을 끝낸다. 칸이 없으면 바로 끝낸다. `Final`이 null이어도 된다.

### 3.2 낙석 표시(RF2)

새 `Display/Map/FieldRockfallPresenter.cs`: 돌 풀, 터널 자리 읽기, 경고 칸 표시. 경고 칸 표시는 둘을 함께 켜고 끈다(2026-11-01 사용자 A안).

- 테두리·채우기: 새 강조 층 `RockfallWarning`. 평소 층이라 입력이 없어도 보이고 행동 중으로 치지 않는다. 지금 채우기는 행동 중에만 그려지므로 `FieldCellFillStack`이 평소 채움 층도 쌓게 한다.
- 느낌표: 새 `Display/Field/FieldCellMarkers.cs`(칸 → 인스턴스 재사용, `Show`, `Clear`, `Release`)가 칸마다 프리팹을 바닥에 눕혀 놓는다. 높이는 채우기와 같고 색은 이미지 그대로다.

입구:

- `Render(StageGimmickStateSet set, mapper)`: 진입·결과 끝. 경고 단계면 켜고, 대기 단계이거나 상태가 없으면 끈다.
- `ShowWarning(state, mapper)`: Warning 사건 때 켠다.
- `ClearWarning()`: 충돌 시작 때 끈다.
- `Clear`, `Release`: 표시 정리 목록에 더한다. 전투가 바뀌면(`BattleInstanceId`) 이 경로로 비운다.

### 3.3 돌 낙하 조각(RF3)

새 `Presentation/Pieces/CombatRockfallDropPiece.cs`: 돌 하나의 낙하(높이 → 칸 표면, ease-in). 칸마다 하나를 `CombatComposition.ForAction`에 넣는다. 순서를 섞어 조금씩 차례로 떨어지고, 맞은 유닛이 있는 칸의 돌은 마지막에 함께 떨어진다(2026-11-01 사용자, 계획 RP-6). 착지 이펙트·흔들림은 있는 큐 조립으로 붙인다. `CombatPieceRunPlayer`가 진행·취소하므로 결과 끝 사실 반영도 기다린다. 취소하면 돌을 지운다.

### 3.4 여러 명이 함께 맞을 때(RF4)

`CombatConcurrentGroups`에 `AttachRockfallRecipients`를 더한다. Impact 사건 바로 뒤에 이어지는, 주체가 `RecipientIds`에 있는 근원 없는 캐릭터·상태 사건만 한 묶음으로 둔다. 아이템 사건을 붙이는 `AttachItemEvents`와 같은 꼴이다(Q-RF2).

Impact 사건은 묶음 밖 장벽이라 돌이 먼저 보이고, 체력·상태가 앞질러 오지 않는다(인계 §5.4). 토네이도 처리가 먼저 들어간 뒤 이 묶음을 켠다(인계 §1.2).

### 3.5 값(RF5)

새 View 표 `RockfallVisual`(`ThornFieldVisual` 꼴, 설정 하나). 하붑과 표를 나눠 서로의 값을 건드리지 않게 한다.

| 칸 | 뜻 |
|---|---|
| 돌 프리팹, 느낌표 프리팹 | 필수 |
| 느낌표 크기·띄움, 낙하 높이·시간·간격 | 범위 검사 |
| 출발 흩뿌림, 돌 크기·회전 범위 | 돌마다 다른 값(§10) |
| 경고 큐 `warningCues`, 충돌 큐 `impactCues` | 터널 폭발·착지 이펙트·흔들림. 자리 보정·지연이 큐에 있다(계획 RP-3) |
| 이름·설명 | 호버 설명 |
| 경고·착지 소리 프리셋 | 기본 -1 |

터널 자리는 맵 프리팹 안의 빈 오브젝트 `RockfallTunnelBoom`이다(Q-RF3). 연결 줄(`ViewTableKey`·`ViewDataBase`·`ViewDataBaseFactory`·표시 Factory)은 민형님 공유 문서에 적는다.

### 3.6 안내·설명(RF6)

- `CombatActionNotice`: `AnkleBroken` 문구를 "이동 불가 상태라 이동할 수 없습니다."로 바꾼다. 현강님 줄이라 변경을 공유한다.
- `CombatEnvironmentText`: 경고 칸 호버 설명을 더한다(인계 §1.2). 피해 비율은 Buffer `StageGimmicks`의 `RockfallGimmickSpec`에서 읽는다.

### 3.7 소리(RF7)

`CombatEventSounds`에 경고·충돌 갈래와 슬롯 칸(연결 대기 null)을 더한다. AudioSystem 요청은 사운드 작업자 안내에 적는다.

### 3.8 표시 규칙(RF8)

- 프리팹 레이어는 가시밭과 같이 낮·밤 카메라에 모두 보이는 값으로 맞춘다. 충돌체를 두지 않는다.
- 칸 프리팹 모드와 GridOutline 모드 모두 `FieldGridMapper`만 쓴다.
- 표시 정리 목록(`Clear`, `Release`)에 더한다.

## 5 결정 대기

호버 설명은 넣는다(인계 §1.2). 남은 턴 글자는 넣지 않는다. 필요해지면 `NextBoundaryCount`와 완료 누계로 Core 조회 없이 계산한다(인계 §2.3).

| ID | 결정(2026-11-01 사용자) |
|---|---|
| Q-RF1 | 임시 외형: 돌은 공 모양 단순 도형. 최종 외형은 모두 토네이도처럼 프리팹으로 온다. ~~터널 자리에 조금 긴 막대~~, ~~경고 칸 표지는 일단 두지 않는다~~(아래 2026-11-01 지시로 바뀜) |
| Q-RF2 | 여러 명이 맞으면 동시에 반응한다(§3.4) |
| Q-RF3 | 터널 자리는 맵 프리팹 안의 빈 오브젝트 `RockfallTunnelBoom`의 위치·회전이다(2026-11-02 사용자 지시로 `StageViewPropData` 값에서 바뀜, 계획 §6.3). 없으면 폭발 없이 진행한다 |

2026-11-01 사용자가 정한 외형: 돌은 낙하 조각(§3.3)대로 떨어지고(2026-11-02 사용자 지시로 맵의 능선에서 출발해 곡선으로 떨어짐, §10), 칸에 닿으면 사라지며 그 칸에 민형님 이펙트 `FallingRocks`를 재생한다. 터널은 경고 시작에 `Boom`을 옆으로 돌려 터널 폭발로 쓴다. 막대는 터널에서 터지는 연출이 없을 때의 대안이었으므로 만들지 않는다. 기획서 9쪽대로 폭발까지 2턴, 그 뒤 낙석까지 2턴이다. 떨어질 칸은 유닛 범위와 같은 테두리·채우기에, 느낌표를 바닥에 눕혀 함께 보인다(A안). 느낌표는 사용자 이미지 `Sprites/rockfall_warning.png`이고, 경고 색은 이 이미지 색에 맞춰 시작한다. 칸·값의 자세한 모양은 [계획](../plans/2026-11-01-combat-rockfall-view-plan-Hojin.md) §1 RP-1·RP-3·RP-5~RP-7이 원본이다.

## 6 인계 문서와 다른 점

- 경고 칸 표시는 강조 층과 느낌표 이미지다. 인계 §8.2의 프리팹 안 데칼 대신 칸 강조를 함께 쓴다.
- 인계 §9.2는 사건이 건너뛰어지면 시험으로 잡으라고 한다. View 작업은 새 시험을 만들지 않는 규칙(2026-10-27 사용자)이라 재생 확인으로 대신한다. 인계 §9.4의 나머지 목록을 Unity 확인 항목으로 쓴다.

## 8 원칙 점검(코드 전 예상, 약 8.7/10)

| 기준 | 판단 |
|---|---|
| SSOT | 칸·단계는 Core 상태 하나. 맞은 유닛은 `RecipientIds`, 피해는 Core 체력 사건. View는 인스턴스 표만 갖는다 |
| SOLID | 처리기·표시·낙하 조각을 나눈다. 전용 처리기 칸이라 사실 처리기가 늘지 않는다. 약점: 처리기 표·필드 창구 인자와 동시 묶음의 특수 규칙이 는다 |
| FW | 이펙트·카메라·조각 실행은 있는 창구, 값은 View DB 표, 새 서비스 등록 없음 |
| 독립성 | 낙하 곡선은 조각 하나, 외형은 프리팹·SO만 고친다. 하붑·토네이도 내부를 몰라도 된다. 공유 파일은 형식 표·처리기 표·필드 창구·표시 Factory·동시 묶음 |

남는 위험:

- 필드 창구 필수 인자가 늘어 표시 Factory와 용근님 특성 미리보기 Factory의 줄을 맞춰야 한다. 새 시험은 만들지 않는다.
- 컴파일과 재생 확인은 사용자가 Unity에서 한다.

## 9 구현 메모(2026-11-02)

원본은 [계획 §1·§6](../plans/2026-11-01-combat-rockfall-view-plan-Hojin.md)이다. 설계와 달라진 것:

- 경고 칸: 표지 없음 → 강조 층 테두리·채우기 + 바닥 느낌표(RP-2).
- 터널 자리: 스테이지 값 → 맵 프리팹 오브젝트 `RockfallTunnelBoom`(RP-1).
- 값: 이펙트 칸 → 큐 입력 둘(RP-3).
- 돌: 공 모양 → `smallrock (3)` 프리팹, 능선에서 곡선으로 낙하(이 문서 §10), 착지에 `FallingRocks`(RP-6·계획 §6.4).
- 터널 폭발: `Boom` 하나 → 셋 + 흔들림(§6.7).
- 호버: `CombatEnvironmentText.Build(state, cell)`로 인자를 줄였다. 칸은 대기 단계에 비어 있어 단계를 따로 보지 않는다(RP-10).
- 이동 불가: 안내 "이동 불가 상태라 이동할 수 없습니다.", 짧은 글자 "이동불가"(RP-11). 사유 `AnkleBroken`은 특성·기믹 속박이 함께 쓴다.
- 상태 설명의 출처: 낙석이면 표의 이름, 다른 기믹이면 `기믹 {키}`(§6.8).


## 10 돌 출발 능선(RG1~RG6, 2026-11-02 구현 완료)

피드백: 돌이 한 곳에서 원뿔처럼 나온다. 사용자 요청: 돌산 위에서 돌이 떨어지는 느낌으로, 넓은 능선에서 출발하고 돌마다 회전·크기를 다르게 한다.

### 10.1 원뿔로 보이는 까닭

| 사실 | 근거 | 화면 |
|---|---|---|
| 돌의 옆 방향이 모두 터널 한 점을 향한다 | `CombatRockfallEventHandler.AddDrop`의 `side` | 위에서 보면 궤적이 `RockfallTunnelBoom` 한 점으로 모여 부채꼴이 된다 |
| 옆 거리가 칸마다 같다(지금 에셋 20) | `dropSideDistance` | 터널에서 20보다 가까운 칸의 돌은 터널 반대편에서 출발한다 |
| 돌의 위치만 움직인다 | `CombatRockfallDropPiece.PointAt` | 돌지 않아 던진 물건처럼 보인다 |
| 돌 크기가 모두 같다 | `FieldRockfallPresenter.CreateStone` | 같은 돌이 반복되어 보인다 |

곡선 자체는 그대로 쓸 수 있다. 옆으로 일정하게 가고 아래로 점점 빨라지는 식이라, 능선에서 굴러 나와 떨어지는 모양과 맞는다.

### 10.2 설계

**RG1 출발 자리.** 맵 프리팹에 능선 구간을 두고, 돌은 구간 위에서 자기 칸과 가장 가까운 점에서 출발한다. 거리는 가로 평면에서 잰다. 궤적이 거의 나란해져 부채꼴이 사라진다. 구간 끝을 벗어난 칸은 끝점에서 출발해 조금 기운다.

**RG2 능선 표현.** 맵 프리팹 안의 빈 오브젝트 둘 `RockfallRidgeStart`·`RockfallRidgeEnd`다(Q-RG1). 맵마다 돌산 자리가 달라 터널처럼 프리팹에 둔다. 배경을 옮기거나 돌려도 따라오도록 쓰는 순간 월드 위치를 읽는다.

**RG3 높이와 시간.** 출발 높이는 능선 오브젝트의 높이다(Q-RG2). 옆 거리와 높이가 모두 능선에서 나오므로 `dropSideDistance`를 지운다. `dropHeight`는 능선이 없는 맵에서만 쓴다. 착지까지 시간은 모든 돌이 `dropSeconds`로 같다. 칸마다 다르면 "유닛이 맞는 칸의 돌은 마지막에 함께 착지"(RP-6)가 깨지기 때문이다. 대신 먼 칸의 돌이 더 빠르게 날아간다.

**RG4 돌마다 다른 값.** 사건마다 새로 뽑는다. 규칙과 무관한 화면 값이라 빈 칸 순서 섞기와 같은 View 난수를 쓴다.

| 새 칸(`RockfallVisualDataSO`) | 시작 값(재생 뒤 조정) | 뜻 |
|---|---|---|
| `dropStartScatter` | 1.5 | 출발 자리를 가로·높이로 흩뜨리는 최대 거리. 줄을 맞춘 느낌을 없앤다 |
| `stoneScaleMin`·`stoneScaleMax` | 0.7·1.3 | 프리팹 크기에 곱하는 배율 |
| `spinDegreesMin`·`spinDegreesMax` | 180·540 | 초당 회전 각도 |

회전축은 진행 방향에 수직인 축에 작은 흔들림을 더해 굴러가는 모습을 만든다(Q-RG3). 시작 회전도 돌마다 다르다. 곧게 떨어지는 경우에는 진행 방향이 없어 무작위 축을 쓴다.

**RG5 구조.**

- 새 값 `Presentation/Pieces/CombatRockfallDrop`: 칸·옆 변위·위 변위·크기·회전축·회전 속도·시작 회전. 출발 자리는 칸 + 옆 변위 + 위 변위다.
- 새 규칙 `Presentation/Pieces/CombatRockfallDrops`: `FromRidge`(칸·능선·설정)와 `Straight`(능선이 없는 맵)가 값 하나를 만든다. 출발 자리 계산과 난수는 여기에만 둔다.
- `CombatRockfallDropPiece`: 값 하나를 받아 위치와 회전을 그린다. 회전은 경과 시간에서 계산해 쌓이지 않는다.
- `CombatRockfallEventHandler.AddDrop`: 규칙을 불러 조각에 넘기기만 한다. 터널 방향 계산을 지운다.
- `ICombatRockfallField`: `TryGetRidge(out Vector3 start, out Vector3 end)`를 더하고, `RentStone`이 배율을 받는다. 풀에서 다시 쓰는 돌의 크기는 늘 프리팹 크기에서 다시 계산한다.
- `StageViewPropPresenter`: 이름 상수 둘과 찾기. 터널 찾기를 이름을 받는 함수 하나로 합친다.
- `FieldRockfallPresenter` 생성 인자 둘 → Factory 줄 둘(`CombatSceneDisplayFactory:145`·`CombatTraitPreviewFactory:74`, 민형님·용근님 공유).

**RG6 터널과의 관계.** 터널은 경고 폭발 자리로만 남는다. 돌은 터널을 읽지 않는다. 터널 없음 경고의 "돌은 칸 위에서 곧게 떨어집니다" 문구를 뺀다.

### 10.3 경계 경우

| 경우 | 게임 | 도구 |
|---|---|---|
| 능선 끝점이 하나씩 있음 | 능선에서 출발 | 아무것도 안 나옴 |
| 둘 다 없음, 또는 한쪽만 있음 | 칸 위 `dropHeight`에서 곧게 떨어지고 경고 로그 한 번. 회전·크기 변화는 그대로 | 낙석이 켜져 있으면 경고만, 저장됨 |
| 같은 이름이 둘 이상 | 터널과 같이 전투 진입 때 멈춤 | 오류, 저장 안 됨 |
| 두 끝점이 같은 자리 | 그 점 하나에서 출발. 원뿔이 다시 보이지만 멈추지 않는다 | 검사 없음 |
| 재생 취소 | 지금처럼 돌을 돌려준다 | - |

### 10.4 바뀌지 않는 것

Core, 떨어지는 칸, 경고 표시, 돌 순서와 간격, 착지 큐(`FallingRocks`·흔들림), 소리, 맞은 유닛의 동시 반응.

### 10.5 에셋과 범위

- `RockfallVisual_Default`: `dropSideDistance` 줄을 지우고 새 칸 다섯을 넣는다. SO 코드와 한 커밋이다.
- 맵 프리팹: 능선 끝점 둘은 사용자가 돌산을 보며 놓는다. 지금 끝점이 필요한 맵은 `NewStageTest.prefab` 하나다(`Test`·`Stage_Test2`가 함께 쓰고, 낙석은 `Test`만 켜져 있다). 놓기 전까지 돌은 곧게 떨어진다.
- 돌에 충돌이 없어 경로에 바위 메시가 있으면 뚫고 지나간다. 능선은 돌산의 전투판 쪽 경사면 위에 두고 재생에서 본다.
- 도구·문서: `CombatStageSoAssets`의 이름 사본과 수 세기, 검사 줄, `SO모드 사용법.md` §5.11, 폴더 배치 안내.
- 범위 밖: 칸마다 작은 돌을 더 떨어뜨리기, 경사면을 따라 구르기(바닥 높이를 읽어야 해 비용이 크다), 터널 폭발, 소리.
