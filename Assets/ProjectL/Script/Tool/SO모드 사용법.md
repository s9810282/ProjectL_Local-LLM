# 전투 스테이지 편집 — SO 모드 사용법 (기획자용)

> 2026-11-09 UXR-d: 현재 코드의 화면 위치·도구·저장/초안·기믹 설명을 대조해 정리했습니다. **컴파일 미확인, 최신 Unity 조작·전투 확인 대기**입니다. 고지대 이웃 모양 개선(B1)은 계속 보류하며 기존 기능은 유지합니다. 단계별 이력과 기능 대조 결과는 [설계](../../../../docs/superpowers/specs/2026-10-27-combat-stage-editor-so-mode-design-Hojin.md)·[계획 §20.9](../../../../docs/superpowers/plans/2026-10-27-combat-stage-editor-so-mode-plan-Hojin.md#209-uxr-d-문서기능-대조-기록-2026-11-09)에 있습니다.

- 작성자: 호진(이호진)

게임이 실제로 쓰는 전투 스테이지 데이터(DB의 SO 에셋)를 Unity 안에서 열고, 고치고, 새로 만드는 방법을 설명합니다.

- **DT 모드**(엑셀 배치 파일)는 [사용법.md](사용법.md)를 보세요. DT 모드로 만든 엑셀은 게임에 바로 쓰이지 않습니다.
- **SO 모드**로 저장한 값은 게임이 그대로 읽습니다. 표에 등록하면 Run 후보로 나옵니다. 그래서 저장·등록 전에 검사를 거칩니다(§8).

빠른 순서: **틀 선택 → 새로 만들기/복제 → 배치 → 필요한 바닥·참조 설정 → 검사 → 저장 → 필요한 경우 등록 → Unity 진입 확인**입니다. 새 스테이지·전용 SO·새 필드는 해당 생성 버튼을 누를 때 파일이 생깁니다. 마지막 `저장` 전까지 모든 작업이 메모리에만 있는 것은 아닙니다.

| 창 내부 사용법 주제 | 이 문서에서 자세히 보기 |
|---|---|
| 처음 만들기 | §1 시작, §3 화면 구성, §4 따라 하기 |
| 배치 복사 | §5.1~5.9 배치/복사/공개 대상, §5.11~5.13 낙석·하붑 |
| 바닥 타일 | §5.10 배경·선택·회전·복사 |
| 공유 SO | §6 전용 복제, §7 도구 밖 DB 입력 |
| 검사·저장·등록 | §8 검사/실패/초안 보호/등록 |
| 안 될 때 | §5.7 숨김 안내, §8.3 초안 보호, §9 문제별 확인 |

## 1. 시작하기

1. Unity 상단 메뉴 **ProjecL → 전투 스테이지 편집**으로 창을 엽니다.
2. 창 맨 위 머리줄에서 **DT | SO** 중 **SO**를 누릅니다.
3. 상단 **스테이지** 선택란 또는 **전체 목록**에서 스테이지를 엽니다.

머리줄 버튼

| 버튼 | 하는 일 |
|---|---|
| 목록 새로고침 | 프로젝트의 SO를 다시 찾습니다. 다른 곳에서 SO를 만들거나 고쳤다면 누르세요. |
| 에셋에서 다시 읽기 | 열린 스테이지를 저장된 에셋 값으로 다시 엽니다. 저장 안 한 변경은 버립니다(확인창이 뜸). |
| 검사 | 저장할 때와 같은 검사를 돌려 문제만 보여 줍니다. 에셋은 바꾸지 않습니다. |
| 저장 | 검사 오류가 없으면 에셋에 씁니다. 검사 오류로 중단되면 아무것도 쓰지 않습니다. 쓰기 도중 실패는 §8.3을 보세요. |
| 사용법 | 현재 작업의 빠른 사용법을 창 안에서 엽니다. 상세 사용법 파일·기능 위치로 이동할 수 있습니다. |

머리줄 아래에는 스테이지 이름·키, **저장 안 됨 / 미저장 변경 없음**, 현재 작업 영역·보기, **미검사 / 변경 후 재검사 필요 / 검사 오류 / 조건부 확인 / 검사 통과**가 나옵니다. `검사 통과`는 저장 완료나 실제 전투 진입 성공을 뜻하지 않습니다. **사용법**은 창 내부의 `처음 만들기 / 배치 복사 / 바닥 타일 / 공유 SO / 검사·저장·등록 / 안 될 때`를 엽니다. 현재 영역·도구에 맞는 주제가 먼저 열리며, 도움말의 **상세 사용법 파일**로 이 문서를 엽니다.

도구 아래 **이 도구 사용법 / 바닥 타일 사용법**에서도 같은 도움말을 엽니다. **닫고 돌아가기(Esc)**는 기존 영역·선택·클립보드·시점을 유지합니다. 열 때 미완료 드래그는 취소하며 이미 칠한 값은 유지합니다. 기능 위치 버튼은 해당 화면으로 이동할 뿐 편집·검사·저장·등록을 자동 실행하지 않습니다. **안 될 때**는 기존 검사 결과·공개/숨김 진단·초안 보호 UI를 연결하며, 상세 원인 알림을 성공 안내로 바꾸지 않습니다.

## 2. 전투 스테이지 한 벌은 무엇으로 이루어지나

전투 스테이지 하나는 SO 세 개가 한 벌입니다. 도구가 셋을 함께 열고 함께 저장합니다.

```text
Stage Root (Stage_<이름>)            ← 스테이지 키, 맵 키, 맵 역할(Regular/Boss), 아래 전투 데이터 연결
  └─ Combat Stage Data (Combat_<이름>) ← 배치(적 유닛·구조물·본부·지형·장애물·오브젝트·레일), 승리 조건, 적 레벨…
       └─ 참조: 필드 · 로스터 · 경제 · 적 로드아웃 · 본부 정의 · 구조물 목록
View Stage Data (StageViewProp_<이름>) ← 같은 스테이지 키. 배경 맵(맵 SO/프리팹)·위치/회전/배율 보정·카메라 설정·지형/오브젝트 외형 회전
```

- **짝 View**는 Stage Root와 **스테이지 키가 같은** View Stage Data입니다. 짝 View가 없으면 저장할 수 없습니다. 같은 키의 View가 둘 이상이면 열리지 않습니다.
- **참조 SO**(필드·로스터·경제·적 로드아웃·카메라 설정)는 여러 스테이지가 **같이 쓰는** 경우가 많습니다. 예를 들어 `Field_13x13_P3E9`는 Normal_B·Normal_C 두 곳이 같이 씁니다(2026-10-27 기준). 같이 쓰는 SO를 고치면 다른 스테이지도 바뀌므로, 도구는 이를 막고 "전용 복제"를 권합니다(§6).
- **표 등록**: 스테이지가 게임에 나오려면 Stage Root가 `StageRootDataTable`에, View가 `StageViewPropDataTable`에 들어 있어야 합니다. 도구의 **표에 등록** 버튼이 둘을 함께 넣고 뺍니다(§8.4).

## 3. 화면 구성

상단의 **배치 / 바닥 타일 / 스테이지 설정**으로 작업 영역을 고릅니다. 배치·바닥 타일은 세 칸이며 경계선을 끌어 패널 너비를 바꿀 수 있습니다. 새로 만들기·복제는 상단 버튼으로 엽니다.

- 배치 속성: **선택 / 아군 구역 / 무작위 지형**. 같은 칸에 여럿이면 `속성 대상`에서 하나를 고릅니다.
- 스테이지 설정: **기본 정보 / 필드·아군 구역 / 공유 SO·본부·구조물 / 배경·타일·카메라 / 기믹 / 등록·맵 생성 규칙**. 기믹 안에 레일·낙석·하붑이 있습니다.
- 검사 결과와 **공개·숨김 안내**는 속성 상단에 있습니다. 스테이지 값과 참조는 위의 스테이지 설정 분류에서 찾습니다.

### 3.1 상단과 왼쪽

| 구역 | 내용 |
|---|---|
| 전투 스테이지(상단 선택란·전체 목록) | 모든 전투 스테이지(Stage Root)입니다. "키 · 맵 · 역할"과 등록 상태를 보고 엽니다. |
| 새 스테이지(상단 새로 만들기 / 복제) | 틀 스테이지를 골라 새 스테이지 한 벌을 만듭니다(§4.1). |
| 정의 목록 | 맵에 놓을 정의(SO)입니다. 누르면 그 정의를 놓는 도구가 됩니다. **적 유닛**(놓을 수 있음), **아군 유닛**(회색, 놓을 수 없음), 구조물, 지형, 장애물, 오브젝트. 이름은 게임 화면과 같은 한국어 이름이고, 괄호 안은 에셋 이름입니다. |
| 기믹 배치(배치 왼쪽) | **하붑 시작 위치 / 낙석 켜기**는 도구 선택 또는 맵으로 끌어 놓기, **낙석 모양·설정 / 하붑 모양·설정**은 기존 설정 패널 열기입니다. |
| 바닥 타일 왼쪽 | 현재 세트의 종류, 배경·타일 설정과 2D/3D 타일 회전 바로가기입니다. |
| 스테이지 설정 왼쪽 | 기본 정보·필드/아군 구역·공유 SO·배경·기믹·등록 분류를 고릅니다. |

> 아군 유닛은 스테이지에 미리 놓지 않습니다. 전투에서 플레이어가 손패로 놓습니다. 스테이지 데이터에도 아군을 놓는 칸이 없습니다.

### 3.2 가운데 (맵)

- 맨 위: 배치 도구 단추(§5.1)
- **아군 구역** 도구일 때 **칠하기 | 지우기**(§5.8), 배치 작업 영역의 **2D / 3D** 전환과 **시점 초기화**(3D일 때). 타일 편집은 상단 **바닥 타일** 작업 영역에서 합니다(§5.10).
- 지금 도구 안내 한 줄
- **복사 · 붙여넣기 · 좌우 뒤집기 · 좌우 대칭 복사** 단추(§5.4)
- **공격 범위(참고용)**: 끄기 / 고른 적 / 모든 적 겹쳐 보기(§5.6)
- 범례와 맵

맵 좌표는 **왼쪽 아래가 (0, 0)**이고, 오른쪽으로 X, 위로 Y가 커집니다. 칸 바탕색은 **아군 구역**(아군을 놓는 칸)과 **적 배치 가능**(나머지 전부) 둘입니다. 적 구역은 따로 없습니다(§5.8).

### 3.3 오른쪽

| 구역 | 내용 |
|---|---|
| 공통 검사 결과·공개/숨김 안내 | 검사 오류·경고와 원인 위치 이동, Player 비공개/판정 오류/위치 미정을 구분합니다. 도움말의 검사·안 될 때 주제에서도 접근합니다. |
| 배치 → 선택 | 고른 칸·구역, 여러 배치의 **속성 대상**, 정의·X/Y·회전·개별 삭제(§5.9). 지도 키/끌기는 고른 칸 기준이며 속성 대상과 구분합니다. |
| 배치 → 아군 구역 / 무작위 지형 | 구역 편집과 참고 수(§5.8), 고정 칸 없는 토네이도 목록(§5.9). |
| 바닥 타일 → 타일 구성·선택 정보 | 선택/복사 수와 타일 세트·종류·높이·크기·원점·맞춤 안내(§5.10). |
| 설정 → 기본 정보 | 스테이지/맵 키·역할·시드·승리 조건·적 레벨·벽 모서리·배치 통계. |
| 설정 → 필드·아군 구역 / 공유 SO·본부·구조물 | 필드 참조·새 필드·구역, 로스터·경제·적 로드아웃·본부 정의·구조물 목록과 전체 참조 SO 필드(§6). |
| 설정 → 배경·타일·카메라 | 짝 View 생성, 배경 방식·맵 SO/프리팹·보정·카메라 참조·바닥 타일(§5.10). |
| 설정 → 기믹 / 등록·맵 생성 규칙 | 레일·낙석·하붑 설정(§5.11~5.13), 표 등록/빼기·맵 생성 줄(§8.4). |

## 4. 따라 하기: 새 전투 스테이지 만들기

### 4.1 한 벌 만들기

1. 상단 **새로 만들기 / 복제**를 누릅니다.
2. **틀**: 비슷한 스테이지를 고릅니다. 새 스테이지는 틀의 참조(필드·로스터·경제·적 로드아웃·카메라 등)와 View 값을 이어받습니다.
3. **이름**: 예) `Normal_F`. 파일이 `Stage_Normal_F`, `Combat_Normal_F`, `StageViewProp_Normal_F`로 만들어집니다(틀과 같은 폴더).
4. **스테이지 키**: **제안**을 누르면 틀 키의 백 단위에서 빈 키를 줍니다. 일반 전투는 11xx, 보스는 21xx입니다.
5. 버튼을 고릅니다.
   - **배치 비우고 만들기**: 배치 없이 시작합니다.
   - **배치까지 복제**: 틀의 배치를 그대로 가져옵니다.
6. 생성 버튼을 누르면 SO 세 파일을 만들고 그 스테이지를 엽니다. 이때는 **표에 등록되지 않은 상태**입니다(Run 후보에 들어가지 않음).

배치 비우기로 만들 때는 검사할 복제본에서도 옛 호환 벽·지형을 먼저 비웁니다. 본부 자리·참조는 틀에서 이어받습니다. 배치까지 복제할 때는 호환 배치도 보존해 검사하므로 겹침 오류가 있으면 새 파일을 만들지 않습니다. 틀 원본은 바뀌지 않습니다.

### 4.2 배치하기

1. 왼쪽 **정의 목록**에서 예를 들어 "언데드 헤비"를 누릅니다(도구가 "적 유닛"으로 바뀜).
2. 맵의 칸을 누르면 놓입니다. 고정 적 유닛·구조물·본부는 **아군 구역(아군 색) 밖**에 놓으세요(§8.5).
3. 지형·장애물·오브젝트·레일은 누르거나 끌어서 칠합니다. **Shift+끌기**로 사각형을 한 번에 칠할 수 있습니다.
4. 아군을 놓을 칸을 바꾸려면 **아군 구역** 도구로 칠하거나 지웁니다(§5.8). 그대로 두면 필드의 아군 줄 수(아래 줄)가 아군 구역입니다.
5. 잘못 놓았으면 **Ctrl+Z**(Unity Undo)로 되돌립니다.

### 4.3 값 정하기

- **스테이지 설정 → 기본 정보**: 승리 조건·적 레벨 등.
- **필드·아군 구역**: 맵 크기·아군 구역과 참고 경고(§5.8).
- **공유 SO·본부·구조물**: 적 로드아웃·경제·로스터·본부 정의·구조물 목록(§6).
- **배경·타일·카메라**: 배경 맵과 보정·카메라 설정. **기믹**에서 레일·낙석·하붑을 정합니다.

### 4.4 검사 → 저장 → 등록

1. 머리줄 **검사**. 오른쪽 위에 문제가 나오면 고칩니다.
2. 머리줄 **저장**. 검사를 다시 하고, 통과해야 씁니다.
3. **스테이지 설정 → 등록·맵 생성 규칙 → 표에 등록**. "맵 키 N의 Regular 스테이지로 Run 후보에 들어갑니다" 확인창이 뜹니다. 창에는 맵에서 바뀌는 수(예: "맵 1 전투 후보 2 → 3")도 나옵니다. 등록하면 그 맵의 Run에서 이 스테이지가 나올 수 있습니다. 등록하면 그 맵을 만들 수 없게 되는 경우는 막힙니다(§8.4).

### 4.5 게임에서 확인하기

유닛·본부 칸 규칙 일부는 **전투에 들어갈 때만** 검사됩니다(§8.5). 꼭 한 번 들어가 보세요.

1. 메뉴 **ProjectL → Play From Boot**를 켭니다.
2. **ProjectL → Play From Boot 설정...**에서 Battle Definition = **Database**, Dev Battle Stage = **PlacedStage**, Dev Stage Data = 만든 `Combat_<이름>`을 고릅니다.
3. Play를 누르면 그 스테이지로 바로 전투에 들어갑니다.
   - PlacedStage는 **표에 등록된 일반(Regular) 스테이지**만 됩니다. 보스 스테이지는 이 방법으로 들어갈 수 없습니다.
   - 콘솔에 오류가 나오면 그 문구가 원인입니다.

## 5. 맵 편집 자세히

### 5.1 도구

| 도구 | 하는 일 |
|---|---|
| 선택 | 칸 고르기, 끌어 옮기기, 상자 선택(§5.2) |
| 적 유닛 | 정의 목록에서 고른 적 유닛을 놓습니다. |
| 구조물 | 정의 목록에서 고른 구조물을 놓습니다. |
| 적 본부 | 누른 칸으로 적 본부를 옮깁니다. 본부 정의는 설정 → 공유 SO·본부·구조물에서 고릅니다(하나뿐). 지운 본부도 정의를 다시 고르면 지우기 전 자리에 돌아옵니다. |
| 지형 · 장애물 · 오브젝트 | 고른 정의를 누르거나 끌어서 칠합니다. |
| 레일 | 누르거나 끌어서 레일 칸을 더합니다. |
| 지우기 | 누른 칸의 맨 위 배치를 지웁니다. 본부도 지워집니다. 아군 구역은 건드리지 않습니다. |
| 아군 구역 | 아군 배치 구역 칸을 칠하거나 지웁니다(§5.8). 배치는 건드리지 않습니다. |
| 타일 회전 | 2D에서는 판 안, 3D에서는 판 밖 타일도 선택·회전합니다. 타일 Ctrl+C/V는 **바닥 타일 → 선택**에서 사용합니다(§5.10). |
| 하붑 시작 | 클릭/끌어 놓기로 시작 위치를 정하고 하붑·시작 지정을 켭니다. 이후 이동은 무작위입니다(§5.12). |
| 낙석 | 아무 칸을 눌러 낙석을 켭니다. 클릭한 칸을 낙하 위치로 정하지 않습니다(§5.11). |

지우기 도구는 **본부를 포함한 맨 위 배치**를 지우며 아군 구역은 지우지 않습니다. 본부는 선택 속성의 삭제·Delete·상자 지우기로도 지울 수 있습니다. 본부 정의만 비우고 자리·회전은 보존하므로, 정의를 다시 고르면 돌아옵니다. 아군 구역은 **아군 구역** 도구에서 지웁니다.

**정의 목록에서 끌어 놓기**

왼쪽 정의 목록(적 유닛·구조물·지형·장애물·오브젝트)의 항목을 눌러 맵으로 끌어 놓으면 그 칸에 하나가 놓입니다. 2D·3D 둘 다 됩니다('타일' 보기는 안 됨).

- 끄는 동안 놓을 자리가 칸 크기대로 보입니다. 초록 = 놓을 수 있음, 빨강 = 막힘. 막힌 칸에 놓으면 이유가 알림에 나오고 놓이지 않습니다.
- 맵 밖에 놓거나 Esc를 누르면 취소되고 붓도 그대로입니다.
- 놓으면 그 정의가 붓으로 고른 상태로 남아, 이어서 클릭으로 더 놓을 수 있습니다. 한 번이 Ctrl+Z 한 번입니다.
- 움직이지 않고 떼면 지금처럼 클릭(붓 고르기)입니다.

### 5.2 선택 도구

| 조작 | 결과 |
|---|---|
| 칸 누르기 | 그 칸을 고릅니다(오른쪽 '고른 칸'에 나옴). |
| 배치가 있는 칸에서 끌기 | 그 배치를 옮깁니다. 놓일 자리가 초록이면 옮겨지고, 빨강이면 그대로입니다. |
| 빈 칸에서 끌기, 또는 **Shift+끌기** | 상자 선택. Shift+끌기는 배치가 있는 칸에서 시작해도 늘 상자입니다. |
| 상자 안 칸에서 끌기 | 상자 안 배치를 묶음으로 옮깁니다. 하나라도 막히면 통째로 안 옮깁니다. |
| Esc | 끌기 취소. 끌고 있지 않으면 상자 선택을 지웁니다. |

### 5.3 칠하기 도구(지형·장애물·오브젝트·레일·지우기·아군 구역)

- 누르거나 끌면 지나가는 칸마다 칠합니다(끌기 한 번 = Undo 한 번).
- **Shift+끌기**: 사각형으로 한 번에 칠합니다. 막힌 칸은 건너뛰고, 건너뛴 수를 알려 줍니다.
- 아군 구역 도구는 막는 칸이 없습니다. Shift+끌기는 사각형 전체를 칠하거나 지우고, 바뀐 칸 수를 알려 줍니다.

### 5.4 복사 · 붙여넣기 · 좌우 대칭

| 버튼(단축키) | 하는 일 |
|---|---|
| 복사 (Ctrl+C) | 상자 안의 적 유닛·구조물·장애물·지형·오브젝트·레일을 담습니다. 본부는 빠집니다. |
| 붙여넣기 (Ctrl+V) | 고른 칸이 복사한 상자의 **왼쪽 아래 칸** 자리가 되게 붙입니다. 다른 스테이지에 붙여도 됩니다. 막힌 칸은 건너뜁니다. |
| 좌우 뒤집기 (상자/전체) | 상자 안(상자가 없으면 맵 전체)을 맵 가운데 세로선 기준으로 뒤집습니다. 모두 옮긴 결과가 겹치지 않을 때만 합니다. 회전은 R90 ↔ R270으로 바뀝니다. |
| 좌우 대칭 복사 (상자/전체) | 원래 것은 두고 반대편에 대칭으로 하나 더 놓습니다. 막힌 칸은 건너뜁니다. 본부는 하나뿐이라 건너뜁니다. |

이 버튼들과 묶음 옮기기는 **아군 구역을 옮기지 않습니다.** 구역은 배치가 아니라 판의 값입니다. 좌우가 바뀐 구역이 필요하면 아군 구역 도구로 다시 칠하세요.

영역 복사는 낙석·하붑 설정과 바닥 타일을 담지 않습니다. 바닥 타일은 별도의 선택 모드·클립보드를 씁니다(§5.10). 두 복사 기능 모두 검사 통과가 선행 조건은 아닙니다. 스테이지 전체의 **배치까지 복제**와 **배치 비우고 만들기**는 둘 다 틀의 낙석·하붑 설정을 이어받습니다.

### 5.5 단축키

아래는 배치 편집 단축키입니다. 입력 칸(숫자·글자)에 포커스가 있으면 맵 단축키는 작동하지 않고 Ctrl+C/V는 입력 칸의 복사·붙여넣기로 처리됩니다. 맵을 눌러 포커스를 옮긴 뒤 영역을 고르세요. 검사는 단축키를 활성화하는 절차가 아닙니다.

| 키 | 하는 일 |
|---|---|
| Delete | 상자가 있으면 상자 안 배치(본부 포함)를, 없으면 고른 칸 맨 위 배치를 지웁니다. |
| R | 고른 배치를 시계 방향으로 돌립니다. |
| Esc | 끌기·상자 선택 취소 |
| Ctrl+C / Ctrl+V | 복사 / 붙여넣기 |
| Ctrl+Z / Ctrl+Y | 되돌리기 / 다시 하기(Unity Undo) |

**바닥 타일 → 선택**에서는 R/Shift+R로 타일을 돌리고 Ctrl+C/V로 타일 종류·회전을 복사·붙여넣습니다(§5.10). 배치 복사와 클립보드가 따로이며 배치 Delete는 적용하지 않습니다. Esc는 끌던 사각형을 먼저 취소하고, 드래그 중이 아니면 타일 선택을 비웁니다. **2D·3D의 타일 회전 도구**는 고르기·돌리기용입니다. 타일 Ctrl+C/V를 쓰려면 바닥 타일 작업 영역의 선택 모드로 전환하세요. 숫자·글자 입력 중에는 타일 격자를 눌러 포커스를 옮깁니다.

### 5.6 공격 범위 미리보기 (참고용)

- **고른 적**: 맵에서 적 유닛이 있는 칸을 고르면 그 적의 공격 범위를 칠합니다. 방향이 있는 공격이면 **전체 · ↑ · → · ↓ · ←** 버튼으로 방향별 범위를 볼 수 있습니다.
- **모든 적 겹쳐 보기**: 모든 고정 적의 범위를 겹쳐 칠합니다. 칸의 `×n`은 그 칸에 닿는 적 수입니다.
- 진한 주황 = 사거리, 옅은 주황 = 스플래시로만 닿는 칸
- **특성·버프/디버프에 따른 사거리 보정을 반영하지 않은 기본 범위**입니다. 벽·지형·고지대·모래폭풍·유닛 점유·대포 인접 금지는 반영하지 않습니다. 실제 범위는 전투에서 확인하세요.

### 5.7 3D 보기

- **배치 → 3D**를 고르면 배경 맵 위에 실제 전투 유닛·구조물 프리팹과 지형·오브젝트 외형이 게임과 같은 자리·방향으로 나옵니다. 배경은 스테이지 설정의 배경 방식대로 고릅니다.
- 바닥 타일 방식이면 타일도 게임처럼 놓이고(§5.10), 칸 높이는 **타일 윗면 + 지형**입니다. 유닛·오브젝트는 그 높이에 서고, 고지대 위 오브젝트는 블록 윗면에 섭니다. 약한 지반·낭떠러지 칸은 그 타일이 숨고 외형이 타일 자리에 놓입니다(낭떠러지는 프리팹이 없어 빈 구멍).
- 칸 위 덧그리기(아군 구역·범위·상자)는 타일 높이를 따르지 않고 지형이 올린 높이만 따릅니다(게임 격자와 같음).
- 3D에서도 2D와 **똑같이 편집**됩니다(누르기·끌기·상자·Shift 칠하기).
- 외형이 없는 정의는 층 색 상자로 그려집니다.
- 조명·배경은 참고용입니다.
- **토네이도:** 고른 칸이 중심인 정사각형(한 변은 지형 정의의 `tornadoSideLength`, 기본 3)에 놓습니다. 배율·위치 보정은 판정 칸 수 ÷ 프리팹 기준 칸 수만큼 키웁니다. 높이는 덮는 칸 중 판 안 칸의 원래 바닥 타일 높이 최댓값입니다. 음수 높이도 유지하며 약한 지반·낭떠러지로 교체된 높이는 쓰지 않습니다. 2D 표식과 저장 위치는 중심 칸 그대로이고, 무작위 시작은 위치 미확정이라 고정 외형을 그리지 않습니다.
- **고지대 이웃 모양 보완은 보류**입니다. 기본 외형·높이와 Core 규칙은 유지하지만 도구에서는 끝·모서리 없이 가운데 모양으로 표시합니다.
- **Player 기준 (끄면 전체 배치):** 기본은 꺼짐입니다. 켜면 공개 대상에 Player가 있는 지형·오브젝트만 표시합니다(빈 목록은 비공개). 표시할 지형만 높이·바닥 교체·타일 숨김에 참여합니다. 속성의 **공개·숨김 안내**는 `Player에게 비공개 N / 판정 오류 M`을 나눠 표시합니다. 이는 전투 화면의 완전 재현은 아닙니다.
- Player 기준에서는 클릭·지우개·Delete/R·상자 삭제·묶음 이동·복사·뒤집기·대칭 복사가 표시 대상만 처리합니다. 숨은 배치도 충돌 검사에는 남으므로 빈칸처럼 보여도 놓기가 거절될 수 있습니다. 전체 배치를 편집하려면 토글을 끄거나 2D로 바꾸세요.
- 숨은 배치 또는 공개 판정 오류가 포함된 복사본은 Player 기준에서 붙이지 않습니다. 중단 안내의 **전체 배치로 보기 / 2D에서 수정**은 보기만 전환합니다. 목적지 칸을 확인하고 **붙여넣기(Ctrl+V)를 다시 누르세요.** 자동 붙여넣기는 하지 않으며 원래 공개 목록을 보존합니다.
- 정상 비공개는 `Player에게 비공개 · 현재 3D에서 숨김`, 정의 누락·잘못된 공개 목록은 `표시 판정 오류`로 구분합니다. 전체/2D/타일/설정에서도 오류 수·원인은 남습니다. 선택 속성의 정의·공개 대상 값을 직접 수정하고, 잘못된 공개 목록은 기존 비우기 버튼으로 복구하세요. 진단 오류를 저장 검사의 오류 수에 임의 합산하지 않습니다.
- 고정 오류 행의 **위치 보기 (2D)** 또는 **배치 수정 (맵 밖)**으로 대상을 찾습니다. 무작위 시작 지형은 **고정 위치 없음**으로 별도 집계하며 **무작위 지형에서 수정 / 무작위 지형 열기**로 갑니다. 공개 분류와 겹칠 수 있는 별도 수이며, 전체 보기에서도 고정 외형이 생기지는 않습니다.
- 보기 전환만으로 저장값·초안·Undo가 바뀌지 않습니다. 공개 대상 편집·Undo/Redo·새로고침 시 표시와 높이·타일 숨김이 함께 갱신됩니다. 2D와 타일 보기·타일 회전은 기존 방식입니다.

| 조작 | 시점 |
|---|---|
| 오른쪽 버튼 끌기 (또는 Alt+왼쪽 끌기) | 돌리기 |
| 가운데 버튼 끌기 (또는 Shift+오른쪽 끌기) | 옮기기 |
| 휠 | 확대·축소 |
| 시점 초기화 | 처음 시점으로 |

### 5.8 아군 배치 구역

전투 시작 전 배치 국면에서 플레이어가 아군을 놓을 수 있는 칸입니다. 맵의 **아군 색** 칸이 아군 구역이고, 나머지는 모두 **적 배치 가능** 칸입니다. 적 구역은 따로 없습니다. 고정 적과 무작위로 나오는 적은 아군 구역 밖이면 어디든 놓입니다.

정하는 방법은 둘입니다. 지금 어느 쪽인지는 범례와 **배치 → 아군 구역** 또는 **설정 → 필드·아군 구역**의 **정한 곳** 줄에 나옵니다. 색은 같습니다.

| 정한 곳 | 뜻 | 바꾸는 법 |
|---|---|---|
| 필드 아군 줄 수 N줄 (칸 목록 비어 있음) | 아래부터 N줄 전체 | '아군 배치 구역'의 **필드 아군 줄 수** 슬라이더(1~세로) |
| 칸 n개 (직접 지정) | 전투 데이터의 칸 목록에 든 칸만. 떨어진 조각도 됩니다 | 맵의 **아군 구역** 도구 |

**아군 구역 도구**

- 도구 줄의 **아군 구역**을 고르고, 바로 아래 **칠하기 | 지우기**에서 고릅니다.
- 누르거나 끌면 칸마다, **Shift+끌기**는 사각형으로 칠하거나 지웁니다. 끌기 한 번, 사각형 하나가 Undo 한 번입니다.
- 배치가 있는 칸도 칠할 수 있습니다(막는 칸 없음). 맵 밖은 무시합니다.
- 칸 목록이 비어 있을 때(필드 줄 수) 처음 칠하거나 지우면, 지금 보이는 아래 줄 칸을 먼저 칸 목록으로 옮긴 뒤 편집합니다. 그래서 보이던 구역이 끊기지 않고, 아래 줄에서 한 칸만 빼는 것도 됩니다. 알림이 뜨고, Ctrl+Z 한 번이면 필드 줄 수로 돌아갑니다.
- **마지막 칸은 지울 수 없습니다.** 칸 목록이 비면 구역이 필드 줄 수로 돌아가 버리기 때문입니다. 필드 줄 수로 돌아가려면 '아군 배치 구역'의 **칸 목록 비우기(필드 줄 수로)**를 누릅니다(확인 창).
- 기존 **지우기** 도구, 복사·붙여넣기·좌우 뒤집기·대칭 복사·묶음 옮기기는 구역을 건드리지 않습니다.

**필드 아군 줄 수**

- **필드 SO 값**입니다. 필드를 다른 스테이지도 같이 쓰면, 바꿀 때 "전용 복제" 확인창이 뜨고 이 스테이지 전용 필드를 만든 뒤 그것만 바꿉니다.
- 칸 목록이 있으면 이 스테이지에서는 쓰이지 않아, 슬라이더 대신 읽기 줄만 나옵니다.
- 필드의 **적 배치 깊이**(Enemy Deployment Depth)는 지금 게임이 읽지 않습니다. 도구에서 고치지 않고 값은 그대로 둡니다.

**참고 수와 경고**

'아군 배치 구역' 아래에 "아군 구역 n칸(놓을 수 있는 칸 약 a) · 적이 놓일 수 있는 칸 약 m · 적 로드아웃 출현 k" 줄이 나옵니다(적 로드아웃이 없으면 k는 빠짐).

- a = 아군 구역 칸 − 벽·낭떠러지 지형 칸 − 장애물·구조물·본부 칸
- m = 아군 구역 밖 칸 − 같은 빼기. 게임이 무작위 적의 칸을 고르는 방식과 같습니다.
- "약"인 까닭: 무작위 시작 지형, 숨김 호환 벽, 공개 대상은 세지 않습니다. 그래서 게임 판정과 조금 다를 수 있습니다.

| 경고 | 뜻 |
|---|---|
| ① 아군 배치 구역 안에 고정 적 배치 n개 | 전투 진입 때 멈춥니다. 적을 옮기거나 구역을 바꾸세요. |
| ② 적 로드아웃 출현 수(k)가 적이 놓일 칸(약 m)보다 많음 | 전투 진입 때 멈출 수 있습니다. 구역을 줄이거나 Spawn Count를 줄이세요. |
| ③ 아군 구역에 아군을 놓을 칸이 없음 | 배치 국면에 아군을 하나도 놓을 수 없습니다. |
| ④ 고정 적 배치와 적 로드아웃을 함께 씀 | 전투 진입 때 멈춥니다. 고정 적 유닛과 적 로드아웃 중 하나만 쓰세요. |

위 아군 구역 참고 경고는 저장·등록을 막지 않습니다. 벽·낭떠러지와 고정 배치의 겹침 오류(§8.2)는 저장·등록을 막습니다. 작업 중간 상태를 저장할 수 있게 하려는 것입니다. 표에 등록하기 전에 경고가 없는지 보세요.

**게임 화면**

칸 목록으로 정한 스테이지도 게임 화면에 아군 색과 "놓을 수 있는 칸" 표시가 칸대로 나옵니다(2026-10-29 전투 화면 쪽 작업이 들어옴).

### 5.9 고른 칸에서 고치기

**배치 → 선택**에서 같은 칸에 여러 배치가 있으면 **속성 대상**을 고릅니다. X/Y는 함께 입력한 뒤 적용합니다. 속성에서 고른 대상과 지도 끌기·Delete/R의 칸 기준 대상은 다를 수 있으므로, 특정 배치만 지울 때는 해당 속성의 **이 배치 지우기**를 사용하세요.

| 배치 | 고칠 수 있는 값 |
|---|---|
| 적 유닛 | 유닛 정의, X·Y, 회전, **격파 목표**(보스 격파 승리 조건용 표식), 시작 아이템 |
| 구조물 · 장애물 | 정의, X·Y, 회전 |
| 지형 · 오브젝트 | 정의, X·Y, 공개 대상(None/Player/Enemy/Neutral 등 현재 열거 목록), 외형 회전(View, 고지대·토네이도는 없음), 지형은 "무작위 시작"(토네이도만), 토네이도는 "가로 방향"(자동·왼쪽·오른쪽. 왼쪽·오른쪽 가장자리 중심은 안쪽으로 정해져 이 값을 쓰지 않음) |
| 적 본부 | X·Y, 회전, 이 배치 지우기 |

새로 놓는 지형·오브젝트의 공개 대상은 기본으로 **Player + Enemy**가 선택됩니다(None·Neutral 제외). 클릭·드래그·사각형 칠하기에 동일하게 적용되며, 배치 후 개별 변경할 수 있습니다. 기존 배치와 복사/붙여넣기·대칭 복사·스테이지 복제는 원래 공개 설정을 유지합니다.

- 무작위 시작 지형은 고정 칸이 없으므로 **배치 속성 → 무작위 지형**에서 따로 고칩니다. 공개·숨김 안내의 **무작위 지형 열기**로도 이동할 수 있습니다.
- 지형·오브젝트의 `sourceId`는 도구가 자동으로 정합니다(바꾸지 않음).
- **토네이도도 외형 회전이 없습니다.** 패널에 "토네이도는 회전 없음"으로 나오고, 다른 지형을 토네이도로 바꾸면 그 칸의 외형 회전은 같이 지워집니다. 남아 있으면 저장할 수 없습니다. 고지대는 붙은 이웃 칸이 모양(끝·모서리)과 회전을 정합니다. 외형 회전이 하나라도 들어 있으면(R0이어도) 전투 화면이 오류로 멈추므로, 도구는 외형 회전 칸 대신 "이웃 모양이 정함"만 보입니다.
  - 벽 같은 다른 지형을 고지대로 바꾸면, 그 칸에 넣어 둔 외형 회전은 같이 지워지고 알림이 뜹니다. Ctrl+Z 한 번이면 둘 다 돌아옵니다.
  - 예전 데이터에 외형 회전이 남아 있으면 경고와 **외형 회전 지우기** 버튼이 나옵니다. 지울 때까지 검사·저장이 막힙니다.
  - 이웃 모양을 쓰는 지형은 외형 표(TerrainVisual)의 모양 칸(OneSide~FourSide)이 하나라도 찬 지형입니다. 지금은 고지대뿐입니다.

### 5.10 배경과 바닥 타일

**배경 방식** (스테이지 설정 → 배경·타일·카메라)

| 방식 | 배경 | 쓰는 칸 |
|---|---|---|
| 프리팹 | 맵 프리팹 그대로 | 맵 프리팹 |
| 맵 SO | 맵 작업실의 맵 SO(프리팹 + 베이크 정보) | 맵 SO |
| 프리팹 + 바닥 타일 | 구멍 난 맵 프리팹 + 구멍을 채우는 칸 단위 타일 | 맵 프리팹 + 바닥 타일 |

- 방식을 바꿔도 쓰지 않게 된 칸의 값은 지우지 않습니다("값이 남아 있지만 이 방식은 쓰지 않습니다"). 게임은 그 값을 읽지 않고, 방식을 되돌리면 그대로 씁니다.
- 바닥 타일 방식에서는 위치 보정의 가로(x·z)를 기준 타일이 정하고 높이(y)만 씁니다. 회전 보정 Y는 90° 단위로 맞춰지고, X·Z가 0이 아니면 전투에 들어갈 때 멈춥니다.
- 바닥 타일 확인은 사용자가 정한 확인용 복제 스테이지에서 하세요. `Test` 원본이나 미저장 `Stage_Test2` 초안을 확인 목적으로 임의 저장·폐기하지 않습니다.

**바닥 타일 묶음** (바닥 타일 오른쪽 또는 설정 → 배경·타일·카메라, 바닥 타일 방식일 때)

| 칸 | 뜻 |
|---|---|
| 타일 세트 | 종류마다 **Prefabs 후보 목록·공유 윗면 높이 하나**를 정한 SO(`CombatMapTileSet_…`). 후보가 하나면 그대로, 여러 개면 칸마다 하나를 같은 확률로 고릅니다. 여러 스테이지가 함께 쓰며, 내용은 **Inspector에서** 고칩니다('타일 세트를 Inspector에서 보기'). |
| 가로·세로 칸 수 | 배경 구멍의 최대 크기(필드 크기와 따로). 바꾸면 있던 칸은 그대로, 새 칸은 세트 첫 종류입니다. 1~128칸. |
| 타일 크기 | 타일 한 칸 크기. **0보다 큰 소수와 칸 간격의 소수 배수도 지원**합니다. 배경 배율이 곱해집니다. 칸 높이·바닥 교체 대상은 칸 중심 아래 타일로 정합니다. |
| 타일 위치(MapTileRoot) | 구멍 가운데 자리(배경 기준). y는 타일 바닥 높이입니다. |
| 기준 타일 | 게임 (0,0) 칸이 놓일 타일. 화면 기준 좌하단 타일이 (0,0)이고 배경 회전과 무관합니다. |

- 비어 있으면 **타일 만들기**가 나옵니다. 지금 필드 크기·칸 간격·배경 배율로 "타일 한 장 = 칸 하나"인 배치를 만듭니다. 위치·기준 타일은 배경 구멍을 보고 고치세요.
- 종류별로 프리팹·높이·쓰인 칸 수가 나옵니다. 세트에 없는 종류, 칸 수가 가로 × 세로와 다름, 세트 없음은 **저장 검사가 막습니다.**

**타일 보기** (상단 **바닥 타일** 작업 영역)

- 타일 맵 전체를 화면 방향으로 그립니다(아래 = 필드 −Z, 왼쪽 = −X). 칸 색·글자 = 종류, **흰 테두리 = 필드가 놓일 자리**(타일 맵 밖으로 넘치면 빨강), **노란 테두리 = 기준 타일**.
- 모드 줄: **칠하기 | 선택 | 기준 타일**.
  - 칠하기: 종류를 고르고 누르기·끌기는 칸마다, Shift+끌기는 사각형, **모두 이 종류로**. 끌기 한 번이 Ctrl+Z 한 번이고, 바뀌는 칸이 없으면 기록하지 않습니다.
  - 선택: 타일을 고른 뒤 돌리거나(아래 "타일 돌리기") 복사·붙여넣기합니다(아래 "타일 복사·붙여넣기").
  - 기준 타일: 누른 타일로 기준 타일을 옮깁니다(필드 자리가 따라 움직임).
- 에셋의 칸 순서는 배경 회전 전 방향이라 화면과 다를 수 있습니다. 도구가 바꿔 쓰므로 화면에서 보이는 대로 칠하면 됩니다.
- 타일마다 **검은 띠**가 프리팹의 앞쪽(+Z) 변을 가리킵니다. 돌린 타일은 이름 아래에 각이 나옵니다.

**타일 복사·붙여넣기** ('타일' 보기 선택 모드)

1. 타일을 고르고(고르는 법은 아래 표) **복사** 또는 Ctrl+C. 고른 칸만 담기므로 떨어진 모양도 유지됩니다.
2. 필요하면 다른 스테이지를 엽니다. 복사한 내용은 창을 닫을 때까지 남습니다(대상 스테이지에 바닥 타일이 먼저 있어야 합니다).
3. 붙일 자리의 타일을 고르고 **붙여넣기** 또는 Ctrl+V. **고른 타일의 왼쪽 아래**가 복사한 묶음의 왼쪽 아래가 됩니다. 한 번이 Ctrl+Z 한 번이고, 붙인 타일이 고른 상태로 남습니다.

맵 전체를 옮기려면 Ctrl+A → Ctrl+C, 다른 스테이지에서 왼쪽 아래 타일을 고르고 Ctrl+V입니다.

- 복사되는 것은 칸의 종류와 회전뿐입니다. 타일 세트·가로·세로·크기·위치·기준 타일은 복사되지 않습니다.
- 회전은 화면에서 본 각이 유지되고, Random은 Random으로 남습니다.
- 타일 맵 밖으로 넘치는 칸은 버리고, 대상 세트에 없는 종류의 칸은 건너뜁니다. 가로 ≠ 세로 타일에 90°·270°가 들어오면 그 칸은 0°로 둡니다. 어느 경우든 알림에 칸 수가 나옵니다.

**타일 돌리기** ('타일' 보기 선택 모드, 2D·3D '타일 회전' 도구)

타일마다 0°·90°·180°·270° 또는 **Random**을 지정합니다. 먼저 타일을 고르고, 고른 타일의 회전 옵션을 한 번에 바꿉니다.

| 입력 | 고르기 |
|---|---|
| 클릭 | 그 타일 하나만 |
| 끌기 | 지나간 타일들 |
| Ctrl+클릭 | 그 타일을 더하거나 빼기 |
| Ctrl+끌기 | 지나간 타일을 더하기 |
| Shift+끌기 | 사각형 안 타일 |
| Ctrl+Shift+끌기 | 사각형 안 타일을 더하기 |
| Ctrl+A | '타일' 보기·3D = 타일 맵 전부, 2D = 판 위 타일 전부 |
| Esc | 고르기 비우기(끄는 중이면 그 끌기만 취소) |

- 돌리기: 회전 줄의 **↺ 90°·↻ 90°**, 각 지정 **0°·90°·180°·270°**, 단축키 **R**(시계)·**Shift+R**(반시계). 한 번이 Ctrl+Z 한 번입니다. 고르기 자체는 Ctrl+Z에 남지 않고, 스테이지·가로·세로·타일 세트를 바꾸면 비워집니다.
- **Random** 버튼은 고른 타일을 생성할 때 각을 고르게 합니다. 90° 버튼·R·Shift+R은 Random 칸을 유지하고 고정 각인 칸만 돌립니다. 고정 각 버튼을 누르면 Random에서 그 각으로 바뀝니다.
- '타일' 보기의 **? 표시는 Random**입니다. 검은 띠는 현재 예시 방향이고, 툴팁·고른 칸 정보에서 `Random (예시 …°)`를 확인합니다. 저장하는 값은 예시 각이 아니라 Random입니다.
- **랜덤 다시 뽑기**는 이 창의 프리팹/각 미리보기만 바꿉니다. Repaint·카메라 조작·보기 전환에는 결과가 유지되며, 다시 뽑기는 SO·작업본·Undo를 바꾸지 않습니다. 실제 전투는 진입 때 별도로 고릅니다.
- 각은 **화면에서 본 시계 방향, 프리팹 원래 모습에서 돈 양**입니다(0° = 돌리지 않음). 배경이 뒤집힌(배율 음수) 스테이지가 아니면 화면 각 = 인스펙터 `Rotations` 값입니다.
- **판 밖 타일**은 '타일' 보기나 **3D**에서 고르세요. 3D '타일 회전' 도구는 판 밖을 눌러도 그 자리의 타일을 고르고(끌기·Shift+끌기도 판 밖까지, 사각형은 타일 맵 끝에서 멈춤), 판 밖 타일에도 하늘색 테두리를 그립니다. 판 밖을 눌러도 오른쪽 '고른 칸'은 바뀌지 않습니다. 2D는 판 칸만 그려 판 안 타일만 고릅니다. 고른 타일은 세 보기가 함께 씁니다(보기를 바꿔도 남음).
- 2D·3D: 고른 타일이 덮는 칸에 하늘색 테두리(이 도구일 때만), 3D는 타일이 실제로 돌아가 보입니다. 고른 칸 줄의 '바닥 타일'에 "회전 90°".
- **타일 크기가 가로 ≠ 세로**면 0°·180°만 됩니다(90° 버튼이 막힘). Random도 이 두 각에서 고릅니다. 이미 고정 90°·270°인 타일이 있으면 경고가 뜨고 저장 검사가 막습니다.
- 타일은 **프리팹 피벗을 중심으로** 돕니다. 피벗이 타일 가운데가 아닌 프리팹은 돌리면 칸에서 벗어납니다.
- 저장하면 View `mapTiles.rotations`에 씁니다. 모두 0°면 빈 목록으로 씁니다(게임은 빈 목록 = 모두 0°).
- 같은 종류에 등록한 프리팹 후보는 같은 크기·피벗·윗면 높이로 제작합니다. 후보별 높이를 따로 적지 않습니다. 도구는 후보 목록·개수·공유 높이와 고른 칸의 예시 프리팹을 보입니다.

**2D·3D에서 보이는 것**

- 2D: 칸마다 **아래쪽 띠**가 그 칸에 깔리는 타일 색입니다. 어두운 띠 = 타일 맵 밖(배경 위), 검은 줄무늬 = 약한 지반·낭떠러지(게임은 그 타일을 숨김). 범례에 판 안의 종류가 나옵니다.
- 고른 칸 줄에 "바닥 타일 Test3 · 높이 −0.1 · 타일 (x, y)"가 나옵니다.
- 3D: §5.7.

**맞춤 문제 알림**

맵 아래·바닥 타일 묶음·저장 뒤 알림에 같은 내용이 나옵니다. **저장은 막지 않습니다.** 문제가 있으면 필드 자리·2D 띠·3D 타일은 그리지 않습니다.

| 알림 | 뜻 |
|---|---|
| 이대로면 전투에 들어갈 때 멈춤 | 필드 보기가 GridOutline이 아님 / 회전 보정 X·Z로 기울어짐 / 타일 크기·배율·칸 간격 비율이 양의 유한 값이 아님 / 기준 타일이 타일 맵 밖 |
| 경고 | 필드가 타일 맵 밖으로 넘침(넘친 칸은 배경 위에 놓임) / 타일 한 장에 칸 여럿(약한 지반·낭떠러지 칸은 그 타일 전체를 비움) |

**고친 것이 안 보일 때**

- 타일 세트(프리팹·높이)나 필드 보기를 Inspector에서 고쳤으면 머리줄 **목록 새로고침**을 누르세요. 자동으로는 다시 읽지 않습니다. 저장하지 않은 편집·Undo·3D 시점은 그대로 남습니다.
- 2D 표시와 기본 전체 배치 3D 표시는 공개 대상과 관계없이 지형을 보여 줍니다. 3D의 `Player 기준`을 켜면 Player에게 공개된 지형만 표시하며, 높이와 바닥 타일 숨김에도 같은 공개 대상 필터를 적용합니다.

### 5.11 낙석

**스테이지 설정 → 기믹**의 레일 아래에 있습니다. 배치 화면 왼쪽 **낙석 모양·설정**으로도 바로 갑니다. 꺼도 값은 지워지지 않고, 편집만 비활성화됩니다. 새로 만들기·복제하면 틀의 값이 그대로 따라옵니다. 모양은 격자로 그리며(§5.13), 아래 수치는 **세부 설정**, X/Y 줄 목록은 **고급 좌표**에 있습니다.

| 칸 | 뜻 |
|---|---|
| 낙석 사용 | 이 스테이지에서 낙석이 일어나는지 |
| 터널 폭발 사용 | 세부 설정에서 켜고 끕니다. 기본은 켜짐. 끄면 터널 폭발 이펙트·폭발 흔들림만 생략하며, 스테이지별 짝 View에 저장됩니다 |
| 대기 | 경고를 띄우기 전까지의 진영 종료 횟수. 1 이상 |
| 경고 | 경고 칸이 보인 뒤 돌이 떨어질 때까지의 진영 종료 횟수. 1 이상 |
| 돌 수 최소·최대 | 한 번에 떨어지는 돌 수의 범위. 최소 1 이상, 최대는 최소 이상. 놓을 칸이 모자라면 돌이 더 적어집니다 |
| 최대 체력 손실 % | 맞은 유닛이 최대 체력 기준으로 잃는 비율. 0~100 |
| 묶임 턴 | 맞은 쪽을 묶는 턴 수. 1 이상 |
| 돌 하나의 칸(오프셋) | 돌 하나가 차지하는 칸 모양. 기본은 (0, 0) 한 칸이면 됩니다. 비어 있으면 안 되고, 음수·중복은 안 되며, x·y 각각의 가장 작은 값이 0이어야 합니다 |

어느 칸에 떨어질지는 전투 중에 무작위로 정해져 도구에서 미리 볼 수 없습니다. 구조물이 있는 칸과 벽·낭떠러지 칸에는 떨어지지 않습니다.

값이 잘못되면 검사에서 **"낙석 값:"** 으로 시작하는 오류가 나오고 저장되지 않습니다(문구 뒤쪽은 영어이고, `minimumRockCount`처럼 어느 값인지 이름이 나옵니다). 낙석을 끄면 값을 검사하지 않습니다.

**터널 폭발 자리**

**폭발을 끄려면:** 낙석을 켠 뒤 **세부 설정 → 터널 폭발 사용** 체크를 해제하고 **검사 → 저장**하세요. 다음 전투 진입부터 적용됩니다. 경고 칸·느낌표·경고음, 돌의 낙하, 착지 효과·착지 흔들림·소리, 피해·묶임은 유지됩니다. 터널 오브젝트를 지우거나 이름을 바꿀 필요가 없습니다.

설정은 Undo/Redo·초안·저장/재열기·스테이지 복제에 포함됩니다. 낙석을 껐다 켜도 유지되고, **배치 비우고 만들기**에서도 틀의 값을 이어받습니다. 영역/타일 복사나 모양 기본값 복원은 이 설정을 바꾸지 않습니다. 짝 View가 없으면 설정이 비활성화되므로 먼저 짝 View를 만드세요.

폭발 사용을 켜면 맵 프리팹 안의 빈 오브젝트 `RockfallTunnelBoom`의 위치·회전에서 폭발이 납니다. 이름이 정확히 같아야 합니다.

| 프리팹의 `RockfallTunnelBoom` | 게임 | 도구 |
|---|---|---|
| 1개, 낙석·터널 폭발 켜짐 | 폭발 + 경고 칸 | 아무것도 안 나옴 |
| 0개, 낙석·터널 폭발 켜짐 | 폭발 없이 경고 칸과 돌만 나옴 | 경고만, 저장됨 |
| 0개 또는 1개, 낙석 켜짐·터널 폭발 꺼짐 | 폭발 없이 경고 표시·낙하·착지 유지 | 터널 누락 경고 없음, 저장됨 |
| 0개, 낙석 꺼짐 | 상관없음 | 아무것도 안 나옴 |
| 2개 이상 | 낙석이나 터널 폭발이 꺼져 있어도 전투 진입 때 멈춤 | 오류, 저장 안 됨 |

**돌 출발 능선**

돌은 맵 프리팹 안의 빈 오브젝트 `RockfallRidgeStart`와 `RockfallRidgeEnd`를 이은 구간에서 출발합니다. 돌산의 전투판 쪽 경사면 위에 두 끝을 놓으세요. 출발 높이는 이 오브젝트의 높이입니다. 돌에 충돌이 없어서 경로에 바위가 있으면 뚫고 지나갑니다. 이름이 정확히 같아야 합니다.

| 프리팹의 끝점 | 게임 | 도구 |
|---|---|---|
| 둘 다 1개씩 | 능선에서 출발 | 아무것도 안 나옴 |
| 하나 또는 둘 다 없음, 낙석 켜짐 | 칸 위에서 곧게 떨어지고 경고 로그 한 번 | 경고만, 저장됨 |
| 하나 또는 둘 다 없음, 낙석 꺼짐 | 상관없음 | 아무것도 안 나옴 |
| 같은 이름이 2개 이상 | 낙석이 꺼져 있어도 전투 진입 때 멈춤 | 오류, 저장 안 됨 |

돌의 크기·회전·흩뿌림과 곧게 떨어질 때의 높이는 `DataBaseSO/ViewGroup/RockfallVisual/Item/RockfallVisual_Default.asset`에서 고칩니다. 스테이지마다 따로 두지 않습니다.

터널과 능선 끝점 수는 **검사** 또는 **저장**을 누를 때 셉니다. 프리팹을 고친 뒤에는 검사를 다시 누르세요. 맵 SO 방식 스테이지는 세지 않고 패널에 안내만 나옵니다.

### 5.11.1 낙석 켜기를 배치 화면에서 (GP-a)

- **낙석** 도구(도구 줄 끝)로 맵의 아무 칸이나 누르면 낙석이 켜집니다. 낙석 위치는 전투 중 무작위로 정해지므로 맵에는 그리지 않습니다. 이미 켜져 있으면 안내만 합니다.
- 왼쪽 **기믹 배치 → 낙석 켜기**를 맵의 아무 칸에 끌어 놓아도 켜집니다.
- 끄기는 낙석 도구 줄의 **낙석 끄기** 또는 기믹 설정의 '낙석 사용'입니다. 도구 줄의 **모양·세부 설정**으로 돌 모양·주기 설정에 갑니다.

### 5.12 하붑

**스테이지 설정 → 기믹 → 하붑** 또는 배치 화면 왼쪽 **하붑 모양·설정**에서 사용 여부를 켜고 모양/값을 설정한 뒤 **검사 → 저장**합니다. 구름의 상대 모양은 설정 안의 격자로 그리며(§5.13), 주기는 **세부 설정**, X/Y 줄 목록은 **고급 좌표**에 있습니다. 시작 위치는 아래 입력이나 배치 화면의 **하붑 시작** 도구로 지정합니다. 지정하지 않으면 무작위로 시작하고, 이후 이동은 항상 무작위입니다.

| 항목 | 뜻 |
|---|---|
| 하붑 사용 | 끄면 입력만 비활성화하고 기존 값은 보존 |
| 이동 주기(진영 종료 횟수) | 위치를 다시 정하는 간격. 1 이상이며 초 단위가 아님 |
| 이동 전 경고(진영 종료 횟수) | 이동 전에 경고 단계로 들어가는 시간. 1 이상, 이동 주기 이하 |
| 하붑 영역 모양(상대 좌표) | 왼쪽 X·오른쪽 Y. 영역 안의 칸을 추가·수정·삭제하며 맵의 실제 위치를 지정하는 값은 아님 |
| 시작 위치 지정 | 켜면 전투 시작 때 아래 칸에 놓고, 끄면 전투마다 무작위. 이동은 늘 무작위. 꺼도 X·Y 값은 보존 |
| 시작 X·Y | 모양의 상대 좌표 (0,0) — 모양을 감싸는 상자의 왼쪽 아래 — 이 놓일 보드 칸(맵 칸 글자 `x,y`와 같은 좌표). 기본 12칸 모양은 이 칸이 비어 있고(네 귀퉁이 없음) 구름은 X~X+3, Y~Y+3 범위에 생김. 지정하면 2D·3D 맵에 구름 칸을 그리고 '덮는 칸' 줄에 범위를 보임 |

- 기본 주기·모양은 기존 게임 설정을 따릅니다. 기본 12칸 모양에는 (0,0)이 없어도 정상입니다. 목록은 비거나 중복·음수가 있으면 안 되며 X/Y 각각의 최소값이 0이어야 합니다. 불러오기·고급 좌표 입력은 자동 보정하지 않으며, 격자에서 그린 모양만 확정 때 상대 좌표를 맞춥니다(§5.13).
- 사용 중 값이 잘못되면 **하붑 값:** 오류가 나고 저장·등록·새로 만들기가 막힙니다. 낙석도 잘못됐으면 두 오류를 함께 보여 줍니다. 하붑을 끄면 상세 값 검사는 건너뛰되 저장/다시 열기에서 값을 보존합니다.
**배치 화면에서(GP-a)**

- **하붑 시작** 도구(도구 줄 끝)로 칸을 누르면, 누른 칸이 구름 가운데 근처가 되도록 시작 위치가 정해집니다. 하붑 사용·시작 위치 지정도 함께 켜지고 Undo 한 번으로 되돌립니다. 다른 칸을 누르면 옮겨집니다. 구름이 판 밖으로 나가는 칸은 놓지 않고 안내합니다.
- 왼쪽 **기믹 배치 → 하붑 시작 위치**를 누르면 같은 도구가 되고, 맵으로 끌면 놓일 구름 칸 그림자(초록 = 놓을 수 있음, 빨강 = 판 밖)가 보이며 놓으면 설치됩니다.
- 시작 위치 비우기: **선택** 도구에서 상자 선택 없이 구름 칸을 누르고 Delete. 그 칸에 다른 배치가 있으면 배치부터 지우며, 배치가 없는 구름 칸에서 시작 위치를 비웁니다. 하붑 시작 도구 줄의 **시작 위치 비우기(무작위로)**도 시작 지정만 끕니다. 하붑 사용 여부는 유지하므로, 켜져 있었다면 무작위로 시작합니다. 지우개·상자 Delete는 시작 위치를 비우지 않습니다. 하붑을 끄려면 기믹 설정의 **하붑 사용**을 끕니다.
- 도구 줄에 '하붑: 켜짐/꺼짐 · 시작 기준점: (x, y)/무작위'와 **모양·세부 설정** 바로가기가 있습니다. 이 좌표는 **시작 X/Y와 같은 왼쪽 아래 기준점**이며 클릭한 가운데 칸과 다를 수 있습니다. 마우스를 올린 칸에 그림자는 그리지 않습니다(끌어 놓는 동안만).

- Undo/Redo·초안은 기존 편집과 같습니다. **배치 비우고 새로 만들기와 배치까지 복제는 하붑 설정을 보존**합니다. 선택 영역/타일 Ctrl+C/V는 하붑 설정을 복사하지 않습니다.
- 시작 위치를 지정하면 구름이 판 안에 들어가는지 저장 검사가 봅니다. 판 밖이면 **하붑 시작 위치 …** 오류로 저장이 막히고(오류를 누르면 그 칸으로 감), 음수는 **하붑 값:** 오류입니다. 하붑이나 시작 위치 지정을 끄면 두 검사 모두 건너뜁니다.
- 무작위일 때 영역이 필드에 들어갈 수 있는지와 실제 동작은 **Play From Boot PlacedStage**로 확인하세요. 검사 통과가 전투 진입 성공을 보장하지 않으며 다음 이동 위치 미리보기나 새 경고 이펙트는 없습니다.

### 5.13 낙석·하붑 모양을 마우스로 그리기 (GSE-a)

1. 배치 화면 왼쪽의 **낙석 모양·설정** 또는 **하붑 모양·설정**을 누릅니다. 기존 **스테이지 설정 → 기믹**으로 들어가도 같습니다. 바로가기는 설정을 열기만 하며 사용 여부는 바꾸지 않습니다.
2. 해당 기믹을 켜고 **칠하기**로 클릭/드래그해 칸을 더하거나 **지우기**로 지웁니다. 낙석은 **돌 하나의 모양**, 하붑은 **구름 영역의 모양**입니다. 실제 맵에서 등장할 위치를 그리는 것은 아닙니다.
3. 마우스를 놓으면 한 획이 반영됩니다. **Ctrl+Z / Ctrl+Y**는 기존 Unity Undo/Redo를 사용합니다. 드래그 중 **Esc**, 다른 창으로 이동, 다른 명령/작업 영역으로 전환하면 미완료 획은 취소됩니다.
4. 필요한 주기·돌 수·피해 등은 **세부 설정**, 원래 X/Y 목록은 **고급 좌표**에서 편집한 뒤 상단 **검사 → 저장**을 누릅니다. 기본 모양 버튼은 모양만 복원하고 다른 수치는 유지합니다.

- **보기:** 휠로 마우스 위치를 중심으로 확대/축소하고, 가운데 버튼 또는 Alt+끌기로 이동합니다. `전체 모양`은 목록 전체를 맞춰 보여 주고 `칸 크기`는 현재 화면 중심을 유지하며 칸 크기를 돌립니다. 너무 축소된 상태에서는 확대 후 칠하도록 안내합니다. 보기 조작은 저장 값·검사 상태를 바꾸지 않습니다.
- **좌표:** 격자로 바꾼 모양은 왼쪽/아래 기준 상대 좌표로 맞춥니다. 이때 화면에서 그리던 자리는 유지합니다. 단순 열기·보기 전환·고급 좌표 입력에는 이 변환이 적용되지 않습니다. 큰/음수 좌표도 원본대로 볼 수 있으며 정수 범위를 넘는 변환은 원본을 남기고 안내합니다.
- **기존 기능:** 꺼도 설정 보존, 빈 모양/잘못된 값의 기존 검사, 저장/초안/Undo·새로 만들기/복제를 유지합니다. 선택 영역 Ctrl+C/V는 배치를, 바닥 타일 선택 모드의 Ctrl+C/V는 타일 종류·회전을 복사하며 둘 다 기믹 설정은 복사하지 않습니다. 빈 칸 지우기나 이미 있는 칸 칠하기만으로는 작업본을 변경하지 않습니다.
- **위치·진입:** 낙석 낙하 위치와 하붑 이후 이동은 Core가 무작위로 정합니다. 하붑 시작 위치는 별도 도구·입력으로 지정할 수 있습니다(§5.12). 모양 격자는 전투 위치 미리보기가 아닙니다. **컴파일·Unity 확인은 미완료**이며 모양 편집 확인 목록은 계획 §16.2입니다.

## 6. 공유 SO와 전용 복제

**설정 → 공유 SO·본부·구조물**의 각 참조 아래에서 "`<SO 이름>` 값 · `<공유 상태>`"를 펼치면 그 SO의 전체 값이 나옵니다. 필드는 **필드·아군 구역**, 카메라는 **배경·타일·카메라**에서 찾습니다.

| 상태 | 할 수 있는 것 |
|---|---|
| 다른 스테이지 n개와 공유 | **읽기만** 합니다. 고치려면 위의 **이 스테이지 전용으로 복제** 버튼을 누릅니다. |
| 이 스테이지만 씀 | 바로 고칠 수 있습니다. 값은 작업본에 담아 두었다가 **스테이지를 저장할 때** 검사한 뒤 함께 씁니다. 키 칸은 막혀 있습니다. |

- **전용 복제**는 필드·로스터·경제·적 로드아웃만 됩니다. 원본과 같은 폴더에 `<원본 이름>_<스테이지 이름>`으로 복사하고, 새 키를 주고(필드는 `<원본 fieldId>_<스테이지 키>`), 원본이 든 표에 등록합니다. 참조는 **스테이지를 저장해야** 새 SO로 바뀝니다.
- **새 필드 만들기**(설정 → 필드·아군 구역): 가로·세로·대기 칸·아군 줄 수(칸 목록이 빌 때 쓰임, 1~세로)를 넣어 새 필드(`Field_<가로>x<세로>`)를 만들고 이 스테이지 필드로 겁니다. 적 배치 깊이는 묻지 않고 지금 필드 값을 그대로 둡니다(게임이 읽지 않음).
- 필드 값을 펼치면 맨 위에 "적 배치 깊이(Enemy Deployment Depth)는 Core가 읽지 않습니다" 줄이 나옵니다. 그 값은 고쳐도 게임에 영향이 없습니다.
- 본부 정의·카메라 설정은 전용 복제 대상이 아닙니다(읽기만).

## 7. DB의 SO를 직접 만들고 값 넣기 (도구 밖)

> **가능하면 도구로 만드세요.** 도구의 새 스테이지·전용 복제·새 필드는 키 정하기, 표 등록, 검사를 대신 해 줍니다. 손으로 만들면 키 중복이나 등록 누락이 쉽게 생깁니다.

### 7.1 만드는 방법

1. Project 창에서 만들 폴더(§7.2)를 엽니다.
2. 빈 곳을 우클릭 → **Create → ProjectL → Database → …**에서 종류를 고릅니다(아래 표).
3. 이름을 정하고 Inspector에서 값을 넣습니다(§7.4).
4. **표에 등록**합니다(§7.3). 등록하지 않은 SO는 게임이 찾지 못합니다.
5. 도구 머리줄 **목록 새로고침**을 누르면 도구 목록에 나옵니다.

| 만들 것 | Create 메뉴 |
|---|---|
| Stage Root | ProjectL / Database / InGame / **Stage Root Data** |
| 전투 데이터 | ProjectL / Database / InGame / Stage / **Combat** |
| View Stage Data | ProjectL / Database / View / **ViewStageData** |
| 필드 | ProjectL / Database / InGame / **FieldData** |
| 로스터 | ProjectL / Database / InGame / **UnitRosterData** |
| 경제 | ProjectL / Database / InGame / **StageEconomyData** |
| 적 로드아웃 | ProjectL / Database / InGame / **EnemyLoadoutData** |
| 카메라 설정 | ProjectL / Database / View / **Combat Camera Settings** |
| 유닛·구조물·지형·장애물·오브젝트 정의 | ProjectL / Database / InGame / UnitData · StructureData · TerrainDefinition · ObstacleDefinition · ObjectDefinition |

> 유닛·구조물·지형·장애물·오브젝트 **정의**를 새로 만들 때는 게임 화면용 외형 표(View DB)에도 항목이 있어야 합니다. 외형이 없으면 이름이 에셋 이름으로 나오고, 3D 미리보기는 색 상자로 나오며, 게임 화면에서도 보이지 않을 수 있습니다. 새 정의는 담당 작업자와 함께 만드세요. 이 문서는 스테이지 한 벌과 참조 SO까지 다룹니다.

### 7.2 폴더와 표

| 종류 | 에셋 폴더 (`Assets/ProjectL/DataBaseSO/…`) | 등록할 표 |
|---|---|---|
| Stage Root | `InGameGroup/Stage/Root` | `InGameGroup/Stage/StageRootDataTable` |
| 전투 데이터 | `InGameGroup/Stage/Combat` | (표 없음 — Stage Root가 가리킴) |
| View Stage Data | `ViewGroup/StageViewProp/Item` | `ViewGroup/StageViewProp/StageViewPropDataTable` |
| 필드 | `InGameGroup/Field/Item` | `InGameGroup/Field/FieldDataTable` |
| 로스터 | `InGameGroup/Loadout/Item` | `InGameGroup/Loadout/UnitRosterDataTable` |
| 경제 | `InGameGroup/Economy/Item` | `InGameGroup/Economy/StageEconomyDataTable` |
| 적 로드아웃 | `InGameGroup/Loadout/Item/Enemy` | `InGameGroup/Loadout/EnemyLoadoutDataTable` |
| 카메라 설정 | `ViewGroup/CombatCamera` | (표 없음 — View가 가리킴) |

### 7.3 표에 등록하기

1. 표 에셋을 눌러 Inspector에서 엽니다.
2. **Database Items** 목록의 `+`를 누르고, 새 칸에 만든 SO를 끌어다 놓습니다.
3. 저장합니다(Ctrl+S).

- **같은 표 안에서 키가 겹치면 안 됩니다.** 겹치거나 값이 잘못된 SO가 하나라도 있으면 게임 시작(부트)의 DB 생성이 실패합니다.
- 표 위의 Group·Catalog 에셋은 고치지 않습니다(이미 표를 갖고 있음).
- 전투 스테이지는 Stage Root 표와 View 표에 **함께** 넣어야 합니다. 도구의 **표에 등록** 버튼을 쓰면 둘을 함께 처리하고, 맵 생성 규칙(§8.4)도 봅니다. 여기서 직접 고치면 그 검사를 거치지 않습니다.

### 7.4 SO별 값

**Stage Root**

| 값 | 뜻 |
|---|---|
| Stage Key | 모든 스테이지에서 유일한 키. 일반 전투 11xx, 보스 21xx(상점 1201, 강화 1202, 이벤트 1301은 이미 씀) |
| Map Key | 이 스테이지가 나오는 스테이지 맵(챕터) 키 |
| Map Role | Regular(일반 노드) / Boss(보스 노드) |
| Stage Data | 전투 데이터(`Combat_<이름>`) |

**View Stage Data**: Stage Key(Stage Root와 같게), 배경 방식(Mode)과 맵 SO 또는 맵 프리팹(방식이 고른 것만 씀, 그 안에 `Day Camera` 가상 카메라가 있어야 함 — §8.5), 위치·회전·배율 보정, **카메라 설정(필수)**, 지형·오브젝트 외형 회전.

**필드**: Field Id(유일한 글자 키), 가로(Column Count), 세로(Row Count), 대기 칸(Reserve Capacity), 아군·적 배치 깊이(각각 1 이상).

- 아군 배치 깊이(Player Deployment Depth) = 전투 데이터의 아군 구역 칸 목록이 비었을 때 쓰는 아군 줄 수(아래부터). 세로 이하여야 합니다.
- 적 배치 깊이(Enemy Deployment Depth) = 지금 게임이 읽지 않습니다. 1 이상이면 됩니다.

**로스터**: Roster Key, Unit Definitions(이 스테이지에 쓰이는 유닛 정의 목록).

**경제**: Economy Key, 시작 골드, 수동 드로우 비용, 클리어 보상(골드·명성·참가자 경험치, Clear Rewards Configured를 켜야 씀).

**적 로드아웃**(무작위로 나오는 적)

| 값 | 뜻 |
|---|---|
| Loadout Key | 표 안에서 유일 |
| Entries | 나올 수 있는 적 유닛과 가중치(1 이상). **적이 될 수 있는 1×1 유닛만** 넣을 수 있습니다. |
| Spawn Count | 뽑을 적 수. **적이 놓일 수 있는 빈 칸(아군 구역 밖, 벽·낭떠러지·구조물·장애물 칸 제외) 수보다 많으면 전투 진입 때 멈춥니다.** 고정 적 유닛을 놓은 스테이지에는 적 로드아웃을 걸 수 없습니다. |
| Random Seed | 적을 뽑고 칸을 고를 때 쓰는 씨앗 값입니다. |

**전투 데이터**: 배치 목록은 도구로 편집하세요(Inspector로 고치면 칸 계산·겹침을 직접 맞춰야 함). **스테이지 설정 → 기본 정보**의 시드·승리 조건·적 레벨·벽 모서리, **기믹**의 레일 사용·첫 발동·반복, **필드·아군 구역**과 **공유 SO·본부·구조물**의 참조·구조물 목록이 이 SO의 값입니다. 레일 주기의 단위는 **진영 종료 횟수**로, 플레이어 진영이나 적 진영의 턴이 끝날 때마다 1씩 셉니다.

- **Deployment → Player Deployment Cells**: 아군 배치 구역 칸 목록입니다. 비우면 필드의 아군 배치 깊이(아래부터)를 씁니다. 도구의 **아군 구역** 도구로 칠하세요(§5.8). 칸이 판 밖이거나 겹치면 게임 시작(부트)의 DB 생성이 실패합니다.
- "메인 캐릭터 자리" 값은 지금 전투에서 쓰이지 않습니다. 메인 캐릭터는 첫 손패로 주어지고, 플레이어가 놓습니다.

## 8. 검사·저장 규칙

### 8.1 세 단계로 막습니다

| 언제 | 무엇을 막나 | 막히면 |
|---|---|---|
| ① 놓을 때 (바로 막기) | 맵 밖, 같은 층 겹침 | 놓이지 않고 알림이 뜸 |
| ② 검사·저장·등록 때 | §8.2의 규칙 | 저장·등록하지 않음. 오른쪽 위에 문제 목록 |
| ③ 전투에 들어갈 때 (Core) | §8.5의 규칙 | 전투가 시작되지 않고 오류로 멈춤 |

**①의 "같은 층"**

- 적 유닛끼리, 구조물·본부끼리, 장애물끼리, 레일끼리는 같은 칸에 못 놓습니다.
- 지형·오브젝트는 **같은 정의끼리만** 같은 칸에 못 놓습니다. 다른 지형은 겹칠 수 있습니다.
- **다른 층끼리**(예: 적 유닛과 구조물)는 ①에서 막지 않습니다. 대신 ③에서 막힙니다.

### 8.2 검사·저장 때 보는 것

검사는 저장하지 않는 복사본에 작업본을 써 보고, 게임이 데이터를 읽는 방식(`GetData`) 그대로 읽어 봅니다. 여기에 고정 배치의 벽·낭떠러지 겹침 검사도 수행합니다. **검사 통과가 전체 전투 진입 성공을 보장하지는 않습니다.** 무작위 출현·로스터·정의 등록 등 나머지 규칙은 전투에서 확인하세요.

| 분류 | 규칙 |
|---|---|
| 한 벌 | Stage Root·전투 데이터·짝 View가 모두 있어야 함. 짝 View의 스테이지 키 = Stage Root 스테이지 키 |
| 키 | 스테이지 키는 다른 모든 Stage Root와 겹치면 안 됨 |
| 참조 | 필드·로스터·경제는 꼭 있어야 함. View의 카메라 설정도 꼭 있어야 함 |
| 승리 조건 | 보스 격파면 "격파 목표" 표식이 붙은 적 유닛이 **정확히 1개**, 본부 파괴면 **0개**이고 본부가 있어야 함. 구조물은 격파 목표가 될 수 없음 |
| 값 범위 | 적 레벨 ≥ 1, 레일 첫 발동·반복 ≥ 1(진영 종료 횟수), 회전 값이 올바름, 구조물 목록에 빈 칸 없음, 필드 아군·적 배치 깊이 ≥ 1 |
| 아군 구역 | 칸 목록의 칸은 판 안이고 겹치지 않아야 함 |
| 고정 배치 | 벽·낭떠러지와 고정 적·적 구조물·본부의 회전된 점유 칸 전체가 겹치면 오류. 이름·좌표를 보고 옮겨야 저장·등록할 수 있음. 공개 대상·3D 보기와 무관하며 호환 벽/지형도 포함 |
| 환경 배치 | 지형·장애물·오브젝트 정의가 비면 안 됨. 장애물이 회전 뒤 맵을 벗어나면 안 됨. 원본 ID(sourceId) 중복 금지. 무작위 시작은 토네이도만. 고정 중심 토네이도는 정사각형이 판 안에 들어가야 하고, 왼쪽·오른쪽 가장자리가 아닌 중심은 가로 방향을 정해야 함(지금은 전투 진입 때 멈추는 규칙을 저장 때 막음). 진입 한도는 약한 지반만 |
| View 배경 | 방식이 쓰는 칸이 있어야 함(프리팹·프리팹 + 바닥 타일 = 맵 프리팹, 맵 SO = 맵 SO). 바닥 타일 방식은 타일 세트가 있고, 가로·세로 ≥ 1, 칸 수 = 가로 × 세로, 모든 칸 종류가 세트에 있고, 타일 크기 > 0, 기준 타일 ≥ 0. 타일 회전 목록은 비었거나 가로 × 세로개이고, 타일 크기가 가로 ≠ 세로면 90°·270° 금지(§5.10) |
| View 외형 회전 | 가리키는 지형·오브젝트 sourceId가 전투 데이터에 있어야 함. 고지대(이웃 모양 지형)에는 외형 회전이 있으면 안 됨(R0이어도, §5.9) |
| 낙석 | 켜져 있으면 값이 규칙에 맞아야 함. 맵 프리팹의 `RockfallTunnelBoom`·`RockfallRidgeStart`·`RockfallRidgeEnd` 중 같은 이름이 둘 이상이면 낙석이 꺼져 있어도 저장 안 됨(§5.11) |
| 하붑 | 켜져 있으면 이동 주기·경고 시간·상대 칸 목록·지정한 시작 위치(음수 아님)가 기존 Core 값 규칙에 맞아야 함(§5.12). 시작 위치를 지정하면 구름이 판 안이어야 함. 무작위면 실제 필드에 들어가는지는 전투 진입에서 확인 |
| 맵 생성 | 표에 등록된 스테이지의 맵 키·맵 역할을 바꿔 저장하면 §8.4 맵 규칙을 봄. 저장하면 그 맵이 깨지면 막음 |
| 맵 밖 | 필드를 줄였을 때 맵 밖에 남은 배치·아군 구역 칸이 없어야 함("맵 밖 아군 구역 칸 (x, y)") |
| 공유 SO | 고친 공유 SO는 이 스테이지만 써야 함(다른 스테이지도 쓰면 전용 복제 먼저) |

#### 오류 위치와 작업 상태 읽기

- 검사 결과의 **위치 보기 (2D)**는 문제 칸과 원인 배치를 엽니다. 벽·낭떠러지 고정 배치 겹침, 도구가 찾는 맵 밖 배치 등 위치 정보가 있는 오류에만 나옵니다. 일반 SO·맵 규칙 오류의 문구에서 좌표를 추측하지 않습니다.
- 문제 칸은 판 밖이지만 앵커는 판 안이면 **배치 보기 (2D)**, 앵커도 판 밖이면 **배치 수정 (맵 밖)**을 사용합니다. `이동할 좌표`의 X·Y를 함께 정한 뒤 **좌표 함께 적용**을 누르세요. 판 밖 아군 구역 칸은 **스테이지 설정 → 필드·아군 구역**에서 수정합니다.
- 위치 이동은 선택을 해당 대상으로 바꾸고 기존 상자를 해제합니다. 일반적인 전체/2D 보기 전환은 선택·클립보드를 유지합니다. 두 동작 모두 미확정 끌기를 취소하며 저장이나 자동 수정을 하지 않습니다. 무작위 시작 지형에는 좌표 점프를 제공하지 않습니다.
- 수정·Undo/Redo·다시 읽기·새로고침 뒤에는 이전 검사 위치 결과를 쓰지 않습니다. **변경 후 재검사 필요**면 다시 검사하세요. 외부에서 에셋을 바꿨다면 **목록 새로고침**도 필요합니다.
- **조건부 확인**은 보스 교체나 기존 맵 문제 등의 경고가 남았다는 뜻입니다. 확인 취소·파일 쓰기 실패·저장 후 표 변경 실패는 별도 작업 알림으로 확인합니다. 파일 쓰기에 실패하면 검사 통과만 보고 저장됐다고 판단하지 마세요.

### 8.3 저장은 어떻게 되나

- **검사 오류가 없어야** 씁니다. 검사 오류로 중단되면 아무 파일도 바꾸지 않습니다. 경고·조건부 확인은 실제 전투에서 별도로 확인합니다.
- 쓰는 순서: 이 스테이지만 쓰는 공유 SO의 고친 값 → Stage Root · 전투 데이터 · View.
- 쓰기 도중 실패하면 작업본과 미저장 상태를 유지합니다. 이미 쓴 에셋까지 되돌리는 기능은 아니므로 오류 내용을 확인한 뒤 다시 저장하세요. 에셋 저장은 성공했지만 뒤의 표 반영이 실패한 경우에는 **에셋은 저장됨**으로 남고 표 오류를 별도로 안내합니다.
- Undo/Redo(Ctrl+Z/Y)는 저장 전 작업본에 적용됩니다.
- 다른 스테이지를 열거나 다시 읽기를 하면 저장 안 한 변경을 버릴지 묻습니다.

**초안과 저장·등록·공유의 차이**

| 이름 | 보관 위치와 의미 |
|---|---|
| 초안 | 이 PC의 미저장 작업 보관. 읽을 수 있는 현행 형식이면 창을 열 때 편집 작업본으로 복원하며 SO에 자동 저장하지 않음 |
| 보호 원문 | 구형·손상·원본 스테이지 누락 등으로 바로 복원할 수 없는 초안 원문을 이 PC에 따로 하나 보관. 버전 이력이나 영구 백업은 아님 |
| 원문 내보내기 | 원문을 파일로 따로 보관. SO 저장이나 게임에서 사용할 스테이지 파일 생성이 아니며, 내보냈다고 보관 중인 원문을 지우지 않음 |
| 저장 | 검사 후 프로젝트의 SO 에셋에 반영 |
| 등록 | 저장된 스테이지를 Run 후보 표에 반영(§8.4) |
| 공유 | 저장한 SO와 필요한 `.meta` 등을 사용자가 Git으로 커밋·push. 초안·보호 원문은 자동 공유되지 않음 |

**상단에 ‘초안 보호’가 나오면**

- 스테이지가 열리지 않아도 공통 상단에서 이유와 원문 정보를 확인할 수 있습니다. 먼저 **보호 원문 내보내기**로 별도 보관할 수 있습니다.
- **보호 초안 복원**은 현재 도구에서 읽을 수 있고 원본 스테이지가 있는 보호본에만 가능합니다. 현재 작업 교체를 확인한 뒤 미저장 작업본으로 복원하며, 보호 원문은 남깁니다. 구형 원문을 자동 변환하지 않습니다.
- 저장된 에셋으로 작업하려면 **보호본을 유지하고 에셋에서 다시 열기**를 사용합니다. 기존 미저장 작업 교체 확인은 그대로 적용됩니다. 더 필요 없는 보호본만 **보호본만 폐기**로 확인 후 지울 수 있습니다.
- 원문이 충돌하면 현재 작업이 읽기 전용으로 보호될 수 있습니다. **활성 원문 내보내기**와 **보호 원문 내보내기**로 각각 확보하고, 내용을 확인한 뒤 필요한 대상만 폐기하세요. **활성 원문만 폐기**는 현재 메모리 작업본을 버리는 명령이 아닙니다. 다른 원문을 자동 덮어쓰지 않습니다.
- 읽기·보관·정리 실패는 **보관 상태 재확인 / 실패 작업 재시도**로 다시 확인합니다. 보호본이 있다는 이유만으로 정상 편집을 막지는 않습니다. 저장 완료 뒤 추가 변경 없이 창을 닫으면 새 초안을 만들지 않으며, 이후 편집·Undo/Redo로 미저장이 되면 다시 보관합니다.
- 보호본 보관 후 활성 초안 삭제 확인만 실패했다면, 재시도에서 같은 원문이 보호돼 있는지 확인한 뒤 차단을 해제합니다. 보호본이 없거나 다르면 계속 보호 상태를 유지합니다.

DP-a 보호 처리와 TXT-a 안내는 코드 반영 상태이며 **컴파일 미확인, Unity 확인 대기**입니다. 실제 초안은 보존하고, 저장·복원·Undo 확인은 별도의 확인용 대상에서 진행하세요.

### 8.4 표 등록 규칙

- **저장한 뒤에만** 등록·빼기를 할 수 있습니다(저장 안 한 변경이 있으면 막음).
- 등록할 때도 §8.2 검사를 다시 하고, 통과해야 등록합니다.
- Stage Root 표와 View 표에 **함께** 넣고 **함께** 뺍니다.
- **등록** = 그 맵(맵 키)의 Run 후보에 들어갑니다(Regular면 일반 노드, Boss면 보스 노드).
- **빼기** = Run 후보에서 빠지고, Play From Boot PlacedStage로도 열 수 없습니다.
**맵 생성 규칙**

등록·빼기를 할 때, 그리고 등록된 스테이지의 맵 키·맵 역할을 바꿔 저장할 때 도구가 **맵 생성 규칙**을 봅니다. Run이 챕터 맵을 만들 때 쓰는 규칙이고, 어기면 그 맵의 Run 시작이 오류로 멈춥니다.

- 맵마다 보스(맵 역할 Boss) 스테이지가 **정확히 1개**.
- 맵 SO(StageMap)의 출현 설정에서 가중치나 최소 개수가 있는 종류(전투·상점·회복·강화)는 후보 스테이지가 **1개 이상**. 종류는 Stage Root가 가리키는 상세 SO로 정해집니다(전투 데이터 = 전투, 상점 = 상점, 이벤트 = 회복, 강화 = 강화).
- 맵 SO 값 자체의 규칙도 같이 봅니다. 중간 층 수 = 층 수(Depth Count) − 2입니다.
  - 가중치 합 > 0, 최소 폭(Width Min)은 1 이상 최대 폭(Width Max) 이하.
  - 첫 층 1개(Single First Layer)를 켜면 시작 바로 다음 층(깊이 1)은 노드 하나입니다. 모든 길이 그 노드를 지나고, 그 층의 자리는 1로 셉니다.
  - 첫 층 스테이지(First Stage Key, 0이면 무작위)를 넣으면 그 노드는 늘 그 스테이지입니다(예: 챕터 1-1 고정 맵 `Stage_LD_P20` = 1120). 첫 층 1개가 켜져 있어야 하고, 그 맵의 일반 스테이지여야 합니다. 그 스테이지는 다른 노드에는 나오지 않으므로, 그 종류가 다른 노드에도 나올 수 있으면 같은 종류 후보가 하나 더 있어야 합니다. 이 스테이지를 표에서 빼면 맵이 깨집니다(도구가 막음). 출현 시작 깊이는 보지 않고, 그 종류 최소 개수에 하나로 셉니다.
  - 출현 시작 깊이(Min Depth)는 1 이상이고, 쓰는 종류는 중간 층 수 이하. 1은 시작 바로 다음 층입니다.
  - 시작 깊이 1인 종류 중 가중치가 0보다 큰 것이 하나 이상(첫 층을 채울 종류).
  - 깊이마다: 그 깊이 이상에만 나오는 종류의 최소 개수 합 ≤ 최소 폭 × 그 깊이부터 마지막 중간 층까지의 층 수(첫 층 1개면 깊이 1 자리는 최소 폭이 아니라 1로 셈). 층마다 노드가 최소 폭만큼만 나와도 배치되는지 보는 검사입니다. 예: 중간 층 4, 최소 폭 2에서 상점·회복·강화가 깊이 2부터 최소 1씩이면 3 ≤ 2 × 3이라 통과합니다.
  - 어기면 "MapKey n의 출현 설정을 배치할 수 없습니다: …" 문구로 막힙니다. 깊이·최소 폭을 늘리거나 최소 개수·시작 깊이를 줄이세요.

| 경우 | 도구 |
|---|---|
| 바꾼 뒤에도 지켜짐 | 확인 창에 바뀌는 수(예: "맵 1 전투 후보 2 → 3")를 보이고 진행합니다. 저장은 창 없이 진행합니다. |
| 이번 변경이 맵을 깨뜨림 | 막고, 알림에 까닭을 적습니다(예: "보스 스테이지가 없습니다", "Combat는 … 후보 스테이지가 없습니다"). |
| 보스가 둘이 됨 | **보스 교체** 창이 뜹니다. "기존 보스를 빼고 진행"을 고르면 기존 보스를 표에서 빼고 진행합니다. |
| 전부터 깨져 있던 맵 | 경고 창을 띄우고, 확인하면 진행합니다(이번 변경이 원인이 아님). |
| 맵 키에 맵 SO가 없음 | 막지 않습니다. 그 맵 키로는 Run이 만들어지지 않는다는 안내만 나옵니다. |

- **보스 바꾸기**: 새 보스 스테이지에서 **표에 등록**을 누르거나, 등록된 스테이지의 맵 역할을 Boss로 바꿔 저장합니다. 보스 교체 창에서 "기존 보스를 빼고 진행"을 고르면 한 번에 바뀝니다. 기존 보스를 먼저 빼면 보스가 없어져 막힙니다.
- **스테이지 설정 → 등록·맵 생성 규칙**의 **맵 생성 줄**에 이 스테이지의 자리(예: "맵 1 전투 후보")와 그 맵의 상태(예: "보스 Stage_Normal_A(1101) · 폭 2~3(첫 층 1) · 첫 층 고정 1120 · 전투 2(80·1) · 상점 1(9·1, 깊이 2~) · 회복 1(7·1, 깊이 2~) · 강화 1(7·1, 깊이 2~)", 괄호는 가중치·최소 개수, 시작 깊이는 1이 아닐 때만)가 나옵니다. 빨간 상자가 보이면 그 맵은 지금 Run 시작이 멈추는 상태입니다.
- 맵 생성 줄은 **목록 새로고침** 때의 값입니다. 도구 밖에서 표나 맵 SO를 고쳤으면 새로고침하세요. 막을지는 늘 그 순간의 파일로 다시 판정합니다.
- 맵 SO의 최소 폭·첫 층 1개·첫 층 스테이지·출현 가중치·최소 개수·시작 깊이는 도구에서 고치지 않습니다(맵 SO 인스펙터에서). 개발 진입 고정 노드(Play From Boot PlacedStage)는 시작 깊이를 보지 않고, 첫 층 노드(Dev Node Id 2)를 고르면 첫 층 스테이지 대신 그 스테이지가 놓입니다.
- 표를 Inspector에서 직접 고치면(§7.3) 이 검사를 거치지 않습니다. 직접 고쳤다면 Run을 한 번 시작해 보세요.

### 8.5 전투에 들어갈 때만 검사되는 것 (Core)

다음은 도구가 저장을 막지 않습니다. 도구가 아는 것은 경고만 띄웁니다. **꼭 §4.5로 전투에 들어가 확인하세요.**

| 규칙 | 도구 경고 |
|---|---|
| 고정 적 유닛·구조물·본부는 **아군 배치 구역 밖**이어야 함 | '아군 배치 구역' 아래 경고 ① |
| 고정 적 유닛과 적 로드아웃은 **함께 쓸 수 없음** | 경고 ④ |
| 적 배치에는 **적이 될 수 있는 유닛**만 (아군 유닛·메인 캐릭터 불가) | 정의 목록에서 아군을 뺌, 예전 배치면 경고 |
| 적 유닛·구조물·본부·장애물은 **서로 다른 층이라도 같은 칸에 겹치면 안 됨** | 없음 |
| 적 유닛·구조물·본부는 **벽 지형 칸 위**에 놓으면 안 됨 | 없음 |
| 적 로드아웃 Spawn Count ≤ 적이 놓일 수 있는 빈 칸 수 (아군 구역·벽·낭떠러지·구조물·장애물 칸 제외) | 경고 ②(참고 수는 "약", §5.8) |
| 놓은 유닛·구조물 정의가 각 표(UnitDataTable·StructureDataTable)에 등록돼 있어야 함 | 없음 — 정의 목록은 표 등록과 상관없이 프로젝트의 모든 정의를 보여 줍니다 |
| 바닥 타일 맞춤: 필드 보기 GridOutline, 회전 보정 X·Z 없음, 타일 크기·칸 간격의 비율이 양의 유한 값, 기준 타일이 타일 맵 안 | 맞춤 문제 알림(§5.10) — 저장은 막지 않음 |
| View의 배경 맵 안에 이름이 정확히 **`Day Camera`인 가상 카메라**(Cinemachine Virtual Camera)가 있어야 하고, 가상 카메라끼리 이름이 겹치면 안 됨 | 없음 — 아래 "배경 맵 카메라" |

**배경 맵 카메라**

- 배경 맵은 View Stage Data의 **배경 방식(Mode)**이 고릅니다. `Prefab`·`PrefabWithTiles`는 맵 프리팹, `MapDefinition`은 맵 SO의 프리팹이고, 방식이 고르지 않은 칸은 값이 있어도 쓰지 않습니다. 방식은 **설정 → 배경·타일·카메라 → 배경 방식**에서 바꿉니다(§5.10). 맵 안 가상 카메라는 이동·줌·흔들림에 사용하며, View의 **카메라 설정**(카메라 조작 값)과는 다른 것입니다.
- 지금(2026-10-29) 일반 스테이지 A~C(`Prefab`)와 Test(`PrefabWithTiles`)가 쓰는 맵 프리팹 `Test/StageTest`, 그리고 맵 프리팹 `Stage`에는 두 카메라가 있습니다. 보스 View(`StageViewProp_Boss`)는 `MapDefinition`이라 맵 SO `Map_Map`(`Map.prefab`)을 쓰는데, 여기에는 가상 카메라가 **없어** 전투에 들어갈 때 멈춥니다. 보스 스테이지를 틀로 새로 만들 때도 이 방식과 맵을 이어받습니다.
- FBX 배치 도구로 만든 맵은 카메라 이름이 `Map Camera`, `Map Camera 2`로 붙습니다. 전투에 쓸 가상 카메라 하나를 `Day Camera`로 바꾸세요.
- 필수 이름의 원본은 설정 표 `CombatPresentationSettings_Default`의 `morningTransitionCamera`입니다.
- 2026-11-02: Night 카메라 존재 검사와 밤 화면 전환 설정(레이어·카메라·색)을 제거했습니다. `Night Camera`·`NightMap`은 맵의 필수 구성요소가 아닙니다. 배치·전투 자동 화면 전환은 현재 꺼져 있으며 Day 카메라 검사와 아침 설정은 유지합니다. 밤 국면·BGM과 공용 Render의 수동 화면 전환은 그대로입니다.

## 9. 자주 막히는 경우

| 상황 | 확인할 것 |
|---|---|
| 스테이지가 안 열림 ("View가 n개") | 같은 스테이지 키의 View Stage Data가 둘 이상입니다. 하나만 남기세요. |
| "짝 View가 없습니다" | 설정 → 배경·타일·카메라 → **틀의 View로 만들기**를 누르거나, 같은 키의 View를 만드세요. |
| 버튼 복사는 되는데 Ctrl+C/V가 안 됨 | 숫자·글자 입력 칸에서 맵으로 포커스를 옮긴 뒤 상자/타일을 고르세요. 배치의 타일 회전 도구에서는 타일 복사 키를 받지 않으므로 **바닥 타일 → 선택**으로 이동합니다. 검사 통과는 필요하지 않습니다(§5.5). |
| 도움말 중 Delete/R/Ctrl+C/V가 안 됨 | 지도 입력이 꺼진 상태입니다. **닫고 돌아가기 / Esc** 후 편집하세요. 단순 닫기는 기존 선택·클립보드·시점을 유지합니다. |
| 초안 보호 때문에 편집·저장이 막힘 | 실패/충돌 원문을 덮지 않도록 보호 중입니다. **사용법 → 안 될 때** 또는 상단 보호 UI에서 원문 내보내기·대상별 정리·재시도를 확인하세요. 내보내기만으로 삭제되지 않습니다(§8.3). |
| 저장된 표시인데 표 오류 또는 초안 정리 실패가 나옴 | 에셋 쓰기는 성공했을 수 있습니다. 실제 오류 문구에서 표 반영/초안 정리를 구분하세요. 실패했다고 모든 에셋이 롤백된 것은 아닙니다(§8.3). |
| Player 기준에서 배치가 안 보이거나 붙여넣기 거절 | **공개·숨김 안내**에서 비공개/판정 오류/위치 미정을 구분하세요. 전체/2D로 보기를 바꿔도 오류를 고치거나 붙여넣기를 자동 실행하지 않습니다(§5.7). |
| 하붑 시작 위치를 비웠는데 하붑이 계속 나옴 | 시작 지정만 해제돼 무작위로 시작합니다. 없애려면 기믹의 **하붑 사용**을 끄세요(§5.12). |
| 낙석을 클릭한 칸에 떨어뜨리고 싶음 | 낙석 도구는 사용 여부만 켭니다. 실제 낙하 위치는 자동이며 모양 격자는 돌 하나의 상대 영역입니다(§5.11~5.13). |
| 저장이 안 됨 | 오른쪽 위 빨간 문제 목록을 보고 고친 뒤 다시 저장하세요. |
| 공유 값을 못 고침 | "다른 스테이지 n개와 공유"입니다. **이 스테이지 전용으로 복제**를 먼저 누르세요. |
| 등록 버튼이 안 눌림 | 짝 View가 없거나, 이미 둘 다 등록돼 있습니다. 저장 안 한 변경이 있으면 먼저 저장하세요. |
| 등록·빼기·저장이 "맵 생성 규칙에 걸려" 막힘 | 알림 문구를 보세요. "보스 스테이지가 없습니다" = 보스를 빼려 함(새 보스를 먼저 등록해 교체), "보스 스테이지가 n개" = 보스 교체 창에서 기존 보스를 빼고 진행, "… 후보 스테이지가 없습니다" = 그 종류의 마지막 후보를 빼려 함(다른 후보를 먼저 등록) (§8.4) |
| 고지대에 외형 회전 칸이 없음 | 정상입니다. 고지대는 이웃 칸이 모양과 회전을 정합니다(§5.9). |
| 놓이지 않음 | 맵 밖이거나 같은 층이 이미 있습니다(알림 확인). 적 유닛이면 정의 목록에서 적 유닛을 골랐는지 보세요. |
| 전투 진입 때 멈춤 | 콘솔 문구를 보세요. "초기 배치가 아군 배치 구역 규칙에 맞지 않습니다" = 고정 적이 아군 구역 안(경고 ①), "보드 범위 또는 점유와 충돌" = 다른 층끼리 겹침, "적 출현 수를 배치할 빈 칸이 부족합니다" = 적 로드아웃 수가 많음(경고 ②), "직접 저작한 적 배치와 EnemyLoadout은 동시에 사용할 수 없습니다" = 고정 적과 적 로드아웃을 함께 씀(경고 ④), "역할 또는 소유 권한" = 아군 정의, "화면 전환 카메라가 맵 프랍에 없습니다: Day Camera" = 배경 맵에 그 이름의 가상 카메라가 없음, "같은 이름의 버추얼 카메라가 둘 있습니다" = 배경 맵의 가상 카메라 이름이 겹침(§8.5 배경 맵 카메라), "[FieldCellSpacing] … GridOutline 모드뿐입니다" = 필드 보기가 GridOutline이 아님, "[CombatMapTileAlignment] … 정수배가 아닙니다" = 타일 크기 × 배율, "… 타일 칸 … 밖입니다" = 기준 타일, "… 평행하지 않습니다" = 회전 보정 X·Z(모두 §5.10 맞춤 문제 알림) |
| "Stage data not found. StageKey: n" | 표에 등록하지 않은 스테이지로 Play From Boot(Selected·PlacedStage)에 들어갔습니다. **표에 등록** 뒤 들어가고, 확인이 끝나면 빼세요. |
| 바닥 타일을 고쳤는데 3D·2D가 그대로 | 맞춤 문제 알림이 있으면 타일을 그리지 않습니다. Inspector에서 타일 세트를 고쳤으면 **목록 새로고침**(§5.10). |
| '타일 회전' 도구로 눌러도 안 골라짐 | 바닥 타일 방식이 아니거나, 맞춤 문제 알림이 있거나, 그 자리에 타일이 없습니다(타일 맵 밖). 판 밖 타일은 2D에서는 고를 수 없으니 3D나 '타일' 보기를 쓰세요. 맞춤 문제가 있어도 '타일' 보기 회전 모드에서는 고르고 돌릴 수 있습니다(§5.10 타일 돌리기). |
| 타일 90° 버튼이 막힘 / "회전 … 돌릴 수 없습니다"로 저장이 막힘 | 타일 크기가 가로 ≠ 세로입니다. 0°·180°만 쓰거나 타일 크기를 정사각으로 바꾸세요. |
| "회전 수가 가로 × 세로와 다릅니다"로 저장이 막힘 | Inspector에서 `Rotations` 길이를 잘못 넣었습니다. 비우거나, 툴에서 타일 하나를 돌리면 0°로 다시 채워집니다(그 전 값은 버림). |
| 아군 구역 마지막 칸이 안 지워짐 | 정상입니다. 칸 목록이 비면 필드 줄 수로 돌아가므로, '아군 배치 구역'의 **칸 목록 비우기**를 쓰세요(§5.8). |
| 새로 만든 SO가 목록에 없음 | 머리줄 **목록 새로고침** |
| 에셋 목록 읽기 실패 후 검사·저장이 꺼짐 | 목록이 없으면 검사·저장을 실행할 수 없습니다. **목록 새로고침** 후 원인 알림을 확인하세요. 목록을 정상적으로 읽으면 다른 차단 사유가 없는 경우 다시 사용할 수 있습니다. 사용법·초안 내보내기는 계속 가능합니다. |
| 3D가 비어 있거나 색 상자만 | View의 맵 SO/프리팹, 정의의 외형 표 등록을 확인하세요. |
