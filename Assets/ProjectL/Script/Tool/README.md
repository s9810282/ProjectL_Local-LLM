# ProjecL 제작 도구

처음 사용하는 경우 [전투 스테이지 편집 사용법](사용법.md)을 참고하세요. 실행, DT 읽기, 유닛 배치, 타일 편집과 엑셀 저장 순서를 설명합니다.

Unity 상단 **ProjecL → 전투 스테이지 편집**으로 전용 창을 엽니다. Project 창의 에셋 우클릭 메뉴 **ProjecL → 전투 스테이지 편집**에서도 열 수 있습니다. 창은 Unity의 다른 탭 옆에 도킹할 수 있습니다. **ProjecL → 데이터 폴더**는 `Assets/DataTable`을 선택합니다.

## 전투 스테이지 제작

1. 오른쪽 **맵 · 타일 정보**에서 Stage 키, 이름, Seed, 맵 크기와 배치 깊이를 입력하고 **맵 설정 적용**을 누릅니다.
2. 프로젝트의 `Assets/DataTable/CharacterMaster.xlsx`, `MethodMaster.xlsx`, `ObstacleMaster.xlsx`는 창을 열 때 자동으로 읽습니다. 왼쪽 **유닛 엑셀 읽기** 또는 **장애물 엑셀 읽기**로 다른 원본 파일을 읽거나 **프로젝트 DT 다시 읽기**로 프로젝트 원본을 갱신할 수 있습니다. 현재 DT의 실제 데이터 행만 목록에 표시합니다. 원본에 데이터 행이 없으면 목록은 비어 있습니다.
3. 왼쪽 유닛 목록에서 유닛을 선택하면 오른쪽에 능력치가 표시되고 유닛 배치 도구가 선택됩니다. 가운데 맵의 빈 바닥을 클릭해 배치합니다. 진형은 `Character_PositionType`의 **1=아군, 2=적군**으로 자동 결정되며 따로 선택하지 않습니다. **선택 / 이동**에서는 유닛 선택 후 빈 바닥을 클릭하면 이동하며 오른쪽 배치 정보에서 좌표도 수정할 수 있습니다. DT에 없는 Character 키나 진형이 미지정인 유닛은 새로 배치할 수 없습니다.
4. **높이 / 바닥 / 벽 / 레일 / 지우기**로 타일을 편집합니다. 벽은 먼저 현재 DT 장애물 목록에서 항목을 선택합니다. 클릭·드래그로 칠할 수 있으며 한 드래그는 하나의 되돌리기 작업입니다. 지우기는 유닛이 있으면 유닛을 지우고, 없으면 타일의 종류·높이·Terrain 키·Obstacle 키를 초기화합니다. 유닛이 있는 타일은 벽으로 바꿀 수 없습니다.
5. 3D 창은 우클릭 회전, 휠 줌, Shift+우클릭 또는 중간 버튼 이동입니다. **2D 보기**도 클릭·드래그로 편집할 수 있습니다. Unity의 Undo/Redo와 창의 되돌리기 버튼을 사용할 수 있습니다. 입력 필드를 편집하지 않을 때 Delete는 선택 유닛 삭제, Esc는 선택 해제입니다.
6. **엑셀 내보내기**로 `CombatLayout_<StageKey>.xlsx`를 저장합니다. 기본 저장 위치는 `Assets/DataTable`입니다. **엑셀 열기**로 계속 편집할 수 있습니다. 새 맵/파일로 바꾸면 편집 이력은 초기화됩니다.

편집 초안은 프로젝트별 EditorPrefs에 보관되어 창을 다시 열거나 에디터를 재시작했을 때 복원할 수 있습니다. 이 초안은 팀에 공유되는 파일이 아니므로 배치는 엑셀로 저장해 공유하세요. 창 제목 아래의 `*`는 엑셀로 저장하지 않은 변경을 뜻합니다.

## 툴창 안의 레이아웃

왼쪽은 접을 수 있는 **유닛 / 장애물 · 벽 / 타일** 구역, 가운데는 **3D/2D 맵 편집**, 오른쪽은 **선택 정보** 영역입니다. Unity Inspector를 사용하지 않습니다. 유닛의 DT 목록·배치 목록과 장애물의 DT 목록·편집 도구·배치된 벽 목록을 독립적으로 펼치거나 접습니다. 오른쪽 전체 맵·선택 타일 정보·맵 설정도 접을 수 있습니다. 접기는 배치 데이터를 변경하지 않습니다.

장애물은 `Assets/DataTable/ObstacleMaster.xlsx`를 자동으로 읽습니다. **장애물 엑셀 읽기**로 다른 원본을 고를 수 있습니다. 등록된 이름·키·생명력이 목록에 나오며 선택 후 맵을 클릭·드래그해 벽으로 배치합니다. 오른쪽 **장애물 정보**에는 생명력·피격/파괴 효과·효과 적용 지점·설명 키를 표시합니다. 기존 벽 목록의 좌표를 클릭하면 타일을 선택하고 Obstacle 드롭다운으로 종류를 변경할 수 있습니다. TerrainMaster와는 별개이며 원본 엑셀은 수정하지 않습니다.

유닛 목록 또는 배치한 유닛을 선택하면 오른쪽 **유닛 정보**에 이름, DT 진형, 생명력·방어력·공격력, 이동·공격 방식, 추가 원본 DT 정보를 표시합니다. 배치한 유닛은 인스턴스 키·좌표·타일 높이도 표시하며 위치를 수정하거나 삭제할 수 있습니다. 능력치와 진형은 DT 기반 읽기 전용이고 표시 색상은 편집할 수 있습니다.

상단 **맵 정보**, **타일 선택** 도구 또는 오른쪽 **맵 · 타일 정보** 탭으로 맵 정보를 확인합니다. 전체 맵 미리보기, 선택한 타일의 좌표·높이·종류·Terrain 키와 맵 설정을 표시합니다. 작은 미리보기의 타일을 클릭해 선택을 바꿀 수도 있습니다. **타일 선택**은 유닛이 있는 타일도 선택하며 유닛을 이동시키지 않습니다.

현재 원본 DT를 배치 엑셀의 표시용 사본보다 우선해서 사용합니다. 원본 DT를 다시 읽으면 기존 배치의 소속도 DT 진형에 맞춰 갱신합니다. 원본 DT에 없거나 진형이 잘못된 배치가 있으면 위치 데이터는 유지하되 내보내기 전에 원본 DT를 확인하도록 안내합니다.

## 데이터 계약

기존 SchemaVersion 1 배치를 읽을 수 있습니다. Obstacle 키가 연결된 배치는 SchemaVersion 2로 저장합니다. 이전 브라우저 도구 [`전투스테이지 편집/`](전투스테이지%20편집/README.md)은 버전 1만 지원하므로 장애물 배치는 Unity 도구에서 편집하세요. 버전 2 구분으로 이전 도구가 장애물 종류를 누락한 채 다시 저장하는 것을 방지합니다.

| 시트 | 용도 |
|---|---|
| CombatStageMaster | Stage 키·이름·Seed·크기·추가 설정 |
| CombatCellMaster | 모든 셀의 좌표·높이·종류·Terrain 키·Obstacle 키 |
| CombatUnitMaster | 배치 인스턴스 키·Character 키·소속·좌표·셀 높이 |
| EditorCharacterMaster | 불러온 Character 데이터와 표시 색상 사본, 참조를 읽었을 때 저장 |
| EditorMethodMaster | 불러온 Method 데이터 사본, 참조를 읽었을 때 저장 |
| EditorObstacleMaster | 불러온 Obstacle 데이터 사본, 참조를 읽었을 때 저장 |

`CombatCell_ObstacleKey`는 `CombatCell_TerrainKey`와 별개이며 0은 미지정입니다. 기존 버전 1 파일에 Obstacle 컬럼이 없으면 0으로 읽습니다. 원본 DT에서 제거된 Obstacle 키는 배치에서 자동 삭제하지 않으며 내보내기 전에 원본을 수정하거나 배치 연결을 변경해야 합니다.

맵 폭 1~40, 높이 3~40, 셀 높이 0~20입니다. 좌표는 왼쪽 아래 `(0, 0)`이며, 3D 표시 위치는 `(X, Elevation × 0.45, -Y)`입니다. 유닛은 한 칸을 점유합니다. Cell / Unit 키는 스테이지 안에서 고유하므로 여러 스테이지를 합칠 때는 `(StageKey, Key)`로 식별해야 합니다. 유닛 높이는 저장 시 해당 셀에서 계산합니다. 축소 영역에 유닛이나 편집한 타일이 남아 있으면 크기를 줄일 수 없습니다.

원본 CharacterMaster / MethodMaster / ObstacleMaster 엑셀과 기존 테이블 SO는 이 도구가 수정하지 않습니다. 원본 DT를 갱신하면 표시 색상을 유지하며 캐릭터 데이터를 다시 읽습니다. 새 배치는 현재 DT 목록에서만 만들며 키를 직접 입력하는 기능은 제공하지 않습니다.

이동·공격 범위는 브라우저 도구와 같은 **DT 형태 미리보기**입니다. 십자/대각/8방향 직선/방향별 90도 부채/평면 원형을 표시하며 이동 범위에서 벽 자체를 제외합니다. 중간 장애물, 유닛 점유, 단차, 행동비용, 시야, 스플래시 등 실제 전투 계산은 하지 않습니다. 부채 방향은 미리보기 설정이며 배치 파일에 저장하지 않습니다.

배치 엑셀을 저장하는 기능과 게임에 적용하는 기능은 별개입니다. 현재 `CombatLayout_<StageKey>`는 기존 ExcelImporter의 고정 파일명 등록 대상이 아니므로 자동으로 SO가 생성되지 않습니다. 배치용 데이터/SO/조회 등록과 런타임 변환, Core 단차 지원은 별도 연결이 필요합니다.

## 구현 및 검증

`Editor/ProjectL.Tool.Editor.asmdef`는 도구를 에디터 전용으로 구성합니다. 기존 ExcelImporter 패키지의 NPOI를 사용하며 추가 패키지는 필요 없습니다. 3D 미리보기는 별도의 PreviewRenderUtility를 사용하여 작업 중인 Scene에 게임 오브젝트를 생성하지 않습니다.

`Assets/Tests/EditMode/Tool/CombatLayoutWorkbookTests.cs`에 엑셀 왕복, 시트 계약, 잘못된 데이터 거부, 맵 축소 보호, 기존 파일 보존·교체 테스트 7개가 있습니다. Unity Test Runner에서 `ProjectL.Tool.Editor.Tests`를 실행할 수 있습니다.

`CombatCharacterCatalogTests.cs`에는 DT 진형 기반 배치, 등록되지 않은 유닛과 잘못된 좌표 거부, 원본 진형 갱신, 내보내기 검증 테스트 5개가 있습니다. 레이아웃 수정 후 실제 asmdef에 선언된 참조로 에디터·테스트 어셈블리를 컴파일하고 테스트 총 12개를 Mono에서 실행해 통과했습니다.

이전 버전 1 검증에서는 Unity 6000.0.73f1 API 기준 컴파일, Mono에서 위 테스트 7개 실행, 프로젝트 DT 읽기, SheetJS와 브라우저 모델을 이용한 엑셀 양방향 호환을 확인했습니다.

`CombatObstacleCatalogTests.cs`에는 Obstacle DT 기반 배치, Terrain·높이 보존, 잘못된 배치 거부, 삭제된 참조 검증, 장애물 엑셀 왕복, 이전 버전 호환, 버전 2 필수 컬럼 검증, 원본 장애물 읽기 테스트 8개가 있습니다. ObstacleMaster 연결과 접기 UI 수정 후 Unity 6000.0.73f1 API와 실제 asmdef 참조로 에디터·테스트 어셈블리를 컴파일하고 전체 테스트 20개를 Mono에서 실행해 통과했습니다. Unity 창에서 직접 조작하는 시각 검증은 수행하지 않았습니다.
