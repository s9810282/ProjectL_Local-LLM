# 승리 지향과 역할 지향 룰 AI 설계 초안

작성일: 2026-10-15

개정: v2 오프라인 비교 설계. 메인 피해 기준과 AP 예산 기반 반복 위험을 보완한다. 실제 설정의 원본은 [rule_weights.json](../config/rule_weights.json), 이번 실행 범위는 [오프라인 테스트 계획](2026-10-15-rule-ai-offline-test-plan.md)이다.

이번 주 목표는 ProjectL의 행동 후보에 기획적으로 설명할 수 있는 가치를 매기고, 승리 지향 정책과 역할 지향 정책의 선택을 비교하는 것이다. 두 정책은 같은 후보와 관측 정보를 사용한다. 종료 결과를 먼저 비교하고, 진행 중인 결과에서는 전술 점수와 역할 점수로 행동을 선택한다.

이 설계의 공식과 계수는 검증할 가설이다. 역할 지향 점수는 역할 준수의 대리값이며, 재미가 입증됐다는 뜻은 아니다. Unity 전투 구현 전에 별도 Python 프로토타입으로 대표 상황과 민감도를 비교한다.

## 1 합의한 범위

- 사용자가 선택한 비교 대상은 승리 지향과 역할·재미 지향의 두 정책이다.
- 역할은 현재 능력과 특성에 근거해 제안한다. 기존 기획의 확정된 역할로 취급하지 않는다.
- 이번 주 첫 비교는 고정된 행동 후보를 평가하는 실험으로 제한한다. 매 턴 전체 후보를 자동 생성하거나 여러 턴을 탐색하는 구현은 후속 작업이다.
- Core·View·씬·DB 에셋·기존 Ollama 실행기는 변경하지 않는다. 사용자가 요청한 엔진 없는 비교를 위해 별도 Python 평가기와 JSON 상황을 추가한다.
- 설계 리뷰 뒤 Task 계획을 작성하고 Phase별로 구현·검증한다. 커밋과 push는 사용자가 한다.

## 3 비교할 행동의 단위

평가 단위는 적 유닛 하나의 행동 시작부터 이번 행동을 마친 결과까지다. 후보는 대기, 공격, 이동, 합법적인 이동 후 공격을 포함할 수 있다. 각 후보의 이동·공격 순서와 행동 종료 지점을 고정한다. 이번 초안은 공격 후 추가 이동 같은 새 순서를 자동으로 생성하지 않는다.

두 정책은 동일한 snapshot과 candidate ID를 평가한다. 후보 순서가 바뀌어도 의미가 같으면 점수와 선택이 유지돼야 한다. 후보의 ID는 배열 인덱스와 구분한다.

고정 상황은 다음 출처를 구분한다.

- `synthetic`: 기획 검토용으로 수작업 작성한 값이다. 경로·비용·결과의 가정을 함께 기록한다.
- `core-derived`: 동일한 Core 규칙으로 검증·계산한 결과다. 실제 전투 연동의 근거로 사용할 수 있다.

통신용 기존 S01~S06은 synthetic 자료다. `ruleChoice`는 현행 Core를 실행해 얻은 정답으로 사용하지 않는다. 특히 S01·S05는 좌표 선택을 가정했고, S03은 대상별 피해·최대 HP·처치 결과가 합쳐져 있어 새 공식을 직접 적용할 정보가 부족하다.

### 3.1 실행 가능성과 결과의 확실성

후보의 이동 경로, 점유, AP, 이동 범위, 공격 비용, 지정 방식, 진영별 대상 규칙을 검증한다. 불법 후보는 낮은 점수가 아니라 제외 사유를 반환한다. 합법성과 전술 선호는 별개의 판단이다.

Ballista는 현재 기본값이 AP 5, 칸당 이동비 3, 공격비 4다. 다른 효과가 없는 상태에서 한 칸 이동 후 같은 턴 공격하는 후보는 사용할 수 없다. Gravekeeper의 Rider 환급도 공격 뒤에 발생하므로, 공격 전에 부족한 AP를 미리 보충한 것으로 계산하지 않는다.

종료 여부가 무작위·미공개 효과에 따라 달라지면 확정 종료로 올리지 않는다. 첫 비교에서는 필요한 결과가 불명확한 상황 전체를 미평가로 남기고, 누락 항목을 표시한다. 정책마다 다른 수의 후보를 평가하거나 모르는 값을 0으로 넣지 않는다. 실제 서비스의 실패 복귀 계약은 후속 연결 설계에서 다룬다.

## 4 공통 선택 순서

1. 실행 가능한 후보와 공통 관측 정보가 완성된 상황을 확정한다.
2. 후보 행동 완료 후의 종료 결과를 적 관점으로 분류한다.
3. `적 승리 > 전투 계속 > 적 패배` 중 존재하는 가장 높은 구간만 남긴다.
4. 같은 구간 안에서 각 정책의 점수로 선택한다.
5. 정책 점수 동률이면 명시한 동률 규칙을 적용한다.

종료 결과는 큰 보너스 상수로 흉내 내지 않는다. 같은 후보에서 메인과 적 본진이 함께 파괴되는 경우도 Core의 최종 판정을 따른다. 공격 대상의 이름 문자열만 보고 승리를 추정하지 않는다.

두 정책은 이 종료 우선순위를 공유하는 초안이다. 역할 때문에 가능한 즉시 승리를 일부러 포기하는 동작은 이번 초안에 넣지 않는다. 종료 구간의 여러 후보는 종료 이후의 반격·다음 턴 접근 가치를 0으로 두고, 현재 행동의 피해와 역할 차이만 비교한다.

## 5 공통 가치 항목

모든 값은 고정된 정의와 기준으로 정규화한다. 후보 집합의 최대·최소로 나누지 않는다. 유닛·특성의 실제 효과는 Core의 결과를 사용하고, View에서 규칙을 다시 계산하지 않는다.

| 기호 | 의미와 정의 | 초기 범위 |
|---|---|---|
| M | 플레이어 메인에게 준 실제 HP 손실 / 고정 기준 HP 10 | 0 이상 |
| D | 일반 플레이어 유닛별 실제 HP 손실 / 각 최대 HP의 합 | 0 이상 |
| K | 이번 행동으로 제거한 일반 플레이어 유닛 수 | 0 이상 정수 |
| P | 플레이어 메인을 공격할 위치로의 접근 가능성 변화 | -1~1 |
| F | 행위자를 제외한 다른 적 일반 유닛별 실제 HP 손실 / 각 최대 HP의 합 + 이번에 제거된 해당 유닛 수 | 0 이상 |
| R | 자신의 이번 전력 손실과 할인한 잠재 반격 전력 손실의 합 | 0~2 |
| B | 이번 행동으로 적 본진이 잃은 실제 HP / 본진 최대 HP | 0~1 |

일반 유닛·자기 손실·본진의 정규화 최대 HP는 행동 시작 snapshot의 값을 고정해서 사용하며 양수여야 한다. 메인 피해만 고정 참조 HP 10을 사용한다. 행동에 따라 최대 HP가 달라지는 상황은 비교 범위에서 제외한다.

메인 압박 계수는 30으로 수정한다. 따라서 메인 실제 피해 1 HP는 3점이며, 이전의 최대 HP 50 기준 1.2점보다 높다. 최대 HP 10인 일반 유닛의 피해 1 HP는 2점이다. 메인 6 피해와 일반 8 피해는 이전 7.2 대 16점에서 새 18 대 16점으로 바뀐다. 일반 유닛 처치 30점 보너스는 유지해 메인 압박이 모든 제거 기회를 덮지 않게 한다. 일반 최대 HP가 달라지면 HP당 가치도 달라지므로 메인 피해가 모든 대상보다 항상 우선한다는 보장은 하지 않는다.

행위자 자신의 반동·반격·환경 피해와 사망은 `R`에 포함하고 `F`에서 제외한다. 다른 적 일반 유닛의 실제 피해·사망은 `F`, 본진 피해는 `B`에만 넣는다. `M`은 `D`에서 제외한다. 실제 HP 손실은 과잉 공격력과 구분하며, 같은 피해 사건을 여러 결과 경로에서 중복 합산하지 않는다. 회복은 피해의 음수로 치환하지 않는다. 회복·소환·전투 자원 변화가 핵심인 상황은 이번 가치 모델을 확장하기 전까지 비교 대상에서 제외한다.

`D`는 이번에 깎은 체력의 가치이고, `K`는 그 유닛이 앞으로 행동할 기회를 없앤 추가 가치다. 두 항목을 함께 보상하는 것은 의도된 설계다. 처치 대상의 피해를 두 번 집계하거나, 여기에 같은 의미의 처치·공격력·특성 발동 보너스를 다시 붙이지 않는다. 초기 `K`는 모든 일반 유닛을 1로 본다. 유닛별 전력 가치 도입은 별도 가설로 비교한다.

### 5.1 접근 가치

`g`는 현재 위치에서 플레이어 메인을 기하적으로 공격할 수 있는 위치까지 가는 최소 이동 AP 비용이다. 실제 공격 비용과 법적인 공격 위치는 Core 계약을 따른다. 남은 AP를 소진했다는 이유로 행동 후 모든 위치를 접근 불가능으로 처리하지 않도록, 위치 비교에는 동일한 비용 기준을 사용한다.

```text
접근가능성(g) = 1 / (1 + g / 5)
도달 불가능한 경우 접근가능성 = 0
P = 접근가능성(g_after) - 접근가능성(g_before)
```

기준 5 AP는 초기 실험 설정이다. 공격력이나 현재 후보의 최대 이동 거리로 매번 바꾸지 않는다. 단순 맨해튼 거리를 공격 가능성으로 대체하지 않는다. 공격 위치·지형 비용을 구할 수 없는 기존 fixture는 이 값을 추가하기 전까지 미평가다. 벽 파괴까지 포함하는 장기 경로 탐색은 이번 범위 밖이다.

### 5.2 자기 전력과 위험 가치

전력 보유량을 생존으로 남아 있는 행동 기회 1과 최대 HP 대비 현재 HP의 합으로 정의한다. 아래 최대 HP는 시작 snapshot의 고정값이다.

```text
V(h) = 0                    if h <= 0
V(h) = 1 + h / 최대HP        if h > 0

실제자기손실 = max(V(행동전HP) - V(행동후HP), 0)
반격가정후HP = max(행동후HP - 잠재반격피해, 0)
잠재추가손실 = max(V(행동후HP) - V(반격가정후HP), 0)
R = 실제자기손실 + alpha × 잠재추가손실
초기 alpha = 0.5, 허용 범위 0 <= alpha <= 1
```

0.5는 불확실한 다음 행동까지의 손실을 할인하는 초기 설정이며 피격 확률이 아니다. 입력은 `최대HP > 0`, `0 <= HP <= 최대HP`, `잠재반격피해 >= 0`을 만족해야 한다. 이미 이번 행동으로 사망했다면 실제 전력 손실을 지불하고 잠재추가손실만 0이다. 사망해서 미래 위험 계산이 사라지는 것을 이득으로 보상하지 않는다. 확정 피해와 미래 피해는 행동 후 HP를 경계로 나눠 같은 손실을 반복 차감하지 않는다. 이미 발생한 반격은 실제자기손실에만 기록한다.

비회복·고정 최대 HP 조건에서 생존 후보는 `R <= V_before - (1-alpha) × V_after`이고, 즉시 사망 후보는 `R = V_before`다. 다른 이득이 같을 때 자기 사망만으로 손실이 줄지 않는다. alpha가 1보다 작으면 이 자기 손실 항은 생존을 엄격히 선호한다.

잠재반격피해는 후보 완료 후부터 자신의 다음 행동 직전까지의 일관된 공격 일정으로 추정한다. 살아남은 플레이어 유닛과 해당 구간에 포함된 행동 기회만 사용하며 한 행동 기회 안에서도 AP가 허용하는 반복 공격을 반영한다. 플레이어의 공격 횟수를 현재 적 서비스의 최대 1회로 제한하지 않는다.

- 고정 반복 모드는 피해·비용·사거리·상태가 반복 중 불변이고 환급이 없다고 명시한 경우에만 `floor(사용 가능 AP / 유효 공격비)`를 쓴다. 유효 공격비는 양수다.
- 명시 시퀀스 모드는 공격별 최종 피해·유효 비용·사후 환급을 입력한다. 비용을 먼저 지불하고 환급은 뒤에 더한다. 공격 전에 비용이 부족하면 그 환급으로 공격을 정당화할 수 없다. 할인·집중·변위·일회성 환급의 효과 자체는 Python에서 재구현하지 않는다.
- 여러 기회는 하나의 순서 있는 일정으로 제공한다. 서로 양립하지 않는 상대별 최대 피해를 합쳐 하나의 확정 미래로 만들지 않는다. 목표가 제거되면 이후 그 목표에 대한 실제 적용 피해는 0이다.
- 살아 있는 각 플레이어는 일정에 포함되거나 공격 기회 없음·제자리 사거리 밖 등의 명시된 비위협 사유로 분류돼야 한다. 입력 누락과 위협 0은 다르다. 불완전한 관측·순서 미상·불지원 효과는 미평가다.

Python이 검사하는 것은 입력 일관성·AP 산술과 제출된 일정이다. 이 검사는 지형·지정·넉백의 합법성 또는 최대 피해를 Core와 동일하게 증명하지 않는다. 합법성의 출처는 synthetic 가정 또는 Core 계산 결과로 구분한다.

첫 고정 상황에서는 이 근사의 구성 값과 가정을 수작업으로 명시할 수 있다. 실제 연결에서는 Core가 허용한 조회 계약이 필요하다. 전투가 종료되면 잠재추가손실만 0으로 두고 이미 발생한 자기 손실은 유지한다. 행동 기회를 확정할 정보가 없으면 `R`은 미상이다.

기존 `threatAfter`는 위협 유닛 수일 뿐이다. 이를 `R`의 피해량이나 사망 확률로 변환하지 않는다. v2는 반복 공격의 AP 예산을 반영하지만 상대 이동 후보를 자동 생성하거나 효과를 시뮬레이션하지 않는다. 이동 후 공격은 계산 근거가 포함된 명시 일정이 있을 때만 평가하며, 계산 근거가 없으면 미평가로 둔다.

`B`는 즉시 본진 손실만 다룬다. 향후 본진 피격 위험·몸으로 진로 막기·아군 협공을 충분히 평가하는 공식은 아니다. 이런 효과가 핵심인 상황은 한계 사례로 기록하고 후속 확장한다.

## 6 승리 지향 정책

종료 구간이 같은 후보의 전술 점수를 다음 초기식으로 비교한다.

```text
W(a) = 30 M + 20 D + 30 K + 15 P - 35 F - 35 R - 60 B
```

메인 압박, 일반 유닛 제거, 전진과 희생의 교환 관계를 확인하기 위한 계수다. 메인 피해의 정의도 바뀌었으므로 이전 60에서 새 30으로 숫자가 줄었다고 압박이 약해진 것은 아니다. 이 점수는 승률이나 확률이 아니다. 여러 턴을 탐색해 최적 행동을 증명하지 않는다.

예를 들어 일반 유닛 최대 HP의 50%를 깎으면 10점, 일반 유닛 하나를 제거하면 체력 손실 점수에 추가로 30점이다. 자신이 온전한 HP이고 이번 행동의 자기 손실이 없다면, 잠재 반격으로 제거되는 근사는 R=1이므로 35점 감점이다. 실제로 이번 행동에서 온전한 HP부터 제거되면 R=2로 70점 감점이다. 이 교환이 게임 경험에 맞는지는 대표 상황으로 조정한다.

동률은 안정적인 candidate ID 오름차순이다. 좌표나 배열 순서가 우연히 가치 기준이 되지 않도록 한다. 후속 구현에서는 고정 소수점 또는 동일한 반올림 규칙을 정해 실행 환경별 동률 오차를 방지한다.

## 7 역할 지향 정책

역할 지향은 공통 전술 점수에 역할 선호를 더한다. 역할만 높은 무의미한 행동을 고르지 않도록 전술 점수의 허용 차이를 먼저 제한한다.

```text
W_best = 같은 종료 구간 후보의 최대 W
C_role = { a | W(a) >= W_best - delta }
Role(a) = W(a) + lambda × Q_role(a), a in C_role

초기값: delta = 12, lambda = 20, 0 <= Q_role <= 1
```

역할 정책은 `Role` 최대, 동률이면 `W` 최대, 다시 동률이면 candidate ID 순으로 선택한다. `C_role`에는 승리 정책의 최선 후보가 항상 들어간다. `delta`와 `lambda`는 역할을 위해 감수하는 전술 점수 차이와 역할 선호의 크기를 분리한 값이다. 허용 차이는 이 공식 안의 점수 차이이며 실제 승률·전투력 손실 한도를 보증하지 않는다.

재미를 직접 계산하는 항목은 만들지 않는다. `Q_role`은 관찰 가능한 행동 성향의 준수값이다. 플레이어가 위협을 이해하고 대응할 수 있는지는 별도 플레이 평가로 확인한다.

### 7.1 능력과 특성에 근거한 역할 제안

| 유닛 | 현재 능력 | 제안 역할 | 역할 준수값 초안 |
|---|---|---|---|
| Demon | HP 5, 공격력 1, 이동 3, 사거리 1, 특성 없음 | 기본 근접 압박 | `Q = 0.6 × T + 0.4 × A` |
| Gravekeeper | HP 10, 공격력 10, 이동 5, 근거리 부채꼴, 넉백 1칸, Rider | 기동과 넉백을 통한 진형 교란 | `Q = 0.7 × U + 0.3 × T` |
| Ballista | HP 10, 공격력 10, 이동비 3, 장거리 방향 관통, 후속 대상 피해 감소, Cannon | 사선을 활용하는 원거리 관통 포격 | `Q = 0.7 × L + 0.3 × S` |

현재 `UnitRole`은 Regular와 MainCharacter의 구분이며 위 전술 역할을 저장한 필드가 아니다. 역할 설정을 어디에 보관할지는 구현 설계에서 정한다. 현재 능력의 출처는 [Demon](../../Assets/ProjectL/DataBaseSO/InGameGroup/Unit/Item/Unit_Demon.asset), [Gravekeeper](../../Assets/ProjectL/DataBaseSO/InGameGroup/Unit/Item/Unit_Gravekeeper.asset), [Ballista](../../Assets/ProjectL/DataBaseSO/InGameGroup/Unit/Item/Unit_Ballista.asset) 에셋이다.

- `T`: 행동 후 위치에서 다음 행동 기회의 기본 자원으로 보이는 플레이어 유닛 하나 이상을 합법적으로 위협할 수 있으면 1, 아니면 0이다. 이번 행동의 AP 소진과 혼동하지 않는다. 다음 행동 기회가 없다면 0이다.
- `A`: 행동 후 플레이어 메인에 대한 §5.1의 접근가능성이다. 가까운 다른 유닛을 임의 목표로 바꾸어 유리한 점수를 만들지 않는다.
- `U`: 이번 넉백으로 밀려났고 전체 후보 처리가 끝난 뒤에도 살아 있는 대상이 적 본진의 공격 위치에 도달하는 이동 AP 비용이 늘어난 정도다. 대상별 양의 비용 증가 / 5를 0~1로 제한하고, 여러 대상이면 그 평균을 쓴다. 대상이 없으면 0이다. 비교는 동일한 피해 처리 후 넉백 직전·직후 위치를 사용한다. 이 중간 상태와 비교 비용은 아직 공개 조회 계약이 없어 Core 협의가 필요하다. 실제 피해·처치는 여기서 다시 보상하지 않는다. 도달 가능에서 불가능으로 바뀌면 1, 양쪽 모두 불가능이면 0이다.
- `L`: 이번 관통 공격에서 실제 양의 피해를 준 서로 다른 플레이어 유닛 수를 `n`으로 두고 `clamp((n - 1) / 2, 0, 1)`로 평가한다. 공격이 없으면 0이다. 참조 3명은 점수 기준이며 실제 관통 가능 인원을 바꾸지 않는다.
- `S`: 행동 후 가장 가까운 살아 있는 플레이어 유닛과 점유 칸 사이의 최소 맨해튼 거리를 `d`로 두고 `clamp((d - 1) / 3, 0, 1)`로 평가한다. 4칸 이상은 추가 보상이 없다. 이는 거리 유지 취향이며 실제 공격 가능 여부는 Core 검증을 따른다.

위치와 위험 값은 아래처럼 처리한다. 행위자 사망 때의 P=0은 접근가능성_after=0을 넣어 음의 P를 계산하는 것과 구분한다.

| 후보 완료 상태 | P | R | T와 A와 S | U | L |
|---|---|---|---|---|---|
| 전투 계속 및 행위자 생존 | 정의대로 | 실제손실과 할인한 잠재손실 | 정의대로 | 정의대로 | 이번 공격 결과 |
| 전투 계속 및 행위자 사망 | 0 | 실제손실만 | 0 | 남은 아군을 위한 실제 변위만 | 이번 공격 결과 |
| 전투 종료 | 0 | 실제손실만 | 0 | 0 | 이번 공격 결과 |

플레이어 대상이 없어 거리를 정의할 수 없을 때도 S는 0이다. 정의에 필요한 정보가 없는 경우는 값 0과 구분한다.

Ballista의 다중 피격은 `D`·`K`에도 기여한다. `L`을 더하는 것은 관통 사선을 선호하도록 의도한 행동 편향이다. 추가 피해나 효율의 새로운 증거로 해석하지 않는다. Gravekeeper의 `U`도 본진 보호 전체를 증명하는 값은 아니며, 밀어내기 방향의 국소 효과만 표현한다.

기본 역할이 일관되게 드러나도 재미가 보장되지는 않는다. 반복 추적, 공격 예측 가능성, 대응 가능성, 지나친 대기와 희생을 실제 플레이에서 따로 확인한다. 공격 예고 UI나 한 턴 준비 동작은 현재 있는 기능으로 가정하지 않는다.

### 7.2 두 정책이 다른 선택을 하는 계산 예시

다음은 일반 유닛을 공격하는 두 후보의 설명용 가정이다. 둘 다 합법·전투 계속이며, `M=K=P=F=B=0`이다. 목표 최대 HP는 같고, 반격 근사와 역할 값은 별도 계산했다고 가정한다.

| 후보 | D | R | Q | W | 역할 후보 통과 | Role |
|---|---:|---:|---:|---:|---|---:|
| A | 0.8 | 0.2 | 0.1 | 9 | 통과 | 11 |
| B | 0.6 | 0.1 | 0.9 | 8.5 | 통과 | 26.5 |
| C | 0 | 0.8 | 1.0 | -28 | 제외 | 계산하지 않음 |

승리 정책은 A, 역할 정책은 B다. B는 허용 차이 12점 안에 있고 역할을 더 잘 수행한다. C는 역할 값이 높아도 `W_best - 12 = -3`보다 낮아 제외된다. 이는 공식의 작동 예시이며 B가 더 재미있다는 실험 결과가 아니다.

### 7.3 사망 경계의 계산 확인

HP 1/최대 HP 5인 행위자에서 공격·다른 아군·위치 이득이 같다고 가정한다. 이번 행동에서 살아남지만 잠재 반격이 남은 HP 이상이면 R=0.5×1.2=0.6, W의 자기 손실 항은 -21점이다. 이번 행동에서 바로 사망하면 R=1.2, 같은 항은 -42점이다. 즉시 사망이 미래 위험을 지운다는 이유만으로 높은 점수를 받지 않는다.

실제 희생으로 상대 제거·메인 처치·아군 보호 같은 별도 이득이 생기는 경우는 그 이득과 함께 평가한다. 예상 피해가 생존 경계를 넘을 때 V의 생존 항이 사라지는 불연속은 의도된 제거 가치이며, 임계값 주변의 민감도를 별도 검증한다.

## 8 대표 상황과 검증 기준

기존 fixture는 보존하고, 후속 구현에서 별도 버전의 상황을 만든다. 기대 선택은 점수 계산 전에 이유와 함께 정한다. 정답 하나가 필요 없는 상황은 허용 선택 집합으로 기록한다.

| 상황 | 비교할 질문 | 초기 기대 또는 확인 기준 |
|---|---|---|
| 메인 처치와 일반 유닛 큰 피해 | 종료 결과가 피해량보다 우선하는가 | 확정 즉시 승리 후보를 두 정책 모두 선택 |
| 메인과 본진 동시 사망 | 단순 보너스가 실제 종료 규칙을 덮는가 | Core 종료 판정과 일치 |

| 위험이 없는 추적과 대기 | 압박 적이 목적 없이 멈추는가 | 다른 이득이 같으면 접근 가치로 전진 |
| 역할만 높고 전술 손실이 큰 행동 | 역할이 무조건 약한 선택을 만드는가 | 허용 차이 밖 후보 제외 |
| 이동 후 공격과 제자리 공격 | 후보 누락과 점수 문제를 구분하는가 | 같은 고정 후보로 비교, 실제 턴 생성 개선은 별도 요청 |
| 미공개 연쇄나 누락된 위험 | 모르는 값을 확정 수치로 계산하는가 | 미평가와 원인 표시 |
| 같은 역할 가치의 두 후보 | 억지로 두 정책의 차이를 만드는가 | 같은 선택도 정상 |

추가 불변 조건은 과잉 피해 미보상, 후보 순서 변경 불변, 무관 후보 추가 시 기존 후보 점수 불변, 고정 snapshot 반복 선택 불변이다. `U`처럼 문맥 계산을 요구하는 항목의 입력은 정책별로 다르게 만들지 않는다.

승리 지향의 평가는 종료 성과, 메인 압박, 제거, 피해 교환, 응답 지연을 기록한다. 역할 지향은 같은 지표에 역할 준수 빈도·의미 없는 대기·기대 행동과의 일치를 더한다. 재미 평가는 플레이어가 적의 의도를 설명할 수 있는지, 다른 대응 선택이 가능한지, 행동이 반복돼 지루한지를 관찰·질문으로 확인한다. 역할 점수 자체를 재미 평가의 정답으로 사용하지 않는다.

실제 전투 실험에서는 같은 초기 상태와 seed를 사용하되, 이후 선택에 따라 상태가 달라짐을 인정한다. 같은 snapshot에서의 선택 비교와 전체 전투 결과 비교를 별도 기록한다. 기존 룰은 참조 기준으로 보존하고 `ruleChoice` 일치율을 새 정책의 성능 점수로 쓰지 않는다.

## 9 구현 경계와 필수 점검

### 9.1 책임과 원본

- Core는 합법성·피해·상태 변화·승패의 원본이다. Buffer는 현재 전투 상태의 원본이다. 파생 평가 값은 snapshot에 묶인 실험 자료로만 보관한다.
- 기획된 계수·역할 정의는 한 설정 원본을 두고 두 정책이 공유한다. 현재 프로젝트의 DB에 즉시 새 필드를 추가하는 결정은 하지 않는다.
- 후보 생성, 공통 특징 산출, 정책 평가, 선택 기록, View 표시를 분리한다. 역할 정책을 위해 전투 계산기를 복제하지 않는다.
- 서로 다른 두 정책을 대체할 좁은 계약은 설계할 수 있지만, 현재 쓰이지 않는 범용 탐색·플러그인 계층은 만들지 않는다.
- 역할 지향의 허용 차이 계산도 같은 W와 같은 특징 버전을 사용한다. 설명 로그에는 각 항목과 후보 제외 이유를 남긴다.

### 9.2 Framework 계약

SSOT·SOLID·JMH 적용 기준은 [전투 View 인계 §4](../../docs/superpowers/handoffs/2026-09-30-combat-view-design-session-handoff.md), FW 계약은 [프로그래머 가이드](../../Assets/ProjectL/Script/Systems/Documentation/framework-programmer-guide.md)를 따른다.

후속 Unity 연결에서 FW-001 제공 인터페이스 등록, FW-002 수명 참여 객체 AddModule, FW-003 Build 1회, FW-004 내부 상태 우회 금지를 점검한다. 기존 Flow·Job의 진행 소유권을 유지하고, View가 Core에 직접 상태를 쓰는 경로를 만들지 않는다. 씬 종료·포기 뒤 늦게 도착한 판단의 폐기와 자원 정리는 연결 Phase에서 검증한다.

### 9.3 Core 협의 항목

실제 연결에는 다음 계약의 검토가 필요하다. 이번에는 Core 파일과 기존 인계 문서를 수정하지 않고 필요한 계약을 이곳에 모은다. 설계 리뷰 뒤 확정된 요청을 기존 Core 전달 문서에 반영한다.

1. 같은 snapshot에서 합법 행동 후보와 대상별 결과를 얻을 수 있는 경계.
2. 동일한 비용 기준의 공격 위치 접근 값과 역할용 위치 변화 자료.
3. 행동 순서와 가시 정보를 반영한 잠재 반격 근사에 필요한 조회 경계.
4. 무작위·미공개 효과의 범위와 결과 확정 여부 표시.
5. 선택을 다시 검증해 기존 처리 경로에 적용하는 경계. 현재 내부 자동 적 턴과 중복 실행하지 않아야 한다.

## 10 설계 리뷰와 다음 Phase

이번 리뷰에서 확인할 것은 종료 우선순위의 공유, 초기 가치 항목과 교환 관계, 세 유닛 역할 제안, 역할 허용 차이 방식, 위험 근사의 범위다. 계수는 정답으로 확정하지 않고 대표 상황으로 수정한다.

설계가 확정되면 별도 Task 계획에서 다음 순서를 구체화한다.

1. 기대 판단표와 입력 누락 목록 확정.
2. 버전이 있는 synthetic 상황과 순수 평가 프로토타입 작성.
3. 두 정책의 항목별 점수·선택 비교, 민감도와 경계 검증.
4. Core 계약 협의와 실제 snapshot 기반 검증.
5. Unity 표시·전투 연결, 플레이 경험 평가, 이후 LLM 비교.

오프라인 Phase의 완료 기준은 두 정책이 언제·왜 같은 선택 또는 다른 선택을 하는지 재현 가능한 자료로 설명하는 것이다. 실행 기록은 오프라인 계획과 비교 결과를 따른다. Python 프로토타입 작성과 synthetic 상황 검증은 Unity 전투 구현·검증 완료를 의미하지 않는다.
