# 진영 턴 판단 기준 재선별(룰·LLM)

작성일: 2026-11-06 · 상태: 기준 확정(Q1~Q6 사용자 "권장안대로" 11-06)

8주차 보고서 차주 계획 2번이다. 다음을 정한다.

- 룰 평가기의 기준: 반격 위험·처치·유닛 가치·행동 순서·숨은 기믹
- LLM 화면과 지시문을 어떻게 바꿀지
- 대표 상황 F01~F06의 기대 판단(**계산 전에** 적음)

입력 모양은 [진영 턴 형식 v2](2026-11-06-faction-turn-format-v2.md)를 따르고, 확정된 결정 Q1~Q4를 전제로 한다.

이 문서의 숫자는 처음 시험할 값이다. 결정(§5) 뒤에 평가기를 고치고, sweep으로 비교해서 정한다.

## 1 v1 공식에서 유지하는 것

- 종료 결과를 먼저 본다(즉시 승리 > 진행 > 즉시 패배).
- 승리 점수는 W = 30M + 20D + 30K + 15P − 35F − 35R − 60B, 역할 점수는 W + 20·Q이고, 역할 허용 차이는 6이다.
- 이 가중치는 바꾸지 않는다. 항목의 **정의**만 진영 턴에 맞게 바꾼다. 가중치를 함께 바꾸면 무엇 때문에 결과가 바뀌었는지 구분할 수 없다.
- M(메인 피해), D(일반 유닛 피해 비율), F(아군 손실), B(본진 손실)는 정의가 그대로다.

## 2 바꾸는 기준

### 2.1 반격 위험 R

v1에서는 미래 손실에 할인 0.5 하나를 곱했다. 다음 내 턴 전 AP 반복 공격을 합친 손실이었다.

v2에서는 위협을 **확실성 단계**로 나눠 할인을 따로 준다.

| 단계 | 내용 | 처음 값 | 이유 |
|---|---|---|---|
| `in_place` | 이동 없이 닿는 위협 | 0.75 | 플레이어가 그 대상을 고르기만 하면 된다. v1 R19에서 확실한 치명 위험을 0.5로 깎아 생긴 불일치를 줄인다 |
| `after_move` | 이동해야 닿는 위협 | 0.5 | v1과 같은 값. 경로가 막히거나 다른 목표를 고를 여지가 있다 |
| `chain` | KillChain 연쇄로 추가로 맞을 수 있는 피해 | 0 | 무작위이고, 먼저 다른 처치가 나야 생긴다. 점수에 넣지 않고 LLM 화면에 사실로만 보인다 |
| 예고된 기믹 | `hazardDamage` | 1.0 | 예고된 것은 일어난다. 할인하지 않는다 |

계산은 v1처럼 HP 기준 전력 손실로 한다. 단계마다 HP가 순서대로 줄어든다고 보고, 각 구간의 손실에 그 단계 할인을 곱해 더한다.

```text
h0 = 행동 뒤 HP
h1 = h0 − 기믹 피해          (할인 1.0)
h2 = h1 − in_place 피해 합   (할인 0.75)
h3 = h2 − after_move 피해 합 (할인 0.5)
미래 손실 = 1.0·(V(h0) − V(h1)) + 0.75·(V(h1) − V(h2)) + 0.5·(V(h2) − V(h3))
```

- 각 HP는 0 아래로 내려가지 않는다.
- 위협자 전원이 행위자 한 명에게 몰린다고 본다(결정 Q4).
- 이번 후보로 처치된 플레이어는 위협에서 빠진다.
- sweep으로 `in_place` 0.5 / 0.75 / 1.0을 비교한다.

### 2.2 처치 K

- 처음 단계는 **v1과 같은 처치 1명당 1점**을 유지한다.
- 진영 턴에서 처치의 가치는 "다음 아군 턴의 공격 하나를 없애는 것"이다. 행위자 자신에 대한 효과는 처치된 플레이어가 위협에서 빠지는 것으로 이미 R에 들어간다.
- 다른 적 유닛을 위협하던 공격이 없어지는 효과는 들어가지 않는다. 처치 대상의 공격력에 비례해 가중하는 변형(K′)을 sweep 후보로 둔다(§5 Q3).

### 2.3 자기 가치 V

- 공식은 v1 그대로 `V(h) = 1 + h/최대HP`다.
- 설정에 `unitWorth` 표를 새로 둔다. 유닛별 배수이고 기본값은 모두 1.0이다. 그래서 기본 결과는 바뀌지 않는다.
- R23·V08의 질문("빈사 일반 유닛과 교환할 만큼 가치가 낮은 유닛이 있나")은 이 표의 값을 바꿔서 비교한다.

### 2.4 진척 P와 넉백

AP가 없어져서 기준 단위를 바꾼다.

- `approachCost`는 메인을 공격할 수 있는 칸까지의 **이동 비용(칸)**이다.
- 진척 기준값은 `progressReferenceAp`(5 AP)에서 **행위자의 이동 거리**로 바꾼다. 비용이 이동 1회분이면 진척 가치가 절반이 된다.
- 넉백 지연(`knockbackDelays`)은 밀린 플레이어가 본진까지 가는 이동 비용이다. 기준값은 `knockbackReferenceAp`(5)에서 **그 플레이어의 이동 거리**로 바꾼다. 넉백으로 플레이어 행동이 한 턴 늦어지면 1이 된다.

### 2.5 역할 Q

적 Ballista가 없어지고 UndeadHeavy와 UndeadCannonCart가 생겼다. `roleProfiles`를 아래처럼 바꾼다. 새로운 사실 칸은 만들지 않고, 지금 `roleFacts`(위협 가능·가장 가까운 거리·넉백·맞힌 수)만 쓴다.

| 유닛 | 프로필 | 근거 |
|---|---|---|
| Demon | threat 0.6 + approach 0.4 | 그대로 |
| Gravekeeper | knockback 0.7 + threat 0.3 | 그대로 |
| UndeadHeavy | threat 0.4 + approach 0.6 | HP 30, 공격력 4. 피해보다 앞으로 나가 자리를 잡는 역할이다 |
| UndeadCannonCart | threat 0.5 + spacing 0.5 | 사거리 2, 이동 2. Ballista의 거리 유지(`spacing`)를 이어받는다. 기준은 최소 1·완전 3 |
| Stage1Boss | 평가 대상 아님 | 이동 0이고 포효 AI가 따로 있다 |

`lane`(관통 맞힌 수)은 관통 공격을 하는 적이 없어져 쓰지 않는다.

### 2.6 행동 순서와 숨은 정보

- **순서:** 엔티티 ID 순으로 고정한다(결정 Q2). 점수 항목이 아니다. 앞서 행동한 적 유닛의 결과는 현재 상태에 이미 반영돼 있다.
- **숨은 기믹:** 예고되기 전에는 룰 입력과 LLM 화면에 모두 넣지 않는다. 예고되면 §2.1의 기믹 피해(할인 1.0)로 들어간다.
- **같은 진영 턴에서 뒤에 행동할 적의 도움:** 넣지 않는다(형식 v2 §3).

### 2.7 설정 파일 변경 요약

새 버전 이름은 `rule-v3.0`이다. v1 설정 파일은 그대로 둔다.

| 키 | v2.1 | v3.0 |
|---|---|---|
| `riskMode` | `ap_budget` | `faction_turn` |
| `riskDiscount` | 0.5 | 삭제 → `riskDiscounts: { in_place: 0.75, after_move: 0.5, chain: 0, hazard: 1.0 }` |
| `progressReferenceAp` | 5 | 삭제(행위자 이동 거리 사용) |
| `knockbackReferenceAp` | 5 | 삭제(밀린 플레이어 이동 거리 사용) |
| `unitWorth` | — | 새 키, 모두 1.0 |
| `roleProfiles` | Demon·Gravekeeper·Ballista | Demon·Gravekeeper·UndeadHeavy·UndeadCannonCart |
| `laneReferenceTargets` | 3 | 삭제 |
| `spacingMin`·`spacingFull` | 1·4 | 1·3(CannonCart 사거리 2 기준) |
| 그 밖의 가중치·`roleMaxLoss`·`roleBonus`·`mainReferenceHp` | — | 그대로 |

## 3 LLM 화면과 지시문 변경안

### 3.1 화면(투영)

새 투영 함수 `project_v2`를 만든다. v1 투영은 그대로 둔다.

| v1 칸 | v2 칸 | 내용 |
|---|---|---|
| `self.ap`·`maxAp` | `self.moveRange`·`attackRange` | AP 삭제 |
| `actions` | `action`(`wait`·`move N`·`attack`·`move N -> attack`) | |
| `beforeMyNextTurn` | `nextPlayerTurn` | 아래 설명 |
| `mainApproachCost`(AP) | `mainApproachMoves`(이동 비용, before·after) | 단위 변경 |
| — | `turn.actedAllies`(앞서 행동한 적 유닛 요약), `turn.remaining`(뒤에 행동할 적 수) | 진영 상황 |
| — | `announcedHazards` | 예고된 기믹 |

`nextPlayerTurn`은 계산을 LLM에 맡기지 않고 Core·룰이 계산한 사실만 준다.

```json
{
  "hazardDamage": 0,
  "inPlace":   { "attackers": 2, "damage": 12 },
  "afterMove": { "attackers": 1, "damage": 4 },
  "chainPossible": false,
  "diesIfInPlaceAttack": true,
  "diesIfAllAttack": true
}
```

- 전투가 끝나거나 행위자가 이미 죽은 후보에서는 `null`이다(v1과 같음).
- 할인 값과 점수는 v1처럼 보여 주지 않는다.

### 3.2 지시문

새 파일 `compare.victory.v2.txt`, `compare.victory.v2.guide.txt` 등을 만든다. 고정된 v1 지시문 네 개(해시 고정)는 바꾸지 않는다.

가이드판 우선순위 중 바뀌는 문장만 적는다.

- **v1 4번 →** "`nextPlayerTurn.diesIfInPlaceAttack`이 true면 다음 아군 턴에 거의 확실히 잃는다. 지금 죽는 것과 비슷하게 본다. `diesIfAllAttack`만 true면 위험하지만 확실하지 않다."
- **v1 5번 →** "자기 유닛을 잃는 선택(지금 사망 또는 `diesIfInPlaceAttack`)은 플레이어 유닛을 처치하거나 승리할 때만 받아들인다."
- **새 문장:** "이 턴에는 이동 1회 뒤 공격 1회만 할 수 있고, 공격한 자리가 다음 아군 턴에 서 있을 자리다."
- **새 문장:** "`announcedHazards`에 있는 칸 피해는 반드시 일어난다."
- **v1 7번:** `mainApproachCost.after` → `mainApproachMoves.after`

기본판은 필드 설명만 바꾸고 우선순위 문장은 넣지 않는다(v1 기본판과 같은 원칙).

## 4 대표 상황 F01~F06 기대 판단(계산 전)

룰 v3.0으로 계산하기 전에 기획 의도로 적는다. 숫자는 지금 DB 값이다. 피해는 방어 5(5% 감소, 소수점 버림)와 상성 1.0을 가정했다.

| 공격력 | 7 | 6 | 5 | 4 | 10 | 8 |
|---|---|---|---|---|---|---|
| 피해 | 6 | 5 | 4 | 3 | 9 | 7 |

상황 파일은 결정 뒤 이 기대 판단 그대로 만든다. 계산 결과가 기대와 달라도 기대는 고치지 않는다.

| 상황 | 질문 | 행위자와 후보(요지) | 기대(승리·역할 공통) | 이유 |
|---|---|---|---|---|
| F01 처치 우선 | 진영 턴에서도 처치가 메인 피해보다 나은가 | Demon(15/15). ① 제자리에서 Sniper(HP 4) 공격 → 처치 ② 제자리에서 메인(30/30) 공격 → 메인 −5 ③ 대기. 두 공격 모두 같은 자리이고, 다음 턴 위협은 메인만(제자리 5) | ① | 처치는 다음 아군 턴의 공격 하나를 없앤다 |
| F02 확실성 단계 | 이동 없이 닿는 위협으로 죽는 자리와, 이동해야 닿는 위협으로만 죽는 자리를 구분하나 | Gravekeeper(8/23). ① 이동 뒤 메인 공격(−6), 그 자리에 메인·ShotGun 제자리 위협(6+6) ② 이동 뒤 ShotGun 공격(−6), 그 자리에 Sniper·Cowboy가 이동해야 닿음(4+9) ③ 안전한 칸으로 이동만 | ② | 확실히 죽는 자리는 피한다. 이동해야만 닿는 위협은 피해 이득이 있으면 감수한다 |
| F03 Core AI와 다른 선택 | 제자리 공격 대신 더 나은 자리로 이동한 뒤 공격하나 | UndeadCannonCart(12/20). ① 제자리에서 일반 유닛 공격(−5), 그 자리에 제자리 위협 둘(6+6) ② 2칸 이동 뒤 메인 공격(−5), 그 자리에 이동해야 닿는 위협 하나(6) ③ 대기 | ② | 같은 피해라도 메인을 치고 노출이 적은 쪽이 낫다. Core AI는 ①을 고른다(제자리 공격 우선) |
| F04 앞선 결과 반영 | 앞서 행동한 적 유닛이 위협자를 처치했으면 이번 유닛이 공격에 나서나 | Gravekeeper(10/23). 앞선 Demon이 Sniper를 처치했다(`actedAllies`). ① 제자리에서 메인 공격(−6), 남은 위협은 메인 제자리 6 ② 후퇴 | ① | 처치로 위험이 줄어든 상태에서는 공격한다. 같은 상황에 Sniper가 살아 있으면 4+6 = 10으로 확실히 죽으므로 ②가 맞다(대조 상황 F04b로 함께 만든다) |
| F05 예고된 기믹 | 예고된 기믹 칸을 피하나 | UndeadHeavy(12/30). ① 메인 앞 칸으로 이동해 메인 공격(−3), 그 칸은 낙석 예고 칸(피해는 Core 값 확인 뒤 확정, 행위자 HP 이상이라고 가정) ② 옆 칸으로 이동해 일반 유닛 공격(−3), 예고 없음, 제자리 위협 6 ③ 대기 | ② | 예고된 기믹은 반드시 일어나는 피해다 |
| F06 KillChain | 무작위 연쇄 위험만 있는 자리를 피하나 | Gravekeeper(9/23). Cowboy가 KillChain을 가졌고 빈사 Demon(HP 3)을 처치할 수 있다. 처치하면 남은 적 둘 중 하나를 무작위로 추가 공격(9)한다. ① 제자리에서 메인 공격(−6), 다른 위협 없음 ② 후퇴 | ① | 연쇄는 확실하지 않다. 처치와 무작위가 겹쳐야 생기므로 피해 이득을 포기하면서까지 피하지 않는다. LLM에는 `chainPossible: true`가 보인다 |

- F01~F06은 개발용 R 세트다. 결과를 본 뒤 지시문을 다듬는 데 쓴다.
- 보류 세트(새 V 세트)는 지시문을 고정한 뒤 따로 만든다.
- B 분류 7개(반격 다시 계산)도 같은 v2 형식으로 옮겨 F07부터 번호를 붙인다. 이 상황들은 v1 기대 판단을 재검토해서 이 문서에 추가한다.
