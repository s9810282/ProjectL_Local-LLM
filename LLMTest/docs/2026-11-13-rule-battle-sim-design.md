## Part A 전투 시뮬레이터

### A1 목적

적 AI 정책을 바꿔 끼우며 같은 스테이지·같은 플레이어 상대로 전투를 끝까지 돌리고, 결과를 숫자로 비교한다(§A6).

### A2 입력: 게임 에셋을 그대로 읽는다

복사본을 만들지 않는다. 같은 값이 두 곳에 있으면 게임 쪽이 바뀔 때 어긋난다. 시뮬레이터가 `Assets/ProjectL/DataBaseSO/InGameGroup/`의 Unity YAML을 직접 읽는다(표준 라이브러리만, 조사 때 만든 작은 파서를 정리해 옮김).

| 읽는 것 | 에셋 |
|---|---|
| 스테이지 | `Stage/Combat/Combat_*.asset`: 판 참조, 목표 종류, 적 배치, 적 본진 자리, 아군 배치 칸, 지형 배치, 증원, 기믹 설정 |
| 판 | `Field/Item/Field_*.asset`: 가로·세로 |
| 유닛 | `Unit/Item/**/Unit_*.asset`: HP, 공격력, 방어, 사거리, 병과, 지정 방식, 벽 처리, 특성 |
| 병과 | `Category/Item/CategoryConfig_Default.asset`: 병과별 이동력 |
| 지정 방식 | `Targeting/Item/TargetingMethod_*.asset`: 공격 모양, 고르는 법, 스플래시, 각도 |
| 지형 | `Terrain/Item/Terrain_*.asset`: 종류(벽·낭떠러지·약한 지반…) |
| 구조물 | `Structure/Item/Structure_Headquarters.asset`: 적 본진 2×2, HP 30 |
| 아군 구성 | `Loadout/Item/PlayerLoadout_1.asset`: 메인 Akimbo + ShotGun·Ballista·Cowboy (메인이 `Unit_MainCharacter`가 아니라 Akimbo다) |

게임 코드에만 있는 값(병과 상성표, 피해 계산 순서 등)은 Python 상수로 두고 원본 파일·줄을 주석으로 단다.

### A3 규칙: 넣는 것 / 단순화 / 1판에서 뺌

| 규칙 | 1판 | 게임 규칙(근거) |
|---|---|---|
| 턴 | 넣음 | 플레이어 턴 → 적 턴 반복, 플레이어 먼저. 턴 시작에 그 편 유닛이 행동 가능이 된다(`CombatTurnCalculator.cs`) |
| 유닛 행동 | 넣음 | 이동 → 공격 / 공격만 / 이동만. 공격 뒤에는 아무것도 못 함. 한 유닛씩, 순서 자유(`UnitActionUseRules.cs:10-13`) |
| 턴 상한 | **시뮬레이터 전용** | 게임에는 없다. 시뮬레이터는 N라운드에서 "시간 초과"로 끝낸다(§A9 Q-A4) |
| 이동 | 넣음 | 병과 이동력(일반 3·기병 4·중장 3·대포 2·보스 0), 상하좌우 한 칸씩, 같은 칸 두 번 안 됨. 벽·낭떠러지·모든 유닛(아군 포함)·구조물이 막음(`MovementRouteValidator.cs`) |
| 공격 모양 | 넣음 | 사거리 안 정사각형 안에서 지정 방식 모양(한 칸 고르기·방향 고르기·전체, 부채꼴·직선·스플래시, 앞쪽 각도). 자기는 안 맞음(`AppointShapeCalculator.cs`) |
| 피해 | 넣음 | 공격력 → 스플래시 % → 병과 상성(기병→대포 1.2, 중장→기병 1.5 등) → 방어 1당 1% 감소 → 고지대 70%·모래폭풍 80% → 최소 1(`CombatDamageCalculator.cs:66-119`) |
| 시야(벽) | 넣음, 게임 식 그대로 | 직사는 공격자 → 목표 선분이 벽을 지나면 안 됨(벽 모서리 깎기 포함), 곡사(대포 계열·Ballista)는 무시, 고지대에서 아래로 치면 무시(`AttackOcclusionResolver.cs`) |
| 대포 규칙 | 넣음 | 빈 칸 조준 가능, 바로 옆 칸 조준 불가, 스플래시가 아군도 맞힘 |
| 승패 | 넣음 | 목표 1 = 적 본진 파괴, 목표 2 = 보스 처치. 메인 캐릭터가 죽으면 패배(승리보다 우선)(`BattleOutcomeCalculator.cs`) |
| 적 증원 | 넣음 | 적 턴 시작, 본진이 살아 있을 때만. 판의 적이 상한(4)보다 적은 만큼, 턴마다 최대 1마리, 유한한 목록에서 남은 수 가중 무작위. 본진 주변 빈 칸 중 아군 유닛 바로 옆이 아닌 곳. 나온 턴에는 행동 못 함(`NexusReinforcementCalculator.cs`) |
| 지형 | 넣음 | 벽, 낭떠러지(밀려 들어가면 즉사), 약한 지반(2번 들어가면 낭떠러지가 됨), 고지대(받는 피해 70%, 아래로 벽 너머 공격) |
| 넉백·밀기 | 넣음 | 맞은 쪽을 공격자 반대 방향으로 N칸, 막히면 멈춤, 낭떠러지면 즉사 |
| 특성 | 일부(§A9 Q-A3) | 1판 권장: 적 일반 특성 전부(넉백·재생·제자리 사격·자폭·단독 행동·무장 해제·발목 꺾기·방어구 파괴) + 아군 시작 구성 특성(처치 연쇄·충격 볼트·끌어오기·사냥꾼 표식). 보스 포효는 보스 스테이지를 넣을 때 |
| 배치 단계 | **단순화** | 손패·덱 없이 시작 구성 4명을 배치 칸에 정해진 규칙으로 놓는다(§A4). 게임도 전투 중에는 유닛을 더할 수 없다 |
| 기믹 | **1판에서 뺌** | 낙석·하붑·기차·토네이도는 끈다(결과에 "기믹 끔" 표시). 일반 15판 중 기믹이 없는 판은 P20 하나뿐이라, 기믹 판을 빼는 대신 끄고 돌린다. 나중에 기차 → 낙석 → 하붑 → 토네이도 순서로 넣는다 |
| 오브젝트·장애물·아이템 | 뺌 | 지금 LD 스테이지에 배치가 없다 |
| 무작위 | 시드로 고정 | 증원 고르기·자리, 처치 연쇄 대상. 같은 시드면 같은 전투 |

게임과 같은지는 규칙마다 Core 줄을 보고 손으로 계산한 시험으로 확인한다. 게임 Core를 밖에서 돌릴 수 있게 되면, 같은 판을 양쪽에서 돌려 맞춰 본다.

### A4 플레이어 쪽(상대 모형)

시뮬레이터에는 플레이어 역할을 하는 규칙도 필요하다. 적 AI의 결과는 상대가 누구냐에 따라 크게 달라진다. 예를 들어 플레이어가 늘 돌진하면 기다리는 적이 좋은 점수를 받는다.

- **돌진형:** 칠 수 있으면 처치 > 본진 > 가장 큰 피해 순서로 치고, 못 치면 본진 쪽으로 간다. 메인은 앞줄보다 한 줄 뒤를 지킨다.
- **신중형:** 적 공격 범위 밖에서 기다렸다가 먼저 칠 수 있을 때 들어간다. 이 상대와 신중한 적 AI가 만나면 서로 기다리는 대치가 생기는데, 이것이 "기다림" 문제를 재는 상황이다.
- 배치: 배치 칸 중 본진에 가까운 줄부터 가운데로 채우고, 메인은 그 뒤 줄에 놓는다(둘 다 같은 규칙).

### A5 적 정책 끼우는 자리

적 턴에 시뮬레이터는 정책에게 "지금 판 상태"를 주고 "다음 행동 하나(유닛·이동·공격)"를 받는다. 게임처럼 한 번에 한 행동이고, 보낼 행동이 없다고 하면 적 턴이 끝난다.

| 정책 | 내용 |
|---|---|
| 단순 탐욕 | 시뮬레이터 확인용 기준. 칠 수 있으면 가장 큰 피해, 아니면 가장 가까운 플레이어 쪽으로 |
| **게임 AI(rule-game)** | 지금 게임 AI를 실제 판 위로 옮긴 것. 점수식은 `tools/rule_game.py`를 그대로 쓰고(한 곳), 판에서 사실을 계산하는 부분(위협 필드·교전 비용·다음 턴 공격·후보 줄이기: 이동 후보 6개, 정밀 2개)을 새로 만든다 |
| 연구 정책 | 위협 합산, 기다림 줄이기, 플레이 타입. 하나씩 게임 AI와 비교한다 |

### A6 재는 것

| 지표 | 내용 |
|---|---|
| 결과 | 적 승(메인 사망) / 플레이어 승(본진·보스) / 시간 초과, 걸린 라운드 |
| 난이도 | 적 승률, 플레이어가 잃은 유닛 수·HP |
| 기다림 | 첫 공격까지 라운드, 적 턴마다 아무것도 안 한 유닛 비율(이유별: 칠 게 없음·교환 손해·죽을 자리뿐), 적-플레이어 거리 변화 |
| 실수 | 확실한 처치를 놓친 횟수, 몰아치기로 죽은 횟수, 지형 즉사로 잃은 수, 아군 오폭 |
| 플레이 타입 차이 | 타입마다 행동 분포(공격·이동·대기 비율, 본진·메인과의 거리) |

턴마다 행동 기록(누가 어디로 가서 누구를 쳤나, 그때 점수)을 남겨, 숫자가 이상하면 그 전투를 다시 읽을 수 있게 한다.

## Part B 적 AI 규칙을 정할 때 고려할 것

### B1 게임 규칙이 정하는 조건

규칙 조사로 알게 된 것 중 AI 설계를 바꾸는 것만 모았다.

1. **승리 조건이 다르다.** 적은 메인을 죽여야만 이기고, 플레이어는 적 본진(보스 판은 보스)을 부숴야 이긴다. 턴 제한이 없다.
   - 적에게는 시간 압박이 없다. 본진 앞에서 기다리는 것은 지는 행동이 아니라 방어다. 그래서 "기다림"은 승패 문제라기보다 재미 문제다.
   - 다만 기다리면 언제 어디서 싸울지를 플레이어가 고른다(먼저 치는 쪽이 플레이어가 된다).
2. **잃는 값이 다르다.** 플레이어는 전투 중 유닛을 더할 수 없다. 적은 본진이 살아 있으면 판의 적이 4마리 아래로 줄 때 증원을 받는다(최대 8마리, 턴마다 1).
   - 적 유닛 하나를 잃는 것은 플레이어 유닛 하나를 잃는 것보다 가볍다. 본진을 부수면 증원도 멈춘다.
   - 게임 AI는 "다음 턴에 죽을 수 있는 자리"를 −200으로 매긴다. 처치(3000)의 약 1/15이라 이미 위험을 가볍게 보는 쪽이다. 기다림은 위험 회피보다 다른 곳(§B2-3)에서 나온다.
3. **메인을 죽이면 바로 이긴다.** 지금 구성의 메인은 Akimbo(HP 30, 방어 5)다. 메인을 노릴지, 본진을 지킬지가 적 AI의 가장 큰 방향 선택이다.
4. **한 유닛씩, 순서는 자유.** 그래서 순서가 곧 협공이다(먼저 깎고 나중에 끝내기, 넉백으로 낭떠러지에 밀기, 길 비켜 주기). 아군도 길을 막는다.
5. **지형 즉사가 크다.** 넉백(Gravekeeper 1칸, 보스 3칸, 기병 1칸)으로 낭떠러지에 밀면 즉사하고, 약한 지반은 두 번 밟히면 낭떠러지가 된다. 플레이어도 Ballista(충격 볼트)·Cowboy(끌어오기)로 적을 밀고 당긴다.
6. **병과·지형 상성.** 중장→기병 1.5배 같은 상성, 고지대(받는 피해 70%, 벽 너머로 쏨), 대포(바로 옆은 못 치고 아군도 맞힘), 제자리 사격 특성(안 움직이면 피해 2배)이 있다. 일부러 안 움직이는 게 맞는 유닛이 있으니 "기다림"을 셀 때 이유를 나눠야 한다.
7. **공개 정보만 쓴다.** 게임 AI는 지형의 공개 상태를 본다. 연구 정책도 플레이어가 모르는 정보를 쓰지 않는다.
8. **증원 자리는 본진 주변, 아군 바로 옆은 안 된다.** 플레이어가 본진에 붙으면 증원을 막을 수 있다. 본진 지키기의 근거가 된다.

### B3 정할 것

- **Q-B1 적의 기본 자세:** 본진 방어 / 메인 사냥 / 플레이 타입마다 다르게. 권장: 타입마다 다르게, 기본 타입은 시뮬레이터 결과를 보고 정함.

### B4 판단 방식: 결과로 판단, 적 턴 전체를 본다 (2026-11-13 사용자 결정)

- **결과로 판단:** AI는 특성·기믹을 따로 알지 않는다. 할 수 있는 행동을 규칙 엔진에서 받고, 행동마다 엔진으로 결과 판을 미리 만들어 본 뒤, 결과 판을 일반 기준(HP·처치·메인·본진·위험·위치)으로 점수 매긴다. 특성·기믹이 늘면 엔진만 늘고 AI는 그대로다.
  - 그래서 규칙 엔진은 "판 상태 + 행동 → 다음 판 상태"를 계산하는 함수로 만들고, 판 상태는 싸게 복사할 수 있어야 한다(S-b).
  - 지금 게임 AI도 자기 행동의 결과는 미리 계산하지만, 위험(위협 필드)은 손으로 쓴 근사(제자리, 가장 센 한 방)라 넉백·끌어오기·기믹·몰아치기를 못 본다(F04b).
- **보는 범위 = 적 턴 전체:** 적 유닛 모두의 행동 묶음(누가 먼저, 어디로, 누구를)을 한 턴 계획으로 보고, 턴이 끝난 판(턴 끝 효과 포함)을 평가한다. 플레이어의 다음 턴은 직접 돌리지 않는다.
- 남은 것(§B5): 계획 찾는 방법, 끝난 판의 위험 계산, 판 점수 항목, 예측 때 무작위 처리.

### B5 다음에 정할 것(초안)

- **Q-E1 계획 찾기:** 유닛 5마리 × 행동 약 100가지에 순서까지 더하면 다 볼 수 없다.
  - (a) 차례대로 고르기: 지금 게임 방식. 가장 좋은 행동 하나를 고르고, 그 판에서 다음 행동을 고른다.
  - **(b) 빔 탐색(권장):** 계획 후보 K개를 들고 행동을 하나씩 늘려 가며 좋은 K개만 남긴다. K가 클수록 협공(먼저 깎고 나중에 끝내기, 넉백 연계)을 잘 찾는다. K를 그대로 난이도 손잡이로 쓸 수 있고, 계산량을 K로 조절해 게임에 옮기기 쉽다.
- **Q-E2 끝난 판의 위험:** 플레이어 턴은 돌리지 않는다. 대신 끝난 판에서 플레이어 유닛 각각이 할 수 있는 가장 좋은 공격을 엔진으로 계산해, 대상마다 맞을 피해를 더한다(권장). 몰아치기가 들어가고, 넉백·끌어오기·지형 즉사도 엔진이 계산하니 저절로 들어간다. 플레이어 유닛끼리의 순서 연계는 빠진다.

### B6 판 평가(Q-E3, 2026-11-13 사용자 "권장대로" — E3-1~E3-6 모두 권장안. 탐색 설계·계획은 `2026-11-13-turn-planner-design.md`)

2026-11-13 사용자 결정: 연구 AI(결과로 판단 + 턴 전체 빔 탐색)를 **진영 공통**으로 만들어, 먼저 강한 플레이어 모형으로 쓰고 같은 엔진을 적 연구 AI로 쓴다. 그래서 판 평가도 두 진영 몫을 함께 정한다.

**언제 평가하나:** 계획하는 진영의 턴이 끝난 판(턴 끝 효과 포함). 이긴 판 +∞, 진 판 −∞.

**점수 = 전력 + 목표 − 위험 + 기회** (모두 "전력 점" 한 단위로, 내 몫 − 상대 몫)

| 항목 | 제안 | 정할 것(권장) |
|---|---|---|
| E3-1 유닛 값 | 전력 = 공통 피해 × 남은 HP. 다친 유닛은 덜 위험하고, 센 유닛을 먼저 잡는 것이 이득이 된다(란체스터 법칙: 전투력 ∝ 공격력 × 체력) | (a) HP 비율만 / **(b) 공격력 × HP** |
| E3-2 증원 | 적은 본진이 살아 있는 동안 남은 증원 목록도 전력으로 친다(할인). 본진을 부수면 이 몫이 사라진다 | 할인율 **50%** |
| E3-3 메인 | 메인 전력에 가중치. 메인이 죽으면 지므로 양쪽 모두 메인 HP를 크게 본다 | 메인 배수 **3** |
| E3-4 본진 | 본진 HP 비율 × 본진 값. 본진 값 = 전투 시작 때 적 전체 전력(본진을 0으로 만드는 것 = 적을 다 잡는 것만큼) | 본진 값 기준 **시작 적 전력 합** |
| E3-5 위험 | 상대 유닛마다 다음 턴에 "가장 좋은 공격 하나"를 고른다고 보고(Q-E2), 대상마다 맞을 피해를 더한다. 예상 손실 = min(합, HP), 합 ≥ HP면 그 유닛 전력 전부. 거기에 겁 계수를 곱한다 | 겁 계수 **0.5**(플레이 타입 손잡이: 신중 0.8 · 돌격 0.3) |
| E3-6 기회 | 내 유닛마다 다음 턴에 칠 수 있는 가장 좋은 대상의 예상 피해 × 기회 계수. 닿는 대상이 없으면 가장 가까운 공격 자리까지 거리만큼 작은 벌점 | 기회 계수 **0.5**, 거리 벌점 **작게** |

**왜 이렇게 나눴나:**
- 전력·목표는 "지금 판이 얼마나 좋은가", 위험·기회는 "다음 상대 턴과 내 다음 턴에 무슨 일이 날 수 있나"다. 앞보기를 내 턴 하나로 정했으니(B4), 그 뒤 두 반 턴을 위험·기회 두 항목이 대신 본다.
- 기다림을 줄이는 손잡이는 기회 계수(E3-6), 겁의 손잡이는 겁 계수(E3-5)다. 둘의 비가 플레이 타입의 핵심이고, 빔 크기가 난이도의 핵심이다.
- 특성·기믹은 엔진이 결과에 반영하므로 평가 항목에 따로 넣지 않는다(B4).

**계산량 주의:** 위험을 엔진으로 정확히 돌리면(상대 유닛마다 이동+공격 전부 시뮬레이션) 평가 한 번이 너무 비싸다. 그래서 턴 시작에 상대 유닛마다 "어느 칸을 칠 수 있나"를 한 번 구해 두고, 평가 때는 그 표와 피해 식(방어·상성 포함)으로 빠르게 계산한다. 그 턴 동안 내가 움직여 길이 막히는 변화는 무시한다(근사).
