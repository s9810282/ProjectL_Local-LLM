# 7주차 차주 계획 수행 정리와 발표·공유 안내

작성일: 2026-10-22

7주차 보고서의 "차주 계획" 3건을 수행한 기록을 한 곳에 모았다. 세부 근거는 각 문서에 있고, 이 문서는 **무엇을 했는지**와 **남에게 어떻게 보여줄지**만 다룬다.

| 1. 특성·아이템 변형 상황과 가중치 재비교 (M2) | 실제 DB 값으로 R17~R24 추가, 24상황 × 16설정 민감도. 역할 허용 차이 12 → 6 반영 | [변형 비교](2026-10-22-rule-ai-variant-comparison.md) |

계획 3건을 모두 수행했고, 3번은 초안 작성을 넘어 구현과 비교 실험까지 진행했다. Unity·Core 코드는 바꾸지 않았다.

## 2 핵심 결과

### 2.1 룰 AI

- 실제 유닛 값(Gravekeeper 공격력 10 등)에서는 기존 R02의 "메인 압박 대 일반 피해" 갈등이 생기지 않는다. 메인 계수 경계(약 26.67)는 가설 상황 위의 값이었다.
- 역할 허용 차이를 6으로 낮춰 R06·R08·R21을 함께 만족시켰다. 다른 선택은 바뀌지 않았다.
- 남은 불일치 2건은 계수가 아니라 모델 구조 문제다.
  - **R19**: 확실한 반격 사망을 위험 할인 0.5가 절반만 반영한다.
  - **R23·V08**: 모든 적 유닛의 생존 가치가 같아 약한 Demon의 교환을 거부한다.

### 2.2 로컬 LLM (Qwen3.5 4B, Q4_K_M)

| 항목 | 결과 |
|---|---|
| 형식 | 스키마 강제에서 오류 0건(전체 요청 수백 건) |
| 지연 | 요청당 약 1초. `localhost` 대신 `127.0.0.1`을 써야 함(Windows에서 약 2초 추가). 모델이 처음 올라올 때는 약 54초 |
| 반복 | 같은 입력이면 선택·점수·이유 문장까지 같음 |
| 순서 | 후보 순서만 바꿔도 판단 약 4분의 1이 바뀜. 위치가 선택을 정하는 경우가 있음 |
| 지시문 | 우선순위를 말로 준 가이드판이 기본판보다 기대에 가까움 |
| 이유 문장 | 사실과 다른 말, 언어 섞임, 고르지 않은 행동 설명. 근거로 쓰기 어려움 |

두 순서 모두에서 기대와 맞은 비율(판단 수 대비):

| | R 세트(42판단) | V 보류 세트(16판단) |
|---|---:|---:|
| 룰 정책 | 90% | 94% |
| LLM 기본판 | 45% | 44% |
| LLM 가이드판 | 69% | 69% |

**한 줄 결론:** 지금 조건에서는 룰 정책이 더 정확하고 일관된다. LLM은 우선순위를 말로 주면 크게 나아지고 새 상황에서도 그 향상이 유지되지만, 순서 의존과 점수·선택 불일치가 남는다. V08 한 건에서 LLM이 룰의 구조적 약점(유닛별 가치)을 넘었다.

### 3.1 실제로 돌려 보여줄 때

준비물은 Python 3.10 이상, Ollama와 모델 `hf.co/unsloth/Qwen3.5-4B-GGUF:Q4_K_M`이다. 시연 전에 모델을 한 번 불러 두면 첫 요청의 약 54초 대기를 피한다.

```powershell
# 0. 모델 미리 올리기(첫 로딩 시간 제거)
python LLMTest/tools/run_ollama_test.py S01

# 1. 룰 정책: 24개 상황의 선택과 기대 일치
python LLMTest/tools/run_rule_test.py

# 2. 같은 후보를 LLM에게: R19 하나, 승리 지시문
python LLMTest/tools/run_llm_compare.py R19 --policy victory

# 3. 순서를 뒤집으면 답이 바뀌는 장면
python LLMTest/tools/run_llm_compare.py R19 --policy victory --order reverse
```

2번과 3번에서 R19 승리 지시문은 파일 순서에서 관통(`a_lane_shot`), 뒤집으면 후퇴(`b_retreat`)를 고른다. 둘 다 화면상 `c1`이다. 시연 전에 한 번 돌려 같은 결과가 나오는지 확인한다.

여러 실행을 나란히 보여줄 때:

```powershell
python LLMTest/tools/compare_llm_runs.py LLMTest/results/llm_compare/20261022T093910.183849Z LLMTest/results/llm_compare/20261022T093930.411270Z
```

## 5 예상 질문

- **왜 후보 ID를 `c1`로 바꿨나?** 원래 ID에 `safe_move`, `pointless_self_death` 같은 평가 단어가 있어 답을 흘린다. 원래 ID는 결과에서 되돌려 비교한다.
- **왜 순서를 섞어 보나?** 룰은 순서와 무관하다. LLM도 같은 후보에 같은 판단을 하는지 확인해야 공정하다. 실제로 판단 약 4분의 1이 순서에 따라 바뀌었다.
- **가이드판에 정답을 알려준 것 아닌가?** 우선순위를 말로 줬을 뿐 계수나 정답은 넣지 않았다. 다만 같은 기획 의도에서 썼으므로 "지시를 따르는 능력"의 증거로 해석한다. 그래서 고정 뒤 새 상황으로 다시 쟀다.
- **룰은 왜 R19·R23·V08을 틀리나?** 위험 할인이 확실한 사망을 절반만 반영하고, 모든 적 유닛의 생존 가치를 같게 본다. 계수 조정으로 맞추면 다른 판단이 무너져 모델 구조 개선 과제로 남겼다.
- **게임에 바로 넣을 수 있나?** 아직 아니다. Core가 후보와 결과 사실을 줄 조회 경계(입력 대응 문서 Q1~Q5)가 먼저 필요하다. LLM을 쓴다면 두 순서 일치·최고점 확인·실패 시 룰 복귀를 함께 둔다(LLM 문서 §6.6).
- **지연은 괜찮나?** 요청당 약 1초, 두 순서로 물으면 약 2초다. 모델 첫 로딩(약 54초)은 전투 전에 미리 처리해야 한다.

## 6 주간 보고서(8주차)에 옮길 때

이 문서의 표를 그대로 옮기기보다 아래처럼 요약하는 것을 권한다. 진행률 숫자는 직접 판단해 정한다.

**금주 실적**

| No | 관련 M | 업무 | 결과 / 산출물 |
|---|---|---|---|
| 1 | M2 | 특성·아이템 변형 상황과 가중치 재비교 | R17~R24 추가, 24상황 × 16설정 비교, 역할 허용 차이 6 반영, 남은 불일치 2건 원인 분석 |
| 2 | M2·M3 | 실제 전투 정보와 오프라인 입력 대응 | 필드별 Core 출처 표, 가정·실제 차이 13건, 입력·적용 계약 초안 |
| 3 | M3 | 로컬 LLM 실행 검증과 공통 비교 입력 | 형식 오류 0, 지연 약 1초, 공통 입력 구현, 룰 대 LLM 비교·순서 불변·보류 검증 |

**이슈 및 리스크 후보**

- LLM 판단이 후보 순서에 따라 바뀜 → 두 순서 일치 채택과 룰 복귀로 대응.
- 룰 모델의 구조 한계(위험 할인, 유닛별 가치) → 다음 비교 과제로 분리.
- 기대 판단을 작성자 혼자 정함 → 독립 기대 판단 필요(아래 문의).

**차주 계획 후보**

- 유닛별 전력 가치·확실성별 위험 할인 프로필 비교(R19·R23·V08).
- 독립적으로 정한 기대 판단으로 추가 검증, 더 큰 모델 비교 검토.
- Core 요청 Q1~Q5를 Core 전달 문서에 옮길지 결정.

**문의 사항 후보**

- LLM 판단을 룰 정책 수준으로 끌어올리는 방향(순서 의존을 줄이는 질의 방식, 판단 예시를 포함한 지시문, 더 큰 모델 비교)이 적절한지.
- 기대 판단을 작성자가 정하는 지금 방식에서, 독립 검증을 위해 다른 사람(팀원·교수)이 기대를 정하는 단계가 필요한지.

## 7 공유 전 정리

- 커밋은 직접 한다. 이번에 바뀌거나 생긴 것:
  - 문서 4개(`docs/2026-10-22-*.md`), `README.md`
  - 설정 `config/rule_weights.json`(역할 허용 차이 6)
  - 도구 `tools/llm_projection.py`, `run_llm_compare.py`, `compare_llm_runs.py`, 수정된 `run_ollama_test.py`·`run_rule_test.py`
  - 지시문 `prompts/compare.*.txt` 4개, 상황 `rule_fixtures/R17~R24`, `validation_fixtures/V01~V08`, 테스트 `tests/test_llm_projection.py`
  - 결과 `results/llm/`, `results/llm_compare/`, `results/rules/20261022*`(약 10MB). 문서가 이 폴더를 근거로 링크하므로 함께 올리는 것을 권한다.
- 커밋 전 확인: `python -m unittest discover -s LLMTest/tests`(27건 통과 상태).
- 공유받는 사람이 직접 돌리려면 Ollama와 같은 모델이 필요하다. 없으면 결과 폴더의 `run.json`·`report.md`로 같은 내용을 볼 수 있다.
