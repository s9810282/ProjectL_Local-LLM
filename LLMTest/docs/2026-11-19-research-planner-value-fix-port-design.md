작성일: 2026-11-19 · 상태: **결정 완료(2026-11-19 사용자 "권장대로 진행해" = Q-VP1~Q-VP5 모두 A). VP-0~VP-d 완료(§8) — **기본 프리셋 에셋에서 값 셋이 켜졌다(행동 규칙 0.25·걸음 벌점 대상 고정·기회 모으기). 이 저장소의 조정 에셋은 계획 AI를 쓰므로 게임 안 적의 행동이 바뀐다. Unity 재생 확인 대기(§8.5).** 재생 확인용 스테이지 `Combat_Research_AiCheck`를 만들었다(§8.6, 시뮬레이터에서 옛 적과 새 적의 차이가 나오는 것을 확인, Unity 진입 미확인). 옛 값 프리셋 `EnemyTurnPlannerPreset_Before1119`, 연결 줄 패치 다시 만듦. VP-a~VP-c는 Unity 컴파일 확인됨(사용자), VP-d는 프리셋 SO 머리말 한 줄이 바뀌어 컴파일 미확인. ## 1 배경과 범위

- 시뮬레이터에서 지금 적(`plan4:g1:l1`)은 칠 수 있는 유닛 턴의 23%에서 치지 않았고, 그중 67%는 플레이어 유닛을 잡을 수 있는 경우였다. 원인은 판 값의 두 항목이다(손잡이 설계 §12.8).
  - 걸음 벌점: 가까운 상대를 잡으면 남은 상대가 멀어서 모든 유닛의 벌점이 한꺼번에 는다.
  - 다음 턴 기회: 같은 대상을 노리는 유닛 수만큼 남은 HP를 겹쳐 센다.
- 두 항목을 고치고 행동 규칙을 넣은 값(`plan4:g1:l1:i0.25:v1:b1`)은 칠 수 있는데 안 침 0.23 → 0.06, 한 유닛이 3턴 이상 이어서 공격을 피한 판 41 → 0(360판 중)이다(§13.3).
- **Unity 연구용 계획 AI(`Assets/ResearchEnemyPlanner/`)는 시뮬레이터 식을 그대로 옮긴 것이라 같은 두 항목이 있다**(§2). 같은 버릇이 있을 것으로 보지만 Unity에서 재지는 않았다.
- 이번에 옮길 것: 행동 규칙(`:i`), 걸음 벌점 대상 고정(`:v`), 기회 모으기(`:b`). 셋 다 끌 수 있고, 끄면 지금 동작과 같아야 한다.
- 옮기지 않는 것: 성격 값(자기 보존 `:p`, 다친 유닛 살리기 `:y`) — §5.
- 올리는 곳은 지금처럼 이 연구 저장소의 Core 사본뿐이다. 팀 저장소·develop에는 올리지 않는다. 기본 적 AI(Utility)는 건드리지 않는다.

## 3 설계

### VP1 값 자리: 지금 값 묶음과 프리셋에 칸 셋

- `EnemyTurnPlannerStyle`에 `MustAct`(실수, 기본 0), `StepAnchor`(켬/끔, 기본 끔), `PooledChance`(켬/끔, 기본 끔)를 더한다. 생성자는 끝에 선택 인자로 받는다. **코드 기본값은 모두 끔 = 지금 동작**이다(측정 도구의 기본값 기록 대조가 그대로 통과해야 한다).
- `EnemyTurnPlannerPresetSO`에 같은 칸 셋과 툴팁(뜻·기본값·시뮬레이터 손잡이 이름 `:i`·`:v`·`:b`)을 더하고, `Formula` 설명에 두 줄을 더한다. 범위 검사는 `MustAct ≥ 0`.
- 재생 때 콘솔의 계획 시간 줄 끝에 세 값을 붙인다(지금 성향 값이 붙는 자리).
- 값이 흐르는 길(프리셋 → 조정 에셋 → 결정 설정 → 세션 → 계획)은 그대로다. 새 길을 만들지 않는다.

### VP2 걸음 벌점 대상 고정

- `PlannerEvaluator.StepTargets(board, side)` 하나를 만든다: 그 판에서 살아 있는 상대 + (켰을 때) **계획 시작 판에서는 살아 있었지만 이 판에서는 필드에 없는 상대**. 끄면 지금 `Targets`와 같다.
- 거리 표를 만드는 세 곳(`Opportunity`, `PlannerReply.StepPenalty`, `QuickMoveScore`)이 이 함수를 부른다. 거리 대상의 정의가 한 곳에만 있게 한다.
- 쓰러진 상대의 칸 = **계획 시작 판의 칸**(평가기가 시작 판 `Base`를 갖고 있다). 죽은 캐릭터의 사실에는 칸이 남지 않기 때문이다(§8.1). 시뮬레이터도 같은 정의로 맞췄다(§8.2). 같은 계획 안에서 밀리거나 끌려온 뒤 죽은 상대는 죽은 자리가 아니라 계획을 시작할 때 서 있던 자리로 센다.
- 다음 턴 계획은 그때 살아 있는 상대로 새로 시작한다. 남은 상대 쪽으로의 끌림은 한 턴 뒤에 돌아온다(시뮬레이터와 같다).

### VP3 기회 모으기

- `Opportunity`에서 켰을 때 대상(`PlannerTarget.Key`)마다 피해를 모으고, 끝에 `Loss(대상, 모은 피해)`를 더한다. `Risk`와 같은 꼴이다. 끄면 지금처럼 유닛마다 값을 더한다.
- 예상 피해 기억(`PlannerDamageMemo`)은 `BestStrike` 안이라 그대로 쓰인다.

### VP4 행동 규칙

- `PlannerBeam`에 "제자리 벌점"을 둔다: 그 판에서 아직 이동도 공격도 하지 않은(`UnitActionUse.Available`) 살아 있는 우리 유닛마다 `MustAct × 공격력 × 최대 HP`(메인은 × 메인 배수). `MustAct`가 0이면 0이다.
- 계획을 고르는 세 곳이 "값 − 제자리 벌점"으로 견준다: 단계마다 최고 갱신(`Run`), 다시 매김 후보 고르기, 깊은 값 비교(`EnemyTurnPlanner.Plan`). 빔 안에서 판을 줄 세우는 값과 깊은 값 계산 자체는 바꾸지 않는다(시뮬레이터 `idle_cost`·`_plan_value`와 같다).
- 뜻: 행동해서 판 값이 유닛 전력 × `MustAct`보다 많이 떨어질 때만 제자리에 있는다.

### VP5 기본 프리셋의 값

- 코드 기본값은 끔으로 두고, 게임이 쓰는 기본 프리셋 에셋(`EnemyTurnPlannerPreset_Default.asset`)에서 세 값을 켠다(행동 규칙 0.25, 둘 다 켬). 옛 값을 그대로 담은 프리셋 에셋을 하나 더 만들어 견줄 수 있게 한다(§6 Q-VP1).

### VP6 고칠 파일

| 파일 | 바꾸는 것 |
|---|---|
| `Contracts/Combat/EnemyAi/EnemyDecisionSettings.cs` | `EnemyTurnPlannerStyle`에 값 셋(끝 선택 인자) |
| `DataBaseSystem/Data/InGame/Table/EnemyAi/Item/EnemyTurnPlannerPresetSO.cs` | 칸 셋·툴팁·`Formula`·범위 검사 |
| `Assets/ResearchEnemyPlanner/PlannerEvaluator.cs` | `StepTargets`, `Opportunity`(모으기·거리 대상), `QuickMoveScore`(거리 대상) |
| `Assets/ResearchEnemyPlanner/PlannerReply.cs` | `StepPenalty`의 거리 대상 |
| `Assets/ResearchEnemyPlanner/PlannerBeam.cs`, `EnemyTurnPlanner.cs` | 제자리 벌점과 고르는 세 곳 |
| 계획 시간 줄을 쓰는 곳(`CombatAdvanceService`) | 로그에 값 셋 |
| 에셋 | 기본 프리셋 값, 옛 값 프리셋 하나(+ `.meta`) |
| `LLMTest/core_port/hooks.patch`, 하네스 | 연결 줄 패치 다시 만들기, 켠 값 확인 판(§4) |

새 `.cs`는 없다.

## 4 확인 방법

| 번호 | 확인 | 방법 |
|---|---|---|
| 1 | 끄면 지금과 같다 | 측정 도구의 기본값 결정 기록(한 턴 더 보기 켬·끔, 판 11개 × 씨앗 2)이 옮기기 전과 바이트까지 같다 |
| 2 | 켜면 잡는다 | 측정 도구에 막판 판 하나를 더한다: HP 1인 플레이어 유닛 옆에 적 둘, 메인은 멀리(시뮬레이터 시험 `ValueFixTests.test_the_planner_finishes_the_dying_unit`과 같은 판). 끄면 잡지 않고 켜면 잡는다 |
| 3 | 켠 값이 닿는다 | 벤치마크 판 11개에서 켠 값의 계획 수치·첫 행동이 끈 값과 달라지고, 거절·지금 AI로 넘긴 것·후보 예외가 0이다 |
| 4 | 기본 적 AI는 그대로 | 기존 Core 적 AI 시험(측정 도구, 614개 중 통과 603·건너뜀 11)이 전과 같다 |
| 5 | Unity | 컴파일, EditMode 시험(`EnemyAdvancePreparation`·`EnemyAiTuning`), 인스펙터의 새 칸, 재생 때 콘솔 줄 끝의 값, 재생에서 적이 다 죽어가는 유닛을 잡는지 — 사용자 확인 |

- 시뮬레이터와 Unity 판의 판 값이 같은 수인지 대조하는 일(TP-10)은 이번에도 하지 않는다. 식이 같은지는 코드 대조로만 본다.
- Unity에서 "칠 수 있는데 안 침"을 세는 도구는 없다. 재생을 눈으로 보는 것이 확인이다.

## 5 범위 밖

- 성격 값: 안정 운영형(`p1:y1`)은 시뮬레이터에서 경계에 있고(손잡이 설계 §15) 이번에는 옮기지 않는다. 옮길 때는 값 둘(자기 보존, 다친 유닛 살리기)과 프리셋 에셋 하나("안정 운영")다.
- 집단 돌입형·역할 정적형: 시뮬레이터에서도 아직 없다.
- 본부가 맞을 때 남은 유닛이 몸을 사리는 문제(손잡이 설계 §13.8).
- 계획 시간 줄이기, 배경 스레드(다른 세션의 [배경 병렬 설계](2026-11-18-planner-background-parallel-design.md)).

## 6 정할 것 — **모두 A로 정함(2026-11-19 사용자 "권장대로 진행해")**

| 번호 | 내용 | 권장 |
|---|---|---|
| Q-VP1 | 게임에서 켤지 | **A** 코드 기본값은 끔, 기본 프리셋 에셋에서 켠다(행동 규칙 0.25·걸음 벌점 대상 고정·기회 모으기). 옛 값 프리셋 에셋을 하나 남긴다 / B 기본 프리셋은 그대로 두고 새 프리셋 에셋만 만든다(조정 에셋에서 바꿔 끼워야 켜진다) |

| Q-VP4 | 성격 프리셋(안정 운영형)도 같이 | **A** 이번에는 넣지 않는다. 셋이 Unity에서 확인된 뒤 따로 / B 같이 넣는다 |

  - **U8에서 움직이는 방향은 뜻이 없다.** 길이 없으면 걸음 벌점이 모든 칸에서 0이라 이동 후보의 값이 모두 같고, 먼저 만든 후보가 뽑힌다. 이 판에서는 8마리가 플레이어 반대쪽 구석으로 3칸씩 간다. 규칙의 정의대로다(손해가 없으면 행동한다). 길이 전혀 없는 판에서만 생긴다.
- **확인 2(막판 판):** 끔·행동 규칙만 = HP 1 유닛을 안 잡음, 대상 고정을 켠 값 셋(대상 고정만 / 대상 고정 + 기회 모으기 / 셋 다) = 잡음, 기회 모으기만 = 안 잡음.
- **G16 다시 보기(Q-VP6 A):** 행동 규칙을 더해도 그대로다. 끔·행동 규칙만 = 이번 턴에 메인을 잡음, 대상 고정 + 기회 모으기·셋 다 = HP 20 남김. VP-d의 Unity 재생 확인 항목에 "메인을 잡을 수 있는 턴에 잡는가"를 넣는다.
- 시험 실행기가 저장소 루트에 만든 `TestResult.xml`은 지웠다.
