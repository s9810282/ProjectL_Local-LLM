# 룰 AI 설계 보완과 오프라인 비교 계획

작성일: 2026-10-15

Unity 전투 연결 전에 메인 압박과 반복 공격 위험을 보완하고, 엔진·Ollama 서버 없이 JSON 상황의 두 정책을 비교한다. 이번 승인 범위는 설계 개정과 독립 Python 검증 도구다. 기존 게임 로직·에셋·Ollama 실험 파일은 보존한다.

## 1 Phase A 실행 범위

1. 설계 v2: 메인 피해를 고정 10 HP 기준으로 바꾸고 계수 30을 적용한다. 반복 위험은 AP 예산 또는 공격별 시퀀스로 검증한다.
2. 설정: 공식 계수와 역할 기준을 `config/rule_weights.json`에 모은다. 이전 v1과 두 변경의 개별 적용은 비교 프로필로 만든다.
3. 입력: 기존 S01~S06을 보존하고 `rule_fixtures`에 버전 있는 synthetic 상황을 작성한다. 기대 선택과 이유는 계산 결과를 보기 전에 기록한다.
4. 평가: `tools/rule_policy.py`는 공통 특징·전술 점수·역할 점수·제외 사유를 계산한다. 입력이 불완전하면 미평가로 처리한다.
5. 실행: `tools/run_rule_test.py`는 단일·일괄 실행, 이전식 비교, 계수 민감도, JSON·CSV·Markdown 결과 저장을 지원한다.
6. 검증: 의미 있는 입력 검증·종료 우선순위·반복 비용·환급 선지불 금지·사망 경계·순서 불변 조건을 자동 확인한다.
7. 보고: 예상과 실제 선택, 이전식과의 차이, 계수 변화로 뒤집히는 상황, 남은 모델 한계를 기록한다.

Phase A 완료 뒤 멈추고 결과를 리뷰한다. Unity 연결·Core API 변경·실제 게임의 후보 자동 생성은 다음 Phase이며 이번에 시작하지 않는다.

## 2 계산 전에 정한 대표 기대 판단

| 사례 | 기대 판단 또는 비교 목적 |
|---|---|
| 즉시 메인 처치 | 두 정책 모두 종료 승리 우선 |
| 메인 6 피해와 일반 8 피해 | 두 정책 메인 압박. 이전식은 일반 피해 |
| 메인 6 피해와 일반 빈사 처치 | 두 정책 일반 제거. 압박이 모든 처치를 덮지 않음 |
| Ballista의 반복 공격 노출과 안전 이동 | 반복 AP를 포함하면 두 정책 안전 이동, 단발 근사와 차이 확인 |
| 같은 단발 피해와 다른 AP | 많은 반복 기회가 있는 노출을 낮게 평가 |
| Gravekeeper의 유효 넉백 | 전술 차이가 작을 때 역할 정책은 본진에서 밀어내는 후보 선호 |
| 기존 Ballista 설명의 메인 4 피해 | 입력을 그대로 보존해 재계산. 새 메인 기준에서 두 정책이 관통으로 같아질 수 있음 |
| 과도한 역할 손실 | 허용 차이 밖 역할 후보 제외 |
| 아군 피해 동반 포격 | 실제 아군 손실과 적 이득을 분리 표시 |
| 빈사 행위자의 무익한 사망 | 위험이 사라진다는 이유로 사망이 유리해지지 않음 |
| 불법 이동 후 공격 | 기본 AP 5에서 Ballista 이동 3 후 공격 4는 제외 |
| 비용 4 공격 뒤 환급 2, 시작 AP 3 | 환급을 선불처럼 사용하지 않음 |
| 반격자 처치·행동 기회 없음 | 해당 공격을 위험에 포함하지 않음 |
| 관측 누락·불완전 순서 | 0 위험으로 대체하지 않고 미평가 |

계수 민감도는 한 번에 한 항목만 바꾼다. 메인 계수 20·25·30·35·40, 위험 할인 0.25·0.5·0.75·1, 역할 허용 차이 0·6·12·18, 역할 보너스 10·20·30을 비교한다. 민감도 결과를 기대값에 맞추기 위해 상황을 바꾸지 않는다.

## 3 경계와 원본

- JSON은 합법성·피해·행동 순서를 수작업 가정으로 제공한다. Python은 Core 규칙 엔진이 아니다.
- Core의 HP·AP·상태를 직접 변경하거나 View에서 전투 규칙을 복제하지 않는다.
- 반복 고정 모드는 불변 최종 피해·양수 비용·환급 없음일 때만 사용한다. 변동 효과는 명시 시퀀스와 가정으로 제공하거나 미평가다.
- 숫자 설정은 한 파일을 원본으로 사용하고 실행 결과에 설정과 입력 해시를 보관한다.
- 소수 계산과 비교는 Decimal을 사용하며 bool·NaN·무한대·누락 값을 정상 숫자로 받지 않는다.
- 실행할 때마다 별도 결과 폴더를 만들고 이전 결과를 덮어쓰지 않는다.
- 기존 스테이징·커밋·원격 연결을 변경하지 않는다. 커밋·push는 사용자 담당이다.

## 4 실행 기록

Phase A 완료. 설계 v2와 설정 원본, 평가기·실행기·16개 JSON 상황을 추가했다. 2026-10-15 최종 실행에서 16개 프로필 × 16개 상황을 비교했고 기본 기대 판단 불일치는 0개였다. 이 중 14개는 선택 평가, 2개는 의도된 미평가다. 경계 검증 18개가 통과했다.

결과는 [대표 비교와 계수 판단](2026-10-15-rule-ai-offline-comparison.md), [원본 실행 보고서](../results/rules/20261015T065616.016452Z/report.md)에 있다. 메인 계수와 위험 할인에 따라 선택이 뒤집히는 상황을 확인해 가중치를 최종 확정하지 않았다. 게임 구현은 시작하지 않고 리뷰 지점에서 멈춘다.
